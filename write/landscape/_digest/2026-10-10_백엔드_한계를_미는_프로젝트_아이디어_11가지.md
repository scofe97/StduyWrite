## 요점

- 검색 엔진 기본기: 웹 문서 수집(크롤링 또는 공식 덤프), HTML 정규화, 불용어 제거, 역색인 및 BM25 랭킹 알고리즘 적용으로 파이프라인을 구축합니다.
- 하이브리드 검색과 RAG: BM25 색인과 벡터 DB를 결합한 하이브리드 검색을 구성하고, 검색 문맥을 프롬프트에 주입해 LLM 답변을 생성합니다.
- GitHub App 기반 대량 처리: Webhook 10초 내 응답을 위해 이벤트를 큐에 넣고, 워커가 JWT 설치 토큰과 API 한도를 관리하며 diff를 분석합니다.
- 배포 플랫폼 파이프라인: 요청 큐잉, 컨테이너/MicroVM 빌드 실행, 배포 ID별 S3 불변 산출물 저장, 리버스 프록시 라우팅으로 무중단 롤백을 구현합니다.
- 백엔드 포트폴리오 핵심 난점: 알고리즘보다 외부 API 연동, 비동기 작업 큐, 분산 세션 공유(Redis 브로커), 빌드 격리 인프라가 시스템 완성도를 결정합니다.



## 경고

- ⚠ 질의 확장으로 인한 출처 편향 제거 단언: 질의를 여러 개 만들어 재귀 탐색해도 검색 재현율이 높아질 뿐 출처 자체의 편향은 제거되지 않습니다 (원문 78줄, 156줄). — 미확인: 출처 편향 여부는 설계 의견이라 근거 없음
- ⚠ 단순 블록 결합을 "정교한 RAG"로 표현: 검색된 문맥을 프롬프트에 붙이는 구조는 RAG의 가장 기본형에 해당합니다 (원문 78줄, 155줄). — 미확인: RAG 기본형 여부는 용어 평가라 근거 없음
- ⚠ Vercel 배포 시스템을 단순 Docker 컨테이너 실행으로 단순화: 멀티테넌트 환경에서 임의 사용자 코드를 실행할 때 커널 공유 취약점이 있으므로 MicroVM 등의 격리 계층이 필요합니다 (원문 108~116줄, 159줄). — 확인됨: [Firecracker v1.10.0](https://raw.githubusercontent.com/firecracker-microvm/firecracker/v1.10.0/README.md) (멀티테넌트용 마이크로VM 격리 목적만, 커널 공유 서술은 문서에 없음)
- ⚠ YC 투자사 즉시 취업 등 과장 홍보: 온라인 강의 플랫폼 프로모션 구간과 맞물린 근거 없는 홍보성 표현입니다 (원문 34줄, 161줄). — 미확인: 강의 홍보 표현은 공식 문서 대상 아님
- ⚠ Skribbl 클론 다중 서버 증설 시 상태 공유 누락: 서버를 2대 이상으로 늘리면 단일 서버 메모리만으로는 방 상태 전달이 불가능해 Redis Pub/Sub 등 이벤트 브로커가 필요합니다 (원문 136줄). — 확인됨: [Socket.IO 다중 노드](https://raw.githubusercontent.com/socketio/socket.io-website/f0c28bb342afa96b0c4ff64c5e87948d1448330e/docs/categories/02-Server/using-multiple-nodes.md)
- 확인됨: 검색 엔진 랭킹 기본 유사도로 BM25를 채택하는 설명은 공식 명세와 일치합니다 ([Elasticsearch 유사도 문서](https://www.elastic.co/docs/reference/elasticsearch/index-settings/similarity)).
- 확인됨: GitHub App은 사용자 OAuth가 아닌 JWT 기반 1시간 만료 설치 토큰으로 동작합니다 ([GitHub Apps 토큰 문서](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-an-installation-access-token-for-a-github-app)).
- 확인됨: 대량 PR 처리는 Webhook 10초 내 응답([GitHub Webhooks 문서](https://docs.github.com/en/webhooks/using-webhooks/best-practices-for-using-webhooks))과 API 호출 한도([GitHub Rate Limits 문서](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api))를 고려해야 합니다.
- 확인됨: Vercel 배포 시 고유 URL 부여와 45분 빌드 시간제한은 공식 명세와 일치합니다 ([Vercel Deployments](https://vercel.com/docs/deployments), [Vercel Builds](https://vercel.com/docs/builds)).
- 확인됨: 사진 얼굴 매칭의 특징값 추출은 민감정보에 해당해 정보주체 동의가 필요합니다 ([개인정보보호법 시행령](https://www.law.go.kr/법령/개인정보보호법시행령) 제18조 제3호).
