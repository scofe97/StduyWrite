## 요점

- 에이전트 멀티플렉서 필요성: 코딩 에이전트 다중 구동 환경에서는 터미널 확인과 타이핑이 사람의 병목이 됩니다. 따라서 세션 지속성과 병렬 시야 및 원격 실행을 지원하는 멀티플렉서가 요구됩니다.
- 상태 인식과 tmux 호환성: tmux 구조와 키 바인딩을 유지하며 사이드바에 에이전트 상태를 색상으로 표시합니다. 상태는 `working`·`blocked`·`done`·`idle`로 나뉘며 공식 안내([`herdr --skill`](../../10_AI/docs/herdr/01-01.CLI reference.md) 확인됨)와 맞습니다.
- 상태 전이 규칙과 저장소 격리: 상태는 TUI 클라이언트 포커스 여부로 갱신됩니다. 여러 세션 간 코드 충돌을 막는 저장소 격리는 도구가 아닌 git worktree가 전담합니다.
- 오케스트레이터 에이전트 운용: 메인 에이전트가 소켓 API와 창 식별자를 이용해 서브에이전트 창을 생성하고 작업을 분배합니다. 사람은 진행 중 개입과 가설 검증에 집중합니다.
- 야간 무중단 실행과 시스템 잠자기 제약: 멀티플렉서는 터미널 종료만 방지합니다. 단독 노트북 환경에서 덮개를 닫으면 Herdr 서버와 프로세스가 모두 중단됩니다.
- closed-display 환경 구성: 장시간 로컬 실행은 덮개를 열고 전원을 연결해야 합니다. 덮개를 닫으려면 전원과 외부 디스플레이를 연결한 closed-display mode를 구성해야 합니다([공식 지원 문서](https://support.apple.com/en-us/102501) 확인됨).
- 오픈소스 지표 및 투자 이력: 저장소 스타 수와 인큐베이터 투자 이력 등 공개 지표가 공식 경로로 확인되었습니다([GitHub 저장소](https://github.com/herdrdev/herdr), [투자사 페이지](https://www.ycombinator.com/companies/herdr) 확인됨).



## 경고

- ⚠ 노트북을 덮어도 에이전트가 돌아간다는 단정: 원문은 노트북을 덮어도 에이전트가 계속 동작한다고 단정합니다(22·87행). 로컬 노트북은 덮개를 닫으면 프로세스가 중단되므로 원격 서버나 closed-display mode가 필수적입니다. — 미확인: 덮개 닫힘 동작은 공식 원문을 못 찾음
- ⚠ 자식 에이전트의 권한 생략 모드 자율 선택: 원문은 메인 에이전트가 지시 없이 자식 창의 위험 권한 스킵 모드를 골랐다고 서술합니다(75행). 프롬프트 브리프에 금지 행동이 명시되었는지는 확인되지 않았습니다. — 미확인: 프롬프트 브리프 내용은 공식 문서 대상 아님
- ⚠ 미확인 도구 명칭(에이전트용 브라우저): 원문에서 언급된 브라우저 '어사이드'는 자막만으로 실존 여부나 명칭이 확인되지 않았습니다(36행). — 미확인: 자막 속 도구 명칭은 공식 근거 없음
- ⚠ 타 도구의 잠자기 방지 assertion 여부 미확인: 원문은 특정 도구의 `caffeinate -i` 실행만 확인했습니다(93행). 다른 에이전트 CLI 환경에서도 동일하게 유휴 잠자기를 방지하는지는 검증되지 않았습니다. — 미확인: 타 도구 동작은 공식 문서 대상 아님
