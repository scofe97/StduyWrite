## 요점

- 컨테이너 본질: 리눅스 커널에 `struct container` 객체는 없으며, Namespace(시야 격리)·cgroups(자원 제한)·OverlayFS(계층 조립) 커널 기능의 조합임
- Pod 2-3-2 결합 아키텍처: 호스트 보호 2개(User·cgroup), Pod 공유 3개(Network·IPC·UTS), 컨테이너 개별 격리 2개(PID·Mount)의 3계층 구조로 조율함
- pause 컨테이너 역할: RunPodSandbox 단계에서 기동되어 공유 네임스페이스를 유지(Holding)하고, sigreap 핸들러로 좀비 프로세스를 수거하며 Pod 재시작 시에도 고유 IP를 보존함
- PID 1번 책임과 생명주기: 컨테이너 내부 PID 1 프로세스 종료 시 커널이 zap_pid_ns_processes()를 호출하여 내부 모든 프로세스를 SIGKILL로 즉시 정리함
- 호스트 침해 통제: `hostPID: true` 설정 시 호스트 초기 네임스페이스(Inode 4026531836)에 진입하므로 PSA(Pod Security Admission) restricted 프로파일로 원천 차단함
- CNI 책임 주체 변화: Kubernetes 1.24 dockershim 제거 이후 kubelet 대신 containerd가 pause 컨테이너 생성과 CNI 플러그인 호출(veth pair 연결 및 IP 할당)을 전담함
- 무침습 노드 진단: 경량 이미지 컨테이너 장애 시 호스트의 일방 통행 시야와 `nsenter`를 활용해 타깃 네임스페이스에 진입하여 패킷·소켓 상태를 디버깅함
- 런타임 안정성 보장: containerd 데몬과 runc 프로세스 사이에 containerd-shim을 두어 데몬 재시작 중에도 Pod의 네임스페이스와 표준 입출력(stdio)을 유지함



## 경고

- ⚠ "Time Namespace는 현재 runc 및 Kubernetes에서 사용하지 않음" — runc는 OCI 명세에 따라 Time 네임스페이스를 지원하므로 runc 미지원 단정은 공식 기능과 차이가 있습니다 (원문 208~209줄, 820줄). — 확인됨: [runc v1.2.0 CHANGELOG](https://raw.githubusercontent.com/opencontainers/runc/v1.2.0/CHANGELOG.md)
- ⚠ "Kubernetes 기본 설정에서 /dev/shm 크기는 항상 64MB로 제한됨" — 컨테이너 런타임 종류와 CRI 설정에 따라 기본 크기 정책이 다를 수 있어 일괄 64MB 단정은 검증이 필요합니다 (원문 104~105줄). — 확인됨: [containerd oci/mounts.go](https://raw.githubusercontent.com/containerd/containerd/v1.7.0/oci/mounts.go) (containerd 기본 64MB, CRI-O 는 annotation 으로 변경 가능)
- ⚠ "Kubernetes 1.30+에서 hostUsers: false로 User NS 격리 활성화" — 커널 idmapped mounts와 스토리지 지원 제약이 따르는 기능입니다 (원문 398·971·1331줄). — 확인됨: [Kubernetes User Namespaces](https://raw.githubusercontent.com/kubernetes/website/release-1.35/content/en/docs/concepts/workloads/pods/user-namespaces.md)
- ⚠ "unshare와 mount -t proc으로 컨테이너 조립 가능" — unshare(1) 는 util-linux 2.27 부터 새 마운트 네임스페이스를 기본 private 으로 바꿉니다. 그대로 mount -t proc 해도 호스트 /proc 에 전파되지 않으며, --propagation unchanged 로 이 동작을 껐을 때만 shared 전파 위험이 생깁니다. — 정정: [unshare(1) man](https://raw.githubusercontent.com/util-linux/util-linux/v2.40/sys-utils/unshare.1.adoc)
