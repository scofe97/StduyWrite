## 요점

- 플랫폼 종속성과 접근 통제: Spotify·Reddit·Amazon 등 외부 플랫폼 API에 전적으로 의존하는 프로젝트는 쿼터 축소, 유료화, 스크래핑 차단 같은 정책 변경에 의해 서비스 지속성이 쉽게 무너집니다.
- BitTorrent P2P 네트워킹 핵심: .torrent 메타데이터는 JSON이 아닌 bencode 포맷을 파싱해야 하며, 트래커 질의, 피어 핸드셰이크, 피어 와이어 프로토콜 메시지 제어, 20바이트 SHA-1 조각 해시 검증이 핵심 구현 과제입니다.
- 로컬 SLM 및 프라이버시 보호: 은행 거래내역 등 민감 금융 정보는 외부 API 전송을 지양하고 Ollama 기반 로컬 소형 모델로 처리하며, 금액 산출 오류는 행별 잔액 연속성 검증(대사) 코드로 보정합니다.
- OS 접근 권한의 물리적 한계: 휴대폰 잠금 같은 앱은 OS 전체 차단이 불가능하므로 Android Lock Task(Device Owner 전용)나 iOS Screen Time API(FamilyControls) 같은 플랫폼 제약 내에서 권한을 다뤄야 합니다.
- 백엔드 포트폴리오 선정 기준: 플랫폼 정책 변경에 취약한 API 래퍼보다 BitTorrent(바이너리 프로토콜·TCP 연결·무결성 검증)나 타임캡슐(스케줄링·암호화·발송 멱등성)처럼 복잡성이 서버 코드 내부에 존재하는 프로젝트가 유리합니다.



## 경고

- ⚠ torrent 파일을 JSON 딕셔너리로 바꾼다는 설명: torrent 파일은 bencode 포맷이며 info hash 계산과 조각별 SHA-1 해시 검증이 필수입니다 (원문 82~90줄, 180줄). — 확인됨: [BEP 3](https://www.bittorrent.org/beps/bep_0003.html)

- ⚠ AI들이 비밀리에 동맹을 맺고 제작자에게 맞섰다는 단언: 객관적 근거가 제시되지 않은 화자의 주관적 관찰담입니다 (원문 42줄, 132줄). — 미확인: 화자의 주관적 관찰이라 공식 근거 없음
