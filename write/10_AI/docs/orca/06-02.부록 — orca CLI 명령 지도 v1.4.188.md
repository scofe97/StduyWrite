# 부록 — orca CLI 명령 지도 v1.4.188
---
> 명령 232개를 그룹으로 묶어 어디를 보면 되는지만 알려 주는 지도입니다. 개별 사용법은 여기 옮기지 않습니다 — 설치본의 스키마가 항상 더 정확하기 때문입니다.

## 이 부록의 쓰임

> 외울 대상이 아니라 찾을 자리를 알려 주는 표입니다. 정확한 사용법은 언제나 설치본에서 뽑습니다.

<!-- no-diagram: 이 부록의 사용법을 안내하는 메타 절이라 그릴 구조가 없습니다. -->

명령을 외우지 않아도 됩니다. 세 명령이면 어떤 버전에서도 정답이 나옵니다.

```bash
orca agent-context --json    # 전체 명령 스키마 — usage · flags · notes · examples
orca skills get <주제>        # 설치 버전과 짝이 맞는 공식 가이드
orca <명령> --잘못된플래그     # 오류 응답의 validFlags 가 정답을 알려 줍니다
```

마지막 줄이 실전에서 가장 빠릅니다. 다만 모든 명령이 친절하지는 않습니다. 메시지 타입처럼 목록 없이 짧게 거부하는 자리도 있습니다.

아래 표의 개수는 이 맥북에서 조회한 값이라 **버전이 다르면 달라집니다.**[^count]

나머지 49개 그룹에 53개 명령이 흩어져 있고 대부분 브라우저 조작 동사입니다. 브라우저 계열을 전부 합치면 46개 그룹 77개 명령으로 전체의 33%입니다.

```bash
snapshot  goto  back  forward  reload  click  dblclick  fill  type  inserttext
keypress  hover  drag  scroll  scrollintoview  select  check  uncheck  focus  clear
find  get  is  wait  eval  exec  screenshot  full-screenshot  pdf  console
network  dialog  download  upload  viewport  geolocation  clipboard  highlight  capture
```

**이 평면 배치가 브라우저 계열이 3분의 1에 가까운 비중을 차지하는 이유입니다.** 다른 영역은 `worktree create`처럼 두 단어인데 브라우저는 `click` 하나로 최상위에 놓입니다. 에이전트가 짧게 쓰도록 만든 배치입니다.

나머지는 진단과 실행에 쓰는 것들입니다.

```bash
status  open  serve  agent-context  diagnostics  account  host  vm  claude-teams
```



## 2. 원서 기준과의 차이

> 명령 수와 구성이 버전마다 움직입니다. 원서를 읽을 때 이 표를 옆에 두면 어긋나는 자리를 알 수 있습니다.

![v1.4.154 · v1.4.176 · v1.4.188 의 명령 수 변화](_assets/06-02-version-delta.svg)

| 기준 | 전체 | 오케스트레이션 | 비고 |
|------|------|---------------|------|
| v1.4.154 (원서 앞부분) | 206 | 16 또는 17 | 원서 안에서 02-4와 05-1이 다르게 적었습니다 |
| v1.4.176 (원서 대부분) | 223 | 31 | Run·워커 명령이 들어온 시점 |
| **v1.4.188 (이 노트)** | **232** | **29** | `orchestration run` · `run-stop` 이 스키마에서 사라졌습니다 |

전체는 늘고 오케스트레이션은 줄었습니다. 은퇴 처리가 두 갈래였기 때문입니다.

- `orchestration run` · `run-stop` — 스키마에서 제거
- `coordinator-start` · `coordinator-stop` — 목록에는 남되 호출하면 `orchestration_migration_required`

이 노트를 쓰며 확인한 다른 차이들은 본문 각 편에 적어 두었습니다. 대표적인 것만 옮깁니다.

| 항목 | 원서 | v1.4.188 |
|------|------|----------|
| `click` 이벤트 전달 | 안 됨 (v1.4.163~176 회귀) | **고쳐짐** |
| `check` 기본 동작 | 읽음 처리 | `--ack` 로 명시 확인 |
| 잘못된 메시지 타입 응답 | 8종 목록 안내 | `Invalid input` 만 |
| `cookie` 하위 명령 | get · set | get · set · **delete** |
| `intercept` 하위 명령 | (add 로 서술) | enable · disable · list |
| `--max-concurrent` | 필수 안전장치로 서술 | 은퇴 스텁에만 남음 |



## 3. 자주 틀리는 플래그

> 규칙에서 벗어난 자리만 모았습니다. 나머지는 대체로 예상대로 동작합니다.

![명령별로 예상과 다른 플래그 이름](_assets/06-02-flag-traps.svg)

| 명령 | 틀리기 쉬운 것 | 맞는 것 |
|------|---------------|---------|
| `orchestration gate-resolve` | `--gate` | **`--id`** (다른 게이트 명령은 `--task`) |
| `repo set-base-ref` | `--base-ref` | `--ref` |
| `automations create` | `--cron` | `--trigger` (값으로 cron 을 받습니다) |
| `find` | 플래그 생략 | `--action` 이 필수입니다 |
| `skills get` | `--skill <주제>` | 주제를 위치 인자로 |
| `vm recipe doctor` | 레시피 id 생략 | 위치 인자로 필수 |
| `terminal create` 응답 | `result.handle` | **`result.terminal.handle`** |

마지막 줄은 플래그가 아니라 응답 구조인데, 이 노트를 쓰며 실제로 걸린 자리라 함께 넣었습니다. 잘못 꺼낸 빈 값을 넘기면 뒤따르는 명령이 전부 `terminal_handle_stale`을 돌려주고, 존재한 적 없는 핸들도 같은 코드를 주기 때문에 원인을 찾기 어렵습니다.

응답 구조에 예외가 하나 더 있습니다. `vm recipe doctor`만 결과를 `result` 안에 담지 않고 최상위에 그대로 돌려줍니다.



## 4. 이 노트가 다루지 않은 영역

> 원서에는 있으나 이 노트에서 다루지 않은 자리를 밝혀 둡니다.

<!-- no-diagram: 다루지 않은 범위를 나열하는 절이라 그릴 구조가 없습니다. -->

`linear` 27개는 통째로 비워 두었습니다. 워크스페이스가 있어야 확인할 수 있는데 이 노트에는 없었습니다. 명령 수가 터미널보다 많다는 사실만 [01-02](01-02.ORCA의 구성 — 앱·런타임·CLI·워크트리.md)에 적었습니다.

`emulator` 16개도 붙어 있는 기기가 없어 목록 조회까지만 확인했습니다. iOS 시뮬레이터는 macOS 전용이라 원서가 미실측으로 남긴 영역이고, 이 환경에서 채울 수 있는 자리입니다.

`artifacts`·`storage`·`mouse`·`capture` 같은 브라우저 주변 명령은 존재만 확인했습니다.

원격 런타임과 환경 레시피는 개념까지만 다뤘습니다. 두 번째 기기와 클라우드 계정이 필요합니다.

**공통점이 있습니다.** 전부 확인 수단이 없어서 비운 것이지 중요도가 낮아서가 아닙니다. 원서가 `[참고]` 배지로 같은 구분을 한 것과 같은 이유입니다.
