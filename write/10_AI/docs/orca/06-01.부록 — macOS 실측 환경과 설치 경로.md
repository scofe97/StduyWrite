# 부록 — macOS 실측 환경과 설치 경로
---
> 원서는 Windows 11 기준이고 macOS 절차를 미실측으로 남겼습니다. 이 부록은 그 자리를 채웁니다. 본문 열 편이 서 있는 환경이 무엇인지 밝히는 것이 목적이라 개념 설명은 하지 않습니다.

## 이 노트의 기준 환경

> 본문에서 "실측"이라고 적은 것은 전부 이 구성에서 확인한 값입니다.

<!-- no-diagram: 환경 값을 나열하는 표라 그릴 형태가 없습니다. -->

| 항목 | 값 |
|------|-----|
| OS | macOS (darwin, arm64) |
| ORCA | **v1.4.188** — 원서 기준은 v1.4.176, 일부 절은 v1.4.154 |
| 설치 방식 | Homebrew cask `stablyai/orca` |
| 앱 | `/Applications/Orca.app` |
| CLI | `/opt/homebrew/bin/orca` → 앱 안 실행 파일로 이어지는 심볼릭 링크 |
| 실습 저장소 | 홈 아래 연습용 git 저장소 (본문 예제의 `orca-practice`) |
| 코딩 에이전트 | 실측에서는 셸 터미널만 사용 |

마지막 줄을 밝혀 둡니다. 터미널 운전과 오케스트레이션 실측은 **셸과 짧은 명령으로** 했습니다. 에이전트 TUI에서만 관측되는 항목(작업 중 화면 정지 판정 같은 것)은 원서 서술을 그대로 인용하고 "원서 기준"으로 표시했습니다.



## 1. macOS 설치 구조

> 원서가 적은 Windows 구성과 부품이 하나씩 대응합니다. 이름만 플랫폼에 맞게 바뀝니다.

![Windows 설치 구성과 macOS 구성의 부품 대응](_assets/06-01-layout.svg)

앱 번들 안에 CLI와 번들 엔진이 함께 들어옵니다. [01-02](01-02.ORCA의 구성 — 앱·런타임·CLI·워크트리.md)에서 본 "브라우저 자동화가 왜 추가 설치 없이 되는가"의 답이 여기서도 확인됩니다.

```bash
ls /Applications/Orca.app/Contents/Resources/
# agent-browser-darwin-arm64   ← 원서의 agent-browser-win32-x64.exe 에 대응
# bin/                          ← CLI
# app.asar                      ← 앱 코드 묶음
```

CLI는 별도 설치물이 아니라 앱 번들 안의 실행 파일이고, Homebrew가 그것을 `PATH`에 링크해 둡니다.

```bash
which orca
# /opt/homebrew/bin/orca
readlink $(which orca)
# /Applications/Orca.app/Contents/Resources/bin/orca
```

**앱을 지우면 CLI도 함께 사라진다**는 뜻입니다. 링크만 남으면 명령이 깨집니다.

워크트리가 만들어지는 자리는 원서의 Windows 경로와 형태가 같았습니다. 홈 디렉터리 아래 `orca/workspaces/<프로젝트>/<워크트리>`이고 구분자만 다릅니다.

컴퓨터 유즈 쪽은 구성이 다릅니다. macOS에서는 접근성 주체가 앱 본체가 아니라 번들 안의 **별도 헬퍼 앱**입니다. 시스템 설정에서 찾을 이름이 `Orca`가 아니라는 뜻이라, [04-02](04-02.화면 밖 자동화 — 컴퓨터 유즈·에뮬레이터·예약 실행.md)에서 따로 짚었습니다.



## 2. Homebrew 이름 충돌 — 확인해야 할 함정

> `brew` 명령에서 tap을 생략하면 전혀 다른 제품이 잡힙니다. 버전 표시까지 이상해집니다.

![tap 지정 여부에 따라 다른 제품이 잡히는 상황](_assets/06-01-tap-collision.svg)

이 맥북에서 실제로 마주친 것입니다.[^tap] Homebrew의 기본 저장소에도 `orca`라는 이름의 cask가 있는데 **완전히 다른 제품**입니다.

```bash
brew info --cask orca
# ==> orca (Orca): 1.4.188 → 1.3.1
# Generate images of interactive plotly charts
# https://github.com/plotly/orca/
# Deprecated because it does not pass the macOS Gatekeeper check!
```

설치된 것은 1.4.188인데 "1.3.1로"라는 화살표가 붙고, 관계없는 제품의 폐기 예고가 함께 나옵니다. 이 출력만 보면 자기가 쓰는 도구가 곧 사라지는 줄 알게 됩니다.

tap을 붙이면 제대로 나옵니다.

```bash
brew info --cask stablyai/orca/orca
# ==> orca (Orca): 1.4.188 (auto_updates)
# IDE for orchestrating AI coding agents across terminals and worktrees
# https://onorca.dev/
```

**`brew upgrade --cask orca`처럼 tap 없이 쓰는 명령은 위험합니다.** 이름만 같은 다른 제품으로 바꾸려 들 수 있습니다. tap을 명시하거나, `auto_updates`가 붙어 있으니 앱 자체의 업데이트에 맡기는 편이 안전합니다.

이 함정을 확인하는 방법은 단순합니다.

```bash
brew tap | grep orca                 # stablyai/orca 가 있는지
brew list --cask --versions orca     # 실제 설치 버전
```



## 3. 버전을 확인하는 방법

> 다른 CLI의 습관대로 버전 플래그를 주면 도움말이 나옵니다. 원서가 실측에서 제일 먼저 걸린 지점이고 v1.4.188도 같습니다.

<!-- no-diagram: 명령 두 개의 결과를 비교하는 짧은 절이라 그릴 구조가 없습니다. -->

```bash
orca --version
# orca
#
# Usage: orca <command> [options]
# ...
```

오류도 내지 않고 도움말을 보여 주기 때문에 "왜 버전이 안 나오지" 하며 한참 헤매게 됩니다. 정확한 값은 상태 조회에서 나옵니다.

```bash
orca status --json | python3 -c "import json,sys; print(json.load(sys.stdin)['result']['runtime']['appVersion'])"
# 1.4.188
```

Homebrew로 설치했다면 그쪽에서도 볼 수 있습니다. 다만 앞 절의 이유로 tap을 붙이거나 `brew list --cask --versions`를 씁니다.

명령 개수까지 함께 보고 싶으면 이쪽이 한 번에 끝납니다.

```bash
orca agent-context --json | python3 -c "import json,sys; d=json.load(sys.stdin); print(d['commandCount'], 'commands, schema v'+str(d['schemaVersion']))"
# 232 commands, schema v1
```



## 4. 원서 절차 중 macOS에서 달라지는 것

> 설치 이후의 명령은 플랫폼과 무관하게 같습니다. 달라지는 것은 셸 문법과 경로 표기입니다.

![원서의 Windows 절차와 macOS 절차가 갈리는 지점](_assets/06-01-differences.svg)

본문에서 확인한 차이를 한자리에 모읍니다.

| 항목 | 원서 (Windows) | 이 맥북 |
|------|----------------|---------|
| 명령 종료 이어붙이기 | `--command "<명령> & exit"` | **`; exit`** — `&`는 백그라운드라 zsh가 첫 `exit`를 거부합니다 |
| 사전 검사에서 빈 출력 거르기 | `\| findstr . >nul` | `\| grep -q .` |
| 컴퓨터 유즈 승인 | `unsupported` (승인 항목 없음) | `not-granted` + 별도 헬퍼 앱 승인 필요 |
| iOS 시뮬레이터 | 사용 불가 | 사용 가능 (원서가 미실측으로 남긴 영역) |
| 콘솔 인코딩 | cp949 문제 서술 | 해당 없음 |

**CLI 명령 자체는 플랫폼과 무관하게 같습니다.** 셀렉터 표기, 응답 구조, 오류 코드가 전부 동일했습니다. 원서의 예제를 macOS에서 따라갈 때 손볼 곳은 위 표의 셸 문법 두 줄과 경로 표기뿐입니다.
