# CLI reference
---
> herdr 를 키보드가 아니라 명령으로 다루는 법을 모았습니다. 다른 창의 화면을 읽거나, 다른 창의 에이전트에게 글을 보내거나, 기능 브랜치를 workspace 로 열 때 씁니다.



## 핵심 요약

> herdr 명령은 workspace·tab·pane·agent·worktree 다섯 대상을 다루고, 결과를 JSON 으로 돌려줍니다. 다른 창에 글을 보낼 때는 Claude 가 떠 있는 창이면 `agent prompt`, 셸만 있는 창이면 `pane run` 을 씁니다.

herdr 는 터미널 안에서 도는 작업 공간 관리자입니다. 화면은 세 단계로 짜입니다.

- **workspace**: 작업 단위 하나. 사이드바에 하나씩 보입니다
- **tab**: workspace 안의 화면 하나
- **pane**: tab 을 나눈 창 하나. 이 문서에서는 "창"이라고 부릅니다

창 안에서 Claude 같은 코딩 에이전트가 돌면 herdr 는 그 창을 **agent** 로도 부릅니다. 그리고 그 에이전트가 일하는 중인지 쉬는 중인지를 따로 추적합니다. 명령은 이 대상마다 하위 명령으로 나뉩니다.

| 하고 싶은 일 | 명령 |
|------|------|
| 열린 workspace 보기 | `herdr workspace list` |
| 한 workspace 의 창 보기 | `herdr pane list --workspace <ID>` |
| 에이전트와 상태 보기 | `herdr agent list` |
| 다른 창 화면 읽기 | `herdr pane read <창 ID> --lines 40`, `herdr agent read <이름> --lines 40` |
| Claude 창에 글 보내기 | `herdr agent prompt <이름 또는 창 ID> "<글>"` |
| 셸 창에 명령 보내기 | `herdr pane run <창 ID> "<명령>"` |
| 에이전트에 이름 붙이기 | `herdr agent rename <창 ID> <이름>` |
| 기존 worktree 를 workspace 로 열기 | `herdr worktree open --workspace <원 저장소 ID> --path <폴더>` |
| 화면에 알림 띄우기 | `herdr notification show "<제목>"` |
| 설정 파일 다시 읽기 | `herdr server reload-config` |



## 이 문서의 기준

> herdr 0.9.3 의 도움말과, 같은 날 실제로 실행한 결과를 기준으로 했습니다. 실행해 보지 않고 도움말로만 확인한 명령은 그렇다고 적었습니다.

명령은 대상을 ID 로 가리킵니다. workspace 는 `w4`, 탭은 `w4:t1`, 창은 `w4:p1` 처럼 생겼습니다. 창 ID 앞부분이 그 창의 workspace 입니다. ID 는 herdr 가 붙이는 것이라 사람이 기억할 값이 아닙니다. 사람이 읽는 이름(label)은 따로 붙일 수 있습니다. 에이전트에는 `agent rename` 으로 이름을 붙여 ID 대신 씁니다.

결과는 표준 출력에 JSON 으로 나옵니다. 사람이 읽기 좋게 보려면 `jq` 로 필요한 칸만 뽑습니다. 서버가 거부한 오류는 표준 오류에 JSON 으로 나오며 종료 코드는 1 이고, 명령 형식이 틀리면 종료 코드 2 입니다.

herdr 창 안에서 실행하면 환경 변수로 자기 위치를 압니다. `HERDR_ENV=1` 이 herdr 안이라는 표시이고, `HERDR_PANE_ID`·`HERDR_WORKSPACE_ID` 가 지금 창과 workspace 의 ID 입니다. 셸에서 `echo $HERDR_PANE_ID` 를 치면 그 창의 ID 가 나옵니다.

에이전트에게 herdr 사용법을 알려 주는 설명서는 `herdr --skill` 로 출력됩니다. `agent prompt` 의 세부 동작처럼 도움말에 없는 내용이 여기에 있습니다.



## 상태와 설정 · status·server·default-config

> 서버가 떠 있는지, 설정을 어떻게 바꾸는지를 다루는 명령입니다.

```bash
herdr status                    # 클라이언트·서버 버전과 서버 실행 여부
herdr --default-config          # 기본 설정 전체(주석 포함). 키 이름을 찾을 때 씀
herdr server reload-config      # ~/.config/herdr/config.toml 을 다시 읽음
herdr config reset-keys         # 설정을 백업하고 사용자 키 바인딩을 지움
```

설정을 고친 뒤에는 `server reload-config` 나 단축키(`ctrl+b` → `shift+r`)로 다시 읽힙니다. 키 바인딩은 다시 읽은 뒤에도 클라이언트를 다시 불러와야 먹는 경우가 있었습니다.

`herdr server stop` 은 서버와 그 안의 모든 창 프로세스를 끕니다. 창 안에서 일하는 에이전트도 함께 꺼지므로, 정말 서버를 내릴 때만 씁니다.



## workspace 와 tab

> workspace 는 작업 단위 하나, tab 은 그 안의 화면 하나입니다. 이름 바꾸기와 닫기가 무엇을 바꾸고 무엇을 남기는지 알아 두면 됩니다.

```bash
herdr workspace list | jq -r '.result.workspaces[] | "\(.workspace_id)  \(.label)"'
herdr workspace get <ID>         # 이름, 탭·창 수, worktree 라면 그 경로
herdr workspace rename <ID> <이름>
herdr workspace close <ID>
herdr tab list --workspace <ID>
herdr tab rename <탭 ID> <이름>
```

`workspace rename` 은 사이드바에 보이는 이름만 바꿉니다. worktree 로 연 workspace 라도 저장된 경로는 바뀌지 않습니다. `workspace close` 는 창만 닫습니다. worktree 폴더와 커밋하지 않은 변경은 그대로 남는 것을 실제로 확인했습니다.

`workspace get` 의 결과에서 `worktree.checkout_path` 는 herdr 가 기억하는 폴더입니다. `git worktree move` 로 폴더를 옮기면 이 값이 옛 경로로 남아, 그 workspace 에서 새로 여는 창이 엉뚱한 폴더에서 뜹니다. 고치는 절차는 [세션 세 층 문서](02-02.세션%20세%20층%20—%20메인·저장소·작업%20운영%20규칙.md)에 있습니다.



## pane · 창 읽기와 명령 보내기

> 다른 창의 화면을 읽고, 셸 창에 명령을 치고, 창을 나누거나 닫는 명령입니다.

```bash
herdr pane list --workspace <ID>                 # 창 ID·이름·폴더
herdr pane get <창 ID>                           # 창 하나의 정보
herdr pane read <창 ID> --lines 40               # 화면 끝 40줄
herdr pane rename <창 ID> <이름>
herdr pane split --pane <창 ID> --direction down # 아래로 나누기, 새 창 ID 를 돌려줌
herdr pane resize --pane <창 ID> --direction left --amount 0.17
herdr pane close <창 ID>
```

셸 창에 명령을 보내는 길은 둘입니다. `pane run` 은 글과 Enter 를 한 번에 보냅니다. `send-text` 는 글만 넣으므로 Enter 는 `send-keys` 로 따로 누릅니다. 임시 창을 하나 나눠 두 방법을 모두 시험했더니 글이 그대로 실행됐습니다.

```bash
herdr pane run <창 ID> "echo 연결 시험"
herdr pane send-text <창 ID> "echo 연결 시험"
herdr pane send-keys <창 ID> enter
```

`send-keys` 는 키 이름을 받습니다. `enter`, `esc`, `ctrl+c` 처럼 쓰고, 글자 키는 그 글자를 그대로 줍니다. 플러그인 창에 `m` 을 보내 화면 모드를 바꾸는 것도 이 명령으로 시험했습니다.

Claude 창에 글을 보낼 때는 `pane run` 보다 아래의 `agent prompt` 가 맞습니다. `agent prompt` 만 확인 창에 멈춘 창을 알아보고 거부하기 때문입니다.



## agent · Claude 창에 글 보내고 답 읽기

> 에이전트가 떠 있는 창을 이름으로 부르고, 글을 보내고, 답을 기다려 읽는 명령입니다.

```bash
herdr agent list | jq -r '.result.agents[] | "\(.pane_id)  \(.name // "-")  \(.agent_status)"'
herdr agent get <이름>
herdr agent rename <창 ID> <이름>
herdr agent prompt <이름> "<글>" --wait --timeout 120000
herdr agent read <이름> --lines 20
herdr agent wait <이름> --timeout 600000
herdr agent send-keys <이름> ctrl+c
```

`agent_status` 는 다섯 값 가운데 하나입니다. `working` 은 일하는 중, `idle` 과 `done` 은 입력을 받을 수 있는 상태, `blocked` 는 선택지나 권한 확인 창에 멈춘 상태, `unknown` 은 herdr 가 판단하지 못한 상태입니다. `done` 은 끝난 뒤 아직 아무도 그 창을 보지 않았다는 뜻이 더해집니다.

`agent prompt` 는 받는 창의 입력창에 글을 붙이고 Enter 까지 칩니다. 받는 에이전트에게는 사람이 직접 친 글과 구분되지 않습니다. 설명서에 적힌 동작은 이렇습니다.

- 받는 창은 이름이나 창 ID 로 지정합니다.
- 받는 창이 `blocked` 면 아무것도 보내지 않고 `agent_blocked` 로 거부합니다. 그 확인 창에는 사람이 답해야 합니다.
- 거부하는 경우는 `blocked` 뿐입니다. 일하는 중인 창에도 글은 보내집니다. 다만 그 글이 받는 프로그램 안에서 어떻게 처리되는지는 설명서에 없고, 따로 시험하지 않았습니다.
- `--wait` 를 붙이면 받는 창이 일을 시작했다가 다시 쉬는 상태가 될 때까지 기다립니다. 보낸 뒤 5초 안에 받는 창이 움직이지 않으면 `agent_prompt_stalled` 로 끝납니다.

`agent wait` 는 `--until` 을 주지 않으면 `idle`·`done`·`blocked` 중 하나가 될 때까지 기다립니다. 일하는 중인 창에 글을 넣으면 대화 한가운데 끼어들므로, 먼저 기다렸다가 보내는 데 씁니다.

에이전트 이름은 영문 소문자로 시작하는 32자 이하(`[a-z][a-z0-9_-]{0,31}`)이고 모든 workspace 를 통틀어 하나뿐이어야 합니다. 이름은 창이 아니라 그 창의 에이전트에 붙습니다. 에이전트가 끝나거나 바뀌면 이름도 사라집니다.

`agent send-keys <이름> ctrl+c` 를 두 번 보내 Claude Code 를 끈 적이 있습니다. 3초 안에 에이전트가 목록에서 사라졌고, 창은 남아 그 안의 셸로 돌아왔습니다. 이것은 Claude Code 쪽 동작이라 herdr 설명서에는 없습니다.



## 직접 해 보는 전달 세 가지

> 명령은 셸에서 칩니다. Claude 창이라면 입력란 맨 앞에 `!` 를 붙이면 그 창에서 셸 명령으로 실행되고 결과가 그 대화에 남습니다.

시험 글에는 승인이 아니라는 말과 한 줄로 답하라는 말을 넣습니다. 받는 쪽이 사람이 친 글로 받아들이기 때문입니다.

### 저장소 창에서 그 저장소의 작업 창으로

저장소 본 checkout 창에서 `worktree list` 를 치면 그 저장소의 worktree 와 열린 workspace 가 나옵니다. 작업 창의 에이전트 이름이 workspace 이름과 같다면 바로 그 이름으로 보냅니다.

```bash
! herdr worktree list | jq -r '.result.worktrees[] | "\(.branch)  ws=\(.open_workspace_id // "-")"'
! herdr agent prompt <작업 창 이름> "[테스트 ← be-main] 연결 시험입니다. 승인 아님. '수신 확인' 한 줄로만 답해 주세요." --wait --timeout 120000
! herdr agent read <작업 창 이름> --lines 15
```

### 이름 없는 다른 창으로

이름이 없으면 창 ID 로 보냅니다. Claude 창이면 `agent prompt`, 셸 창이면 `pane run` 입니다.

```bash
! herdr agent list | jq -r '.result.agents[] | "\(.pane_id)  \(.name // "-")"'
! herdr agent prompt <창 ID> "[테스트] 창 ID 로 보낸 글입니다. '수신 확인' 한 줄로만 답해 주세요." --wait --timeout 120000
! herdr pane run <셸 창 ID> "echo 연결 시험"
```

### 메인 창으로

메인처럼 사람이 자주 대화하는 창은 일하는 중일 때가 많습니다. 쉬는 상태가 될 때까지 기다렸다가 보냅니다.

```bash
! herdr agent wait main --timeout 600000
! herdr agent prompt main "[테스트 ← be-main] 연결 시험입니다. '수신 확인' 한 줄로만 답해 주세요." --wait --timeout 120000
! herdr agent read main --lines 15
```

같은 방식으로 여섯 창에 규칙 공지를 보냈고, 여섯 곳 모두 한 줄로 답했습니다.



## worktree · 기능 브랜치를 workspace 로 열기

> git worktree 를 herdr workspace 로 열고 닫는 명령입니다. 다른 저장소의 창에서 부를 때는 기준 저장소를 `--workspace` 로 꼭 알려 줍니다.

```bash
herdr worktree list [--workspace <ID> | --cwd <폴더>]
herdr worktree open --workspace <원 저장소 workspace ID> --path <worktree 폴더> --label <이름> --no-focus
herdr worktree create --workspace <ID> --branch <브랜치> --base <기준> --path <폴더> --label <이름>
herdr worktree remove --workspace <ID> [--force]
```

`worktree list` 는 기준 저장소의 worktree 와, 열려 있다면 그 workspace ID(`open_workspace_id`)를 보여 줍니다. 기준 저장소는 따로 주지 않으면 명령을 부른 창의 저장소입니다.

`worktree open` 은 이미 있는 worktree 폴더를 workspace 로 엽니다. 다른 저장소의 창에서 `--workspace` 없이 불렀더니 `worktree_not_found` 로 실패했습니다. 호출한 창의 저장소에서 그 폴더를 찾았기 때문입니다. 원 저장소 workspace ID 를 넘기자 열렸습니다. 열면 첫 창이 그 폴더에서 뜹니다. reviewr 플러그인이 깔려 있으면 diff 창도 옆에 저절로 붙습니다.

`worktree create` 와 `worktree remove` 는 도움말로만 확인했습니다. 이 환경에서는 브랜치 이름 규칙과 상태 파일을 함께 다루는 스크립트로 감싸 씁니다. `--trust-repository` 는 그 요청 한 번만 git 저장소를 믿겠다는 옵션이라, 실패를 넘기려고 습관처럼 붙이지 않습니다.



## plugin 과 notification

> 플러그인을 깔고 그 동작을 부르는 명령, 화면에 알림을 띄우는 명령입니다.

```bash
herdr plugin install <github 사용자>/<저장소>
herdr plugin list
herdr plugin action invoke <동작 ID> --plugin <플러그인 ID>
herdr plugin pane open --plugin <플러그인 ID> --entrypoint <매니페스트의 창 항목> --placement split --target-pane <창 ID> --direction right
herdr notification show "<제목>" --body "<내용>" --sound request
```

reviewr 의 README 는 플러그인 동작을 키에 묶을 때 `<플러그인 ID>.<동작 ID>` 형식(`persiyanov.reviewr.toggle`)을 쓰라고 안내합니다. herdr 기본 설정 주석에는 이 형식이 나오지 않고, 이 환경에서는 셸 스크립트로 묶어서 이 형식은 시험하지 않았습니다. `plugin pane open` 은 플러그인 창을 원하는 자리에 엽니다. reviewr 를 1대2 비율로 여는 스크립트에서 이 명령을 썼습니다. 화면에 보이지 않는 workspace 에 `--focus` 로 열면 조용히 실패하므로 `--no-focus` 로 다시 시도합니다.

`notification show` 는 사람에게 보이는 알림을 띄웁니다. 다른 에이전트에게 전달되는 것이 아니라서, 창끼리 소식을 주고받는 데는 `agent prompt` 를 씁니다.



## session

> 이름 붙은 herdr 세션을 여럿 두고 오가는 명령입니다. 도움말로만 확인했습니다.

```bash
herdr --session <이름>          # 그 이름의 세션을 열거나 붙음
herdr session list
herdr session attach <이름>
herdr session stop <이름>
herdr session delete <이름>     # 멈춘 세션만 지움
```

세션은 서로 다른 herdr 서버처럼 동작합니다. 시험할 때 지금 쓰는 세션을 건드리지 않으려면 이름 붙은 시험용 세션을 따로 띄웁니다.
