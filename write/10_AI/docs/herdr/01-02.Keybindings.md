# Keybindings
---
> herdr 기본 단축키를 하는 일별로 모았습니다. 키를 바꾸거나 사용자 명령을 키에 묶는 법도 함께 적었습니다.



## 핵심 요약

> herdr 키는 대부분 prefix(`ctrl+b`)를 누른 뒤 한 키를 더 누르는 방식입니다. 자주 쓰는 것은 창 이동 `h`·`j`·`k`·`l`, 찾아가기 `g`, 알림 온 창 `o` 입니다.

| 하고 싶은 일 | 키 |
|------|------|
| workspace 찾아가기 | `ctrl+b` → `g` |
| workspace 목록 | `ctrl+b` → `w` |
| 알림이 온 창으로 가기 | `ctrl+b` → `o` |
| 옆 창으로 이동 | `ctrl+b` → `h` `j` `k` `l` |
| 다음 창으로 돌기 | `ctrl+b` → `Tab` |
| 탭 바꾸기 | `ctrl+b` → `1`..`9`, `n`, `p` |
| 창 나누기 | `ctrl+b` → `v`(세로), `-`(가로) |
| 창 하나를 크게 | `ctrl+b` → `z` |
| 사용 가능한 키 보기 | `ctrl+b` → `?` |



## 이 문서의 기준

> herdr 0.9.3 의 `herdr --default-config` 출력에 적힌 기본값과 주석을 기준으로 했습니다. 키를 바꾸면 이 표와 달라집니다.

키 설정은 `~/.config/herdr/config.toml` 의 `[keys]` 절에 둡니다. 적지 않은 동작은 기본값을 씁니다. 지금 설치본의 기본값 전체는 `herdr --default-config` 로 볼 수 있고, 각 줄의 주석에 키 이름과 예시가 있습니다.

**prefix** 는 다음 키를 herdr 명령으로 받겠다는 신호 키입니다. 기본은 `ctrl+b` 이고, 누른 뒤 한 키를 더 누르면 그 동작이 실행됩니다. tmux 와 같은 방식이라 창 안 프로그램이 쓰는 키와 겹치지 않습니다. 설정에서 `"prefix+n"` 은 prefix 다음 `n`, `"ctrl+alt+n"` 처럼 prefix 가 없는 것은 바로 먹는 키입니다.



## workspace 와 이동

> workspace 를 찾아가거나 만들고 닫는 키입니다. 사람은 ID 대신 이름으로 찾아갑니다.

| 키 | 동작 | 설정 이름 |
|---|---|---|
| `ctrl+b` → `g` | 찾아가기 창을 열고 이동 | `goto` |
| `ctrl+b` → `w` | workspace 목록에서 고르기 | `workspace_picker` |
| `ctrl+b` → `o` | 알림이 가리키는 창으로 이동 | `open_notification_target` |
| `ctrl+b` → `shift+n` | 새 workspace | `new_workspace` |
| `ctrl+b` → `shift+g` | 새 worktree workspace | `new_worktree` |
| `ctrl+b` → `shift+w` | workspace 이름 바꾸기 | `rename_workspace` |
| `ctrl+b` → `shift+d` | workspace 닫기 | `close_workspace` |
| `ctrl+b` → `b` | 사이드바 보이기·숨기기 | `toggle_sidebar` |
| `ctrl+b` → `s` | 설정 화면 | `settings` |
| `ctrl+b` → `shift+r` | 설정 파일 다시 읽기 | `reload_config` |
| `ctrl+b` → `q` | 화면에서 떨어지기(서버와 창은 계속 돎) | `detach` |
| `ctrl+b` → `?` | 도움말 | `help` |

`q` 로 떨어져도 서버와 그 안의 에이전트는 계속 돕니다. 다시 `herdr` 를 치면 그대로 붙습니다. 에이전트를 끄려면 그 창에서 에이전트를 끝내거나 창을 닫습니다.



## 탭

> 한 workspace 안에서 화면을 여럿 둘 때 씁니다.

| 키 | 동작 | 설정 이름 |
|---|---|---|
| `ctrl+b` → `c` | 새 탭 | `new_tab` |
| `ctrl+b` → `1`..`9` | 그 번호 탭으로 | `switch_tab` |
| `ctrl+b` → `n` / `p` | 다음 / 이전 탭 | `next_tab` / `previous_tab` |
| `ctrl+b` → `shift+t` | 탭 이름 바꾸기 | `rename_tab` |
| `ctrl+b` → `shift+x` | 탭 닫기 | `close_tab` |



## 창

> 창 사이를 옮겨 다니고, 나누고, 크기를 바꾸는 키입니다.

| 키 | 동작 | 설정 이름 |
|---|---|---|
| `ctrl+b` → `h` `j` `k` `l` | 왼쪽·아래·위·오른쪽 창으로 | `focus_pane_left` 등 |
| `ctrl+b` → `Tab` / `shift+Tab` | 다음 / 이전 창으로 돌기 | `cycle_pane_next` / `cycle_pane_previous` |
| `ctrl+b` → `v` | 세로로 나누기 | `split_vertical` |
| `ctrl+b` → `-` | 가로로 나누기 | `split_horizontal` |
| `ctrl+b` → `x` | 창 닫기 | `close_pane` |
| `ctrl+b` → `z` | 지금 창을 탭 전체로 키우기·되돌리기 | `zoom` |
| `ctrl+b` → `r` | 크기 조절 모드 | `resize_mode` |
| `ctrl+b` → `shift+p` | 창 이름 바꾸기 | `rename_pane` |
| `ctrl+b` → `e` | 화면 기록을 편집기로 열기 | `edit_scrollback` |

마우스로 창을 클릭해도 포커스가 옮겨 갑니다. 창 안 프로그램도 자기 키를 가지므로, 예를 들어 reviewr 안에서 누르는 `Tab` 은 herdr 의 창 이동이 아니라 reviewr 안의 전환입니다([herdr-reviewr](01-03.herdr-reviewr.md)).

탐색 모드에서는 prefix 없이 `h`·`j`·`k`·`l` 로 창을, `↑`·`↓` 로 workspace 를 옮깁니다. 설정 이름은 `navigate_pane_*`·`navigate_workspace_*` 이고 `focus_pane_*` 과 따로 바꿉니다. 탐색 모드를 여는 키는 기본 설정 주석에 적혀 있지 않아 이 문서에서는 확인하지 못했습니다.



## 비어 있는 동작

> 기본 키가 없지만 설정에서 키를 줄 수 있는 동작입니다. 자주 쓰게 되면 하나씩 묶습니다.

| 설정 이름 | 하는 일 | 주석의 예 |
|---|---|---|
| `last_pane` | 직전 창으로 왕복 | `prefix+tab` |
| `previous_workspace` / `next_workspace` | workspace 차례로 이동 | |
| `previous_agent` / `next_agent` | 에이전트 차례로 이동 | |
| `focus_agent` | n 번째 에이전트로 | `prefix+alt+1..9` |
| `switch_workspace` | n 번째 workspace 로 | `prefix+shift+1..9` |
| `open_worktree` / `remove_worktree` | worktree 열기 / 지우기(확인 창) | |
| `move_tab_previous` / `move_tab_next` | 탭 순서 옮기기 | `alt+shift+left` |
| `resize_pane_left` 등 | 크기 조절 모드 없이 바로 조절 | `ctrl+shift+alt+left` |
| `clear_pane` | 창 화면 지우기 | `prefix+ctrl+k` |



## 키를 바꾸고 명령을 묶는 법

> 동작 이름에 키를 주면 그 동작의 기본 키를 대체합니다. 셸 명령이나 플러그인 동작도 키에 묶을 수 있습니다.

```bash
[keys]
prefix = "ctrl+b"
goto = "prefix+g"
next_tab = ["prefix+n", "f8"]              # 배열로 여러 키 (아래 설명)

[[keys.command]]
key = "prefix+alt+g"
type = "popup"          # shell: 뒤에서 실행 · pane: 임시 창 · popup: 탭 배치를 건드리지 않는 떠 있는 창
command = "lazygit"
width = "80%"
height = "80%"

[[keys.command]]
key = "cmd+r"
type = "plugin_action"                    # reviewr README 의 예시
command = "persiyanov.reviewr.toggle"
```

근거가 서로 다른 두 가지가 위 예시에 섞여 있습니다. 첫째, 키를 배열로 여럿 주는 문법은 기본 설정 주석에 없습니다. 이 환경 설정이 `prefix = ["ctrl+b", "ctrl+ㅠ"]` 처럼 배열로 적혀 있고 그대로 동작하는 것을 근거로 적었습니다. 둘째, `type = "plugin_action"` 은 기본 설정 주석에 나오지 않습니다. 주석이 설명하는 type 은 `shell`·`pane`·`popup` 셋입니다. `plugin_action` 은 reviewr README 가 안내하는 형식이고, 이 환경에서는 `shell` 로 스크립트를 묶어서 시험하지 않았습니다.

키 표기는 `ctrl`·`shift`·`alt`·`cmd` 조합과 `enter`·`tab`·`esc`·방향키 이름을 받고, `minus`·`comma` 같은 기호 이름도 받습니다. 주석은 `ctrl+글자`, 기능 키처럼 확실한 조합을 권합니다. `alt+…`·`cmd+…`·기호 조합은 터미널이 먼저 가로챌 수 있습니다. 실제로 macOS 터미널에서 `alt+…` 를 터미널이 먹는 일이 흔해 `cmd+…` 를 썼습니다.

고친 뒤에는 `ctrl+b` → `shift+r` 이나 `herdr server reload-config` 로 다시 읽힙니다. 키 바인딩은 다시 읽은 뒤에도 클라이언트를 다시 붙여야 먹는 경우가 있었습니다. 설정이 꼬이면 `herdr config reset-keys` 가 설정을 백업하고 사용자 키 바인딩을 지웁니다.

한글 입력 상태에서는 prefix 다음 키가 자모로 들어와 먹지 않을 수 있습니다. 이 환경에서 그 문제를 푼 설정은 [내 herdr 설정](02-01.%EB%82%B4%20herdr%20%EC%84%A4%EC%A0%95%20%E2%80%94%20%ED%95%9C%EA%B8%80%20%EC%9E%85%EB%A0%A5%C2%B7reviewr%201%EB%8C%802%20%EB%B6%84%ED%95%A0%C2%B7%ED%82%A4%20%EB%B0%94%EC%9D%B8%EB%94%A9.md)에 따로 적었습니다.
