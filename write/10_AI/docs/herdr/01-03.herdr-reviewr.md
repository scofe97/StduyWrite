# herdr-reviewr
---
> 에이전트가 고친 코드를 옆 창에서 diff 로 읽고, 줄마다 코멘트를 달아 에이전트 입력창으로 돌려보내는 herdr 플러그인 reviewr 의 사용법입니다. README 에 한 줄로만 나와 헷갈렸던 동작은 설치본 소스로 확인해 적었습니다.



## 핵심 요약

> reviewr 는 파일을 고치지 않고 아무것도 저절로 보내지 않습니다. 사람이 `s` 를 눌러야 코멘트가 에이전트 입력창에 붙고 Enter 도 사람이 누릅니다.

쓰다가 걸린 함정은 셋이었습니다. 하나는 브랜치 비교의 기준입니다. 기본값이 `origin/HEAD` 라서, 이 값이 배포 브랜치를 가리키는 저장소에서는 내 작업과 무관한 커밋 수십 개가 diff 에 섞입니다. 둘째는 키 설정입니다. 설정 파일의 키 배열은 기본값에 덧붙는 게 아니라 기본값을 통째로 바꾸므로, 한글 자모를 넣다가 화살표 키가 빠질 수 있습니다. 셋째는 reviewr 가 창의 폴더를 따라간다는 점입니다. workspace 가 엉뚱한 폴더에서 열리면 reviewr 도 그 폴더 저장소의 diff 를 보여 줍니다.

| 하고 싶은 일 | 키·명령 |
|------|------|
| 리뷰 창 열고 닫기 | 플러그인 액션 `persiyanov.reviewr.toggle` 을 키에 묶음 |
| 에이전트 창과 리뷰 창 오가기 | `ctrl+b` → `h` / `l` |
| 파일 목록과 diff 오가기 | `Tab` (reviewr 안에서만) |
| 줄 고르고 코멘트 달기 | `v` → `j`/`k` → `c` → 입력 → `Enter` |
| 코멘트를 에이전트에 보내기 | `s` |
| 코멘트를 클립보드로 | `y` |
| 비교 범위 바꾸기 | `u` `b` `t` `g` |
| 브랜치 비교 기준 고르기 | `B` |
| 원하는 줄로 가기 | `:` 줄 번호 `Enter` |
| 지금 쓸 수 있는 키 보기 | `?` |



## 이 문서의 기준

> herdr 0.9.3 과 reviewr 0.45.0 의 설치본을 기준으로 했습니다. README 와 소스가 어긋나면 소스를 따랐습니다.

reviewr 는 herdr 에 들어 있는 기능이 아닙니다. herdr 0.9.0 부터 생긴 플러그인 체계 위에서 도는 별도 플러그인입니다. 플러그인 ID 는 `persiyanov.reviewr` 입니다. 설치와 갱신은 아래처럼 합니다. 갱신할 때 지웠다 다시 깔아도 설정은 플러그인 ID 로 묶여 있어 남습니다.

```bash
herdr plugin install persiyanov/herdr-reviewr
herdr plugin uninstall persiyanov.reviewr && herdr plugin install persiyanov/herdr-reviewr
```

설치본의 README 와 Rust 소스는 `~/.config/herdr/plugins/github/persiyanov.reviewr-<해시>/` 아래에 있습니다. 아래에서 "소스로 확인했다"는 말은 이 폴더의 `src/` 를 읽었다는 뜻입니다.



## 열고 닫기 · 토글 키와 자동 열림

> 플러그인의 토글 동작을 herdr 키에 묶어 열고 닫습니다. worktree 로 workspace 를 열면 reviewr 가 저절로 붙습니다.

README 가 권하는 방법은 herdr 설정(`~/.config/herdr/config.toml`)에 플러그인 동작을 키로 묶는 것입니다. `command` 에는 플러그인 이름이 아니라 `<플러그인 ID>.<동작 ID>` 를 적습니다. macOS 터미널은 `alt+…` 조합을 자기가 먹는 경우가 많아서 `cmd+…` 를 권합니다.

```bash
[[keys.command]]
key = "cmd+r"
type = "plugin_action"
command = "persiyanov.reviewr.toggle"
```

키 없이 명령으로 열 수도 있습니다. `herdr plugin action invoke open --plugin persiyanov.reviewr` 는 지금 workspace 에 reviewr 를 엽니다. 토글은 창을 반반(0.5)으로 나눕니다. 비율을 바꾸는 설정은 없어서, 다른 비율이 필요하면 `herdr plugin pane open` 과 `herdr pane resize` 로 직접 엽니다([CLI reference](01-01.CLI%20reference.md)).

worktree 로 workspace 를 새로 만들거나 디스크의 worktree 를 열면 reviewr 가 저절로 열립니다. 이 동작은 reviewr 설정의 `auto_open = false` 로 끕니다. 창 모양은 `toggle_placement` 로 바꿉니다(`split`·`overlay`·`zoomed`·`tab`).

reviewr 안에서 `q` 로 나가면, 아직 보내지 않은 코멘트가 있을 때 먼저 묻습니다. 묻지 않고 버리고 나가는 키는 `Q` 입니다.



## 에이전트 창과 리뷰 창 사이 포커스 옮기기

> 창 사이 이동은 herdr 키로 하고, reviewr 안의 `Tab` 은 파일 목록과 diff 사이만 오갑니다.

| 키 | 동작 |
|---|---|
| `ctrl+b` → `h` | 왼쪽 창(에이전트 터미널)으로 이동 |
| `ctrl+b` → `l` | 오른쪽 창(reviewr)으로 이동 |
| `ctrl+b` → `Tab` | 다음 창으로 순환 |
| 마우스 클릭 | 클릭한 창으로 이동 |
| reviewr 안에서 `Tab` | 파일 목록과 diff 사이 전환 |

herdr 의 창 이동 키 전체는 [Keybindings](01-02.Keybindings.md)에 있습니다. 토글 키로 열면 포커스가 reviewr 로 가고, `s` 로 코멘트를 보내면 포커스가 에이전트 창으로 돌아옵니다.



## 리뷰 흐름 · 고르기·선택·코멘트·보내기

> 다섯 동작이면 한 바퀴가 돕니다. 막히면 화면 아래 안내줄과 `?` 가 다음 키를 알려 줍니다.

1. 파일 목록에서 `j`/`k` 로 파일을 고르면 diff 가 따라 바뀝니다. `]`/`[` 는 변경 묶음(hunk) 단위로 다음 파일까지 이어서 건너뜁니다.
2. `Tab` 으로 diff 에 포커스를 옮깁니다.
3. `v` 를 누르고 `j`/`k` 로 범위를 넓힙니다. 줄 번호 쪽을 클릭하거나 드래그해도 범위가 잡힙니다.
4. `c` 를 누르고 코멘트를 쓴 뒤 `Enter` 로 저장합니다. 코멘트 안에서 줄을 바꾸려면 `Shift+Enter` 를 씁니다.
5. `s` 를 누르면 모은 코멘트 전체가 에이전트 입력창으로 갑니다.

저장한 코멘트는 `e` 로 고치고 `d` 로 지웁니다. `n`/`N` 은 코멘트 사이를 오가고, `l` 은 전체 목록을 띄웁니다. 코멘트가 없는 줄에서 `e` 를 누르면 그 줄을 에디터로 엽니다. 에디터는 `$EDITOR`·`$VISUAL`, 둘 다 없으면 git 의 `core.editor` 를 씁니다.



## 코멘트가 에이전트 입력창에 도착하는 모양

> 코멘트는 git 이나 PR 에 다는 것이 아니라, 위치와 코드를 붙여 에이전트에게 전하는 리뷰 메모입니다. 파일에 저장되지도 않습니다.

`s` 를 누르면 reviewr 는 코멘트를 파일 이름, 시작 줄 순으로 정렬해 블록 하나씩으로 만듭니다. 블록은 위치, 선택한 코드, 코멘트 순서이고 블록 사이는 빈 줄 하나입니다(`src/export.rs` 의 `format_all`).

```bash
src/foo.rs:40-52
(선택한 코드 줄)
이 분기는 빈 목록일 때도 타야 합니다

src/bar.rs:10 (removed)
(삭제된 줄)
이 줄을 지운 이유를 남겨 주세요
```

삭제된 줄에 단 코멘트에는 `(removed)` 가 붙습니다. 코멘트 본문 안의 빈 줄은 블록 구분과 헷갈리지 않도록 지워집니다. 그래서 문단을 나눠 쓴 코멘트는 한 덩어리로 도착합니다.

보내기는 붙여 넣기까지만 합니다. 입력창에 붙이기만 하고 Enter 는 누르지 않습니다. 대신 포커스를 에이전트 창으로 옮겨, 사람이 한마디 덧붙인 뒤 제출하게 합니다(`src/herdr.rs`). 같은 workspace 에 에이전트가 여럿이면 어느 쪽으로 보낼지 고르는 창이 뜹니다.

보내기가 거부되는 경우도 있습니다. 에이전트가 권한 확인 창에 멈춰 있으면 붙여 넣은 글이 그 창에 먹혀 사라지므로 reviewr 가 아예 보내지 않습니다. 이때 코멘트는 그대로 남아 있으니, 확인 창에 답하고 다시 `s` 를 누르면 됩니다. workspace 에 에이전트가 없거나 리뷰가 너무 커도 거부하고, 대신 `y` 로 복사하라고 안내합니다.

보내기는 전부 아니면 전무입니다. 성공하면 보낸 코멘트가 reviewr 에서 지워지고, 실패하면 전부 남습니다. 코멘트는 메모리에만 있어서 reviewr 창을 닫으면 보내지 않은 것은 사라집니다.

### 클립보드 복사 y 는 보내기와 같은 글을 클립보드에 넣습니다

`y` 는 위와 똑같은 블록을 에이전트 입력창 대신 시스템 클립보드에 넣습니다. macOS 에서는 `pbcopy` 를 씁니다. 다른 창의 에이전트에 넘기거나 MR 코멘트·메신저·노트에 붙일 때, 그리고 에이전트가 확인 창에 묶여 보내기가 거부될 때 씁니다.

복사도 보내기처럼 코멘트 목록을 비웁니다. 붙여 넣기 전에 다른 것을 복사하면 코멘트를 잃습니다. 마우스로 드래그해 글자를 고르는 복사는 이것과 별개로, 고른 글자만 클립보드에 들어갑니다.



## 비교 범위 네 가지 · u·b·t·g

> 같은 worktree 라도 무엇과 비교하느냐에 따라 보이는 파일이 달라집니다. 처음에는 커밋하지 않은 변경(`u`)으로 열립니다.

| 키 | 범위 | 비교 대상 |
|---|---|---|
| `u` | uncommitted | 작업 트리와 `HEAD`. staged·unstaged·untracked 를 모두 보여 줌 |
| `b` | branch | 작업 트리와 기준 브랜치의 merge-base. 브랜치의 커밋과 아직 커밋하지 않은 변경을 함께 보여 줌 |
| `t` | last turn | 에이전트의 마지막 턴이 시작된 뒤 바뀐 것만 |
| `g` | commits | `G` 로 고른 커밋 하나 또는 연속한 여러 개 |

last turn 은 2초 간격으로 worktree 를 확인해서 판단합니다. 그래서 두 번의 확인 사이에 시작하고 끝난 짧은 턴은 놓치고, 그 사이 사람이 직접 고친 내용도 섞여 보입니다. commits 는 에이전트가 커밋한 것을 커밋 단위로 끊어 볼 때 씁니다.

네 범위 모두 `.gitignore` 를 따르므로 빌드 산출물은 변경 목록에 나오지 않습니다. 무시된 파일을 봐야 하면 `2`(All files) 탭으로 갑니다.



## 브랜치 비교 기준 · B 로 고르고 worktree 마다 저장된다

> 기준을 고르지 않으면 `origin/HEAD` 가 가리키는 브랜치와 비교합니다. 배포 브랜치가 기본인 저장소라면 처음 한 번 `B` 로 개발 브랜치를 골라야 합니다.

reviewr 가 branch 범위의 기준을 정하는 순서는 셋입니다(`src/git.rs` 의 `resolve_base`).

1. 창을 띄울 때 준 `--base <ref>` 옵션. 이 옵션이 있으면 고르는 창이 꺼집니다.
2. `B` 로 고른 값.
3. 저장소 기본 브랜치. `origin/HEAD` 가 가리키는 브랜치이고, 없으면 `init.defaultBranch`, `main`, `master` 순으로 찾습니다.

함정은 3번에서 생깁니다. `origin/HEAD` 가 배포 브랜치(예: `prd`)를 가리키는데 기능 브랜치는 개발 브랜치(`dev`)에서 땄다면, 두 브랜치 차이만큼의 남의 커밋이 diff 에 섞입니다. 실제로 겪은 규모는 [내 herdr 설정](02-01.%EB%82%B4%20herdr%20%EC%84%A4%EC%A0%95%20%E2%80%94%20%ED%95%9C%EA%B8%80%20%EC%9E%85%EB%A0%A5%C2%B7reviewr%201%EB%8C%802%20%EB%B6%84%ED%95%A0%C2%B7%ED%82%A4%20%EB%B0%94%EC%9D%B8%EB%94%A9.md)에 적었습니다. 아래 명령으로 미리 확인할 수 있습니다.

```bash
git symbolic-ref refs/remotes/origin/HEAD
git rev-list --count origin/prd..origin/dev
```

기준을 고르는 법은 이렇습니다.

1. reviewr 에서 영문 상태로 `B` 를 누릅니다. 헤더의 `vs prd` 를 클릭해도 됩니다.
2. 브랜치 이름을 입력해 목록을 좁힙니다. 목록은 퍼지 검색이고, 줄마다 브랜치의 나이와 `pr base`·`default`·`current` 표시가 붙습니다.
3. `Enter` 로 고르면 헤더가 `vs dev` 로 바뀝니다.

브랜치 대신 `HEAD~2`, 태그, SHA 앞부분을 입력해도 됩니다. 이때 헤더는 `vs HEAD~2 (a1b2c3d)` 처럼 실제로 풀린 커밋을 함께 보여 줍니다. 기본 브랜치를 다시 고르면 저장된 선택이 지워집니다.

고른 값은 worktree 마다 따로 저장됩니다. 저장 위치가 그 worktree 의 git ref `refs/worktree/reviewr/base-pick` 이라서 reviewr 를 닫았다 열어도 남습니다. 같은 저장소의 다른 worktree 에는 번지지 않습니다. worktree 를 새로 열 때마다 한 번씩 골라야 한다는 뜻입니다. 지금 무엇이 저장돼 있는지는 아래로 봅니다. 아무것도 나오지 않으면 고른 적이 없는 것입니다.

```bash
git -C <worktree> cat-file blob refs/worktree/reviewr/base-pick
```



## 원하는 줄로 가기 · 줄 번호 점프

> `:` 를 누르고 줄 번호를 넣은 뒤 `Enter` 를 누릅니다. `:0` 은 첫 줄, `:$` 는 마지막 줄입니다.

번호는 diff 화면의 행 번호가 아니라 파일의 실제 줄 번호입니다. 기준은 변경 후 파일입니다. 새 줄이 하나도 없는 파일(삭제된 파일)에서만 변경 전 번호를 씁니다(`src/app.rs` 의 `line_side`). 마크다운을 렌더링해 보는 중이면 원본 파일의 줄 번호를 씁니다.

목적지가 바뀌지 않아 접혀 있는 구간이어도 reviewr 가 접힘을 펼치고 그 줄로 갑니다. 화면 밖이면 가운데에 놓습니다. 파일 길이보다 큰 번호는 마지막 줄로 맞춥니다. 점프하면 포커스는 diff 로 넘어갑니다.

입력란에는 숫자를 붙여 넣어도 됩니다. 따옴표나 괄호로 감싼 숫자는 감싼 기호를 떼고 받습니다. `src/foo.rs:40` 같은 `파일:줄` 형식은 받지 않으므로, 파일은 먼저 `/` 로 찾아 열고 나서 `:` 로 줄을 찾습니다. 변경하지 않은 파일의 줄은 `2`(All files) 탭에서 같은 방법으로 찾습니다. 줄 번호 말고 글자로 찾으려면 `Ctrl+F` 로 파일 안을 검색합니다.



## 자주 쓰는 키

> 기본 키입니다. 모든 동작은 설정 파일에서 다른 키로 바꾸거나 여러 키를 함께 묶을 수 있습니다.

| 분류 | 키 | 동작 |
|---|---|---|
| 탭 | `1` `2` `3` | Changes / All files / PR(읽기 전용) |
| 이동 | `j` `k` · `↑` `↓` | 커서 이동 |
| 이동 | `]` `[` · `f` `F` | 다음·이전 hunk / 다음·이전 파일 |
| 이동 | `Ctrl+U` `Ctrl+D` · `PageUp` `PageDown` | 반 페이지 / 한 페이지 |
| 찾기 | `/` · `Ctrl+F` · `:` | 파일 이름과 코드 검색 / 파일 안 찾기 / 줄 번호 |
| 리뷰 | `v` `c` `e` `d` | 선택 / 코멘트 / 수정 / 삭제 |
| 리뷰 | `n` `N` `l` | 다음·이전 코멘트 / 전체 목록 |
| 내보내기 | `s` `y` | 에이전트로 보내기 / 클립보드 복사 |
| 보기 | `w` `m` | 줄바꿈 / 마크다운 렌더링 전환 |
| 보기 | `z` `p` `<` `>` | 파일 목록 숨기기 / 목록 위치 / 목록 넓히기·좁히기 |
| 기타 | `r` `?` `q` `Q` | 새로고침 / 키 안내 / 나가기 / 안 보낸 코멘트를 버리고 나가기 |

`m` 은 아무 파일에서나 먹는 키가 아닙니다. 아래 셋을 모두 만족할 때만 동작합니다(`src/app.rs` 의 `toggle_acts`).

- 열린 파일의 확장자가 `.md` 나 `.markdown` 입니다.
- Changes 나 All files 탭입니다. PR 탭에서는 동작하지 않습니다.
- 보여 줄 내용이 있습니다. 삭제된 마크다운 파일이나 너무 커서 안내만 뜨는 파일은 여기서 빠집니다.

조건이 맞지 않으면 상태줄에 아무 말 없이 무시되어 고장처럼 보입니다. `?` 를 누르면 지금 먹는 키만 보여 주므로, 거기에 `m` 이 없으면 이 파일은 렌더링 대상이 아닙니다.

PR 탭은 GitHub·GitLab·Azure DevOps 의 열린 PR(MR)을 읽기만 합니다. `gh`·`glab`·`az` 중 맞는 CLI 가 로그인돼 있어야 하고, `o` 를 누르면 브라우저로 엽니다. reviewr 가 PR 에 무언가를 쓰는 일은 없습니다.



## 설정 파일과 키 바인딩 · 배열은 기본값을 대체한다

> reviewr 설정은 herdr 설정과 다른 파일입니다. 키 배열은 기본값에 덧붙지 않고 기본값을 통째로 바꿉니다.

설정 파일은 `~/.config/herdr/plugins/config/persiyanov.reviewr/config.toml` 입니다. herdr 의 `config.toml` 에 적은 값은 reviewr 에 닿지 않습니다. reviewr 는 새로고침과 토글 때마다 이 파일을 다시 읽습니다. 그래서 고친 뒤 열려 있는 창에서 `r` 만 누르면 적용됩니다. 파일이 잘못되면 전체를 거부하고 창에 오류를 띄웠다가, 고친 뒤 다음 새로고침에서 돌아옵니다.

자주 바꾸는 값은 이 정도입니다.

```bash
theme = "tokyo-night"          # 기본 catppuccin. 터미널 배경의 밝기에 맞춰 직접 고름
default_scope = "branch"       # 처음 열 때의 비교 범위
markdown_view = "rendered"     # .md 를 처음부터 렌더링해서 보기
navigator_position = "bottom"  # 파일 목록 위치. right·bottom·left·top
toggle_placement = "split"     # split·overlay·zoomed·tab
auto_open = false              # worktree workspace 가 생길 때 저절로 열지 않기
```

### 키 배열은 기본값을 통째로 대체합니다

`[keybindings]` 에 동작 이름과 키 배열을 적으면, 그 동작의 기본 키는 모두 사라지고 적은 키만 남습니다. 기본값이 `j` 와 `↓` 인 `down` 에 `["j", "ㅓ"]` 만 적으면 `↓` 가 동작하지 않습니다(`src/keymap.rs` 의 기본 키 표).

설정 파서는 글자 하나 말고도 키 이름 여섯 개를 받습니다. `left`, `right`, `up`, `down`, `pageup`, `pagedown` 이고, 앞에 `ctrl+`·`alt+` 를 붙일 수 있습니다(`src/config.rs` 의 `parse_key`). 그래서 기본 키를 살리려면 이름까지 함께 적습니다.

```bash
[keybindings]
down = ["j", "down"]
up = ["k", "up"]
comment = ["c"]
```

`Tab`·`Esc`·`Enter` 는 바꿀 수 없는 고정 키입니다. 한글 입력 상태에서 쓰려고 자모를 함께 묶은 설정은 [내 herdr 설정](02-01.%EB%82%B4%20herdr%20%EC%84%A4%EC%A0%95%20%E2%80%94%20%ED%95%9C%EA%B8%80%20%EC%9E%85%EB%A0%A5%C2%B7reviewr%201%EB%8C%802%20%EB%B6%84%ED%95%A0%C2%B7%ED%82%A4%20%EB%B0%94%EC%9D%B8%EB%94%A9.md)에 있습니다.



## 알려진 한계

> README 의 Limitations 절에서 실제로 부딪힐 만한 것만 골랐습니다.

- 트루컬러 터미널이 필요합니다. 256색 대체 팔레트가 없어서 기본 터미널에서는 색이 틀어집니다.
- 테마는 터미널 배경의 밝기에 맞춰 사람이 고릅니다. 자동 감지는 아직 없습니다.
- 추가·삭제를 초록·빨강으로만 구분합니다. 색약 사용자를 위한 보조 표시는 아직 없습니다.
- 코멘트는 줄 번호를 따라 옮겨지지 않습니다. 코드가 바뀌면 diff 조각으로 위치를 찾고, 못 찾으면 오래된 코멘트로 표시합니다.
- 2 MB 또는 50,000줄이 넘는 파일은 diff 대신 너무 크다는 안내만 보여 줍니다. 바이너리 파일은 diff 가 없습니다.
- reviewr 는 자기 창의 폴더에서 저장소를 찾습니다. workspace 가 엉뚱한 폴더에서 열려 있으면 다른 저장소의 diff 를 보여 줍니다. worktree 를 옮긴 뒤 생기는 일이고, 고치는 절차는 [세션 세 층 운영 규칙](02-02.%EC%84%B8%EC%85%98%20%EC%84%B8%20%EC%B8%B5%20%E2%80%94%20%EB%A9%94%EC%9D%B8%C2%B7%EC%A0%80%EC%9E%A5%EC%86%8C%C2%B7%EC%9E%91%EC%97%85%20%EC%9A%B4%EC%98%81%20%EA%B7%9C%EC%B9%99.md)에 있습니다.
- herdr 없이 `herdr-reviewr <저장소>` 로 단독 실행할 수 있지만, 보내기와 last turn 범위는 herdr 가 있어야 동작합니다.
