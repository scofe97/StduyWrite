# 내 herdr 설정 — 한글 입력·reviewr 1대2 분할·키 바인딩
---
> 이 맥에서 herdr 와 reviewr 를 쓰려고 바꾼 설정을 모았습니다. 기본 키 설명은 [Keybindings](01-02.Keybindings.md), reviewr 일반 사용법은 [herdr-reviewr](01-03.herdr-reviewr.md)에 있고, 여기에는 그 위에 얹은 것만 둡니다.



## 핵심 요약

> 한글 입력 상태에서도 단축키가 먹도록 두벌식 자모를 키마다 함께 묶었습니다. reviewr 는 1대2 비율로 여는 스크립트를 키에 묶었고, 저장소마다 기준 브랜치를 `dev` 로 골라야 합니다.

손본 곳은 파일 셋입니다.

| 파일 | 바꾼 것 |
|------|------|
| `~/.config/herdr/config.toml` | prefix·동작 키에 자모 추가, prefix 동안 입력기를 영문으로 전환, reviewr 토글 키 |
| `~/.config/herdr/bin/reviewr-split.sh` | reviewr 를 왼쪽 1/3·오른쪽 2/3 으로 여닫는 스크립트 |
| `~/.config/herdr/plugins/config/persiyanov.reviewr/config.toml` | reviewr 키에 자모 추가, 화살표 키 되살리기 |

설정 파일은 바꾸기 전에 날짜를 붙여 백업해 두었습니다(`config.toml.bak-20261009-hangul` 등). 되돌릴 때는 그 파일로 바꾸고 다시 읽게 합니다.



## 한글 입력 상태에서 herdr 키가 먹게 하기

> 한글 상태에서 `ctrl+b` 를 누르면 herdr 에 `ctrl+ㅠ` 로 들어와 prefix 가 안 먹었습니다. prefix 와 동작 키마다 자모를 함께 묶고, prefix 를 누르는 동안 입력기를 영문으로 바꾸게 했습니다.

두벌식에서 `b` 자리는 `ㅠ` 입니다. 터미널이 키를 kitty 키 프로토콜로 보내면서 한글 상태의 `ctrl+b` 가 `ctrl+ㅠ` 로 전달되는 것으로 보입니다. herdr 는 그 프로토콜이 함께 보내는 "영문 배열 기준 키" 칸을 읽지 않아서 둘을 같은 키로 보지 않습니다. 원인 설명은 관찰에서 나온 추정이고, 아래 설정으로 증상이 사라진 것만 확인했습니다.

```bash
[keys]
prefix = ["ctrl+b", "ctrl+ㅠ"]
goto = ["prefix+g", "prefix+ㅎ"]
workspace_picker = ["prefix+w", "prefix+ㅈ"]
open_notification_target = ["prefix+o", "prefix+ㅐ"]
focus_pane_left = ["prefix+h", "prefix+ㅗ"]
focus_pane_right = ["prefix+l", "prefix+ㅣ"]
reload_config = ["prefix+shift+r", "prefix+ㄲ"]
navigate_pane_left = ["h", "ㅗ"]

[experimental]
switch_ascii_input_source_in_prefix = true
```

규칙은 셋입니다.

- 배열은 기본값을 대체하므로 영문 기본 키를 맨 앞에 두고 자모를 뒤에 덧붙입니다.
- Shift 조합은 자모가 따로 있을 때만 묶습니다. `shift+r` 은 `ㄲ`, `shift+w` 는 `ㅉ` 처럼 소문자와 다른 자모가 나옵니다.
- Shift 를 눌러도 소문자와 같은 자모가 나오는 `N`·`G`·`X`·`D`(`ㅜ`·`ㅎ`·`ㅌ`·`ㅇ`)는 다른 동작과 겹치므로 영문 전용으로 남깁니다.

`switch_ascii_input_source_in_prefix` 는 prefix 를 누른 동안만 입력기를 영문으로 바꿨다가 끝나면 원래 입력기로 되돌립니다. prefix 다음 키를 영문으로 받으려는 설정입니다. 이것만으로 자모 묶음이 필요 없어지는지는 따로 시험하지 않아서 둘 다 켜 두었습니다. prefix 자체는 입력기가 바뀌기 전에 눌리므로 `ctrl+ㅠ` 묶음이 필요합니다.

키 설정은 `ctrl+b` → `shift+r` 로 다시 읽은 뒤에도 바로 먹지 않은 적이 있습니다. 그때는 herdr 화면에서 떨어졌다가(`ctrl+b` → `q`) 다시 `herdr` 로 붙으면 됩니다.



## reviewr 를 1대2 로 여닫는 토글

> 플러그인 토글은 반반으로만 열려 diff 가 좁았습니다. 셸 스크립트로 왼쪽 1/3·reviewr 2/3 으로 열게 하고 `cmd+r` 과 `ctrl+b` → `d` 에 묶었습니다.

```bash
[[keys.command]]
key = "cmd+r"
type = "shell"
command = "/Users/<사용자>/.config/herdr/bin/reviewr-split.sh"

[[keys.command]]
key = "prefix+d"            # cmd+r 이 터미널에서 막힐 때. 한글 상태용 prefix+ㅇ 도 같은 명령
type = "shell"
command = "/Users/<사용자>/.config/herdr/bin/reviewr-split.sh"
```

스크립트는 같은 탭에 `reviewr` 라벨 창이 있으면 닫고, 없으면 지금 창 오른쪽에 엽니다. 연 뒤에 왼쪽 창을 1/6 만큼 줄여 1대2 를 만듭니다. 핵심은 두 명령입니다.

```bash
herdr plugin pane open --plugin persiyanov.reviewr --entrypoint pane --placement split \
  --target-pane "$target" --direction right --cwd "$cwd" --focus
herdr pane resize --pane "$target" --direction left --amount 0.1667
```

두 가지를 손봐야 동작했습니다. 창은 비동기로 생기므로, resize 전에 `herdr pane list` 로 창이 나타날 때까지(최대 3초) 기다립니다. 또 화면에 보이지 않는 workspace 에서는 `--focus` 가 조용히 실패하므로 `--no-focus` 로 한 번 더 엽니다.

닫을 때 한 가지는 확인하지 않았습니다. 이 스크립트는 `herdr pane close` 로 reviewr 창을 바로 닫습니다. reviewr 안에서 `q` 로 나갈 때와 달리, 안 보낸 코멘트가 있어도 묻지 않고 사라질 가능성이 큽니다. 코멘트가 남아 있으면 `s`·`y` 로 내보내거나 `q` 로 닫습니다.



## reviewr 키를 한글 상태에서도 쓰기

> reviewr 설정에도 소문자 키마다 자모를 묶었습니다. 그러다 화살표가 빠져서, 키 이름 `down`·`up` 을 함께 적어 되살렸습니다.

```bash
[keybindings]
down = ["j", "ㅓ", "down"]
up = ["k", "ㅏ", "up"]
next-file = ["f", "ㄹ"]
scope-uncommitted = ["u", "ㅕ"]
scope-branch = ["b", "ㅠ"]
scope-last-turn = ["t", "ㅅ"]
scope-commits = ["g", "ㅎ"]
wrap = ["w", "ㅈ"]
rendered = ["m", "ㅡ"]
select = ["v", "ㅍ"]
comment = ["c", "ㅊ"]
edit = ["e", "ㄷ"]
delete = ["d", "ㅇ"]
next-comment = ["n", "ㅜ"]
comments = ["l", "ㅣ"]
send = ["s", "S", "ㄴ"]
copy = ["y", "Y", "ㅛ"]
refresh = ["r", "ㄱ"]
quit = ["q", "ㅂ"]
```

처음에는 `down = ["j", "ㅓ"]` 로 적었다가 `↓` 가 동작하지 않았습니다. reviewr 의 기본값은 `j` 와 `↓` 두 개인데, 적은 배열이 둘을 통째로 대체했기 때문입니다. reviewr 설정은 키 이름 `down`·`up` 을 받으므로 함께 적어 해결했습니다.

대문자 키는 자모로 묶지 않았습니다. `F`·`N`·`B`·`G` 는 Shift 를 눌러도 소문자와 같은 자모(`ㄹ`·`ㅜ`·`ㅠ`·`ㅎ`)가 나와 다른 동작과 겹칩니다. `Q` 는 안 보낸 코멘트를 버리고 나가는 키라 한글 상태에서 잘못 눌리지 않게 뺐습니다. 그래서 기준 브랜치 고르기(`B`) 같은 키는 영문으로 바꾼 뒤 누릅니다.

자모 묶음이 실제로 먹는지는 키를 직접 보내 확인했습니다. `herdr pane send-keys <reviewr 창 ID> m` 을 보내자 마크다운 파일이 렌더링으로 바뀌었고, 이어서 `ㅡ` 를 보내자 원래 보기로 돌아왔습니다. 다만 이 시험은 macOS 입력기를 거치지 않습니다. 실제 키보드로 쳤을 때 입력기가 자모를 조합 중으로 붙잡아 늦게 보내는지는 확인하지 못했습니다. 키가 안 먹으면 영문으로 바꿔 같은 키를 눌러 보고 가립니다.



## 저장소마다 기준 브랜치를 dev 로 고르기

> 회사 저장소 둘 모두 `origin/HEAD` 가 `prd` 를 가리킵니다. reviewr 의 branch 범위가 `prd` 와 비교하지 않도록 worktree 마다 한 번씩 `B` 로 `dev` 를 고릅니다.

기능 브랜치는 `dev` 에서 땁니다. 그런데 reviewr 는 기준을 고르지 않으면 `origin/HEAD` 가 가리키는 `prd` 와 비교합니다. `dev` 가 `prd` 보다 커밋 27개 앞서 있던 날, 메일 기능 worktree 에서 `b` 를 누르니 실제 작업한 54개 파일 대신 164개 파일, +12,498줄이 떴습니다.

```bash
git -C <저장소> symbolic-ref refs/remotes/origin/HEAD          # refs/remotes/origin/prd
git -C <저장소> rev-list --count origin/prd..origin/dev         # dev 가 앞선 커밋 수
git -C <worktree> cat-file blob refs/worktree/reviewr/base-pick  # 이 worktree 에서 고른 기준(없으면 오류)
```

고른 값은 worktree 마다 따로 저장됩니다. 그래서 새 기능 worktree 를 열 때마다 reviewr 에서 영문 상태로 `B` → `dev` → `Enter` 를 한 번 합니다. 헤더가 `vs dev` 로 바뀌면 끝입니다. 2026-10-10 에는 열려 있던 worktree 셋 모두 고른 값이 없었습니다.
