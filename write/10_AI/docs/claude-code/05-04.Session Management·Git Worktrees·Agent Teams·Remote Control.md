# Session Management·Git Worktrees·Agent Teams·Remote Control
---
> 세션 보존과 분기 기법부터 세션 간 메시징, Git 워크트리 기반 병렬 격리, 실험적 다중 에이전트 팀 협업, 원격 조종과 웹 세션 연동까지 대규모 작업을 분할하고 제어하는 고급 기능을 다룹니다.



## 핵심 요약

> 대규모 작업 환경에서는 대화 맥락을 안전하게 분기하고 작업 공간을 파일 시스템 단위로 격리해야 충돌을 방지할 수 있습니다.

소프트웨어 개발이 복잡해질수록 단일 대화창 안에서 모든 작업을 해결하기 어려워집니다. 실험적인 리팩터링을 시도하다가 코드가 엉키거나, 여러 모듈을 동시에 수정하느라 작업 내역이 뒤섞이는 문제가 발생하기 때문입니다. Claude Code는 이러한 혼선을 방지하기 위해 세션을 독립적으로 복제하고 관리하는 다양한 분기 명령을 지원합니다. 또한 실행 중인 세션들이 서로의 상태를 묻고 답할 수 있는 세션 간 통신 경로를 제공합니다.

코드 수정 과정에서 기존 작업 공간을 보호하려면 파일 시스템 차원의 격리가 필요합니다. Git 워크트리 연동을 활용하면 현재 브랜치를 건드리지 않고도 안전한 임시 디렉터리에서 작업을 병렬로 진행할 수 있습니다. 나아가 여러 에이전트가 공유 작업 목록을 두고 협력하는 다중 에이전트 팀 기능과, 외부 기기에서 로컬 세션을 이어받는 원격 조종 기능이 복합적인 개발 환경을 뒷받침합니다.

| 하고 싶은 일 | 쓸 것 |
|------|------|
| 이전 세션 이어 가기 | `claude -c` 또는 `/resume` |
| 세션 이름을 지정하여 재개하기 | `claude -r <이름>` 또는 `/rename <이름>` |
| 현재 대화를 독립 배경 세션으로 복제하기 | `/fork [프롬프트]` |
| 결과를 회수하는 하위 작업 분기하기 | `/subtask <작업내용>` |
| 대화 분기점으로 직접 전환하기 | `/branch [이름]` |
| 다른 세션에 직접 메시지 보내기 | `SendMessage` 또는 `@세션이름` |
| 상대 세션 유휴 시 알림 받기 | `SendMessage`의 `notify_when_idle: true` |
| 격리된 워크트리에서 세션 시작하기 | `claude --worktree` 또는 `claude -w` |
| 백그라운드 세션 워크트리 격리 해제 | 설정 `worktree.bgIsolation: "none"` |
| 다중 에이전트 팀 기능 활성화 | `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` |
| 로컬 세션을 원격 기기에서 제어하기 | `claude remote-control` 또는 `/remote-control` |
| 클라우드 웹 세션을 로컬로 가져오기 | `claude --teleport` 또는 `/teleport` |

## Session Management

> 대화 상태를 디스크에 보존하고 목적에 따라 독립된 세션으로 갈라 작업합니다.

<!-- 도식 후보: state · 세션 포크와 브랜치 및 서브태스크 분기에 따른 컨텍스트 분리 상태 · 원문 09-advanced-features/README.md:64-87 -->

복잡한 개발 작업을 진행하다 보면 기존 작업 맥락을 그대로 유지한 채 새로운 아이디어를 검증해야 하는 상황이 자주 발생합니다. 대화 내역 전체를 처음부터 다시 입력하는 방식은 비효율적입니다. 기존 대화창에서 바로 다른 시도를 하면 앞선 논의와 맥락이 뒤섞여 모델이 혼란에 빠지기 쉽습니다. Claude Code는 이러한 문제를 해결하기 위해 대화 상태를 파일로 보존하고 다양한 방식으로 복제하는 세션 관리 체계를 제공합니다.

기본적인 세션 재개 옵션인 `-c`, `-r`, `--fork-session`의 CLI 실행 방식은 [01-01.CLI reference.md](./01-01.CLI reference.md)의 세션 이어 가기 절을 참조하시기 바랍니다. 대화형 인터페이스 내부에서는 슬래시 명령어를 통해 세션의 이름을 지정하거나 분기 방식을 세밀하게 선택할 수 있습니다.

### 세션 복원과 식별

세션 복원 명령어는 작업의 연속성을 보장합니다. 직전 세션을 즉시 이어갈 때는 CLI에서 `claude -c`를 실행합니다. 식별자로 지정된 세션을 불러올 때는 `claude -r "세션이름"`을 사용합니다. 대화창 내부에서는 `/resume` 명령어를 입력하여 원하는 세션으로 전환할 수 있습니다.

현재 진행 중인 세션에 명확한 식별자를 부여하려면 `/rename` 명령어를 사용합니다. `/rename auth-refactor`처럼 작업 주제를 이름으로 지정해 두면 다른 터미널이나 원격 기기에서 해당 세션을 찾기 수월해집니다.

v2.1.212 버전부터는 인자 없이 `/resume`을 실행했을 때 에이전트 뷰에 과거 세션 선택 창이 표시됩니다. 이 목록에는 화면 목록에서 숨겨졌던 이전 세션들도 포함됩니다. 선택한 세션을 백그라운드 세션으로 즉시 복원할 수 있습니다.

### 대화 복제와 분기 제어

대화를 복제하는 명령어는 복사본이 어디서 어떻게 실행되는지에 따라 세 가지로 나뉩니다.

첫째는 `/subtask <작업내용>` 명령어입니다. 현재 대화 내역 전체를 상속받은 하위 에이전트를 생성하여 백그라운드에서 작업을 수행시킵니다. 이 하위 에이전트는 독립적인 컨텍스트를 유지하며 작업을 끝마친 뒤 그 결과를 현재 대화창으로 회수합니다.

둘째는 `/fork [프롬프트]` 명령어입니다. 지금까지 나눈 모든 대화 맥락을 복사하여 새로운 독립 백그라운드 세션을 생성합니다. 이 세션은 현재 대화창과 완전히 분리되어 독자적으로 동작합니다. 수행 결과는 현재 대화창으로 반환되지 않습니다. 완전히 다른 기술 스택이나 실험적 대안을 병렬로 검증할 때 적합합니다.

셋째는 `/branch [이름]` 명령어입니다. 사용자가 직접 복사본 세션으로 전환하여 작업을 계속 진행하는 방식입니다. 원본 대화는 분기 시점 그대로 보존되므로 나중에 `/resume` 명령어로 언제든지 되돌아올 수 있습니다.

버전 변경에 따른 명령어 역할 변화를 주의해야 합니다. v2.1.212 이전에는 `/fork`가 하위 에이전트를 띄우는 역할을 맡았습니다. v2.1.212에서 `/subtask`가 도입되면서 두 명령어의 역할이 맞바뀌었습니다. 에이전트 뷰를 끄면 `/subtask`를 쓸 수 없으며 이때는 `/fork`가 예전의 하위 에이전트 생성 동작을 대신 수행합니다.

### 세션 요약과 사용량 제한 대기

긴 대화를 진행하다가 잠시 자리를 비운 뒤 돌아오면 직전까지 완료된 작업 내용을 빠르게 파악하기 어렵습니다. v2.1.108에 도입된 세션 요약 기능은 복귀 시점에 지난 작업의 핵심 성과를 간략히 요약하여 보여줍니다. 이 기능은 기본 활성화되어 있으며 `/config` 메뉴의 세션 요약 항목이나 `/recap` 명령어로 수동 호출할 수 있습니다. 환경 변수 `CLAUDE_CODE_ENABLE_AWAY_SUMMARY=0`을 지정하면 요약 출력을 끌 수 있습니다.

작업 도중 계정의 사용량 한도에 도달하여 응답이 멈추는 상황도 고려되었습니다. v2.1.234부터는 사용량 한도가 재설정되는 즉시 세션이 자동으로 작업을 재개합니다. 사용자가 주기적으로 화면을 확인하며 프롬프트를 다시 보낼 필요가 없습니다. 이 설정은 `/config` 메뉴의 사용량 한도 시 자동 재개 항목에서 켜고 끌 수 있습니다.

### 세션 관측과 원격 측정

엔터프라이즈 환경에서는 세션의 동작 품질과 의사결정 과정을 중앙에서 수집하여 분석할 필요가 있습니다. Claude Code는 OpenTelemetry 표준에 맞춘 다양한 원격 측정 로그를 제공합니다.

v2.1.136부터는 `CLAUDE_CODE_ENABLE_FEEDBACK_SURVEY_FOR_OTEL=1` 환경 변수를 통해 품질 설문 데이터를 캡처 파이프라인으로 전송할 수 있습니다. v2.1.193에서는 모델의 응답 텍스트를 담은 `claude_code.assistant_response` 로그 이벤트가 추가되었습니다.

v2.1.300에서는 `api_request` 이벤트에 캐시 생성 토큰 수치가 캐시 수명별로 나뉘어 보강되고, 트레이스 스팬에 공급자 이름 같은 GenAI 속성이 추가되었습니다. v2.1.301부터는 도구 결정 이벤트에 안전성 판정 결과와 권한 모드 속성이 추가되어 세션 내부의 도구 실행 판단을 추적할 수 있습니다.



## Cross-Session Messaging

> 독립적으로 떠 있는 여러 세션이 서로의 맥락을 조회하고 작업 완료를 통지합니다.

<!-- 도식 후보: sequence · 세션 간 메시지 전달 및 notify_when_idle 유휴 통지 흐름 · 원문 09-advanced-features/README.md:158-188 -->

과거의 세션들은 서로 격리된 섬과 같았습니다. 한 세션에서 데이터베이스 마이그레이션 작업을 수행하고 다른 세션에서 API 서버 코드를 작성할 때, API 세션은 마이그레이션 세션이 결정한 테이블 구조나 변경 사항을 알지 못했습니다. 개발자는 한쪽 세션의 대화 내용을 복사하여 다른 쪽 세션에 붙여넣으며 배경 맥락을 반복해서 설명해야 했습니다.

v2.1.224에 추가된 세션 간 메시징은 이러한 단절을 해소합니다. 로컬 머신에서 실행 중인 다른 세션뿐 아니라 클라우드 세션 및 원격 기기의 세션까지 서로 연결하여 메시지를 주고받을 수 있습니다.

### 세션 탐색과 주소 지정

메시지를 보내려면 먼저 통신 가능한 세션 목록을 파악해야 합니다. 모델 내부 도구인 `ListAgents`는 현재 접근할 수 있는 모든 대화 대상을 조회합니다. 사용자가 생성한 서브에이전트, 로컬 머신의 다른 세션, 클라우드 세션, 원격 연결된 다른 컴퓨터의 세션이 모두 목록에 포함됩니다.

목록의 각 항목은 유형 라벨과 함께 표시됩니다. v2.1.229부터는 오프라인 상태와 클라우드 상태를 구분하는 라벨이 추가되어 활성 세션 여부를 즉시 파악할 수 있습니다. v2.1.239부터는 `ListAgents` 결과에 세션 자신의 고유 이름도 함께 표시되므로 상대방에게 자신을 호출할 주소를 정확히 알려줄 수 있습니다.

통신 대상의 이름 자체가 곧 수신 주소가 됩니다. v2.1.232부터는 이름이 완전히 중복되지 않는 한 추가 식별자 없이 세션 이름만으로 메시지를 전달할 수 있습니다.

### 메시지 전송과 유휴 알림

세션에 메시지를 전달할 때는 `SendMessage` 도구를 호출합니다. 수신자 이름과 전달할 질문 내용을 지정하면 상대 세션에 질문이 전달됩니다.

```javascript
SendMessage({ to: "auth-refactor", message: "토큰 갱신 주기 결정을 알려주세요" })
```

상대 세션이 긴 작업을 수행 중일 때는 매번 상태를 확인할 필요가 없습니다. v2.1.236에 추가된 `notify_when_idle` 인자를 활용하면 대상 세션이 작업을 마치고 유휴 상태로 전환되는 시점에 단 한 번의 완료 통지를 보내옵니다.

```javascript
SendMessage({
  to: "auth-refactor",
  message: "마이그레이션 완료 후 알려주세요",
  notify_when_idle: true
})
```

이 통지는 구독자가 능동적으로 선택하는 단발성 알림입니다. 반복해서 상태를 확인하는 폴링 과정이 발생하지 않습니다. 작업이 끝나면 한 번 통지하고 구독이 자동으로 만료됩니다.

대화 입력창에서는 도구를 직접 부르지 않고도 `@세션이름` 형태로 메시지를 전송하는 간편 표기법을 지원합니다. 프롬프트 첫머리에 `@auth-refactor 마이그레이션 테스트가 통과했습니까?`처럼 입력하면 해당 세션에 질문이 직접 전달됩니다.

### 수신 정책과 보안 사다리

다른 세션에서 보내오는 메시지를 무조건 수락하면 현재 진행 중인 작업의 집중도가 흐려질 수 있습니다. v2.1.224부터 도입된 `crossSessionInbound` 설정은 외부 메시지의 수신 방식을 제어합니다.

| 설정값 | 동작 방식 |
|---|---|
| `"accept"` | 수신된 메시지를 현재 세션의 모델에게 즉시 전달합니다 |
| `"hold"` | 메시지가 도착했다는 안내만 표시하고 모델에게 넘기지 않습니다 |
| `"refuse"` | 들어오는 모든 외부 세션 메시지를 거절하고 버립니다 |

이 세 가지 값은 보안 사다리 구조를 이룹니다. 수락보다 보류가 엄격하며 보류보다 거절이 엄격합니다.

상위 범위인 사용자 전역 설정보다 하위 범위인 프로젝트 설정이 엄격할 때만 하위 설정이 적용됩니다. 프로젝트 단위에서 수신 정책을 강화할 수는 있어도 전역 설정이 정한 기준보다 완화할 수는 없습니다. v2.1.232부터는 `/config` 메뉴의 외부 세션 메시지 항목에서 이 값을 조정할 수 있습니다.

### 메시징 도달 범위와 한계

세션 간 메시징은 동일한 머신에서 실행되는 로컬 세션과 사용자의 클라우드 세션 간에 자유롭게 동작합니다. v2.1.225부터는 원격 조종으로 연결된 다른 컴퓨터의 세션과도 이름을 지정하여 통신할 수 있습니다.

다만 클라우드 세션의 응답 방식에는 현재 기술적 제약이 따릅니다. 로컬 세션에서 클라우드 세션으로 메시지를 보내면 클라우드 세션이 이를 수신할 수는 있습니다. 하지만 클라우드 세션이 로컬 세션으로 직접 응답 메시지를 역전송하지는 못합니다. 클라우드 세션이 내린 결론은 해당 클라우드 세션의 대화 기록을 직접 열어 확인해야 합니다.



## Git Worktrees

> 코드 변경 충돌 없이 안전한 임시 디렉터리에서 작업을 병렬로 격리합니다.

<!-- 도식 후보: tree · 원본 저장소와 .claude/worktrees 하위 격리 워크트리 디렉터리 구조 · 원문 09-advanced-features/README.md:383-426 -->

여러 기능 개발을 동시에 진행하거나 위험도가 높은 리팩터링을 시도할 때 가장 큰 문제는 현재 작업 공간의 오염입니다. 기존 브랜치에서 작업 중이던 미완성 코드가 있을 때 새 브랜치로 전환하려면 작업 내역을 임시 저장소에 숨겨두어야 합니다. 브랜치를 오가는 과정에서 빌드 산출물이 깨지거나 의도치 않은 파일 충돌이 발생하기도 합니다.

Claude Code는 Git 워크트리 기능을 활용하여 이러한 불편을 근본적으로 제거합니다. 기존 작업 디렉터리를 전혀 건드리지 않고 완전히 독립된 별도 폴더에 임시 브랜치를 체크아웃하여 작업을 수행합니다.

### 워크트리 분기와 경로 구조

격리된 작업 공간에서 세션을 시작하려면 CLI 옵션으로 `--worktree` 또는 `-w` 플래그를 붙여 실행합니다.

```bash
claude --worktree
```

명령이 실행되면 저장소 내부의 지정된 경로 아래에 새로운 워크트리 디렉터리가 생성됩니다.

```bash
<저장소경로>/.claude/worktrees/<워크트리이름>
```

세션이 이 격리 폴더 안에서 시작되므로, 파일 생성이나 코드 수정이 메인 작업 디렉터리에 아무런 영향을 주지 않습니다. 메인 브랜치에서 서버를 띄워 둔 채로 워크트리 안에서 다른 실험을 안전하게 병행할 수 있습니다.

### 모노레포 부분 체크아웃

방대한 소스 코드가 하나의 저장소에 모여 있는 대규모 모노레포 환경에서는 전체 저장소를 워크트리로 복제할 때 디스크 사용량이 급증하고 초기화 시간이 오래 걸립니다.

설정 파일에 `worktree.sparsePaths` 항목을 지정하면 필요한 디렉터리와 파일만 선택적으로 체크아웃하는 부분 체크아웃 기법을 적용할 수 있습니다.

```json
{
  "worktree": {
    "sparsePaths": ["packages/account-service", "libs/common/"]
  }
}
```

이 설정을 활용하면 수십 기가바이트에 달하는 모노레포 전체를 복제하지 않아도 됩니다. 작업 대상 패키지와 공통 라이브러리 폴더만 가볍게 내려받아 워크트리 세션을 즉시 시작할 수 있습니다.

### 베이스 브랜치와 백그라운드 격리

워크트리를 생성할 때 어느 커밋을 기준으로 새 브랜치를 딸 것인가는 중요한 문제입니다. v2.1.133에 추가된 `worktree.baseRef` 설정은 기준 브랜치를 결정합니다.

기본값인 `"fresh"`는 원격 저장소의 기본 브랜치 최신 상태인 `origin/<기본브랜치>`를 기준으로 분기합니다. 이 방식은 로컬에 남아 있는 아직 푸시되지 않은 커밋을 배제하고 깨끗한 원격 기준으로 작업을 시작합니다. 반면 `"head"`를 지정하면 로컬 작업 공간의 현재 `HEAD`를 기준으로 분기하므로 로컬 커밋 내역을 그대로 이어받을 수 있습니다.

```json
{
  "worktree": {
    "baseRef": "head"
  }
}
```

백그라운드 세션의 격리 여부를 결정하는 `worktree.bgIsolation` 설정도 유용합니다. v2.1.143부터 지원되는 이 설정의 기본 동작은 백그라운드 작업마다 `.claude/worktrees/` 아래에 전용 워크트리를 만들어 주는 것입니다.

만약 네이티브 빌드 결과물이 너무 무거워 워크트리 복제가 부담스럽거나 메인 작업 공간과 직접 협력해야 한다면 값을 `"none"`으로 지정할 수 있습니다. 다만 `"none"`을 쓰면 백그라운드 에이전트와 사용자가 동일한 파일을 동시에 수정하여 충돌이 발생할 위험이 커지므로 주의해야 합니다.

### 수명주기 도구와 자동 정리

세션 내부에서는 워크트리를 제어하는 전용 도구와 수명주기 훅을 사용할 수 있습니다. `EnterWorktree` 도구는 작업 공간을 특정 워크트리로 전환합니다. v2.1.157부터는 세션 진행 도중 다른 워크트리로 옮겨가는 작업도 지원합니다. 작업이 끝나면 `ExitWorktree` 도구로 이전 공간으로 복귀합니다.

워크트리가 생성되거나 삭제될 때는 `WorktreeCreate`와 `WorktreeRemove` 훅 이벤트가 발행됩니다. `WorktreeCreate` 훅을 설정하면 기본 `git worktree` 생성 동작을 대체하므로, SVN이나 Perforce 같은 다른 버전 관리 도구로 작업 공간을 만들고 정리하도록 스크립트를 연결할 수 있습니다.

워크트리 안에서 아무런 코드 변경이 발생하지 않았다면 이름을 붙이지 않은 세션은 종료될 때 해당 디렉터리가 자동으로 삭제됩니다. v2.1.157부터는 에이전트 작업 종료 시 워크트리의 잠금 상태를 자동으로 해제하므로, 수동으로 `git worktree remove`나 `git worktree prune`을 실행하여 정리하기도 수월합니다.



## Agent Teams

> 공유 작업 목록을 중심으로 여러 전문 에이전트가 역할을 나누어 협업합니다.

복잡한 대규모 아키텍처 개선이나 전역 리팩터링은 단일 에이전트의 컨텍스트 창 용량을 쉽게 초과합니다. 파일 수십 개를 동시에 검토하고 테스트 코드와 구현 코드를 병렬로 수정해야 하는 상황에서는 작업을 쪼개어 독립적인 실행 단위에 맡기는 편이 효과적입니다.

Claude Code의 다중 에이전트 팀 기능은 하나의 목표를 달성하기 위해 여러 인스턴스가 협력하는 실험적 협업 모델입니다. 각 에이전트가 자신만의 독립된 컨텍스트 공간을 유지하면서 공유 작업 목록을 통해 유기적으로 소통합니다.

### 팀 구조와 공유 작업 목록

다중 에이전트 팀 기능은 기본적으로 비활성화되어 있습니다. 기능을 활성화하려면 환경 변수를 선언하거나 설정 파일에 플래그를 추가해야 합니다.

```bash
export CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1
```

팀 협업 구조는 팀장 에이전트와 팀원 에이전트로 나뉩니다. 팀장 에이전트는 사용자의 전체 목표를 분석하여 세부 과제로 분할하고 이를 팀원들에게 배분합니다. 각 팀원은 배정받은 하위 과제를 독자적인 컨텍스트 안에서 수행합니다.

이 과정에서 핵심 매개체 역할을 하는 것이 공유 작업 목록입니다. 팀원들은 작업 목록에 등록된 항목들의 상태를 실시간으로 확인하고 완료 여부를 갱신합니다. 팀원 개개인의 역할과 전문 분야는 프로젝트·사용자·관리형·플러그인 범위의 서브에이전트 정의(예: `.claude/agents/`)를 통해 맞춤형으로 지정할 수 있습니다.

### 터미널 분할과 표시 모드

여러 에이전트가 동시에 실행될 때 진행 상황을 시각적으로 관찰하는 방법은 개발 생산성에 큰 영향을 줍니다. `--teammate-mode` 실행 플래그는 팀원들의 화면 표시 모드를 제어합니다.

| 표시 모드 | 특징과 동작 방식 |
|---|---|
| `in-process` | 기본값이며 모든 팀원이 메인 터미널 안에서 실행되고, 에이전트 패널에서 팀원을 골라 봅니다 |
| `tmux` | 분할 창 인터페이스를 활용하여 각 팀원마다 전용 창을 배정합니다 |
| `auto` | 터미널 실행 환경을 감지하여 최적의 화면 분할 방식을 자동으로 선택합니다 |

tmux 환경이나 분할 창을 지원하는 터미널에서 작업할 때는 `tmux` 모드가 유용합니다.

```bash
claude --teammate-mode tmux
```

각 팀원의 사고 과정과 도구 실행 결과가 독립된 분할 창에 실시간으로 표시되므로 병렬 작업의 진행 상태를 한눈에 파악할 수 있습니다.

### 서브에이전트와의 구조적 차이

다중 에이전트 팀은 기존 서브에이전트 기능과 협업 방식에서 차이를 보입니다.

[03-02.Subagents.md](./03-02.Subagents.md)에서 다루는 서브에이전트는 엄격한 부모와 자식 간의 수직적 호출 관계를 갖습니다. 부모 에이전트가 작업을 지시하면 자식 에이전트가 실행되며, 메인 대화에서 띄운 서브에이전트는 기본적으로 백그라운드에서 돕니다. 작업이 완료되면 결과 요약본을 부모에게 보고하고 종료됩니다. 자식 에이전트끼리 서로의 진행 상황을 알거나 직접 조율할 수 없습니다.

반면 에이전트 팀은 수평적 동료 관계를 형성합니다. 팀원 에이전트들은 공유 작업 목록을 매개로 삼아 각자의 진행 상태를 실시간으로 확인하며 자율적으로 작업을 조정합니다. 또한 별도의 독립 창에서 지속적으로 상주하면서 모듈별 변경을 병렬로 처리합니다. 따라서 단일 기능 조사나 특정 파일 수정에는 가벼운 서브에이전트가 적합합니다. 반면 전역적인 대규모 리팩터링이나 기능 구현과 코드 리뷰의 동시 병렬 수행에는 에이전트 팀이 적합합니다.



## Remote Control·Web Sessions

> 외부 기기에서 로컬 실행 환경을 조종하거나 클라우드 세션을 로컬로 이어받습니다.

<!-- 도식 후보: layer stack · 로컬 실행 기반 Remote Control과 클라우드 실행 기반 Web Session 통신 계층 · 원문 09-advanced-features/README.md:273-286 -->

사무실 컴퓨터에서 대규모 마이그레이션 작업을 지시해 두고 이동해야 하거나, 태블릿이나 스마트폰 같은 모바일 기기에서 작업 진행 상황을 확인하고 추가 명령을 내려야 하는 경우가 있습니다. 이때 로컬 개발 환경의 파일과 빌드 도구는 유지하면서 인터페이스만 외부로 확장할 수 있어야 합니다. 반대로 웹 브라우저에서 가볍게 시작한 작업을 로컬 터미널로 가져와 심층 개발로 전환해야 하는 상황도 발생합니다.

Claude Code는 로컬 프로세스를 안전하게 외부 기기에 연결하는 원격 조종 기능과, 브라우저 상에서 독립적으로 동작하는 클라우드 웹 세션 연동 기능을 함께 지원합니다.

### 로컬 실행 기반 원격 조종

원격 조종은 로컬 컴퓨터에서 실행 중인 Claude Code 세션을 외부 브라우저나 스마트폰의 Claude 앱에서 그대로 조종할 수 있게 해 주는 기능입니다. 코드가 클라우드로 이전되는 것이 아닙니다. 모든 도구 실행과 파일 수정은 개발자의 로컬 컴퓨터에서 일어납니다.

2026년 34주차부터 실험 기능 표기를 떼고 정식 지원 단계로 전환되었습니다. <!-- 확인 필요: 공식 문서·설치본에서 찾지 못함 --> Pro, Max, Team, Enterprise 요금제 환경에서 사용할 수 있습니다. `claude remote-control`을 구동한 머신은 Claude 앱의 코드 탭에 기기 카드로 등록되어 스마트폰에서 즉시 원격 세션을 시작할 수 있습니다. <!-- 확인 필요: 공식 문서·설치본에서 찾지 못함 -->

원격 세션을 시작하는 방법은 CLI 명령과 내부 명령어 두 가지입니다.

```bash
# 기본 이름으로 시작
claude remote-control

# 고유 세션 이름을 지정하여 시작
claude remote-control --name "Auth Refactor"
```

이미 대화형 세션이 열려 있는 상태라면 내부에서 `/remote-control`을 입력하고, 새 대화형 세션을 띄울 때는 `claude --remote-control` 또는 단축 옵션인 `claude --rc`로 원격 제어를 활성화할 수 있습니다. v2.1.300부터는 `claude remote-control` 명령에 샌드박스 관련 플래그를 붙일 수 없습니다. 샌드박스가 필요하다면 설정 파일의 `sandbox.enabled` 값을 사용해야 합니다.

외부 기기에서 세션에 연결하는 방법은 세 가지가 제공됩니다. 첫째는 터미널에 출력된 세션 접속 웹 주소를 브라우저로 여는 방식입니다. 둘째는 실행 직후 스페이스바를 눌러 화면에 나타난 QR 코드를 모바일 기기로 스캔하는 방식입니다. 셋째는 claude.ai/code 웹 화면이나 모바일 앱에서 기기 목록을 찾아 클릭하는 방식입니다.

외부 포트를 열지 않는 안전한 아키텍처가 적용되었습니다. 외부에서 들어오는 인바운드 포트를 일절 개방하지 않습니다. 오직 로컬 머신에서 외부로 나가는 TLS 암호화 아웃바운드 HTTPS 연결만을 사용합니다. 인증 토큰 역시 짧은 유효 기간을 가진 전용 토큰을 발행하여 보안을 유지합니다.

### 모바일 연동과 푸시 알림

작업 시간이 오래 걸리는 테스트나 빌드를 실행해 두고 다른 용무를 볼 때, 작업이 끝났는지 계속 화면을 쳐다보는 것은 시간 낭비입니다.

v2.1.110에 도입된 푸시 알림 기능은 모바일 기기로 작업 완료 소식을 전송합니다. `/remote-control`을 켠 상태에서 `/config` 메뉴의 모델 판단 시 푸시 전송 항목을 활성화하면, 장시간 작업이 끝나거나 추가 승인이 필요할 때 스마트폰으로 즉시 푸시 알림이 발송됩니다.

주의할 점은 터미널 프로세스가 유지되어야 한다는 사실입니다. 로컬 컴퓨터의 터미널이 닫히면 원격 제어도 함께 종료됩니다. 네트워크가 일시적으로 끊겼을 때 대화형 세션은 재연결을 시도합니다. 반면 여러 세션을 동시에 중계하는 서버 모드는 약 10분 이상 연결이 두절되면 프로세스를 정리합니다.

### 관리자 통제와 인증 제약

기업 환경에서는 보안 규격 준수를 위해 소스 코드가 존재하는 로컬 환경으로의 외부 원격 접속을 전면 금지해야 할 수 있습니다.

v2.1.128부터 지원되는 `disableRemoteControl` 설정은 조직 차원에서 원격 제어 기능을 차단할 수 있게 지원합니다. <!-- 확인 필요: 공식 문서·설치본에서 찾지 못함 --> 관리자 정책 파일인 `managed-settings.json`에 이 값을 지정하면 개발자가 개별적으로 설정을 해제할 수 없습니다.

```json
{
  "disableRemoteControl": true
}
```

또한 v2.1.139부터 적용된 인증 제약 규칙에 유의해야 합니다. 환경 변수에 `ANTHROPIC_API_KEY`나 `ANTHROPIC_AUTH_TOKEN`이 설정되어 있거나 설정 파일에 `apiKeyHelper`가 등록되어 있으면 원격 조종 기능이 자동으로 비활성화됩니다. 스케줄 작업이나 클라우드 커넥터와 마찬가지로, 원격 연동 기능은 claude.ai의 OAuth 로그인 인증을 전제로 동작하기 때문입니다. 원격 조종을 사용하려면 API 키 환경 변수를 해제하고 OAuth 로그인을 활성화해야 합니다.

### 클라우드 웹 세션과 텔레포트

원격 조종이 로컬 컴퓨터의 프로세스를 외부에서 다루는 방식이라면, 웹 세션은 완전히 Anthropic 클라우드 인프라 위에서 구동되는 독립 세션입니다. 로컬 환경의 도구나 파일 의존성 없이 웹 브라우저만으로 즉시 개발을 시작할 수 있습니다.

CLI에서 클라우드 웹 세션을 직접 생성할 때는 `--remote` 플래그를 사용합니다.

```bash
claude --remote "신규 결제 모듈 프로토타입 작성"
```

웹 세션에서 구현하던 코드를 로컬 환경으로 가져와 실행하고 싶을 때는 텔레포트 기능을 사용합니다. CLI에서 `claude --teleport`를 실행하거나 대화창 내부에서 `/teleport` 또는 단축 명령어 `/tp`를 입력합니다.

화면에 활성 웹 세션 목록이 표시됩니다. 원하는 세션을 선택하면 클라우드에서 나눈 대화 기록과 코드 상태가 로컬 터미널로 즉시 전송되어 로컬 작업으로 전환됩니다. 특정 세션 ID를 알고 있을 때는 `claude --teleport <세션ID>` 형태로 대화상자 없이 즉시 연결할 수도 있으며, v2.1.223부터는 클라우드 세션 안에서 `/teleport`를 입력하면 이 명령을 알려 줍니다.

### 원격 조종과 웹 세션의 차이

두 방식은 어디에서 코드가 실행되고 어떤 도구에 접근할 수 있는지에 따라 명확히 구분됩니다.

| 비교 항목 | 원격 조종 (Remote Control) | 클라우드 웹 세션 (Web Sessions) |
|---|---|---|
| **코드 실행 위치** | 개발자의 로컬 컴퓨터 | Anthropic 클라우드 가상 환경 |
| **로컬 도구 접근** | 로컬 MCP 서버, 로컬 CLI, 전체 파일 접근 가능 | 클라우드 샌드박스 내부 도구만 사용 가능 |
| **호스트 유지 여부** | 로컬 컴퓨터 터미널이 켜져 있어야 유지 | 로컬 컴퓨터 전원을 꺼도 클라우드에서 유지 |
| **주요 활용 목적** | 로컬 개발 환경을 유지하며 외부 기기에서 제어 | 브라우저에서 가볍게 시작 후 로컬로 회수 |

로컬 개발 환경의 빌드 도구나 데이터베이스에 직접 접근해야 한다면 원격 조종을 선택합니다. 컴퓨터를 켜지 않은 상태에서 작업을 발주하거나 브라우저 중심의 가벼운 검토를 원한다면 웹 세션을 활용하는 방식이 적합합니다.
