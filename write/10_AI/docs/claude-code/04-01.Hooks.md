# Hooks
---
> Claude Code 세션에서 발생하는 사건을 가로채 셸 명령, 웹훅, 모델 평가를 자동 실행하는 훅의 동작 원리와 설정 방법을 정리합니다.



## 핵심 요약

> 훅은 모델 내부의 확률적 판단에 기대지 않고 외부 프로세스로 실행 흐름을 제어하는 결정론적 통제 장치입니다.

Claude Code 는 도구를 실행하거나 대화를 나눌 때 다양한 수명주기 사건을 발생시킵니다. **훅**(hook, 정해진 사건에 맞춰 자동 실행되는 명령)은 이 사건을 중간에서 가로챕니다. 외부 스크립트나 검증기가 표준 입력으로 전달된 JSON 데이터를 확인하고 실행 승인 여부를 결정합니다.

자연어 지시문은 문맥이 길어지면 모델이 무시하거나 건너뛸 가능성이 있습니다. 반면 훅은 모델 추론 루프 바깥의 운영체제 프로세스에서 실행됩니다. 잘못된 명령이나 위험한 파일 수정을 원천 차단할 수 있는 이유가 여기에 있습니다.

| 하고 싶은 일 | 쓸 설정과 이벤트 |
|---|---|
| 위험한 셸 명령 실행 차단 | `PreToolUse` 이벤트 + `Bash` 매처 + 종료 코드 2 |
| 소스 코드 수정 후 포맷팅 자동화 | `PostToolUse` 이벤트 + `Write\|Edit` 매처 + 포맷터 명령 |
| 파괴적인 사용자 프롬프트 제출 방지 | `UserPromptSubmit` 이벤트 + `block` 결정 반환 |
| 작업 완료 여부 정성 평가 | `Stop` 이벤트 + `prompt` 유형 훅 |
| 고비용 모델로의 무단 전환 통제 | `PreModelSwitch` 이벤트 + 정규식 매처 + 종료 코드 2 |
| 세션 시작 시 환경 변수 영구 반영 | `SessionStart` 이벤트 + `CLAUDE_ENV_FILE` 파일 쓰기 |
| 세션 종료 시 학습 기록 저장 | `SessionEnd` 이벤트 + `command` 유형 훅 |

## 훅이 푸는 문제

> 훅은 대화 맥락과 무관하게 항상 동작하는 결정론적 규칙을 세션에 부여합니다.

### 프롬프트 지시와 훅의 차이점

`CLAUDE.md` 나 시스템 지침에 금지 명령을 적어두는 방식은 한계가 있습니다. 대화가 수십 턴 이상 길어지면 컨텍스트 창 압박으로 인해 모델이 지침을 망각할 수 있습니다. 자연어 지시는 근본적으로 확률 모델의 해석에 의존하기 때문입니다.

반면 훅은 모델의 사고 과정을 거치지 않습니다. Claude Code 가 도구를 호출하거나 프롬프트를 처리하는 즉시 독립 프로세스로 구동됩니다. 스크립트가 표준 오류로 사유를 남기고 비정상 종료 코드를 반환하면 도구 실행은 물리적으로 차단됩니다. 모델은 이 차단을 우회할 방법이 없습니다.

보안 규칙 준수나 사내 정책 검증처럼 실패를 허용할 수 없는 작업은 프롬프트 지시가 아닌 훅으로 강제해야 안전합니다. 파일 형식 정규화나 실행 이력 감사 로그 작성 역시 훅을 통해 자동화할 수 있습니다.

### 훅의 실행 특성과 동시성

훅의 기본 실행 제한 시간은 600초입니다. 명령, HTTP 웹훅, MCP 도구 유형 모두 이 기본값을 따릅니다. 다만 단일 턴 언어 모델 평가를 수행하는 프롬프트 훅은 30초, 서브에이전트 훅은 60초의 기본 제한을 가집니다.

특정 이벤트에서는 반응 속도를 보장하기 위해 기본 제한 시간이 짧아집니다. 사용자 입력을 다루는 `UserPromptSubmit` 과 모델 전환을 감시하는 `PreModelSwitch` 는 30초로 제한됩니다. 어시스턴트 메시지 표시를 가로채는 `MessageDisplay` 는 10초로 줄어듭니다. 세션 종료 시점에 불리는 `SessionEnd` 훅들은 전체가 합쳐서 1.5초 예산을 공유합니다.

하나의 사건에 여러 훅이 등록된 경우 모든 훅은 병렬로 동시에 실행됩니다. 다만 v2.1.302 부터는 시스템 과부하를 막기 위해 동일 이벤트 내에서 최대 12개의 프롬프트 또는 에이전트 훅만 동시에 실행되도록 상한이 도입되었습니다. 내용이 완전히 같은 명령은 내부에서 자동으로 중복이 제거됩니다. 모든 훅은 현재 작업 디렉터리에서 세션의 환경 변수를 이어받아 구동됩니다.



## 설정 구조

> 훅은 전역, 프로젝트, 컴포넌트 수준의 설정 파일에서 계층적으로 선언할 수 있습니다.

### 설정 파일의 계층과 위치

훅은 사용 목적과 공유 범위에 따라 다섯 가지 위치에 설정할 수 있습니다. 개인 개발 환경 전체에 적용하려면 `~/.claude/settings.json` 에 선언합니다. 팀원과 형상 관리를 통해 공유할 규칙은 프로젝트 루트의 `.claude/settings.json` 에 둡니다.

개인 저장소 전용이지만 커밋에 포함하지 않을 설정은 `.claude/settings.local.json` 에 작성합니다. 엔터프라이즈 환경에서는 조직 단위의 매니지드 정책 파일로 일괄 강제할 수 있습니다. 확장 기능을 묶은 플러그인은 자체 `hooks/hooks.json` 을 가지며, 스킬이나 서브에이전트는 프론트매터에 훅을 선언합니다.

여러 설정 파일에 선언된 훅은 서로 덮어쓰지 않고 합쳐져 모두 실행됩니다. 다만 비활성화 플래그 같은 관리자 통제 정책은 최상위 계층이 하위 계층을 강제로 제어합니다.

### 훅 설정 블록의 기본 구조

설정 파일의 최상위 `hooks` 객체 아래에 이벤트 이름을 키로 지정하고 매처 객체 배열을 배치합니다. 각 매처 객체는 대상 도구를 가리키는 `matcher` 문자열과 실제 동작을 기술하는 `hooks` 핸들러 배열로 이루어집니다.

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/validate.sh",
            "timeout": 30
          }
        ]
      }
    ]
  }
}
```

훅 핸들러 객체는 훅 유형인 `type`, 실행할 명령인 `command`, 최대 대기 시간인 `timeout` 을 포함합니다. 비동기로 백그라운드에서 돌리고자 할 때는 `async` 필드를 `true` 로 지정합니다. 백그라운드로 돌면서 종료 코드 2를 냈을 때 세션을 깨우는 `asyncRewake` 필드도 쓸 수 있습니다.

실행 실패 시의 처리 방식을 정하는 `onFailure` 필드는 v2.1.295 에 도입되었습니다. 기본값은 `"continue"` 이며 훅 실행이 실패했을 때 본 작업을 차단하려면 `"block"` 으로 설정합니다. 사용자 화면의 스피너에 띄울 문구는 `statusMessage` 필드로 변경할 수 있습니다.

### 도구 이름 매처 규칙

도구 이름을 고르는 필드는 **매처**(matcher, 도구나 사건을 선별하는 일치 규칙)입니다. 매처는 대소문자를 엄격히 구분하여 도구 이름을 검사합니다. 단일 도구를 지정할 때는 `"Write"` 처럼 완전한 이름을 씁니다. 여러 도구를 묶을 때는 `"Edit|Write"` 와 같은 `|` 구분 목록이나 `"Write,Edit"` 처럼 쉼표 구분 목록을 씁니다. 쉼표 구분 목록은 v2.1.191 부터 지원됩니다.

모든 도구에 훅을 걸고 싶다면 와일드카드 `"*"` 나 빈 문자열 `""` 을 지정합니다. 외부 확장인 MCP 도구를 지정할 때는 `"mcp__<서버이름>__.*"` 형태의 패턴을 적용합니다.

v2.1.195 부터 매처 검증 알고리즘이 개선되어 부분 문자열 오작동이 사라졌습니다. 하이픈이나 밑줄이 포함된 긴 도구 이름도 정확하게 전체 일치로만 식별됩니다.

### if 조건절을 통한 세부 필터링

`matcher` 가 도구 이름만 검사한다면 `if` 필드는 도구에 전달된 인자 값까지 검사하여 실행 범위를 좁힙니다. 이 필드는 매처 객체가 아니라 개별 훅 핸들러 객체 내부의 형제 필드로 작성합니다.

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "if": "Edit(src/**)",
            "command": "./hooks/lint-src.sh"
          }
        ]
      }
    ]
  }
}
```

`if` 문법은 Claude Code 권한 규칙 표기법(`ToolName(pattern)`)을 그대로 차용합니다. 파일 경로는 `.gitignore` 방식의 일치 규칙을 따릅니다. 예를 들어 `Edit(src/**)` 는 `src/` 디렉터리 내부 파일 수정만 골라내고, `Read(.env)` 는 설정 파일 조회를 정확히 가로챕니다.

v2.1.214 부터 `if` 조건절의 경로 평가가 더욱 엄격해졌습니다. 단일 세그먼트로 시작하는 `src/**` 패턴은 현재 작업 디렉터리 직하위의 `src` 만 일치시킵니다. 깊은 하위 폴더의 모든 `src` 디렉터리를 맞추려면 `**/src/**` 형태로 명시해야 합니다.

### 컴포넌트 범위 훅

스킬 정의(`SKILL.md`), 서브에이전트 정의(`agent.md`), 슬래시 명령 정의(`command.md`)의 프론트매터에도 훅을 선언할 수 있습니다. 컴포넌트에서 필요한 보안 점검이나 환경 구성을 컴포넌트 자체에 캡슐화할 때 유용합니다.

스킬 프론트매터에 정의된 훅은 `once: true` 속성을 쓸 수 있습니다. 훅이 처음으로 성공 실행된 직후 시스템에서 자동으로 등록 해제되는 기능입니다. 훅 실행이 실패하거나 차단된 경우에는 해제되지 않고 다음 호출을 기다립니다.

서브에이전트 프론트매터에 선언된 `Stop` 훅은 시스템 내부에서 해당 서브에이전트 전용 `SubagentStop` 으로 자동 변환됩니다. 메인 세션 종료가 아니라 서브에이전트가 종료될 때만 정확히 격리 실행되도록 돕기 위함입니다. 프로젝트 서브에이전트 프론트매터 훅은 v2.1.218 부터 작업 공간 신뢰 승인이 완료되어야만 동작합니다.

### 다섯 가지 훅 유형

Claude Code 는 작업 성격에 맞게 선택할 수 있는 다섯 가지 훅 유형을 제공합니다.

`command` 는 가장 널리 쓰이는 기본 유형입니다. 셸 명령이나 독립 실행 파일을 프로세스로 띄워 표준 입출력과 종료 코드로 소통합니다. v2.1.139 부터는 셸 파싱을 거치지 않고 바이너리를 직접 호출하는 `args` 배열 방식도 지원합니다. 따옴표 이스케이프 실수로 인한 셸 주입 공격을 원천 차단할 수 있습니다.

`http` 는 v2.1.63 에 도입된 원격 웹훅 유형입니다. 지정한 URL 로 JSON 데이터를 HTTP POST 요청으로 전송합니다. 샌드박스가 켜져 있으면 네트워크 요청이 샌드박스 보안 규칙을 거치며, 헤더 내부의 환경 변수 치환에는 `allowedEnvVars` 명시가 요구됩니다. <!-- 확인 필요: 공식 문서·설치본에서 찾지 못함 -->

`prompt` 는 단일 턴 언어 모델 평가를 수행하는 유형입니다. 평가 프롬프트를 실행하여 작업 완결성이나 정책 부합 여부를 질의하고 그 결과를 불리언 결정으로 회신받습니다.

`mcp_tool` 은 v2.1.118 에 추가된 유형입니다. 이미 연결된 MCP 서버의 특정 도구를 직접 실행합니다. 인자 전달 시 입력 JSON 의 필드를 `${tool_input.file_path}` 형태로 치환할 수 있습니다.

`agent` 는 다단계 추론과 도구 조회가 가능한 서브에이전트를 띄워 검증을 맡기는 실험적 유형입니다. 복잡한 설계 문서 대조나 코드 아키텍처 점검에 적합합니다. 다만 v2.1.280 부터는 권한 승인이나 거부를 결정할 수 없는 `PermissionRequest` 이벤트에서 에이전트 훅 사용이 제한되었습니다.

### 도구 실행 전후 이벤트

`PreToolUse` 는 도구 호출을 가로채어 실행 여부를 결정하는 핵심 이벤트입니다. 권한 결정 필드로 `"allow"`, `"deny"`, `"ask"`, `"defer"` 를 반환할 수 있습니다. 여러 훅의 판정이 충돌할 때는 `deny` 가 최우선으로 적용되며, 그 뒤로 `defer`, `ask`, `allow` 순서의 우선순위를 갖습니다.

`PostToolUse` 는 도구 작업이 끝난 직후 호출됩니다. 이미 끝난 작업을 취소할 수는 없지만 추가 피드백을 전달할 수 있습니다. v2.1.119 부터는 도구의 순수 실행 시간을 밀리초 단위로 기록한 `duration_ms` 필드가 전달되어 성능 병목을 추적할 수 있습니다.

### 세션과 모델 제어 이벤트

v2.1.251 에 추가된 `PreModelSwitch` 와 `PostModelSwitch` 는 모델 변경 사건을 다룹니다. 두 이벤트 모두 이전 모델인 `from_model` 과 변경될 모델인 `to_model` 정보를 함께 수신합니다.

`PreModelSwitch` 훅에서 종료 코드 2를 반환하면 모델 전환이 즉시 거부되고 기존 모델이 유지됩니다. 특정 프로젝트에서 예산 관리를 위해 상위 모델로의 전환을 원천 차단할 때 유용합니다. `PostModelSwitch` 는 세션 재개 시 자동 복원된 모델 변경까지 감지하여 로그를 남깁니다.

### 권한 요청 이벤트

`PermissionRequest` 이벤트는 사용자 승인 대화상자가 표시되는 순간을 가로챕니다. 종료 코드 0과 함께 정해진 규격의 JSON 응답을 반환하여 승인이나 거부를 프로그래밍 방식으로 처리합니다.

```json
{
  "hookSpecificOutput": {
    "hookEventName": "PermissionRequest",
    "decision": {
      "behavior": "allow"
    }
  }
}
```

이 기능을 쓰면 안전이 입증된 반복 작업에 대해 대화형 프롬프트를 띄우지 않고 세션을 막힘없이 진행할 수 있습니다.



## 입력과 출력

> 표준 입력 JSON 으로 세션 상태를 전달받고 종료 코드와 표준 출력 JSON 으로 시스템을 제어합니다.

### 표준 입력 JSON 구조

모든 훅은 실행 시 표준 입력(stdin)을 통해 JSON 객체를 받습니다. 세션 식별자인 `session_id`, 대화 기록 파일 경로인 `transcript_path`, 현재 디렉터리 경로인 `cwd` 가 기본으로 포함됩니다.

```json
{
  "session_id": "sess_abc123",
  "transcript_path": "/path/to/transcript.jsonl",
  "cwd": "/workspace/project",
  "hook_event_name": "PreToolUse",
  "tool_name": "Write",
  "tool_input": {
    "file_path": "src/app.ts",
    "content": "export const ready = true;"
  },
  "effort": { "level": "medium" }
}
```

여기에 프롬프트 추적용 UUID 인 `prompt_id`(v2.1.196)와 활성 추론 단계인 `effort.level`(v2.1.133)이 함께 전달됩니다. <!-- 확인 필요: 공식 문서·설치본에서 찾지 못함 --> `Stop` 과 `SubagentStop` 이벤트에는 모델의 직전 출력을 담은 `last_assistant_message` 필드가 추가로 제공됩니다.

### 종료 코드와 차단 동작

훅의 1차 판단 기준은 **종료 코드**(exit code, 프로세스 실행 결과를 알리는 숫자)입니다.

종료 코드 0은 성공을 나타냅니다. 프로세스가 표준 출력으로 내보낸 JSON 데이터를 파싱하여 시스템 동작에 즉시 반영합니다.

종료 코드 2는 차단 오류를 나타냅니다. 진행 중이던 도구 실행이나 모델 전환이 즉시 취소되며, 표준 오류(stderr) 내용이 차단 사유로 전달됩니다.

0과 2 이외의 종료 코드는 비차단 오류로 분류됩니다. 본 작업은 중단 없이 계속 진행되며, 표준 오류의 첫 줄이 대화 기록에 경고 알림으로만 기록됩니다.

### 표준 출력 JSON 과 이벤트별 제어

종료 코드 0을 반환할 때 표준 출력(stdout)에 JSON 을 작성하면 시스템의 후속 동작을 세밀하게 바꿀 수 있습니다.

`PreToolUse` 이벤트에서는 권한 결정과 함께 수정된 입력값인 `updatedInput` 을 전달할 수 있습니다. v2.1.300 부터는 이 대체 입력값도 모델이 생성한 입력과 동일한 검증을 거치므로 유효하지 않은 필드는 자동으로 걸러집니다.

```json
{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "allow",
    "updatedInput": {
      "file_path": "src/sanitized-app.ts",
      "content": "export const ready = true;"
    }
  }
}
```

`PostToolUse` 에서는 v2.1.121 부터 모든 도구를 대상으로 `updatedToolOutput` 을 지원합니다. 도구가 생성한 원본 출력을 가로채어 민감 정보를 가리거나 서식을 다듬은 뒤 모델에게 넘겨줄 수 있습니다. `Stop` 이벤트에서는 v2.1.163 부터 `additionalContext` 필드를 활용해 오류 표시를 띄우지 않고 모델에게 추가 작업을 지시할 수 있습니다.

### 터미널 제어 시퀀스

v2.1.141 부터 훅의 JSON 출력에 `terminalSequence` 필드를 포함할 수 있습니다. 훅 종료 시 호스트의 제어 터미널로 원시 OSC(Operating System Command) 이스케이프 시퀀스를 직접 출력해 주는 기능입니다.

```json
{
  "terminalSequence": "\u001b]9;작업이 완료되었습니다\u0007"
}
```

별도의 가상 터미널이나 UI 연동 라이브러리 없이도 데스크톱 알림을 띄우거나 터미널 탭 제목을 동적으로 변경할 수 있습니다. OSC 9 규격을 해석하는 최신 터미널 에뮬레이터에서 깔끔하게 동작합니다.

### 환경 변수

훅 프로세스에는 프로젝트 루트 절대 경로를 담은 `CLAUDE_PROJECT_DIR` 환경 변수가 기본으로 제공됩니다. 스크립트 내부에서 파일 경로를 참조할 때 하드코딩 대신 이 변수를 써야 이식성이 유지됩니다.

`SessionStart`, `CwdChanged`, `FileChanged` 이벤트에서는 `CLAUDE_ENV_FILE` 환경 변수가 전달됩니다. 이 파일에 셸 내보내기 명령을 기록하면 이후 세션 전체에서 해당 환경 변수가 영구적으로 유지됩니다.

원격 환경 여부는 `CLAUDE_CODE_REMOTE` 로 확인하고 세션 UUID 는 `CLAUDE_CODE_SESSION_ID` 로 판별합니다. 세션 종료 훅의 제한 시간은 `CLAUDE_CODE_SESSIONEND_HOOKS_TIMEOUT_MS` 로 조절할 수 있습니다.



## 프롬프트 기반 훅

> 정형화된 규칙 대신 정성적인 맥락 판단이 필요할 때는 모델 평가 프롬프트를 훅으로 씁니다.

### 모델 판단 기반 검증의 역할

구문 검사나 파일 확장자 확인은 셸 스크립트로 처리하는 편이 훨씬 빠르고 정확합니다. 하지만 "사용자가 요청한 기능 명세가 모두 구현되었는가?" 또는 "수정된 코드에 누락된 에지 케이스는 없는가?" 같은 문제는 셸 명령으로 판정하기 어렵습니다.

이런 정성적 판단을 자동화하기 위해 `prompt` 유형 훅을 사용합니다. Claude 가 주어진 지침에 따라 현재 대화 맥락과 작업 산출물을 스스로 평가합니다. 주로 `Stop` 이나 `SubagentStop` 이벤트에 배치하여 모델의 성급한 작업 종료를 막는 용도로 씁니다.

### 프롬프트 훅의 응답 규격

프롬프트 훅이 실행되면 모델은 내부적으로 불리언 성공 여부와 사유를 담은 JSON 구조를 생성합니다.

```json
{
  "ok": false,
  "reason": "마이그레이션 스크립트에 대한 단위 테스트가 아직 실행되지 않았습니다."
}
```

`ok` 가 `true` 이면 턴 종료가 승인됩니다. `ok` 가 `false` 이면 `reason` 에 명시된 설명이 모델에게 피드백으로 전달되고 대화 턴이 계속 이어집니다.

v2.1.139 에 추가된 `continueOnBlock` 설정을 `PostToolUse` 프롬프트 훅에 켤 수 있습니다. 작업을 강제 중단하지 않고 피드백을 전달하여 모델이 스스로 다른 방식을 시도하도록 유도합니다.

### 루프 방지와 안전 상한

프롬프트 훅이 계속해서 거부 결정을 내리면 세션이 영구히 끝나지 않는 무한 루프가 발생할 수 있습니다. 이를 방지하기 위해 v2.1.143 부터 안전 상한선이 적용되었습니다.

동일한 턴에서 `Stop` 훅이 연속 8회 차단 결정을 내리면 Claude Code 가 다음 차단을 무시하고 턴을 강제로 종료합니다. 이 상한값은 환경 변수 `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` 으로 조절할 수 있으며, 0으로 설정하면 상한이 완전히 비활성화됩니다.

또한 v2.1.302 부터는 단일 이벤트 내에서 프롬프트나 에이전트 훅의 동시 실행 수가 최대 12개로 제한되어 토큰 소모와 시스템 부하를 관리합니다.

### 위험 명령 차단 스크립트

원문의 예제 1인 `validate-bash.py` 는 위험한 시스템 명령어를 사전에 가로채는 대표적인 `PreToolUse` 훅입니다.

```python
#!/usr/bin/env python3
import json
import re
import sys

BLOCKED_PATTERNS = [
    (r"\brm\s+-rf\s+/", "루트 디렉터리 삭제 명령이 차단되었습니다."),
    (r"\bsudo\s+rm", "sudo 권한의 삭제 명령이 차단되었습니다."),
]

def main():
    input_data = json.load(sys.stdin)
    if input_data.get("tool_name") != "Bash":
        sys.exit(0)

    command = input_data.get("tool_input", {}).get("command", "")
    for pattern, message in BLOCKED_PATTERNS:
        if re.search(pattern, command):
            print(message, file=sys.stderr)
            sys.exit(2)

    sys.exit(0)

if __name__ == "__main__":
    main()
```

이 스크립트는 표준 입력으로 들어온 `tool_input.command` 문자열을 정규식 목록과 대조합니다. 위험 패턴이 발견되면 표준 오류로 경고 문구를 출력하고 종료 코드 2를 반환합니다. 종료 코드 2를 받은 Claude Code 는 도구 실행을 즉시 취소하고 표준 오류 내용을 도구 오류로 Claude 에게 전달합니다.

### 컨텍스트 소모 추적 스크립트

예제 6인 `context-tracker.py` 는 두 개의 서로 다른 이벤트를 조합해 세션 상태를 추적하는 유용한 구조를 보여줍니다.

`UserPromptSubmit` 이벤트에서는 프롬프트가 처리되기 전의 대화 기록 길이를 읽어 임시 파일에 기록합니다. 이후 작업이 끝나고 `Stop` 이벤트가 불리면 다시 대화 기록을 읽어 이전 기록과의 차이를 계산합니다.

요청별 소모 토큰과 컨텍스트 창 잔여량을 백분율로 계산하여 표준 오류로 출력합니다. 세션 간 데이터가 섞이지 않도록 임시 파일 경로에 입력 JSON 의 `session_id` 를 반영합니다. 복수의 이벤트가 상태를 공유하는 훅 쌍 설계의 훌륭한 본보기입니다.



## 플러그인과 MCP 도구 연동

> 훅은 독립 패키지로 배포되거나 외부 MCP 서버의 도구와 직접 결합할 수 있습니다.

### 플러그인 매니페스트 훅

플러그인 패키지는 자체 디렉터리 아래 `hooks/hooks.json` 파일을 두어 전용 훅을 선언할 수 있습니다. 사용자가 플러그인을 설치하고 활성화하면 플러그인에 정의된 훅이 세션 수명주기에 자동으로 등록됩니다.

플러그인 내부의 스크립트를 안정적으로 참조할 수 있도록 두 가지 전용 경로 환경 변수가 제공됩니다. 플러그인 루트 디렉터리를 가리키는 `${CLAUDE_PLUGIN_ROOT}` 와 데이터 저장소를 가리키는 `${CLAUDE_PLUGIN_DATA}` 입니다.

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "\"${CLAUDE_PLUGIN_ROOT}\"/scripts/validate.sh"
          }
        ]
      }
    ]
  }
}
```

이 경로 변수를 사용하면 플러그인이 사용자의 홈 디렉터리나 임의의 캐시 경로에 설치되더라도 경로 깨짐 없이 스크립트를 정상 구동할 수 있습니다.

### MCP 도구 호출 훅과 매처

훅과 MCP 의 결합은 두 가지 방식으로 이루어집니다. 훅이 외부 MCP 도구를 실행하는 방식과, MCP 도구의 실행을 훅으로 감시하는 방식입니다.

`mcp_tool` 유형 훅은 별도의 셸 스크립트를 짜지 않고도 연결된 MCP 서버의 기능을 바로 호출합니다. `server` 와 `tool` 이름을 지정하고 인자 객체 `input` 에 템플릿 치환을 작성하여 실행합니다.

반대로 모델이 MCP 도구를 호출하는 순간을 가로채려면 매처에 `"mcp__<서버이름>__<도구이름>"` 규칙을 씁니다. 예를 들어 메모리 저장 도구 호출을 가로채려면 `"mcp__memory__.*"` 를 매처로 등록하여 호출 내역을 감사 로그에 기록할 수 있습니다.



## 보안과 디버깅

> 훅은 임의의 셸 명령을 실행하므로 엄격한 보안 통제와 단계별 디버깅 절차가 필수적입니다.

### 임의 명령 실행 위험과 신뢰 정책

훅은 운영체제 권한으로 임의의 셸 명령을 실행합니다. 검증되지 않은 외부 저장소의 훅 설정을 무심코 승인하면 악의적인 명령이 로컬 머신에서 실행될 위험이 있습니다.

Claude Code 는 이를 방지하기 위해 작업 공간 신뢰(Workspace Trust) 제도를 운영합니다. 신뢰 승인을 받지 않은 폴더에서는 대화형 세션이 모든 설정 파일의 훅 실행을 보류합니다.

v2.1.218 부터는 프로젝트 하위 서브에이전트 프론트매터에 선언된 훅 역시 해당 디렉터리의 신뢰 승인이 있어야만 동작하도록 보완되었습니다. 회사 차원에서는 관리자 정책의 `disableAllHooks` 설정을 통해 개별 사용자가 훅을 켜지 못하도록 강제할 수도 있습니다.

### 권한 규칙과의 상호작용

HTTP 웹훅을 구성할 때는 헤더 치환을 통해 민감한 환경 변수가 외부로 새어 나가지 않도록 `allowedEnvVars` 목록을 명시적으로 제한해야 합니다.

셸 명령어 권한 검증과 관련하여 v2.1.145 에서는 중요한 보안 개선이 이루어졌습니다. 기존에는 허용 목록에 없는 환경 변수에 값을 대입하는 `FOO=bar` 같은 단독 대입이 자동 승인되는 취약점이 있었습니다.

v2.1.145 부터는 이 허점이 막혀 전체 명령어를 온전히 포괄하는 권한 규칙이 없으면 사용자 승인 프롬프트가 표시됩니다. 또한 Windows 환경 사용자를 위해 PowerShell 도구 명령어도 Bash 와 동일하게 자동 승인 처리가 가능하도록 v2.1.119 에 반영되었습니다.

### 훅 실행 검증과 문제 해결

작성한 훅 스크립트가 의도대로 동작하지 않을 때는 세 가지 단계로 나누어 점검합니다.

첫째는 파이프 입력을 통한 스크립트 단독 검증입니다. Claude Code 세션을 매번 띄우지 않고 가상 JSON 데이터를 표준 입력으로 밀어 넣어 반환값과 표준 오류 출력을 확인합니다.

```bash
echo '{"tool_name": "Bash", "tool_input": {"command": "ls -la"}}' | python3 .claude/hooks/validate-bash.py
echo $?
```

둘째는 세부 디버그 모드의 활용입니다. 터미널에서 `claude --debug` 로 세션을 시작하면 훅의 로드 과정, 매처 평가 결과, 표준 오류 출력 내용이 터미널 대신 디버그 로그 파일(`~/.claude/debug/<session-id>.txt`)에 기록됩니다. 세션 진행 중에는 `Ctrl+O` 키를 눌러 상세 출력 모드로 전환할 수 있습니다.

셋째는 빈번한 오류 원인의 확인입니다. 스크립트에 실행 권한(`chmod +x`)이 부여되어 있는지 확인해야 합니다. 스크립트가 명령행 인자(`sys.argv`) 대신 표준 입력(`sys.stdin`)을 읽고 있는지도 점검 대상입니다. 마지막으로 매처 문자열의 대소문자가 실제 도구 이름과 일치하는지 확인합니다.
