# 11_AI/docs
---
> 도구 하나를 설치본 기준으로 끝까지 파고든 노트를 모읍니다. 개념편이 `11_AI/` 본문에 있다면, 여기는 그 개념이 실제 제품에서 어떤 명령과 상태 모델로 떨어지는지를 봅니다.

## 이 폴더의 자리

> `07_devops/docs/` 와 같은 규약을 씁니다. 다만 1차 자료가 웹 문서가 아니라 설치본이라는 점이 다릅니다.

`11_AI/` 본문(`01-xx`, `02-xx`)은 모델과 엔지니어링 개념을 벤더 중립으로 다룹니다. 그 개념이 실제로 어떻게 구현되는지는 제품마다 다르고, 제품은 버전마다 또 달라집니다. 그래서 제품별 노트를 본문에 섞지 않고 이 폴더로 내립니다.

`hermes/` 가 사례 한 편짜리 읽을거리라면 여기는 도구 하나를 장 단위로 끝까지 따라가는 자리입니다.

근거의 성격도 다릅니다. `07_devops/docs/sonarqube/` 는 공식 웹 문서를 정본으로 삼았지만, 여기 첫 주제인 ORCA 는 **설치본이 정본**입니다. `orca agent-context --json` 이 설치된 버전의 명령 스키마 전체를 뱉어 주기 때문에, 웹 문서보다 이쪽이 항상 더 정확합니다. 원서 저자도 같은 기준을 못 박아 두었습니다 — 막히면 여러분의 설치본이 정답이라고.

## 하위 폴더

| 폴더 | 편수 | 다루는 범위 |
|------|------|------------|
| [`orca/`](orca/) | 본문 10편 + 부록 2편 | ADE(Agentic Development Environment) ORCA — 워크트리 격리, 터미널 관측, 멀티 에이전트 조율, 브라우저·데스크톱 자동화, 운영과 실패 복구 |

## 경계 기준

모델의 능력과 API 동작은 `11_AI/` 본문이 맡고, 도구의 설치·키맵은 [`09_tools/`](../../09_tools/) 가 맡습니다. 이 폴더는 그 사이에 있습니다 — 에이전트를 *여러 개 굴리기 위한* 상태 모델과 명령 표면이 대상입니다. 특정 언어·프레임워크에 종속된 AI 연동(Spring AI 등)은 해당 카테고리로 보냅니다.
