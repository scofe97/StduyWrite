# write 트러블슈팅 드릴

---

> 증상만 보고 진단해 보는 훈련 트랙입니다. 하루 세 문항을 풀고, 막힌 지점이 어느 노트의 어느 문단으로 돌아가는지 남깁니다.

## 이 트랙이 있는 이유

> 이미 있던 두 자산 사이에 비어 있던 자리를 메웁니다. 회상이 아니라 전이를 훈련하는 트랙입니다.

`write/` 에는 트러블슈팅 자산이 이미 두 종류 있었습니다. `02_os/troubleshooting/` 13편과 `08_cloud/troubleshooting/` 12편은 장애 사례에 해설까지 붙여 재구성한 사례집이었고, `_review/` 는 학습 문서를 간격 반복으로 회상시키는 복습 시스템입니다.

없던 것은 그 사이입니다. 사례집은 답이 본문에 적혀 있어 풀 수가 없고, 복습 시스템은 "이 노트를 기억하는가"를 묻지 "이 증상에서 무엇을 의심하는가"를 묻지 않습니다. 사례집 README 스스로도 "먼저 사이트에서 풀어 본 뒤 여기서 대조하는 순서를 권합니다"라고 적어 두었는데, 그 먼저 푸는 단계를 담을 자리가 없었습니다.

2026-09-08 에 사례집 25편을 걷어냈습니다. 해설이 붙은 76건을 안 푼 채로 쌓아 두는 것이 이 저장소의 기준에 맞지 않았기 때문입니다. 증상 한 줄만 [후보 풀](./candidates.md) 로 남기고, 푼 것만 계층 폴더에 사례로 올립니다.

이 폴더가 그 자리입니다. 회상이 아니라 전이(transfer)를 훈련합니다. 아는 것을 떠올리는 일과, 처음 보는 증상 앞에서 아는 것을 꺼내 쓰는 일은 다른 능력입니다.



## 구조

> 문항 파일은 상위 계층 폴더에 공개로 쌓이고, 여기 `_drill/` 에는 운영에 필요한 것만 남습니다.

```bash
write/troubleshooting/
├── README.md              # 계층 지도와 여는 절차
├── os/  kubernetes/  mesh/  cloud/  runtime/
│   └── YYYY-MM-DD_{증상}.md    # 푼 문항 하나가 파일 하나
├── _concepts/             # 문항에서 갈라져 나온 이론 — 주제별로 한 번만
├── _assets/               # 도식 SVG 와 생성기
└── _drill/                # 이 폴더 · 배포 제외
    ├── README.md          # 진입점 (현재 파일)
    ├── sources.md         # 출제 소스, 커버리지 맵, 출제 이력
    ├── _mistakes.md       # 오답 노트
    ├── log.md             # 회차 로그 — 날짜 · 문항 링크 · 점수 · 막힌 지점
    └── _template/
        ├── case-template.md   # 문항 파일 템플릿 (푸는 동안 → 정리 뒤)
        └── drill-prompt.md    # 세션 시작용 프롬프트 1개
```

`_` 접두는 [복습 시스템](../../_review/README.md) 과 같은 "일반 최종본이 아님" 표시입니다. `mkdocs.yml` 의 `exclude_docs: _*/` 가 이 폴더를 배포에서 걷어내고, 계층 폴더의 문항 파일은 공개됩니다.

### 파일 하나의 생애

푸는 동안과 다 푼 뒤가 같은 파일입니다. 형태만 바뀝니다.

| 단계 | 파일 안에 있는 것 |
|------|------------------|
| 출제 | 프론트매터 · 증상 · 세 칸(빈칸) · 대조(끝에) |
| 채점 | 세 칸이 채워짐 · 점수 |
| 정리 | 문제 소개 · 원인 분석 · 해결 방법 · 다른 방법 비교 · 나온 개념 |

정리 뒤의 파일에는 **내 답과 점수가 없습니다.** 그건 [log.md](./log.md) 와 [_mistakes.md](./_mistakes.md) 로 빠집니다. 그래서 남는 파일은 남이 읽어도 되는 사례이고, 공개 폴더에 둘 수 있습니다.



## 하루 루틴

> 평일에는 지면으로 판단만 훈련하고, 주말에는 그중 재현 가능한 것을 실제로 고장 내 봅니다.

### 평일 — 지면 진단 20~30분

[sources.md](./sources.md) 의 커버리지 맵에서 계층을 먼저 고릅니다. 그 폴더의 노트를 열어 그날 문항 세 개를 새로 뽑되 계층을 섞습니다. 근거가 두꺼운 A·B·E 를 축으로 돌리고 C·D 는 순환에 끼워 넣는 배분이 자연스럽습니다. 뽑을 때 그 노트에 내용이 실제로 있는지 확인합니다. 이미 낸 것은 출제 이력에서 거릅니다.

문항 파일은 `troubleshooting/{계층}/YYYY-MM-DD_{증상}.md` 로 만들고 **증상만** 채웁니다. 대조는 파일 끝에 두고, 세 칸을 다 채운 뒤에 내려갑니다. 하루 세 문항이 기본이고 요청하면 더 냅니다.

채점은 정합성만 봅니다. 완전한 해설을 붙이거나 다음 문항을 미리 설명하지 않습니다. 짚지 않은 것이 있으면 되묻습니다.

### 주말 — 로컬 재현 40~60분

그 주에 막혔던 문항 중 `kind`·`docker`·로컬에서 고장을 만들 수 있는 것 1~2개를 고릅니다.

명령은 제시하되 **실행은 직접 합니다.** 실행 전에 출력을 예측해 적고 실제 출력과 대조합니다. 되돌려서 원래 증상이 다시 나오는 것까지가 한 실험입니다. 고쳤다는 사실만으로는 무엇이 원인이었는지 고정되지 않습니다.

실습 기록은 같은 날짜 파일에 `## 실습` 절로 잇습니다.



## 문항 포맷

> 복습 시스템의 다섯 질문(정의·동기·메커니즘·적용·함정)은 회상용이라 진단에 맞지 않습니다. 사례집이 쓰는 순서를 세 질문으로 옮깁니다.

각 문항은 다음 세 칸을 묻습니다.

1. **가설**: 무엇을 의심하는지, 그리고 무엇을 왜 배제하는지 함께 적습니다.
2. **첫 확인**: 명령 하나와, 그 출력이 무엇과 무엇을 가르는지 적습니다. 예상과 반대 결과가 나오면 어느 가설을 버리고 다음에 무엇을 볼지도 함께 적습니다.
3. **처방**: 응급 조치와 재발 방지를 나눠 적습니다.

배제할 것을 함께 묻는 데는 이유가 있습니다. 복습 회차 실측에서 "왜 그런가"는 잘 답하면서 "어디에는 없는가"는 계속 막혔습니다. 부재와 제약을 묻는 축이 약점이므로 매 문항에 넣습니다.

반대 결과까지 묻는 것도 같은 실측에서 나왔습니다. 첫 회차 세 문항 모두 가설과 처방은 세웠는데 "어디를 보면 갈리는지"에서 멈췄고, [오답 노트](./_mistakes.md) 의 반복 패턴 표에도 그 항목이 올라 있습니다. 명령 하나를 대는 것과 그 명령이 빗나갔을 때 다음 수를 아는 것은 다른 능력입니다. 후자가 없으면 확인은 한 번 찔러 보는 일에 그칩니다.

출제할 때는 증상 서술에 원인을 가리키는 단어를 넣지 않습니다. 서술문이 답을 품으면 문항이 죽습니다. 쓴 뒤에 증상만 읽어 답이 유추되면 다시 씁니다.

정답은 문항 옆이 아니라 파일 끝 `## 대조` 절에 모읍니다. `<details>` 로 접지 않습니다. Typora 는 raw HTML 의 접힘을 지원하지 않아 정답이 그대로 보이고, 그러면 가림 효과가 0 이 됩니다.



## 회차가 끝나면 같은 파일을 정리 구조로 채웁니다

> 푸는 동안의 부분을 지우고 다섯 갈래를 채웁니다. 규격의 정본은 [case-template.md](./_template/case-template.md) 입니다.

```bash
## 문제 소개      상황과 주어진 출력을 정확히
## 원인 분석      배제된 것 · 낮아진 것 · 남은 것 세 갈래로. 확정 증거가 없으면 유력 가설로
## 해결 방법      확인 명령과 조치. 응급 · 재발 방지 · 검증을 나눠서
## 다른 방법 비교  같은 증상의 다른 원인, 도구 선택지, 왜 그 방법이 아닌가
## 나온 개념      갈라져 나온 개념과 근거 노트 링크 (필수)
```

`## 나온 개념` 에는 **근거 노트 링크를 반드시 답니다.** 사례집에 같은 주제가 있으면 거기도 한 줄로 교차참조합니다.

내 답과 점수는 이 파일에 남기지 않습니다. [log.md](./log.md) 한 줄과 [_mistakes.md](./_mistakes.md) 로 옮깁니다.



## 스킵과 교체

> 안 배운 문항을 우겨서 풀리지 않습니다. 보폭이 넓어지면 훈련이 아니라 좌절이 됩니다.

출제된 문항이 배운 적 없는 영역이면 "스킵"이라고 말하면 됩니다. 근거를 대라거나 설득하지 않습니다.

스킵하면 즉시 같은 계층의 다른 문항으로 바꿉니다. 남은 것이 없으면 근거가 두꺼운 계층에서 뽑습니다. 스킵한 문항은 출제 이력에 `스킵` 으로 남깁니다. 그 주제를 아직 안 배웠다는 기록이라, 나중에 노트를 쓰면 다시 후보가 됩니다.

하루에 스킵이 2개를 넘으면 그날은 A 계층과 B 계층에서만 뽑습니다. 그 정도로 빗나갔다는 것은 출제 쪽이 근거를 잘못 읽었다는 뜻입니다.



## 채점과 오답

> 점수 척도는 복습 시스템과 같은 0~5 를 씁니다. 두 트랙의 기록을 나중에 함께 볼 수 있게 하려는 것입니다.

점수 기준은 다음과 같습니다.

- **0**: 아무것도 떠오르지 않음
- **1**: 틀린 방향으로 감
- **2**: 일부만 맞고 핵심을 놓침
- **3**: 핵심은 맞고 세부가 빠짐
- **4**: 정확하지만 머뭇거림
- **5**: 막힘 없이 정확함

`quality ≤ 3` 인 문항은 [_mistakes.md](./_mistakes.md) 에 옮겨 적습니다. `quality ≤ 2` 인 문항은 [sources.md](./sources.md) 출제 이력의 재출제 칸에 사흘 뒤 날짜를 적습니다.

### 재출제는 같은 문제가 아닙니다

같은 문제를 그대로 내면 증상 문구가 기억나 답이 딸려 나옵니다. 진단이 아니라 암기 확인이 됩니다.

재출제는 **막힌 지점을 겨냥한 다른 증상**입니다. 오답 노트의 "다시 볼 것"에 적은 지식을 요구하되 상황을 바꿔 냅니다. 같은 손잡이를 다른 문 앞에서 찾게 하는 것이라, 그래야 문제의 답이 아니라 지식이 남습니다.

간격을 사흘로 둔 것은 매일 새 문항이 들어오기 때문입니다. 복습 시스템은 점수 2 이하에 다음 날 재학습을 걸지만, 여기서 그렇게 하면 하루 분량이 두 배가 됩니다. 사흘은 잊을 만한데 완전히 사라지지는 않은 지점입니다.

같은 패턴이 세 번 반복되면 그 문항이 어려운 것이 아니라 근거 노트의 설명이 부족하다는 신호입니다. 해당 사례집이나 학습 노트 본문을 보강합니다.

간격 반복 알고리즘과 졸업 판정은 가져오지 않았습니다. 드릴은 매일 새 증상을 만나는 훈련이라 같은 문항을 주기적으로 되돌릴 이유가 적습니다. 틀린 것만 사흘 뒤에 한 번 더 봅니다.



## 진행 표

> 회차별 기록은 [log.md](./log.md) 에 있습니다. 한 회차가 한 줄이고 문항 링크 셋이 그 줄에 붙습니다.



## 출제

> 문항을 미리 적어 두지 않습니다. 매 회차에 [sources.md](./sources.md) 의 소스에서 그날 것을 새로 뽑습니다.

목록을 두지 않는 이유는 셋입니다.

- 목록의 증상 한 줄이 그날 문제를 미리 알려줍니다
- 미리 채운 근거는 확인 없이 굳습니다
- 소스만 두면 새로 쓴 노트가 자동으로 출제 범위에 들어옵니다

자세한 근거는 sources.md 첫 절에 적었습니다.

계층은 넷입니다.

- **A**: 리눅스 호스트 계층
- **B**: 쿠버네티스 클러스터 내부
- **C**: 서비스 메시
- **D**: 클라우드 네트워킹
- **E**: 런타임 — JVM 과 애플리케이션

A 부터 D 까지가 "패킷이 어디서 사라지나"를 묻는 네트워크 축이라면, E 는 "프로세스가 왜 멈추거나 느려지나"를 묻습니다. 축이 다르므로 같은 회차에 섞으면 시야가 넓어집니다.

뽑는 순서는 내 노트, 사례집 예비 풀 79건, 외부 사이트입니다.
