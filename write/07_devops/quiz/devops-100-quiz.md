# DevOps 100문항 객관식 퀴즈

---

> 회사 실무형 DevOps 기준으로 CI/CD, Git, Jenkins/GitLab CI, Docker, Kubernetes, IaC, Observability, SRE, DevSecOps, 운영 지표를 섞은 100문항이다. 정답은 A/B/C/D에 고르게 분산돼 있다(각 25문항).

기준 개념은 공식 문서 흐름에 맞췄다. [DORA](https://dora.dev/guides/dora-metrics/)는 배포 빈도, 변경 리드타임, 변경 실패율, 장애 복구 시간 같은 지표로 소프트웨어 전달 성과를 측정한다. Kubernetes Ingress는 HTTP/HTTPS 외부 접근을 규칙 기반으로 Service에 연결하는 API 객체이며, Secret은 비밀번호·토큰·키 같은 민감 정보를 담는 객체다. OpenTelemetry는 traces, metrics, logs 같은 telemetry 데이터를 생성·수집·내보내기 위한 vendor-neutral observability 프레임워크다. SLSA는 소프트웨어 공급망의 변조 방지와 무결성 강화를 위한 보안 프레임워크다.

## 1. DevOps 기본 개념

**1. DevOps의 핵심 목적에 가장 가까운 것은?**
A. 개발팀과 운영팀의 책임을 완전히 분리한다
B. 개발, 테스트, 배포, 운영의 흐름을 자동화하고 협업을 강화한다
C. 배포 횟수를 무조건 줄여 변경 위험을 없앤다
D. 운영 업무를 전담 조직으로 몰아 개발자와 분리한다
**정답: B**

**2. DevOps 문화에서 가장 중요한 원칙으로 적절한 것은?**
A. 팀 간 경계를 명확히 하는 사일로 강화
B. 배포 후 검증을 생략해 릴리스 속도를 극대화
C. 빠른 피드백과 지속적 개선
D. 장애 원인을 팀 내부에서만 공유하고 외부에 감춤
**정답: C**

**3. CI의 의미로 가장 적절한 것은?**
A. 운영 서버에 직접 접속해 코드를 수동 수정하는 것
B. 모든 테스트를 배포 후에만 수행하는 것
C. 코드 리뷰 없이 곧바로 병합해 통합 속도를 높이는 것
D. 코드를 자주 통합하고 자동 빌드·테스트로 문제를 빠르게 발견하는 것
**정답: D**

**4. CD에서 Continuous Delivery와 Continuous Deployment의 차이로 맞는 것은?**
A. Delivery는 배포 가능 상태까지 자동화하고, Deployment는 운영 배포까지 자동화한다
B. 둘은 완전히 같은 말이다
C. Delivery는 테스트를 하지 않고 Deployment만 테스트한다
D. Deployment는 빌드를 생략하고 Delivery만 빌드한다
**정답: A**

**5. DevOps에서 "shift-left"의 의미는?**
A. 배포를 항상 주말 밤 트래픽이 적은 시간대로 미루는 것
B. 보안·테스트·품질 검사를 개발 초기 단계로 앞당기는 것
C. 운영 장애를 개발팀에 알리지 않고 운영팀이 먼저 처리하는 것
D. 테스트를 운영 배포 이후로 미뤄 초기 개발 속도를 높이는 것
**정답: B**

**6. DevOps 도입의 좋은 성공 기준은?**
A. 다른 지표와 무관하게 배포 횟수만 증가
B. 배포 속도, 안정성, 복구 시간, 품질이 함께 개선됨
C. 문서를 최소화해 유지보수 부담을 없앰
D. 운영 인력을 줄여 인건비를 절감함
**정답: B**

**7. 자동화가 필요한 이유로 가장 적절한 것은?**
A. 사람의 판단이 개입할 여지를 모두 없애기 위해
B. 실행 로그를 남기지 않아 저장 비용을 줄이기 위해
C. 반복 작업의 오류를 줄이고 재현 가능한 실행을 만들기 위해
D. 장애 발생 시 원인 추적을 어렵게 만들기 위해

**8. DevOps와 Agile의 관계로 적절한 것은?**
A. Agile은 운영 자동화를 원칙적으로 금지한다
B. DevOps는 어떤 개발 방법론과도 결합할 수 없다

**9. "You build it, you run it"의 의미는?**
A. 개발팀이 자신이 만든 서비스의 운영 품질에도 책임을 가진다
B. 개발자는 운영 로그에 접근할 수 없다

**10. DevOps에서 피드백 루프가 짧아야 하는 이유는?**
A. 승인 절차를 모두 제거해 배포를 즉시 반영하기 위해
B. 문제를 빠르게 발견하고 수정 비용을 낮추기 위해

## 4. 빌드, 테스트, 품질

## 빠른 암기 포인트

DevOps 시험은 보통 아래 축에서 나온다.

1. **CI/CD**: build, test, artifact, approval, rollback
2. **Git 전략**: PR/MR, protected branch, trunk-based, feature branch
3. **Docker**: image, container, Dockerfile, registry, multi-stage build
4. **Kubernetes**: Pod, Deployment, Service, Ingress, ConfigMap, Secret, Probe
5. **배포 전략**: Rolling, Blue-Green, Canary, GitOps
6. **IaC**: Terraform state, plan/apply, drift, immutable infrastructure
7. **Observability**: log, metric, trace, RED, USE, SLI/SLO, alert
8. **DevSecOps**: SAST, DAST, SBOM, image scan, least privilege, SLSA
9. **DORA 지표**: deployment frequency, lead time, change failure rate, MTTR
10. **운영 문화**: blameless postmortem, feedback loop, automation, continuous improvement
