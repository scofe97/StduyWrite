# networking-and-kubernetes 오답 노트

> 복습 회차에서 quality ≤ 3 인 질문을 박제한다. 같은 패턴이 3회 이상 반복되면 원본 챕터 본문 보강 트리거.

## 2026-09-06 — 01-02 Transport 계층 Q1: 시퀀스 번호는 무엇을 세는가

- **자기 답**: "서버와 클라이언트가 가진 연속된 번호" — 무엇의 연속인지 미도달
- **정답**: 바이트를 센다. 경로 중간에서 세그먼트가 쪼개져 패킷 경계를 신뢰할 수 없으므로, 바이트를 세야 쪼개짐과 무관하게 양쪽 셈이 유지된다 (원본 §2·§4)
- **원인 추정**: 개념 혼동 — "연속"이라는 성질만 남고 단위가 빠짐. 8일 만의 2연속 재발
- **재방문 트리거**: 2026-09-07 재학습

## 2026-09-06 — 01-02 Transport 계층 Q2: TIME_WAIT 은 어느 쪽에 남는가

- **자기 답**: "일반적으로 서버에서 발생". 확인 질문에서도 "받는 입장에서 발생"으로 방향을 뒤집음
- **정답**: 먼저 `close` 를 호출한 쪽. 역할이 아니라 순서가 정한다. 마지막 ACK 유실에 대비해 2MSL 대기 (원본 §3)
- **원인 추정**: 방향 오류 — 능동/수동 종료자 구분이 서 있지 않음. 2연속 재발
- **재방문 트리거**: 2026-09-07 재학습

## 2026-09-06 — 01-02 Transport 계층 Q4: HTTPS 첫 요청의 왕복 수

- **자기 답**: "대략 15번". 구성 요소(3-way·hello·키 교환) 분해는 정확
- **정답**: 3 왕복 = TCP 1 + TLS 1.2 2. RTT 150ms 경로면 첫 바이트 전 450ms (원본 §5)
- **원인 추정**: 계수 단위 혼동 — 메시지 수와 왕복 수를 구분하지 못함. 지연 환산 미실시
- **재방문 트리거**: 2026-09-07 재학습

## 2026-09-06 — 01-02 Transport 계층 Q5: CLOSE_WAIT 과 TIME_WAIT 중 버그 신호

- **자기 답**: TIME_WAIT (상태 표를 미리 제공한 뒤에도 반대로 답함)
- **정답**: CLOSE_WAIT. 타이머가 없어 애플리케이션이 `close` 를 부르지 않으면 영구히 남는다. TIME_WAIT 은 2MSL 뒤 자동 소멸 (원본 §3)
- **원인 추정**: 판별 기준(타이머 유무) 미보유. 상태 이름은 알아도 소멸 주체를 모름
- **재방문 트리거**: 2026-09-07 재학습

## 2026-09-06 — 01-01 OSI 모델 Q2: NCP 몰락과 IP 분리

- **자기 답**: 몰락 원인을 "유지보수 난이도"로 잡고, NCP→7계층→4계층을 한 줄기로 이음. IP 분리 후 책임 분담 미답
- **정답**: 원인은 네트워크의 **다양성·규모**를 감당 못한 것. RFC 791 이후 전달은 IP 가 best-effort, 신뢰성은 양 끝단 TCP (원본 §1·§3)
- **원인 추정**: NCP 몰락과 OSI 패배를 한 사건으로 묶는 오해 — 2026-08-15 Phase 4 에서 나와 §3 을 보강했던 바로 그 자리의 **재발**
- **재방문 트리거**: 2026-09-07 재학습

## 2026-09-06 — 01-01 OSI 모델 Q3: PDU 이름

- **자기 답**: Frame 하나만. 캡슐화는 "헤더를 붙이며 내려간다"까지
- **정답**: `Data → Segment(TCP)·Datagram(UDP) → Packet → Frame → Bit`. 송신은 내려가며 붙이고 수신은 올라가며 벗긴다 (원본 §2)
- **원인 추정**: 용어 회상 약점. 원리(헤더가 붙을 때마다 이름이 갈림)와 이름표가 연결돼 있지 않음
- **재방문 트리거**: 2026-09-07 재학습

## 2026-09-06 — 01-01 OSI 모델 Q5: NCP 몰락 ≠ OSI 패배

- **자기 답**: "다른 사건"·NCP 확장성까지는 도달. 묶었을 때 생기는 오해 자체를 못 짚음
- **정답**: 묶으면 "OSI 는 안 쪼갠 쪽"이라는 정반대 오해가 생긴다. **NCP 는 덜 쪼개서 졌고 OSI 는 더 쪼갰는데도 졌다** (원본 §3)
- **원인 추정**: 같은 회차 Q2 에서 교정한 직후였으므로 깨끗한 인출 아님. 재확인 필요
- **재방문 트리거**: 2026-09-07 재학습
