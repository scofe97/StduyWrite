# 용어집 — Networking and Kubernetes

> 책 전체의 핵심 용어를 한 문장 정의와 등장 편으로 모은 북키핑 문서입니다. 복습 때 "그 용어 몇 장이었지?"라는 탐색을 없애는 용도이고, 상세 설명·근거는 각 편이 정본입니다.

## 1장 — 네트워킹 기초

| 용어 | 한 문장 정의 | 편 |
|------|------------|-----|
| OSI 모델 | 두 시스템 간 통신 책임을 7계층으로 나눈 개념 프레임워크 — 표준 경쟁에서는 졌지만 계층 공용어로 생존 | 01-01 |
| PDU | 각 계층이 위 계층 데이터를 감싸 만드는 단위 — Data→Segment→Packet→Frame→Bit | 01-01 |
| 캡슐화 | 송신 시 계층을 내려가며 헤더를 붙이고, 수신 시 올라가며 벗기는 동작 | 01-01 |
| RFC | IETF가 관리하는 인터넷 표준 문서 — Proposed Standard와 Internet Standard 두 상태 | 01-01 |
| 3-way 핸드셰이크 | SYN→SYN-ACK→ACK로 양쪽 시퀀스 번호를 교환해 TCP 연결을 수립하는 절차 | 01-02 |
| TIME-WAIT | 먼저 닫은 쪽이 마지막 ACK 유실에 대비해 대기하는 TCP 상태 | 01-02 |
| TLS | TCP 위에 핸드셰이크로 키를 교환해 암호화를 얹는 프로토콜 계층 | 01-02 |
| UDP | 헤더 4필드·수신 확인 없음 — 유실을 견디는 워크로드(DNS·음성)용 전송 프로토콜 | 01-02 |
| CIDR | 네트워크-호스트 경계를 임의 비트로 옮겨 필요한 만큼 주소 블록을 위임하는 표기(/N) | 01-03 |
| BGP / ASN | 인터넷의 경로 광고 프로토콜 / 단일 라우팅 정책 주체를 나타내는 번호 — Calico가 노드 간 라우팅에 사용 | 01-03 |
| TTL | 라우터를 지날 때마다 1씩 줄어 패킷의 무한 순환을 막는 IP 필드 — traceroute가 역이용 | 01-03 |
| ARP | IP 주소를 같은 네트워크 안 MAC 주소로 해석하는 브로드캐스트 프로토콜 | 01-03 |
| VXLAN / VNI | L2 프레임을 UDP에 캡슐화해 L3 위에 L2를 얹는 오버레이 기술 / 그 24비트 식별자(1,600만 세그먼트) | 01-03, 03-02 |
| X-Forwarded-For | 프록시 뒤에서 사라지는 원 클라이언트 IP를 Application 계층에 보존하는 HTTP 헤더 | 01-03 |

## 2장 — Linux 네트워킹

| 용어 | 한 문장 정의 | 편 |
|------|------------|-----|
| 소켓 | 연결의 논리적 종단점 — Linux는 연결을 파일로 표현 | 02-01 |
| veth | 항상 쌍으로 만들어지는 로컬 Ethernet 터널 — 네임스페이스를 잇는 배선 | 02-01 |
| 브리지 | 호스트 안 인터페이스들 사이에서 스위치처럼 동작하는 가상 장치 | 02-01 |
| Netfilter | 패킷이 커널을 지나는 5개 지점(훅)에 프로그램을 걸 수 있는 커널 프레임워크 | 02-01 |
| Martian packet | 그 인터페이스에 존재할 수 없는 출발지 주소를 가진 패킷 — 기본적으로 필터링됨 | 02-01 |
| Conntrack | 연결을 5-tuple의 flow로 추적하는 Netfilter 부품 — 방화벽 응답 구분과 NAT의 전제 | 02-01 |
| iptables | 테이블(기능)·체인(시점)·규칙(조건+타깃) 3계층의 패킷 필터·변형 도구 | 02-02 |
| MASQUERADE | 출발지를 지정 인터페이스의 주소로 바꾸는 NAT 타깃 — 주소를 미리 몰라도 되는 SNAT | 02-02 |
| IPVS | 6가지 스케줄링 모드를 가진 Linux L4 연결 로드밸런서 — kube-proxy 모드 중 하나 | 02-02 |
| eBPF | 샌드박스 프로그램을 커널 안에서 직접 실행하는 시스템 — Cilium의 기반 | 02-02 |
| XDP | 드라이버 수준에서 패킷에 직접 작용하는 eBPF attach point | 02-02 |
| traceroute | TTL을 1부터 올려 보내며 각 홉의 TIME_EXCEEDED 회신으로 경로를 알아내는 도구 | 02-03 |
| setuid | 파일 소유자 권한으로 실행되게 하는 비트 — 진단 도구 최소 설치 관행의 근거 | 02-03 |

## 3장 — 컨테이너 네트워킹

| 용어 | 한 문장 정의 | 편 |
|------|------------|-----|
| cgroup | 프로세스가 자원을 얼마나 쓸 수 있는지 제한·계량하는 커널 기능 | 03-01 |
| namespace | 프로세스가 무엇을 볼 수 있는지 격리하는 커널 기능 — PID·Network·IPC·Mount·UTS·UID 6종 | 03-01 |
| OCI | 컨테이너 이미지 포맷·런타임의 최소 개방 표준 — Composable·Decentralized·Minimalist | 03-01 |
| runC | libcontainer에서 나온 OCI 표준 low-level 런타임 CLI | 03-01 |
| containerd | Docker에서 분리된 high-level 런타임 — 생애주기·이미지·네트워크 부착 관리 | 03-01 |
| containerd-shim | 컨테이너 프로세스의 부모로 남아 daemonless 실행과 데몬 장애 생존을 가능케 하는 부품 | 03-01 |
| CRI | kubelet이 어떤 런타임과도 대화하게 하는 플러그인 인터페이스 — 최초 구현이 dockershim | 03-01 |
| CNM | Docker의 네트워킹 모델(sandbox·endpoint·network) — K8s가 채택하지 않은 쪽 | 03-02 |
| CNI | 런타임과 네트워크 구현 사이의 인터페이스 — 컨테이너 생성 시 연결·IP·경로, 삭제 시 회수 | 03-02, 04-02 |
| VTEP | VXLAN 터널의 양 끝에서 캡슐화·역캡슐화를 수행하는 종단점 | 03-02 |
| container-defined 네트워킹 | 다른 컨테이너의 네트워크 스택을 공유해 127.0.0.1 통신을 가능케 하는 방식 — Pod의 원형 | 03-02 |
| 포트 매핑 | 호스트 포트로 온 트래픽을 컨테이너 포트로 넘기는 다리(-p 호스트:컨테이너) | 03-03 |
| multistage build | 빌드 스테이지의 레이어를 버리고 산출물만 실행 스테이지로 가져와 이미지를 줄이는 기법 | 03-03 |

## 4장 — Kubernetes 네트워킹 입문

| 용어 | 한 문장 정의 | 편 |
|------|------------|-----|
| IP-per-Pod | 모든 Pod가 NAT 없이 통신하는 고유 IP를 갖는다는 K8s 네트워킹 모델 — 포트 충돌을 주소 계층에서 제거 | 04-01 |
| Isolated/Flat/Island | 클러스터 네트워크 레이아웃 3유형 — Pod가 밖에서 라우팅 가능한가의 거래 | 04-01 |
| liveness probe | 실패 시 컨테이너를 재시작하는 검사 — 외부 의존을 넣으면 재시작 폭풍 위험 | 04-01 |
| readiness probe | 실패 시 Endpoints에서 제외해 트래픽만 끊는 검사 | 04-01 |
| startup probe | 성공할 때까지 다른 프로브를 막아 느린 기동에 유예를 주는 검사 | 04-01 |
| IPAM | CNI에서 IP 할당·게이트웨이·경로 결정을 분리한 두 번째 인터페이스 | 04-02 |
| kube-proxy | 서비스 ClusterIP를 준비된 Pod IP로 번역(DNAT)하는 노드 데몬 — userspace·iptables·ipvs·kernelspace 모드 | 04-02 |
| NetworkPolicy | 선택된 Pod의 트래픽을 기본 차단으로 바꾸고 허용 규칙만 합집합으로 더하는 리소스 — 강제는 CNI 몫 | 04-03 |
| LabelSelector | matchLabels·matchExpressions(In·NotIn·Exists·DoesNotExist)로 자원을 고르는 K8s 공용 문법 | 04-03 |
| CoreDNS | 1.13+에서 KubeDNS를 대체한 단일 컨테이너·플러그인 확장형 DNS 서버 | 04-03 |
| ndots / 검색 경로 | 짧은 이름 하나에 다중 질의를 만드는 resolv.conf 설정 — 외부 호출 지연의 단골 원인 | 04-03 |
| Autopath | 검색 경로를 서버 측에서 완성해 질의 수를 줄이는 CoreDNS 플러그인 (메모리 비용) | 04-03 |
| dual-stack | Pod·서비스에 IPv4·IPv6를 함께 주는 모드 — ipFamilyPolicy 3종 | 04-03 |

## 5장 — Kubernetes 네트워킹 추상화

| 용어 | 한 문장 정의 | 편 |
|------|------------|-----|
| StatefulSet | 안정된 네트워크 식별자·스토리지·순서를 보장하는 워크로드 — Pod별 DNS 레코드 | 05-01 |
| Endpoints | 서비스가 라우팅할 준비된(ready) Pod IP 목록 — readiness 결과의 실체 | 05-01 |
| EndpointSlice | Endpoints를 부분집합으로 쪼개 대형 클러스터의 watch 병목을 줄인 리소스 (기본 100/최대 1,000) | 05-01 |
| pause 컨테이너 | Pod의 네임스페이스들을 쥐고 있는 부모 컨테이너 | 05-02 |
| ClusterIP | 준비된 Pod들로 매핑되는 클러스터 내부 전용 가상 IP — 서비스의 기본 유형 | 05-02 |
| NodePort | 모든 노드에 고정 포트(30000~32767)를 여는 유형 — 다른 유형의 토대 | 05-02 |
| externalTrafficPolicy | 외부 트래픽을 노드-로컬로 한정(Local — 소스 IP 보존)할지 클러스터 전체로(Cluster) 보낼지 | 05-02 |
| headless | clusterIP: None — LB 대신 DNS가 ready Pod 전체를 반환, 선택은 클라이언트 몫 | 05-02 |
| ExternalName | 외부 도메인의 CNAME 별칭을 클러스터 DNS에 만드는 유형 — 마이그레이션용 | 05-02 |
| LoadBalancer | NodePort에 외부 통합(클라우드 LB·MetalLB)을 결합한 L4 노출 유형 — 워크로드와 1:1 | 05-02 |
| Ingress | 호스트·경로 기반 L7 라우팅 스펙 — 컨트롤러(구현)와 규칙(설정)의 짝, LB 하나로 fan-out | 05-03 |
| IngressClass | 다중 ingress controller 중 어느 것이 이 Ingress를 처리할지 지정(1.18+) | 05-03 |
| 서비스 메시 | mTLS·재시도·관측을 앱 코드에서 사이드카 프록시로 옮긴 서비스 간 통신 인프라 계층 | 05-03 |
| mTLS | 서비스 간 상호 인증·암호화 — 저자들이 꼽는 메시의 최고 사용처 | 05-03 |

## 6장 — 클라우드 네트워킹

| 용어 | 한 문장 정의 | 편 |
|------|------------|-----|
| VPC / Vnet | 계정 전용의 격리 가상 네트워크 — AWS·GCP는 VPC(GCP는 글로벌), Azure는 Vnet(리전 한정) | 06-01, 06-02 |
| ENI | AWS의 가상 네트워크 카드 — 보조 IP들이 Pod IP의 원천 | 06-01 |
| 보안 그룹 vs NACL | 인스턴스 수준·stateful·allow만 vs 서브넷 수준·stateless·순서 평가 | 06-01 |
| NAT GW / IGW | 사설 서브넷의 아웃바운드 중개자 / VPC의 인터넷 관문 | 06-01 |
| EKS 두 VPC | 컨트롤 플레인은 EKS 소유 VPC, 노드는 고객 VPC — cross-account ENI(최대 4)가 연결 | 06-01 |
| 최대 Pod 공식 | (ENI 수 × (ENI당 IP - 1)) + 2 — m5.large 29, 시스템 Pod 포함 | 06-01 |
| ipamd | 가용 IP warm pool을 유지하며 Pod에 붙이는 AWS VPC CNI의 노드 로컬 데몬 | 06-01 |
| VPC-native | Pod IP를 alias IP로 VPC에서 직접 할당하는 GKE 모드 — NEG의 전제 | 06-02 |
| NEG | LB가 Pod IP를 직접 대상으로 삼게 하는 백엔드 그룹 — 컨테이너 네이티브 로드밸런싱 | 06-02 |
| NSG | Azure의 트래픽 필터 — 우선순위 100~4096, 첫 매치 적용 | 06-02 |
| UDR | Azure의 사용자 정의 라우트 — 삭제 불가한 기본 인터넷 라우트를 우선순위로 제어 | 06-02 |
| kubenet vs Azure CNI | 노드만 라우터블(Pod는 NAT) vs Pod도 라우터블(IP 계획 필수) — AKS의 갈림길 | 06-02 |
| AGIC | Application Gateway를 ingress controller로 쓰는 AKS 구성 — ARM 템플릿을 갱신하는 클러스터 내 Pod | 06-02 |
