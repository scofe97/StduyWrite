## 보강 항목 (4개)

### ⭐ 1. §1 — SNI 가 왜 존재하는지 한 단락

**위치**: 108행 "호스트 분기만 예외인 이유는…" 단락 **바로 뒤**. 그 단락이 *언제*(암호화 전)를 말하므로, 이어서 *왜*를 붙이면 흐름이 끊기지 않는다.

**넣을 내용** — 닭과 달걀 구조가 핵심이다.

- 서버는 **인증서를 내밀어야** 암호화를 시작할 수 있다
- 그런데 한 IP 에 도메인이 여럿이면 **어느 인증서를 내밀지** 먼저 알아야 한다
- 그 정보가 담긴 `Host` 헤더는 **암호화된 본문 안**에 있어 이 시점엔 못 읽는다 — 너무 늦다
- 그래서 핸드셰이크 맨 앞에 **평문으로** 목적지 이름을 알려 주는 필드를 따로 두었다

**12-01 과 잇는 한 줄**: 12-01 §1 봉투 비유에서 **SNI 는 봉투 겉면의 수취인 이름**이다 — 열지 않아도 보이는 유일한 정보. 이 한 줄이 있으면 "왜 호스트만 예외인가"가 12-01 축으로 흡수된다.

**⛔ 하지 않을 것** — TLS 핸드셰이크 전체 절차 설명으로 확장 금지(항목 2 와 중복된다). 항목 2 가 TLS 를 짧게 소개하므로, 여기서는 **SNI 의 존재 이유만** 적고 멈춘다.

### ⭐ 2. §1 진입부 — TLS 자체를 짧게 설명

**문제**: 이 편은 TLS 를 **아는 것으로 전제하고** 시작한다. 33행 §1 제목이 바로 "Ingress 에서 TLS 종료하기"이고, 35행 인용부터 passthrough·termination 을 가른다. TLS 가 무엇을 보장하는지, 왜 인증서와 키가 둘 다 필요한지가 문서 어디에도 없다.

**위치**: §1 인용문(35행) **뒤**, 37행 "프록시가 TLS 를 종료하면…" **앞**. 종료를 말하기 전에 무엇을 종료하는지를 먼저 둔다.

**넣을 내용 — 세 줄이면 충분하다.**

- TLS 가 보장하는 것 셋 — **암호화**(도청 방지) · **무결성**(위변조 감지) · **신원 확인**(이 서버가 진짜 그 도메인인가)
- 이 중 **신원 확인이 인증서의 몫**이다. 인증서는 "이 공개키가 `example.com` 의 것"임을 CA 가 보증한 문서이고, **개인 키**는 그 짝이라 서버만 갖는다. `kubectl create secret tls` 가 `--cert` 와 `--key` 를 **둘 다** 요구하는 이유가 이것이다(50행)
- 그래서 §1 이 뒤에서 다루는 문제 둘이 각각 어느 보장에 걸리는지 이어진다 — **인증서·host 불일치는 신원 확인 실패**(브라우저가 거부), **passthrough 는 암호화가 파드까지 이어지는 것**

**⛔ 하지 않을 것**
- 대칭·비대칭 암호, 키 교환 알고리즘, CA 체인 검증 절차 — 이 편 소관이 아니다. 12-01 §1 이 "OSI 계층 일반론은 이 편의 소관이 아닙니다"로 절제한 것과 같은 선을 지킨다
- mTLS 상세 — 121행이 이미 한 줄로 언급하고 넘어간다. 그 선을 유지한다
- 새 SVG 금지. 산문 세 줄이다

### ⭐ 3. `12-02-cert-host-mismatch-silent-failure.svg` 재작도

**문제**: 25자 이상 산문이 **12개**다. 특히 하단 두 박스가 본문에 있어야 할 서술이다.

- "쿠버네티스는 인증서 내용과 host 규칙이 맞는지 보지 않습니다. / 서버는 잘못된 인증서라도 그냥 내밉니다. / 브라우저가 인증서의 CN·SAN 을 접속한 도메인과 비교해 / 스스로 끊는 것입니다." (4줄짜리 문단)
- "한 원리가 세 곳에 공통으로 적용됩니다 — DNS 매칭 · Ingress host 매칭 · 인증서 SAN 검증. / 셋을 따로 외울 필요가 없습니다. …" (2줄짜리 결론)

**할 일 둘**

**(가) 산문을 본문으로 뺀다.** 위 두 덩어리는 §1 "어기면 어떻게 되나"(69~84행)에 **이미 거의 같은 문장이 있다.** 대조해서 본문에 없는 표현만 흡수하고, SVG 에서는 지운다. 사실이 사라지면 안 되므로 **뺀 문장이 본문에 있는지 반드시 대조**한다.

**(나) 흐름을 실제 구조처럼 그린다.** 현재는 1~4 단계가 **추상 라벨 박스 네 개**로 나열돼 있어(`1. kubectl apply` `2. kubectl get ingress` `3. 프록시 설정 반영` `4. 클라이언트 접속`), *무엇이 어디를 지나는지*가 안 보인다. 실제 컴포넌트를 세우고 그 위에 단계를 얹는다.

```text
그리려는 구조 (예시 — 배치는 작도자 재량)

  내 노트북(kubectl)  →  API 서버  →  컨트롤러  →  프록시 파드
       ①                   ①            ②           ③
     apply 성공         저장됨      설정 생성    인증서 실려 나감
                     검증 안 함    에러 없음      정상 동작
                          ↑
              ⛔ 아무도 인증서와 host 를 대조하지 않습니다

  브라우저  ─(HTTPS)→  프록시
     ④
  여기서 처음 거부 — ERR_CERT_COMMON_NAME_INVALID
  검증 주체가 클러스터 밖에 있습니다
```

핵심 대비는 **"클러스터 안에는 검증하는 주체가 없다"** 가 눈에 보이는 것이다. 초록(정상 통과) → 분홍(거부) 색 대비는 현재 것이 잘 되어 있으므로 **유지**한다.

**(다) 요소 단위 규칙 박스는 유지한다.** `✓ api.example.com` / `✗ foo.api.example.com` 대비는 그림으로 값이 있다(복습 Q4 출제 지점이기도 하다). 다만 그 아래 "12-01 에서 본 경로·호스트 매칭과 같은 원리입니다" 캡션은 본문으로 뺀다.

### ⭐ 4. `12-02-termination-vs-passthrough-visibility.svg` 재작도

**문제**: 25자 이상 산문이 **13개**다. 하단 결론 박스가 특히 무겁다.

- "12-01 에서 커널이 경로로 못 가른 이유가 '페이로드를 안 읽어서'였다면, 여기서는 '읽으려 해도 암호문이어서'입니다. 막히는 지점만 다르고 결과는 같습니다."
- "Ingress 를 쓰는 이유가 HTTP 를 이해하는 중간자를 두는 것이었는데 그 눈을 가리므로, 둘은 상충합니다."
- "종단 간 암호화가 꼭 필요한 경우에만 그 대가를 치릅니다 — 그래서 표준이 되지 못했습니다."

**할 일 둘**

**(가) 산문을 본문으로 뺀다.** 세 문장 모두 §1 110행("그래서 passthrough 는 L7 중간자의 눈을 가리는 선택입니다…")에 대응 서술이 있다. 대조 후 본문에 없는 것만 흡수하고 SVG 에서 지운다.

**(나) 두 경로를 흐름으로 대비한다.** 현재는 좌우 카드 두 장에 각각 세로 목록이 들어 있어 **같은 항목끼리 눈으로 대조하기 어렵다.** 암호가 어디서 풀리는지를 **한 줄 흐름**으로 그리고, 그 아래 볼 수 있는 것 / 없는 것을 같은 높이에 맞춰 배치한다.

```text
그리려는 구조 (예시 — 배치는 작도자 재량)

termination   클라이언트 ══TLS══> [프록시 🔓] ──평문──> 파드
                                     ↑ 여기서 풂 · 인증서를 쥔 쪽
                                  볼 수 있는 것: GET /quote · Host · 쿠키

passthrough   클라이언트 ══TLS════════[프록시 🔒]════════> [파드 🔓]
                                     ↑ 못 풂            ↑ 여기서 풂
                                  볼 수 있는 것: SNI 뿐 (17 03 03 …)

                     ↕ 같은 높이에서 대조되도록 정렬
```

- **암호 구간을 선 스타일로** 구분한다(TLS 구간 = 굵은 이중선, 평문 구간 = 점선 등). 지금은 색 라벨로만 구분돼 "어디까지 암호인가"가 흐름으로 안 보인다
- **자물쇠가 열리는 지점**을 두 경로에서 다른 x 좌표에 두어, 그 위치 차이가 곧 기능 차이임이 보이게 한다
- 기능 3행(경로 분기 / 헤더·재작성 / 쿠키 어피니티)의 ✓✗ 대비는 **유지**하되 같은 y 좌표에 정렬한다
- **SNI 예외 박스는 유지**한다 — 학습자가 두 번 되물은 지점이라 그림에 남을 값이 있다. 다만 항목 1 이 본문에 존재 이유를 적으므로, 박스에는 **"핸드셰이크 중이라 평문"** 사실만 짧게 남긴다
