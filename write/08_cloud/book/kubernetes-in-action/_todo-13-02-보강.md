## 🚩 사실 확인이 필요한 지점 (착수 시 최우선)

**221행(정답 3)의 "rules 배열의 여러 rule은 순차 평가되어"** 가 부정확할 가능성이 높다.

Gateway API 명세는 HTTPRoute rule 우선순위를 **구체성 기반으로 못박았다**고 알고 있다 — ① `path` 가 더 긴 것 ② `method` 매칭이 있는 것 ③ `header` 조건이 많은 것 ④ `queryParam` 조건이 많은 것, 그래도 같으면 생성 시각이 이른 Route → 이름 알파벳 순. 즉 **YAML 선언 순서는 무관**하다.

"순차 평가"라는 표현은 선언 순서로 읽히므로, 12-01 §4에서 학습자가 이미 한 번 걸린 오해(“먼저 선언된 것이 이긴다”)를 이 문서가 **다시 심을 수 있다.**

## 보강 항목 (4개 · 전부 시각화감)

### ⭐ 1. §1 "status로 진단" — 참조 실패는 apply 를 막지 않는다 (시각화 · 최우선)

현재 64행은 조건과 reason 을 **나열만** 한다. 학습자가 오답한 두 가지가 빠져 있다.

**없는 것 ① — 오타를 내도 `apply` 가 성공한다.** 스키마 검증은 `parentRefs` 가 존재하고 `name` 이 문자열인지만 본다. **그 이름의 Gateway 가 실제로 있는지는 다른 오브젝트 조회가 필요해 스키마가 모른다.** 필수값 검사도 "모양"에 속한다는 것을 명시(13-01 §2 "스키마는 모양을 강제하나 행동은 못 한다"와 교차 참조).

**없는 것 ② — 두 조건의 방향 대응.**

| 조건 | 보는 방향 | False 시 reason |
|---|---|---|
| `Accepted` | **위쪽**(부모 Gateway) | `NoMatchingParent` · `NoMatchingListenerHostname` · `NotAllowedByListeners` |
| `ResolvedRefs` | **아래쪽**(백엔드) | `BackendNotFound` · `RefNotPermitted` · `InvalidKind` |

§1의 두 방향 참조(`parentRefs` 위 / `backendRefs` 아래)가 각각 자기 조건을 갖는다는 대응이 이 항목의 핵심. 그래서 `backendRefs` 오타는 `Accepted: True` 인데 `ResolvedRefs: False` 가 된다(부모에는 붙었고 보낼 곳이 없는 상태).

**없는 것 ③ — 같은 사건이 양쪽에 다르게 기록된다.** 13-01과 잇는 지점.

```
오타로 Route 가 안 붙음
├─ Gateway status → listeners[].attachedRoutes: 0        "붙은 게 없다"
└─ Route status   → parents[].Accepted: False            "붙을 곳을 못 찾았다"
```

66행의 팁("전체 그림이 안 보이면 부모 Gateway status 도")이 왜 필요한지가 이 대비로 설명된다.

### ⭐ 2. §2 — 파드 개수 방식과의 대비 (시각화)

현재 86행은 weight 동작만 설명하고 *왜 이게 나은지*가 없다. 학습자는 자력으로 도출했으나 문서에 근거가 없어 다음 독자는 못 따라간다.

**두 문제를 표로.**

| 하고 싶은 일 | 파드 개수 방식 | weight 방식 |
|---|---|---|
| 1% 카나리 | **파드 100개** 필요 (stable 99 + new 1) | weight 99:1, 파드 각 1개 |
| 카나리 비율 조정 | 파드 수 변경(재배포) | 숫자만 수정 |
| 용량 증설 | 파드 수 변경 → **비율도 바뀜** | replica 만 변경, 비율 그대로 |

- **① 해상도가 파드 수에 묶인다** — 0.1% 면 1000개. 트래픽이 적은 서비스인데 비율 때문에 파드를 늘리는 건 낭비다.
- **② 비율과 용량이 한 손잡이에 묶인다** — "트래픽을 더 보내고 싶다"와 "처리 용량을 늘리고 싶다"가 같은 조작이라, new 가 느려서 파드를 늘리면 **의도치 않게 트래픽 비율도 올라간다.** weight 는 둘을 분리한다.
- 11-01의 "k8s 기본은 파드 개수 비율로 대략, 정밀 %는 L7 필요"와 12-01의 "프록시가 파드 목록을 직접 쥐어 정밀 카나리 가능"이 **여기서 완성**되는 지점이므로 두 편에 교차 참조를 건다.
- 88행 Spring 박스의 "라우팅 선언만으로 점진 배포"가 곧 이 뜻(weight 1→5→20→50 동안 파드는 안 건드림)이라는 연결.

### ⭐ 3. §3 — 3층 결합 구조 + 명세가 정한 우선순위 (시각화 · 🚩 사실 확인 후)

현재 120행은 AND 만 적고 **OR 층이 없다.** 학습자는 (a) AND 는 자력 정답했으나 **`rules` 를 여러 개 두는 것을 "문법 에러 아니야?"** 로 봤다 — 배열 중첩 구조가 안 보인다.

**3층 결합표**

| 층 | 결합 |
|---|---|
| 한 `matches` **항목 안**의 조건들(method·path·headers) | **AND** |
| `matches` 배열의 **항목끼리** | **OR** |
| `rules` 배열의 **rule 끼리** | 구체성 우선(아래) |

복수형 이름(`rules`·`matches`·`backendRefs`·`parentRefs`)이 모두 배열이라는 단서를 짚고, "POST 또는 PUT" 을 matches 항목 둘로 쓰는 예를 넣는다.

**`matches` 생략 = catch-all** 도 명시 — 60행의 기본값(`{path: {type: PathPrefix, value: /}}`)이 채워져 모든 경로에 매칭된다. 12-01의 `defaultBackend` 와 같은 역할이나 **별도 필드가 아니라 조건 없는 rule** 로 표현한다는 차이.

**우선순위 규칙**(🚩 섹션의 확인을 거친 뒤 넣는다) — ① path 길이 ② method 유무 ③ header 수 ④ queryParam 수, 동률이면 생성 시각 → 이름. **YAML 순서 무관.** 12-01 §4 "순서가 아니라 구체성"과 같은 원리이고, **Gateway API 는 그걸 명세에 못박아 이식성을 확보**했다는 것(13-01 `support level` 연결)이 이 편의 값이다.

### ⭐ 4. §4 — 필터 분류 축 + 미러링 함정 (시각화)

현재 128행은 여섯을 **평면 나열**해 성격 차이가 안 보인다. 학습자는 `ExtensionRef`·`RequestMirror` 두 후보로 좁혔으나(정답 포함) 이유를 대지 못했다.

**세 갈래로 분류.**

| 갈래 | 필터 | 성격 |
|---|---|---|
| 요청 하나 → 목적지 하나 | Header 2종 · URLRewrite · ExtensionRef | 고치거나 위임하되 흐름은 하나 |
| **흐름 복제** | **RequestMirror** | 백엔드 둘이 동시에 처리, 복사본 응답은 버림 |
| **백엔드 없음** | **RequestRedirect** | 게이트웨이가 직접 응답 → `backendRefs` 불필요 |

- `ExtensionRef` 가 결이 다른 건 **설정을 어디 두는가**(HTTPRoute 밖 별도 오브젝트)이고, `RequestMirror` 는 **트래픽 흐름 구조**를 바꾼다 — 이 구분을 명시하면 학습자가 두 후보에서 헤맨 지점이 풀린다.
- **weight 카나리 vs 미러링 비교표** (§2와 잇는다)

| | weight 카나리 | RequestMirror |
|---|---|---|
| 클라이언트가 신버전 응답을 받나 | **받는다**(1%라도) | **안 받는다** |
| 신버전이 죽으면 | 그 1% 가 실패 | 클라이언트 영향 없음 |
| 무엇을 검증하나 | 실제 응답 품질까지 | 처리 가능 여부·성능·에러율 |

실무 순서(**미러링 먼저 → 그다음 weight 카나리**)까지.

- ⚠️ **문서에 없는 실무 함정 — 복사본도 실제로 처리된다.** 신버전이 DB 에 쓰거나 결제를 호출하면 **부수효과가 두 번** 일어난다. 미러링은 읽기 요청이나 부수효과가 격리된 환경(별도 DB)에 써야 한다. 이 경고가 이 항목에서 가장 값이 크다.
- `RequestRedirect` 는 12-02의 "L7 중간자를 얻으면 딸려 오는 것"에 열거한 항목이 실물로 나타난 것 — HTTP→HTTPS 리다이렉트를 앱 코드 없이 처리한다는 교차 참조.
