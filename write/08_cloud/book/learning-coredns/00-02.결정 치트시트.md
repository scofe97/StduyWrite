# 결정 치트시트 — Learning CoreDNS

---

> 정독 노트 15편이 각자 끝에 두었던 표를 결정 축으로 다시 묶었습니다. 편 순서가 아니라 "지금 무엇을 정해야 하는가" 순서입니다.

절마다 출처 편을 달았습니다. 표의 한 줄로 판단이 안 서면 그 편을 열어 근거를 확인하는 것이 이 문서를 쓰는 방식입니다. 여기 실린 것은 노트가 이미 내린 판단이고, 이 문서가 새로 더한 주장은 없습니다.


## 서버를 고른다 — CoreDNS 인가 아닌가

> 이 책의 서버가 무엇을 못 하는지부터 걸러 냅니다.
> 출처: [01-01. CoreDNS는 무엇을 포기하고 무엇을 얻었는가](./01-01.CoreDNS%EB%8A%94%20%EB%AC%B4%EC%97%87%EC%9D%84%20%ED%8F%AC%EA%B8%B0%ED%95%98%EA%B3%A0%20%EB%AC%B4%EC%97%87%EC%9D%84%20%EC%96%BB%EC%97%88%EB%8A%94%EA%B0%80.md)

| 상황 | 선택 | 이유 |
|------|------|------|
| 쿠버네티스 클러스터 안에서 서비스 이름을 풀어야 한다 | CoreDNS | 오케스트레이터와 직접 연동되고 1.13 부터 기본값입니다 |
| 인터넷 이름을 스스로 끝까지 해석해야 한다 | CoreDNS 단독으로는 안 됩니다 | 완전 재귀를 지원하지 않아 포워더를 따로 둬야 합니다 |
| 동적 업데이트로 존 데이터를 갱신해야 한다 | BIND 쪽 | 표 1-1 의 동적 업데이트가 없습니다 |
| DNSSEC 검증까지 필요하다 | CoreDNS 단독으로는 부족합니다 | 지원이 제한적이고 즉석 서명 중심입니다 |
| 설정을 짧게 유지하고 필요한 기능만 켜고 싶다 | CoreDNS | 안 켠 플러그인은 코드가 실행되지 않습니다 |
| 인터넷에 직접 열리는 권한 서버를 세운다 | CoreDNS 가 유리합니다 | 메모리 접근 오류 부류를 언어가 막아 줍니다 |




## 존을 나눈다 — 어디까지가 내 관리인가

> 위임이 그은 선이 곧 존의 경계이고, 그 선이 질의 경로를 정합니다.
> 출처: [02-01. 위임이 그은 경계가 질의 경로를 정한다](./02-01.%EC%9C%84%EC%9E%84%EC%9D%B4%20%EA%B7%B8%EC%9D%80%20%EA%B2%BD%EA%B3%84%EA%B0%80%20%EC%A7%88%EC%9D%98%20%EA%B2%BD%EB%A1%9C%EB%A5%BC%20%EC%A0%95%ED%95%9C%EB%8B%A4.md)

| 상황 | 판단 | 이유 |
|------|------|------|
| 하위 이름을 다른 팀이 직접 관리하게 하고 싶다 | 서브도메인을 만들어 위임합니다 | 위임하면 상위에는 "어디서 찾는지"만 남고 통제가 넘어갑니다 |
| 존 파일에 하위 이름이 안 보인다 | 그 하위가 위임됐는지 먼저 봅니다 | 존은 도메인에서 위임분을 뺀 것이라 위임된 이름은 파일에 없습니다 |
| 같은 존을 여러 서버가 답하게 하고 싶다 | 한 대를 주 서버로 두고 나머지를 보조 서버로 둡니다 | 둘 다 권한을 가지며 마스터가 죽어도 보조가 답합니다 |
| 인터넷에 직접 닿지 않는 내부 서버가 외부 이름을 풀어야 한다 | 연결이 있는 서버를 포워더로 지정합니다 | 포워더는 이 용도로 자주 쓰입니다 |
| 응답이 최신인지 확신해야 한다 | 권한 있는 서버에 직접 묻습니다 | 캐시된 답은 여전히 유효할 수도 아닐 수도 있습니다 |
| 해석이 느리다 | 캐시가 비어 있는지, TTL 이 너무 짧은지 봅니다 | 캐시가 사다리의 시작점을 끌어내리는 만큼 왕복이 줄어듭니다 |




## 레코드를 고른다 — 무엇을 적어야 그 답이 나오는가

> 타입마다 답할 수 있는 질문이 다르고, 별칭에는 금지 사항이 붙습니다.
> 출처: [02-02. 레코드 한 줄을 읽으면 존 파일이 읽힌다](./02-02.%EB%A0%88%EC%BD%94%EB%93%9C%20%ED%95%9C%20%EC%A4%84%EC%9D%84%20%EC%9D%BD%EC%9C%BC%EB%A9%B4%20%EC%A1%B4%20%ED%8C%8C%EC%9D%BC%EC%9D%B4%20%EC%9D%BD%ED%9E%8C%EB%8B%A4.md)

| 상황 | 판단 | 이유 |
|------|------|------|
| 존의 이름 자체를 다른 이름의 별칭으로 만들고 싶다 | 할 수 없습니다 | 존의 이름은 정의상 `SOA` 를 가져야 하므로 `CNAME` 을 가질 수 없습니다 |
| 별칭에 `MX` 나 `TXT` 를 붙이고 싶다 | 붙이지 않습니다 | 별칭에 다른 타입이 붙으면 조회 결과가 모호해집니다 |
| 백업 메일 서버를 두고 싶다 | `MX` 를 하나 더 두고 선호도를 크게 줍니다 | 낮은 값 전부를 시도한 뒤에만 높은 값을 시도합니다 |
| 같은 서비스 서버 둘에 트래픽을 2 대 1 로 주고 싶다 | 우선순위를 같게, 가중치를 200 과 100 으로 둡니다 | 가중치는 같은 우선순위 안에서 합 대비 몫으로 나뉩니다 |
| 웹 서버가 이미 80 을 쓰는데 API 를 같은 이름으로 노출하고 싶다 | `SRV` 에 다른 포트를 적습니다 | Port 칸이 서비스가 도는 포트를 지정합니다 |
| `SRV` 나 `MX` 의 대상에 별칭을 적고 싶다 | 적지 않습니다 | 저자가 마지막 예제에서 직접 짚는 금지 사항입니다 |




## SOA 타이머를 정한다 — 보조 서버를 얼마나 밀착시킬 것인가

> 세 값이 확인 주기와 버티는 시간과 포기 시각을 각각 정합니다.
> 출처: [02-02. 레코드 한 줄을 읽으면 존 파일이 읽힌다](./02-02.%EB%A0%88%EC%BD%94%EB%93%9C%20%ED%95%9C%20%EC%A4%84%EC%9D%84%20%EC%9D%BD%EC%9C%BC%EB%A9%B4%20%EC%A1%B4%20%ED%8C%8C%EC%9D%BC%EC%9D%B4%20%EC%9D%BD%ED%9E%8C%EB%8B%A4.md)

| 상황 | 판단 | 이유 |
|------|------|------|
| 존 데이터를 자주 바꾼다 | refresh 를 한 시간 이하로 둡니다 | 확인 비용이 질의 하나라 값쌉니다 |
| 보조 서버가 마스터와 끊겨도 한동안 버티게 하고 싶다 | expire 를 길게, 적어도 일주일로 둡니다 | 만료되면 그 존 질의가 전부 Server Failed 가 됩니다 |
| 없는 이름을 묻는 질의가 쏟아진다 | 부정 캐싱 TTL 을 올립니다 | 다만 갓 추가한 이름의 해석이 늦어지는 대가가 있습니다 |




## Corefile 을 짠다 — 어느 엔트리가 이 질의를 받는가

> 라벨이 도메인·포트·프로토콜 셋을 함께 고르고, 겹치면 최장 일치가 이깁니다.
> 출처: [03-01. Corefile은 라벨로 서버를 가른다](./03-01.Corefile%EC%9D%80%20%EB%9D%BC%EB%B2%A8%EB%A1%9C%20%EC%84%9C%EB%B2%84%EB%A5%BC%20%EA%B0%80%EB%A5%B8%EB%8B%A4.md)

| 상황 | 판단 | 이유 |
|------|------|------|
| 같은 설정을 여러 도메인에 걸고 싶다 | 라벨을 나열합니다 | 엔트리 하나가 라벨을 여럿 가질 수 있습니다 |
| 같은 설정 덩어리를 파일 안에서 반복한다 | 재사용 스니펫으로 빼고 `import` 합니다 | 한 곳만 고치면 됩니다 |
| 설정을 환경별로 바꿔야 한다 | 환경 변수 참조 `{$VAR}` 를 씁니다 | 라벨·지시어·인자 어디에도 펼쳐집니다 |
| 표준 포트를 못 쓴다 | 라벨에 `:포트` 를 붙입니다 | 라벨이 포트까지 함께 고릅니다 |
| 같은 도메인을 평문과 DoT 로 다르게 처리하고 싶다 | 블록을 둘로 나누고 한쪽에 `tls://` 를 붙입니다 | 프로토콜도 라벨의 일부입니다 |
| 블록 여럿이 겹치는데 어느 쪽이 걸릴지 모르겠다 | 가장 긴 라벨을 찾습니다 | 도메인 이름이 여러 라벨에 맞으면 최장 일치가 이깁니다 |
| 로그를 파일로 남기고 싶다 | CoreDNS 옵션으로는 안 됩니다 | 표준 출력으로 내보내고 수집은 바깥에 맡기는 설계입니다 |




## 플러그인이 기대와 다르게 돈다

> 가장 먼저 의심할 것은 순서이고, 그 순서는 Corefile 이 아니라 `plugin.cfg` 가 정합니다.
> 출처: [03-02. 플러그인 일곱이면 서버 하나가 선다](./03-02.%ED%94%8C%EB%9F%AC%EA%B7%B8%EC%9D%B8%20%EC%9D%BC%EA%B3%B1%EC%9D%B4%EB%A9%B4%20%EC%84%9C%EB%B2%84%20%ED%95%98%EB%82%98%EA%B0%80%20%EC%84%A0%EB%8B%A4.md) · [09-01. 한 줄을 옮기면 그 플러그인이 쓸모없어진다](./09-01.%ED%95%9C%20%EC%A4%84%EC%9D%84%20%EC%98%AE%EA%B8%B0%EB%A9%B4%20%EA%B7%B8%20%ED%94%8C%EB%9F%AC%EA%B7%B8%EC%9D%B8%EC%9D%B4%20%EC%93%B8%EB%AA%A8%EC%97%86%EC%96%B4%EC%A7%84%EB%8B%A4.md)

| 상황 | 판단 | 이유 |
|------|------|------|
| 지시어 순서를 바꿔도 동작이 그대로다 | 순서로는 고칠 수 없습니다 | 처리 순서는 빌드 때 고정되며 `plugin.cfg` 가 정본입니다 |
| 존 파일 이름만 적고 서버가 못 찾는다 | `root` 로 디렉터리를 주거나 전체 경로를 적습니다 | `file` 은 그 디렉터리 기준으로 파일을 찾습니다 |
| 보조 서버 재시작 때마다 전체 전송이 일어난다 | CoreDNS 에서는 정상입니다 | 백업 존 파일을 남기지 않고 IXFR 도 지원하지 않습니다 |
| 죽은 포워더로 질의가 계속 간다 | 응답이 오고 있는지 봅니다 | `SERVFAIL` 이라도 응답이면 건강한 것으로 셉니다 |
| 모든 포워더가 죽은 것으로 보인다 | 헬스 체크 쪽을 먼저 의심합니다 | CoreDNS 도 그렇게 보고 무작위 하나에 질의합니다 |
| TTL 을 길게 줬는데 캐시가 그만큼 안 남는다 | `cache` 의 최대값을 확인합니다 | 기본 상한 3,600초로 잘라낸 뒤 캐시합니다 |
| 자주 조회되는 답의 지연을 줄이고 싶다 | `prefetch` 를 켭니다 | 기본은 꺼져 있고, 켜면 TTL 이 10% 에 닿을 때 다시 조회합니다 |
| 다른 플러그인에도 답할 기회를 주고 싶다 | `fallthrough` 를 붙입니다 | 없으면 권한을 받은 플러그인이 `NXDOMAIN` 이나 빈 응답으로 끝냅니다 |
| 오류 로그가 같은 메시지로 넘친다 | `errors` 에 `consolidate` 를 겁니다 | 정규식에 맞는 것을 묶어 요약 한 줄로 남깁니다 |




## 존 데이터를 어디에 두는가

> 네 갈래는 기능이 아니라 관리 방식으로 갈립니다.
> 출처: [04-01. 존 데이터를 어디에 둘지가 관리 방식을 정한다](./04-01.%EC%A1%B4%20%EB%8D%B0%EC%9D%B4%ED%84%B0%EB%A5%BC%20%EC%96%B4%EB%94%94%EC%97%90%20%EB%91%98%EC%A7%80%EA%B0%80%20%EA%B4%80%EB%A6%AC%20%EB%B0%A9%EC%8B%9D%EC%9D%84%20%EC%A0%95%ED%95%9C%EB%8B%A4.md)

| 상황 | 선택 | 이유 |
|------|------|------|
| 존이 몇 개뿐이고 파일로 관리해 왔다 | `file` | 가장 익숙하고 문법이 짧습니다 |
| 존이 수백 개다 | `auto` | Corefile 길이와 복잡도를 줄입니다 |
| 존이 계속 늘어난다 | `auto` | 파일만 새로 놓으면 존이 늡니다. 단 `ZONES` 로 적어 둔 도메인 아래여야 합니다 |
| 존 변경 이력을 남기고 여럿이 고친다 | `auto` + `git-sync` | 디렉터리만 보므로 앞단에 Git 을 붙일 수 있습니다 |
| 이름 몇 개만 싣고 싶다 | `hosts` | 존 파일을 만들 필요가 없습니다 |
| 그 데이터를 보조 서버로 전송해야 한다 | `hosts` 는 안 됩니다 | `SOA` 가 없어 온전한 존이 아닙니다 |
| Route 53 의 존을 클러스터 안에서 답하게 하고 싶다 | `route53` | 보조 서버처럼 동기화한 뒤 권한 있게 답합니다 |
| 원서 문법대로 `file { transfer to ... }` 를 썼는데 안 된다 | 별도 `transfer` 플러그인을 봅니다 | 현재 `file` 문법에는 `transfer` 계열이 없습니다 |
| 시리얼 올리는 것을 자꾸 잊는다 | `reload_by_mtime` | 파일 수정 시각으로 다시 읽을지 판단합니다 |




## 이름이 자주 바뀔 때 무엇을 쓰는가

> 사다리의 어느 칸이 필요한지는 이름이 바뀌는 속도가 정합니다.
> 출처: [05-01. 상태를 밖에 두어야 이름이 초 단위로 바뀐다](./05-01.%EC%83%81%ED%83%9C%EB%A5%BC%20%EB%B0%96%EC%97%90%20%EB%91%90%EC%96%B4%EC%95%BC%20%EC%9D%B4%EB%A6%84%EC%9D%B4%20%EC%B4%88%20%EB%8B%A8%EC%9C%84%EB%A1%9C%20%EB%B0%94%EB%80%90%EB%8B%A4.md)

| 상황 | 선택 | 이유 |
|------|------|------|
| 엔드포인트가 사실상 안 바뀐다 | 명령줄 인자 | 가장 단순하고 인프라가 필요 없습니다 |
| 같은 호스트의 컨테이너 몇 개뿐이다 | 그래도 hosts 파일은 피합니다 | 경합 조건과 관리 부담이 이미 검증된 실패입니다 |
| 서비스를 옮겨도 클라이언트를 안 고치고 싶다 | DNS | 매핑을 바꿀 수 있는 간접 계층을 줍니다 |
| 한 IP 에 HTTP API 여럿을 올려야 한다 | `SRV` 레코드 | 포트까지 찾을 수 있어 관례 포트에 안 묶입니다 |
| IP 가 초 단위로 바뀐다 | `etcd` 플러그인 | 존 파일을 고치는 손이 병목이 되지 않습니다 |
| CoreDNS 를 여러 대로 늘리고 싶다 | `etcd` 플러그인 | 상태가 밖에 있어 무상태로 확장됩니다 |
| etcd 를 따로 운영하고 싶지 않다 | `hosts` 플러그인 | 파일 하나면 되고 5초마다 다시 읽습니다 |
| 이미 PowerDNS 스키마의 DB 가 있다 | `pdsql` 외부 플러그인 | 그 스키마 전용이므로 조건이 맞을 때만 씁니다 |
| 컨테이너 오케스트레이터가 있다 | 오케스트레이터에 맡깁니다 | 쿠버네티스 1.13 부터 CoreDNS 가 기본입니다 |
| 클라이언트가 변경을 너무 늦게 안다 | 등록에 짧은 리스를 겁니다 | 리스가 있으면 남은 시간이 TTL 에 반영됩니다(하한 30초) |
| 등록한 가중치와 응답 가중치가 다르다 | 정상입니다 | 같은 우선순위 안에서 합이 100 이 되게 재계산합니다 |




## 쿠버네티스에서 무엇을 선언하면 어떤 레코드가 나오는가

> 선언이 레코드 모양을 정하므로, 원하는 레코드에서 거꾸로 선언을 고릅니다.
> 출처: [06-01. 무엇을 선언했느냐가 레코드 모양을 정한다](./06-01.%EB%AC%B4%EC%97%87%EC%9D%84%20%EC%84%A0%EC%96%B8%ED%96%88%EB%8A%90%EB%83%90%EA%B0%80%20%EB%A0%88%EC%BD%94%EB%93%9C%20%EB%AA%A8%EC%96%91%EC%9D%84%20%EC%A0%95%ED%95%9C%EB%8B%A4.md)

| 원하는 것 | 선언 | 나오는 레코드 |
|------|------|------|
| 이름 하나로 안정적인 주소 하나 | `clusterIP` 에 주소 | `A` 하나와 그 IP 의 `PTR` |
| 이름 하나로 엔드포인트 주소 전부 | `clusterIP: None` | 엔드포인트 수만큼의 `A` |
| 포트까지 함께 찾기 | `ports` 에 `name` 부여 | `_포트이름._프로토콜.…` 의 `SRV` |
| 추가 조회 없이 곧바로 접속 | 위와 같음 | `SRV` 응답의 ADDITIONAL 에 `A` 동봉 |
| 파드마다 다른 이름 | 헤드리스 + StatefulSet | 서수 이름(`headless-0` …) |
| 파드가 죽어도 같은 이름 | StatefulSet | 재생성 후에도 같은 이름, IP 만 바뀝니다 |
| 부하 분산을 노드에서 | `clusterIP` 에 주소 | kube-proxy 가 netfilter 로 무작위 분배합니다 |
| 부하 분산을 클라이언트에서 | `clusterIP: None` | kube-proxy 가 무시하고 클라이언트가 직접 고릅니다 |
| 이름 없는 포트로 `SRV` | 불가능 | `SRV` 레코드가 생기지 않습니다 |




## 기본 Corefile 의 줄을 지울 수 있는가

> 줄마다 이유가 있고, 지워도 되는 조건이 따로 있습니다.
> 출처: [06-02. 기본 Corefile의 줄마다 이유가 있다](./06-02.%EA%B8%B0%EB%B3%B8%20Corefile%EC%9D%98%20%EC%A4%84%EB%A7%88%EB%8B%A4%20%EC%9D%B4%EC%9C%A0%EA%B0%80%20%EC%9E%88%EB%8B%A4.md)

| 줄 | 왜 있나 | 지울 수 있는 조건 |
|------|------|------|
| `errors` | 오류를 로그에 남깁니다 | 지우지 않습니다 · 문제 추적이 어려워집니다 |
| `health` | kubelet 이 감시할 엔드포인트입니다 | 지우지 않습니다 · 프로브가 이것을 부릅니다 |
| `pods insecure` | kube-dns 하위 호환입니다 | 폐기된 파드 레코드가 필요 없으면 지웁니다 |
| `upstream` | `CNAME` 을 되질의해 풉니다 | 1.4 이상이면 지웁니다(지금은 옵션 자체가 없습니다) |
| `fallthrough in-addr.arpa ip6.arpa` | 모르는 IP 의 `PTR` 을 체인 아래로 넘깁니다 | 서비스·파드 CIDR 을 전부 열거했으면 지울 수 있습니다 |
| `prometheus :9153` | 메트릭을 네트워크에 엽니다 | Prometheus 로 긁지 않으면 지웁니다 |
| `forward . …` | 나머지 질의를 상류로 넘깁니다 | 역방향 존을 좁게 잡았고 외부 해석이 필요 없으면 지웁니다 |
| `cache 30` | 응답을 메모리에 둡니다 | 클러스터 안 질의만 다루면 값이 거의 없습니다 |
| `loop` | 질의 루프를 탐지하고 종료합니다 | 지우지 않습니다 · 디버깅 불가능한 실패를 막습니다 |
| `reload` | Corefile 을 다시 읽습니다 | 남기되 문법 오류를 조심합니다 |
| `loadbalance` | `A`·`AAAA` 를 섞습니다 | 헤드리스를 안 쓰면 이득이 적습니다 |




## 배포 매니페스트의 값을 바꿔도 되는가

> 기본값 대부분은 성능 계산이 아니라 kube-dns 호환에서 나왔습니다.
> 출처: [06-03. 복제본 둘과 170Mi는 어디서 온 값인가](./06-03.%EB%B3%B5%EC%A0%9C%EB%B3%B8%20%EB%91%98%EA%B3%BC%20170Mi%EB%8A%94%20%EC%96%B4%EB%94%94%EC%84%9C%20%EC%98%A8%20%EA%B0%92%EC%9D%B8%EA%B0%80.md)

| 값 | 기본 | 왜 그 값인가 | 언제 바꾸나 |
|------|------|------|------|
| Service 이름 | `kube-dns` | kube-dns 에서 무중단 업그레이드 | 바꾸지 않습니다 · 불변 필드라 중단이 따릅니다 |
| `clusterIP` | 고정값 | kubelet 이 `resolv.conf` 에 박습니다 | 바꾸지 않습니다 |
| ClusterRole 자원 | 다섯 | 배포 지침 단순화 | `pods verified` 를 안 쓰면 파드·노드를 뺍니다 |
| `replicas` | 2 | 작은 클러스터 기준 | 오토스케일러에 맡깁니다 |
| CPU limit | 없음 | CPU 바운드라 노드만큼 쓰게 둡니다 | 그대로 둡니다 |
| memory limit | 170Mi | kube-dns 와 같은 값 | 식으로 재서 클러스터에 맞춥니다 |
| `dnsPolicy` | `Default` | 노드의 상류 네임서버를 써야 합니다 | 바꾸지 않습니다 · `ClusterFirst` 면 자기를 봅니다 |
| 오토스케일 신호 | 노드·코어 수 | 거친 잣대지만 단순합니다 | 워크로드가 편중되면 CPU 나 지연으로 바꿉니다 |
| `cache 30` | 한 블록 | 클러스터 안에는 캐시할 값이 없습니다 | 블록을 나눠 밖에만 캐시합니다 |
| `pods insecure` | 켜짐 | kube-dns 하위 호환 | 새 배포에서는 뺍니다 |




## 명세 밖 기능을 켤 것인가

> 얻는 것과 내주는 것이 늘 짝입니다. 공짜인 칸이 하나도 없습니다.
> 출처: [06-04. 명세 밖으로 나가면 이식성을 내준다](./06-04.%EB%AA%85%EC%84%B8%20%EB%B0%96%EC%9C%BC%EB%A1%9C%20%EB%82%98%EA%B0%80%EB%A9%B4%20%EC%9D%B4%EC%8B%9D%EC%84%B1%EC%9D%84%20%EB%82%B4%EC%A4%80%EB%8B%A4.md)

| 기능 | 얻는 것 | 내주는 것 |
|------|------|------|
| `pods insecure` | kube-dns 하위 호환 | 네임스페이스 신원 보장 |
| `pods verified` | 신원 보장 회복 | 메모리 두 배에서 두 배 반 · API 서버 비선형 부하 |
| `pods disabled` | 가장 가볍습니다 | 파드 질의가 전부 `NXDOMAIN` |
| 와일드카드 질의 | ClusterIP 의 엔드포인트를 볼 유일한 길 | 명세 밖 · 이름 불일치로 거부하는 클라이언트 |
| `autopath` | 외부 이름 질의가 여섯에서 하나로 | `pods verified` 가 필요해 메모리를 더 씁니다 |
| 노드 로컬 캐시 | 중앙 부하 감소 · TCP 로 타임아웃 회피 | 노드마다 자원 · 로컬 캐시는 단일 인스턴스 |
| `transfer to` | 클러스터 레코드를 한 번에 조망 | IXFR 없음 · BIND 비호환 |
| `k8s_external` | 외부 IP 를 이름으로 노출 | `kubernetes` 플러그인이 함께 있어야 합니다 |
| `endpoint_pod_names` | 엔드포인트 이름이 예측 가능 | 의존하면 명세 밖으로 나갑니다 |
| `ignore empty_service` | 검색 경로로 다른 클러스터에 넘김 | 데이터 없음과 이름 없음의 구분이 사라집니다 |
| `namespaces`·`labels` | 테넌트별 격리 | 명세에서 가장 멀리 나갑니다 |




## 질의나 응답을 고칠 것인가

> 고치면 되돌릴 짝이 있는지부터 봅니다. 짝이 없는 것이 클래스입니다.
> 출처: [07-01. 질문과 답이 어긋나면 클라이언트가 버린다](./07-01.%EC%A7%88%EB%AC%B8%EA%B3%BC%20%EB%8B%B5%EC%9D%B4%20%EC%96%B4%EA%B8%8B%EB%82%98%EB%A9%B4%20%ED%81%B4%EB%9D%BC%EC%9D%B4%EC%96%B8%ED%8A%B8%EA%B0%80%20%EB%B2%84%EB%A6%B0%EB%8B%A4.md)

| 하고 싶은 일 | 도구 | 대가와 주의 |
|------|------|------|
| 규칙으로 만들어지는 레코드를 파일에 안 적기 | `template` | 매칭 실패가 `fallthrough` 없으면 `SERVFAIL` · 존을 통째로 가로챕니다 |
| 이름 하나를 다른 이름으로 바꾸기 | `rewrite name` 정확 일치 | 질문 복구가 자동 · 이름 수만큼 규칙이 늡니다 |
| 이름 여럿을 한 규칙으로 바꾸기 | `rewrite name regex` | 질문 복구가 안 됨 · `answer name` 을 반드시 짝지어야 합니다 |
| 클래스 바꾸기 | `rewrite class` | 되돌릴 방법 없음 · 관대한 클라이언트에서만 씁니다 |
| 여러 규칙을 같은 질의에 걸기 | `continue` | 기본은 `stop` · 서버 블록에 적힌 순서대로 처리됩니다 |
| 요청에 위치·신원 싣기 | `rewrite edns0` | 민감 정보면 전송 구간 암호화가 필요합니다 |
| 그 옵션을 상류에서 읽기 | `metadata` + `metadata_edns0` | 후자는 외부 플러그인이라 재빌드가 필요합니다 |
| 정적 존에 서명하기 | `dnssec-signzone` + `file` | 재서명과 롤오버가 전부 사용자 몫입니다 |
| 합성 레코드에 서명하기 | `dnssec` 플러그인 | 서버가 개인 키를 상시 보유 · NSEC3 미지원 |

## 플러그인을 직접 쓴다면 무엇을 구현하는가

> 만들려는 것이 무엇이냐에 따라 `ServeDNS` 의 무게가 달라집니다.
> 출처: [09-02. 네 함수를 구현하면 체인의 한 칸이 된다](./09-02.%EB%84%A4%20%ED%95%A8%EC%88%98%EB%A5%BC%20%EA%B5%AC%ED%98%84%ED%95%98%EB%A9%B4%20%EC%B2%B4%EC%9D%B8%EC%9D%98%20%ED%95%9C%20%EC%B9%B8%EC%9D%B4%20%EB%90%9C%EB%8B%A4.md)

| 만들려는 것 | `ServeDNS` 가 하는 일 | 더 필요한 것 |
|------|------|------|

| 백엔드 | 질의로 레코드를 짓고 `w` 에 씁니다 | 데이터 원본 연결은 `OnStartup` 훅에서 합니다 |
| 뮤테이터 | `nonwriter` 로 받아 고쳐 진짜 `w` 에 씁니다 | 존 매칭으로 남의 질의는 그냥 넘깁니다 |

| 체인의 다른 플러그인을 알아야 함 | 해당 없음 | `OnStartup` 훅 · 파싱 시점에는 알 수 없습니다 |
| 지표 내보내기 | 해당 없음 | `OnStartup` 에서 `metrics.MustRegister` |
| metadata 제공 | 해당 없음 | `Metadata` 함수 하나 · 값이 아니라 값 함수를 넣습니다 |
