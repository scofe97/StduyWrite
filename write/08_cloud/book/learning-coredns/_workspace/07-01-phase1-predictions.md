## 채점 중 설명한 것 (도움받은 이해로 구분)

- 1번 뒤: `template` 은 받은 질문 이름 문자열을 `match` 정규식으로 쪼개 `answer` Go 템플릿에 끼운다 — 학습자 확인 질문에 "맞다"로 답함.
- 3번 뒤: 헤어핀(나갔다 꺾여 들어오는 경로)의 뜻, `rewrite` 가 IP 만 안쪽 것으로 주고 앱은 이름을 그대로 써서 TLS 가 통과하는 이유(DNS 는 IP 만 정함, 이름은 SNI·Host 이름표), 인증서를 클러스터 안이 내놓아야 한다는 조건(AI 덧붙임).
- 4번 뒤: MITM 풀네임, 이름 되돌리기는 이름 칸만 바꾸고 IP 는 ClusterIP 그대로, 접속은 IP 로만 정해짐. 학습자가 "IP만 저렇게 응답한거고 내부에서도 DNS이름은 여전히 저거란거지?"로 스스로 정리.
- 회사 클러스터 대조(대화에만 기록, 공개 문서에 옮기지 않음): `hosts` 로 도구 이름을 노드 밖 VIP 하나에 묶은 구성이 노트 2절 헤어핀과 같은 모양.
- 5번 뒤: AI 가 처음에 "auto"를 `answer auto` 로 잘못 읽어 "플러그인이 아니라 옵션"이라 정정했다가 거둠. `autopath` 는 물은 이름→찾은 이름 CNAME 을 앞에 붙여 대응을 지키고(06-04 §5 221행), `rewrite` 는 Answer 이름 칸을 고쳐 쓴다는 대조, `answer auto` 는 역방향 규칙을 안 적어도 CoreDNS 가 되돌려 보는 best effort 하위 옵션이라는 설명. 학습자가 "auto를 쓰면 알아서 되돌려 보내줌"으로 정리.
- 7번 뒤: 관대한 클라이언트(`host`, 경고 뒤 수용) vs 엄격한 리졸버(버릴 수 있음, "반드시"는 아님). 학습자 질문 "CoreDNS는 일종의 리졸버인가?" — 스텁 리졸버(앱·OS 라이브러리)·재귀 리졸버·권한 서버를 구분하고, 클러스터 CoreDNS 는 `cluster.local` 은 직접 답하고 나머지는 `forward` 로 상류에 넘기는 서버라고 설명. 회사 클러스터 대조(대화에만): `hostname.bind` 존을 `chaos` 로 CH 그대로 답하는 구성.
- 8번 뒤: 지사 PC 둘 → 지사 CoreDNS → 본사 로그 예와 스티커 비유, 값 하나를 따라가는 4단계 표, metadata 는 플러그인 사이 메모판. TLD 풀네임과 루트→TLD→권한 흐름, 리졸버 세 층은 02-01 §5·01-01 §5 에 있음을 안내(학습자가 02-01 §5 개선·도식을 요청 → w5 메인 경유 w3 로 브리프). Mac 에서 `dig +qr +ednsopt=65517:0a010203 example.com @1.1.1.1` 를 실제로 돌려 보낸 질의의 `OPT=65517: 0a 01 02 03` 을 보여 줌(학습자가 전체 출력을 주석과 함께 문서에 넣자고 함 → 후보 60).
- 9번 뒤: ZSK/KSK 비교표(서명 대상·부모가 아는가·교체 비용)와 trust anchor→DS→KSK→ZSK→레코드 사슬. 학습자 질문 "서명이 TLS 인증서 같은 거임?" — 둘 다 공개 키 서명이지만 DNSSEC 은 인증서 문서 없이 레코드마다 RRSIG, 공개 키는 존 안 DNSKEY, 신뢰 뿌리는 DNS 루트 하나, 암호화 없이 무결성·출처만 보증한다고 대조.
- 10번 뒤: 믿음이 두 군데(① CoreDNS↔API 서버 ② 앱↔DNS 답)에서 따로 생긴다는 그림과 은행 창구·도장 비유, 미리 서명(존 파일) vs 즉석 서명(합성 레코드)과 개인 키를 서버에 두는 대가.
