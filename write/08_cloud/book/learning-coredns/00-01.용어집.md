# 용어집 — Learning CoreDNS

---

> 이 폴더의 정독 노트 15편에 나온 말을 장 순서로 모았습니다. 정의는 노트가 이미 쓴 것을 한 문장으로 줄인 것이고, 여기서 새로 주장하는 것은 없습니다.

말이 처음 나온 편을 오른쪽 칸에 적었습니다. 뜻이 헷갈리면 그 편을 열어 문맥째 읽는 편이 빠릅니다. 같은 말이 장마다 다른 무게를 갖는 경우도 있어서, 한 줄 정의만으로 판단하지 않는 편이 안전합니다.


## 1장 — CoreDNS 라는 서버

> 이 책이 다루는 서버가 무엇을 물려받았고 무엇을 못 하는지를 부르는 이름들입니다.

| 용어 | 한 문장 정의 | 편 |
|------|------------|-----|
| CoreDNS | Go 로 쓰인 플러그인 기반 DNS 서버 — 안 켠 플러그인은 코드가 실행되지 않는다 | 01-01 |
| Caddy | CoreDNS 가 포크한 Go 웹 서버 — 설정 문법과 플러그인 구조를 물려줬다 | 01-01 |
| 플러그인 체인 | 질의가 지나가는 플러그인의 줄 — 순서는 실행이 아니라 빌드 때 고정된다 | 01-01, 03-02 |
| 완전 재귀 | 루트부터 참조를 따라 스스로 답을 찾는 해석 — CoreDNS 는 지금도 지원하지 않는다 | 01-01 |
| 포워더 | 재귀를 대신 져 주는 상류 DNS 서버 — CoreDNS 는 이쪽에 넘긴다 | 01-01, 03-02 |
| CNCF | 쿠버네티스를 관리하려고 2015년에 만든 재단 — CoreDNS 는 2019-01-24 졸업 | 01-01 |
| 메모리 안전성 | 버퍼 오버플로 부류를 언어가 막는 성질 — BIND 가 수십 년 겪은 오류를 Go 가 걷어낸다 | 01-01 |




## 2장 전반 — 이름공간과 위임

> 이름이 트리 어디에 놓이고 그 관리가 어디서 갈리는지를 부르는 말들입니다.

| 용어 | 한 문장 정의 | 편 |
|------|------------|-----|
| 레이블 | 트리 한 노드의 이름 — 최대 63자 ASCII, 루트만 길이 0인 null 레이블 | 02-01 |
| 도메인 이름 | 레이블을 루트까지 이어 붙인 것 — 아래에서 위로 읽어 점으로 잇는다 | 02-01 |
| 도메인 | 어떤 노드와 그 아래 전부 | 02-01 |
| 존 | 도메인에서 위임한 부분을 뺀 나머지 — 관리의 단위 | 02-01 |
| 위임 | 하위 도메인의 관리를 다른 서버에 넘기는 것 — 넘긴 쪽에는 `NS` 만 남는다 | 02-01 |
| 권한 | 그 존의 데이터를 들고 확정적으로 답할 수 있는 상태 | 02-01 |
| 주 서버 · 보조 서버 | 존 파일을 읽는 쪽과 전송받는 쪽 — 둘 다 그 존에 권한을 갖는다 | 02-01 |
| 리졸버 | OS 안의 클라이언트 측 라이브러리 — 스텁 리졸버는 재귀를 서버에 맡긴다 | 02-01 |
| 재귀 | 루트에서 TLD 로, 다시 권한 서버로 참조를 따라가는 해석 | 02-01 |
| 참조 | 답 대신 "저기 물어라"로 `NS` 를 돌려주는 응답 | 02-01 |
| 루트 서버 | 이름공간의 출발점 — 13대이고 12개 독립 기관이 운영한다 | 02-01 |
| 캐싱 | TTL 동안 답을 들고 있어 해석 사다리의 시작점을 끌어내리는 것 | 02-01 |




## 2장 후반 — 레코드와 존 파일

> 존 파일 한 줄을 읽는 데 필요한 칸 이름과 레코드 유형입니다.

| 용어 | 한 문장 정의 | 편 |
|------|------------|-----|
| 리소스 레코드 | 존 데이터의 한 줄 — NAME · TTL · CLASS · TYPE · RDATA 다섯 칸 | 02-02 |
| 마스터 파일 형식 | 존 데이터를 적는 텍스트 형식 — 빈칸은 앞줄에서 물려받는다 | 02-02 |
| origin | 상대 이름 뒤에 붙는 기준 도메인 — `@` 가 그것을 가리킨다 | 02-02 |
| `SOA` | 존의 매개변수를 담는 레코드 — 시리얼·refresh·retry·expire·부정 캐싱 TTL | 02-02 |
| `A` · `AAAA` | 이름을 IPv4 · IPv6 주소로 잇는 레코드 | 02-02 |
| `CNAME` | 별칭 — 별칭인 이름에는 다른 타입을 함께 붙일 수 없다 | 02-02 |
| `MX` | 메일 서버 — 선호도가 낮을수록 먼저 시도한다 | 02-02 |
| `NS` | 존의 권한 서버 — 위임을 실제로 그리는 레코드 | 02-02 |
| `SRV` | 서비스의 대상과 포트 — 우선순위·가중치·포트·대상 네 칸 | 02-02 |
| `PTR` | 주소를 이름으로 되짚는 레코드 — `in-addr.arpa` · `ip6.arpa` 아래에 산다 | 02-02 |
| refresh · retry · expire | 보조 서버의 확인 주기 · 실패 후 재시도 간격 · 포기하고 `SERVFAIL` 로 넘어가는 시각 | 02-02 |




## 3장 전반 — Corefile 문법

> 설정 파일 한 장이 서버 여럿을 어떻게 가르는지를 부르는 말들입니다.

| 용어 | 한 문장 정의 | 편 |
|------|------------|-----|
| Corefile | CoreDNS 의 설정 파일 — 기본값은 작업 디렉터리의 `Corefile` | 03-01 |
| 엔트리 | 라벨과 정의로 이뤄진 한 덩어리 — CoreDNS 의 서버 하나에 대응한다 | 03-01 |
| 라벨 | 어느 질의를 이 엔트리가 받을지 정하는 것 — 도메인 이름·포트·프로토콜 | 03-01 |
| 서버 블록 | 중괄호로 감싼 정의 — 여는 중괄호는 라벨 줄 끝, 닫는 중괄호는 홀로 한 줄 | 03-01 |
| 지시어 · 서브지시어 | 플러그인을 켜는 줄과 그 블록 안의 설정 줄 | 03-01 |
| 스니펫 · `import` | 재사용할 설정 덩어리와 그것을 펼치는 지시어 | 03-01 |
| 최장 일치 | 여러 라벨에 맞으면 가장 긴 것이 이긴다는 규칙 | 03-01 |




## 3장 후반 — 서버 하나를 세우는 플러그인

> `plugin.cfg` 가 정한 순서 위에서 일곱 플러그인이 각자 맡는 일입니다.

| 용어 | 한 문장 정의 | 편 |
|------|------------|-----|
| `plugin.cfg` | 플러그인 등록 순서를 정하는 파일 — 체인 순서의 정본이고 바꾸려면 재빌드 | 03-02, 09-01 |
| `root` | 존 파일을 찾을 디렉터리를 정한다 | 03-02 |
| `file` | 존 데이터 파일에서 답한다 | 03-02 |
| `secondary` | 존을 전송받아 답한다 — 디스크에 백업을 남기지 않는다 | 03-02 |
| `forward` | 질의를 상류 포워더로 넘긴다 | 03-02 |
| `cache` | 응답을 메모리에 담는다 — 기본 상한 3,600초, 부정 응답 1,800초 | 03-02 |
| `errors` · `log` | 오류와 질의를 표준 출력으로 내보낸다 — 파일로 쓰는 옵션은 없다 | 03-02 |
| `fallthrough` | 자기가 못 찾았을 때 다음 플러그인에 답할 기회를 넘긴다 | 03-02 |
| `max_fails` · `health_check` | 죽음 판정에 필요한 연속 헬스 체크 실패 수(기본 2)와 그 주기(기본 0.5초) | 03-02 |
| `prefetch` | 캐시에서 빠지기 전에 미리 다시 조회해 두는 동작 — 기본은 꺼짐 | 03-02 |




## 4장 — 존 데이터를 어디에 두는가

> 네 갈래가 각각 어떤 관리 방식을 전제하는지를 부르는 말들입니다.

| 용어 | 한 문장 정의 | 편 |
|------|------------|-----|
| `auto` | 디렉터리를 스캔해 `db.*` 를 존으로 읽는다 — 파일만 놓으면 존이 는다 | 04-01 |
| `hosts` | 호스트 테이블 몇 줄을 싣는다 — `SOA` 가 없어 온전한 존이 아니다 | 04-01 |
| `route53` | AWS Hosted Zone 을 보조 서버처럼 당겨 온다 | 04-01 |
| `git-sync` | Git 저장소를 디렉터리로 동기화하는 컨테이너 — `auto` 앞단에 붙인다 | 04-01 |
| `transfer to` | 존 전송을 허용할 대상 — 현재 문법에서는 별도 `transfer` 플러그인으로 옮겨 갔다 | 04-01 |
| `reload` · `reload_by_mtime` | `SOA` 시리얼로 다시 읽을지 판단하는 것과 파일 수정 시각으로 판단하는 것 | 04-01 |
| `no_reverse` | `hosts` 가 `PTR` 을 만들지 않게 한다 | 04-01 |




## 5장 — 서비스 디스커버리

> 초 단위로 바뀌는 이름을 DNS 로 다루려 할 때 나오는 말들입니다.

| 용어 | 한 문장 정의 | 편 |
|------|------------|-----|
| 서비스 디스커버리 | 상대의 현재 주소를 찾는 일 — 이름을 쓰는 사다리의 목적지 | 05-01 |
| DNS-SD | 서비스 *유형* 을 DNS 로 찾는 규약 — 이 책이 다루는 이름 해석과 다르다 | 05-01 |
| SkyDNS 메시지 | etcd 에 넣는 JSON — `host` · `port` · `priority` · `weight` | 05-01 |
| etcd | 분산 키-값 저장소 — 쿼럼(절반 초과)이 살아 있으면 읽기와 쓰기가 계속된다 | 05-01 |
| 역순 키 | 도메인 이름을 뒤집어 만든 etcd 경로 — `users.services.example.com` 이 `/skydns/com/example/services/users` | 05-01 |
| 리스 | etcd 키의 수명 — 남은 시간이 레코드 TTL 에 반영되고 두 옵션이 30초~24시간으로 가둔다 | 05-01 |
| 무상태 | 고유한 상태를 갖지 않아 인스턴스를 자유롭게 늘릴 수 있는 성질 | 05-01 |
| `pdsql` | PowerDNS 스키마의 SQL DB 를 읽는 외부 플러그인 | 05-01 |




## 6장 — 쿠버네티스

> 선언과 레코드가 어떻게 이어지고 그 비용이 어디서 붙는지를 부르는 말들입니다.

| 용어 | 한 문장 정의 | 편 |
|------|------------|-----|
| 선언형 API · 조정 루프 | 원하는 상태를 적어 두면 컨트롤러가 현실을 그것에 맞추는 구조 | 06-01 |
| watch | API 서버가 변경을 밀어 주는 지속 연결 — 폴링의 맞바꿈을 없앤다 | 06-01, 06-02 |
| ClusterIP · 헤드리스 | 가상 IP 하나를 받는 서비스와 `clusterIP: None` 으로 IP 를 받지 않는 서비스 | 06-01 |
| kube-proxy | ClusterIP 를 노드의 netfilter 규칙으로 푸는 데몬 — 헤드리스는 무시한다 | 06-01 |
| StatefulSet | 파드에 서수 이름을 주는 워크로드 — 재생성해도 이름이 살아남는다 | 06-01 |
| 쿠버네티스 DNS 명세 | 클러스터 안 이름의 형태를 못 박은 문서 — `A` · `PTR` · `SRV` | 06-01 |
| 파드 `A` 레코드 | `a-b-c-d.namespace.pod.cluster.local` — 명세가 스스로 폐기했다 | 06-01 |
| `pods` 세 모드 | `insecure` · `verified` · `disabled` — 하위 호환과 신원 보장과 가벼움을 각각 고른다 | 06-04 |
| `ndots:5` | 점이 다섯보다 적은 이름에 검색 경로를 붙여 보게 하는 `resolv.conf` 옵션 | 06-04 |
| `autopath` | 검색 경로 순회를 클라이언트에서 서버 안으로 옮기는 플러그인 | 06-04 |
| `k8s_external` | 외부 IP 를 클러스터 밖 이름으로 노출한다 | 06-04 |
| ClusterRole · ServiceAccount | 권한 묶음과 그것을 받는 신원 — CoreDNS 는 `list` · `watch` · `get` 만 쓴다 | 06-03 |
| cluster-proportional-autoscaler | 노드 수와 코어 수로 복제본을 정하는 오토스케일러 — 둘 중 큰 쪽이 이긴다 | 06-03 |
| `dnsPolicy: Default` | 노드의 `resolv.conf` 를 쓴다는 뜻 — 파드 기본값 `ClusterFirst` 와 다르다 | 06-03 |




## 7장 — 질의와 응답 다루기

> 체인을 지나는 요청과 응답을 환경에 맞게 다듬는 도구의 이름들입니다.

| 용어 | 한 문장 정의 | 편 |
|------|------------|-----|
| `template` | 존 파일 없이 요청만 보고 규칙으로 답을 짓는다 | 07-01 |
| `rewrite` | 질의나 응답의 필드를 바꾼다 — 필드는 다섯에서 일곱으로 늘었다 | 07-01 |
| `answer name` | 정규식으로 바꾼 이름을 응답에서 되돌리는 짝 규칙 | 07-01 |
| `continue` · `stop` | 규칙을 다음으로 잇는 것과 거기서 멈추는 것 — 기본은 `stop` | 07-01 |
| EDNS0 | DNS 메시지에 옵션을 싣는 확장 — `rewrite edns0` 로 넣고 `metadata` 로 읽는다 | 07-01 |
| `metadata` | 플러그인끼리 값을 주고받는 통로 — 값이 아니라 값 함수를 넣는다 | 07-01, 09-02 |
| KSK · ZSK | 부모 존이 가리키는 키 서명 키와 존 데이터를 서명하는 존 서명 키 | 07-01 |
| `DS` 레코드 | 부모 존에 두는 자식 키의 지문 — 키를 나누는 이유가 여기 있다 | 07-01 |
| 즉석 서명 | 합성 레코드를 응답 시점에 서명하는 것 — 서명할 존 파일이 없기 때문 | 07-01 |




## 8장 — 관측과 진단

> 무엇을 볼지와 그 값을 어떻게 깎을지를 정하는 도구의 이름들입니다.

| 용어 | 한 문장 정의 | 편 |
|------|------------|-----|
| `prometheus` | 질의를 세어 지표로 내보낸다 — 라벨 조합만큼 시계열이 는다 | 08-01 |
| `log` | 질의마다 한 줄을 남긴다 — `NAMES` · `class` · 형식 문자열로 좁힌다 | 08-01 |
| `dnstap` | 요청과 응답을 이진 와이어 형식으로 내보낸다 — 소켓은 받는 쪽이 만든다 | 08-01 |
| `consolidate` | 같은 오류를 정규식으로 묶어 요약 한 줄로 접는다 | 08-01 |
| `trace` | 요청 하나를 스팬으로 쪼갠다 — 기본이 전수라 표본율을 적어야 한다 | 08-01 |
| `debug` | 크래시의 스택 트레이스를 남긴다 — 값을 깎을 손잡이가 없어 운영 금지 | 08-01 |




## 9장 — 커스텀 서버

> 빌드 때 정해지는 것과 코드로 정하는 것을 가르는 이름들입니다.

| 용어 | 한 문장 정의 | 편 |
|------|------------|-----|
| 인트리 · 외부 플러그인 | `plugin.cfg` 에 이미 든 것과 저장소 밖에 있어 직접 넣어야 하는 것 | 09-01 |
| `go generate` | `plugin.cfg` 를 읽어 등록 코드를 만드는 단계 — 빌드 전에 돈다 | 09-01 |
| `init` · `setup` · `Name` · `ServeDNS` | 프로세스당 한 번 · 블록마다 한 번 · 이름을 물을 때 · 요청마다 불리는 네 함수 | 09-02 |
| `plugin.Register` | 인트리 플러그인의 등록 관용구 — 지금은 한 줄이다 | 09-02 |
| `nonwriter` | 아래 플러그인의 응답을 가로채는 가짜 `ResponseWriter` | 09-02 |
| `plugin.ClientWrite` | 응답이 이미 클라이언트에 쓰였는지 알려 준다 — `true` 면 썼다는 뜻 | 09-02 |
| 생명주기 훅 | `OnStartup` · `OnShutdown` 을 비롯한 Caddy 훅 여섯 — 재시작에 불리는 것을 가려야 한다 | 09-02 |
