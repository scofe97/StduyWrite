## 요점

한 줄: 컨테이너는 커널 하나를 함께 쓰는 보통 프로세스이고 8종 namespace 가 무엇이 보이는지를 가릅니다. Pod 는 그중 network·IPC·UTS 를 pause 컨테이너에 모아 함께 쓰는 묶음입니다.

- 출발 문제: `chroot` 는 파일시스템만 가리고 프로세스 목록·네트워크·호스트명은 그대로 보였습니다. VM 은 완전히 가리지만 부팅과 자원 비용이 컸습니다.
- 원리: 프로세스가 `getpid()` 같은 시스템 콜을 부르면 커널이 그 프로세스의 namespace 를 보고 다른 답을 줍니다. 같은 프로세스가 호스트에서는 PID 14829, 안에서는 PID 1 로 보입니다.
- 8종: PID·mount·network·IPC·UTS·user·cgroup·time 입니다. mount 가 2002년(2.4.19)에 먼저 들어왔고 time 이 2020년(5.6)에 마지막으로 들어왔습니다.
- 계층 구조: PID 와 user 는 부모가 자식 namespace 를 들여다보는 계층 구조이고, 나머지 여섯은 평면이라고 리포트가 나눕니다.
- 시스템 콜 셋: `clone()` 은 자식을 만들며 새 namespace 를 주고, `unshare()` 는 지금 프로세스를 떼어 내며, `setns()` 는 `/proc/<pid>/ns/*` 파일로 기존 namespace 에 들어갑니다. `docker exec`·`kubectl exec`·`nsenter` 가 `setns()` 쪽입니다.
- 공유 확인: `/proc/<pid>/ns/` 링크의 대괄호 숫자는 nsfs 의 inode 번호입니다. 두 프로세스의 번호가 같으면 그 namespace 를 함께 쓰는 것입니다.
- 살려 두기: `ip netns add` 처럼 ns 파일을 `/var/run/netns/` 에 bind mount 해 두면 안에 프로세스가 없어도 namespace 가 사라지지 않습니다.
- 보안 경계가 아님: namespace 는 가릴 뿐 커널을 함께 쓰므로, cgroups·seccomp·AppArmor·SELinux·user namespace 를 겹쳐야 보안이 됩니다.
- Pod: kubelet 이 `RunPodSandbox` 로 pause 컨테이너를 먼저 띄워 network·IPC·UTS 를 쥐게 하고, 앱과 사이드카가 거기에 합류합니다. PID·mount 는 컨테이너마다 따로이고, `shareProcessNamespace: true` 일 때만 PID 를 함께 씁니다.
- 리포트 보완: Docker 가 user namespace 를 기본으로 켜지 않는 이유를 호스트 볼륨의 UID 불일치로 짚고, ID-mapped mount 를 해법으로 듭니다. veth 를 지나는 비용은 eBPF CNI 가 줄인다고 덧붙입니다.

## 자료와 실습

- 자료:
  - [namespaces(7)](https://man7.org/linux/man-pages/man7/namespaces.7.html): `CLONE_NEW*` 플래그와 `/proc/<pid>/ns` 규칙을 정한 1차 문서입니다. `pid_namespaces(7)`·`user_namespaces(7)` 도 함께 봅니다.
  - [kernel/nsproxy.c](https://github.com/torvalds/linux/blob/master/kernel/nsproxy.c): 프로세스마다 namespace 포인터를 묶는 `struct nsproxy` 를 봅니다. `kernel/pid_namespace.c` 의 `zap_pid_ns_processes()` 도 봅니다.
  - [Kubernetes user namespaces](https://kubernetes.io/docs/concepts/workloads/pods/user-namespaces/): Pod 에 `hostUsers: false` 를 주는 방법과 지원 단계를 확인합니다.
  - [LWN Namespaces in operation](https://lwn.net/Articles/531114/): namespace 별 구현 배경을 다룬 연재입니다.
  - 『Container Security』 2·4·5장: 시스템 콜과 권한, namespace 격리, VM 과의 비교입니다. 정독 노트는 [container-security](../../08_cloud/book/container-security/README.md) 입니다.
  - 『The Linux Programming Interface』 24~28장과 45~48장: 프로세스 생성·종료·시그널과 System V IPC 입니다. 정독 노트는 [tlpi](../../02_os/book/tlpi_the-linux-programming-interface/README.md) 입니다(6장까지).
  - 『Networking and Kubernetes』 2~4장: Linux 네트워킹, 컨테이너 네트워킹, Kubernetes 네트워킹과 CNI 입니다. 정독 노트는 [networking-and-kubernetes](../../08_cloud/book/networking-and-kubernetes/README.md) 입니다.
  - 코드: [containers-from-scratch](https://github.com/lizrice/containers-from-scratch) `main.go`(Go 로 `clone` 플래그 전달)를 봅니다. kubernetes `build/pause/linux/pause.c`(좀비 회수와 무한 대기)도 봅니다.
  - 코드: runc `libcontainer/nsenter/nsexec.c` 는 Go 런타임 스레드가 생기기 전에 C 생성자에서 namespace 를 바꾸는 부분입니다.
- 실습:
  - Level 1: `unshare` 로 PID·mount·UTS 를 나눈 셸을 띄우고 호스트명을 바꾼 뒤, 호스트에서 `lsns`·`ls -l /proc/<pid>/ns` 로 번호를 비교하고 `nsenter` 로 들어갑니다. 함정은 `--fork`·`--mount-proc` 를 빼면 호스트 프로세스가 보이는 것입니다. 완료: 셸 안 `ps aux` 에 `bash`·`ps` 둘만 보이고 호스트 호스트명은 그대로입니다.
  - Level 2: network namespace 둘과 브리지 `br0` 를 만들고 veth 로 이어 HTTP 를 주고받습니다. 함정은 인터페이스를 UP 하지 않거나 `ip_forward`·`FORWARD` 정책에 막히는 것입니다. 완료: 양방향 `ping` 과 HTTP 가 되고 `tcpdump -i br0` 에 패킷이 보입니다.
  - Level 3: Go 로 `clone` 플래그·`uid_map` 기록·`pivot_root` 를 묶은 미니 런타임 `tiny-run` 을 짭니다. 함정은 부모가 `uid_map` 을 쓸 때까지 자식이 파이프로 기다려야 하는 것입니다. 완료: sudo 없이 띄운 안에서 `whoami` 가 root 이고 호스트 `/etc/shadow` 는 읽히지 않습니다.



## 경고

- ⚠ fork 서술: 리포트는 `-f` 없이 `exec bash` 하면 "새 PID namespace 진입이 실패한다" 고 적습니다. 정독 노트는 첫 자식이 PID 1 이 된 뒤 이어지는 fork 가 실패한다고 설명합니다(`Cannot fork`). 리포트 문장이 정확하지 않습니다.
- ⚠ 평면·계층 구분: "여섯은 평면, PID·user 만 계층" 은 리포트 정리입니다. `namespaces(7)` 원문으로 대조하지 않았습니다.
- ⚠ Kubernetes 버전: user namespace 를 "1.30 베타, 1.33 GA" 라고 적었습니다. 지원 단계는 공식 문서로 확인하지 않았습니다.
- ⚠ 리포트 보완 주장: Docker 가 user namespace 를 기본으로 끄는 이유(볼륨 UID 불일치)는 영상이 아니라 리포트가 덧붙였습니다. ID-mapped mount 커널 5.12 와 eBPF CNI 의 지연 단축도 리포트의 보완입니다.
- ⚠ 장 번호: 『Container Security』 2·4·5장은 정독 노트 번호와 맞습니다. 『The Linux Programming Interface』 장 범위는 노트가 6장까지라 대조하지 못했습니다.
- ⚠ 자막 교정: 리포트가 "engine x", "Kublat" 같은 자동 자막 오인식을 고쳐 적었습니다. 고친 용어가 영상 원문과 같은지는 대조하지 않았습니다.
- ⚠ 링크와 이름: 강연 영상 링크는 버렸습니다. 책 저자와 강연자 이름도 뺐습니다.
