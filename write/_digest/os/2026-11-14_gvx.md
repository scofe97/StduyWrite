## 요점

한 줄: gvx 는 Linux VM 없이 gVisor Sentry 로 여러 OS 에서 Linux 컨테이너를 실행하는 Go 프로젝트이고, 실행 엔진·파일시스템·네트워크 구조와 코드 읽기 순서를 정리합니다.

- gvx(GitHub `gfire-sigs/gvx`)는 Windows·macOS·Linux 에서 Linux VM 을 띄우지 않고 Linux 컨테이너와 ELF64 바이너리를 실행하는 Go 프로젝트입니다. gVisor 의 Sentry 가 시스템 콜·VFS·네트워크를 사용자 공간에서 처리하고, 그 결과를 호스트 OS API 에 연결합니다.
- 실행 엔진: WHPX(Windows), HVF(macOS Apple Silicon), Systrap(하드웨어 가상화 없이 시스템 콜을 가로채는 방식, Windows·Linux)입니다.
- 파일시스템: OCI 이미지 레이어는 EROFS 로 바꿔 캐시하고, 쓰기는 tmpfs 상층에 둡니다. named volume 은 `.ext4` 파일 하나(ext4lite), 호스트 디렉터리는 hostfs 로 붙입니다.
- 네트워크: gVisor netstack 위에 두 갈래를 둡니다. NAT(Track A)는 Go `net.Conn` 으로 L4 연결을 중계하고 포트 포워딩과 DNS relay 를 줍니다. WireGuard(Track B)는 L3 패킷을 UDP 소켓 하나로 암호화해 보냅니다.
- Host Lockdown: Windows 는 Restricted Token·Job Object, macOS 는 Seatbelt·`RLIMIT_NPROC`, Linux 는 seccomp 를 씁니다.
- 코드 읽기 순서: 진입점 `cmd/rungv/main.go` 다음에 `pkg/gvx/config.go`·`pkg/gvx/sandbox.go` 를 먼저 봅니다. `sandbox.go` 에서는 `New()` 초기화 순서와 `Close()` 정리 순서를 확인합니다. 그다음은 `pkg/sentry/kernel` → `pkg/sentry/platform` → `pkg/netbackend` → `pkg/sentry/fsimpl/ext4lite` → `pkg/oci` → `pkg/hostlockdown` → `e2e/` 순입니다.
- 선행 학습 순서: 프로세스·시스템 콜 → 메모리·실행 격리 → 파일시스템 → 네트워크 스택 → 가상화·gVisor. 그다음 gVisor → Sentry → Platform → Systrap 으로 내려갑니다.
- 찾을 키워드: 실행 엔진은 `SECCOMP_RET_TRAP`, `Windows Hypervisor Platform`, `Hypervisor.framework` 입니다. 파일시스템·네트워크는 `JBD2`, `gvisor netstack` 입니다. Host Lockdown 은 `Restricted Token`, `Job Object`, `Seatbelt SBPL` 입니다.

- 실습:
  - Level 1: Go `os/exec` 로 외부 Linux 명령의 생명주기(PID·입출력·종료 코드·`context` 취소)를 다루고 OCI 이미지 매니페스트와 레이어를 다운로드해 RootFS 를 구성합니다. 함정은 SHA256 다이제스트 불일치나 아카이브 압축 해제 실패 시 캐시가 오염되는 것입니다. 완료: 다운로드한 OCI 이미지의 RootFS 에서 외부 Linux 명령을 실행하고 프로세스 종료 및 취소를 관리합니다.
  - Level 2: 읽기 전용 레이어와 쓰기 가능한 레이어를 나누는 mini VFS 를 구성하고, Go `net.Conn` 기반 TCP 프록시·NAT 포워더·DNS relay 로 네트워크를 연결합니다. 함정은 이미지 원본 레이어가 쓰기로 오염되거나 포트 포워딩 연결 생명주기 회수가 누수되는 것입니다. 완료: 원본 레이어를 수정하지 않고 변경사항을 분리하며, 실행 환경 안 애플리케이션이 외부 통신과 포트 포워딩을 수행합니다.
  - Level 3: Linux namespace·seccomp·capability·자원 제한으로 실행 환경의 권한을 잠그고, 프로세스 수·syscall 횟수·기동 지연을 Prometheus 로 노출합니다. 함정은 Host Linux 의 namespace·seccomp 격리일 뿐 gVisor Sentry 의 syscall 가로채기와 자체 커널 구현이 아니라는 점입니다. 완료: 허용한 파일과 네트워크만 접근하는 샌드박스를 만들고 자원과 성능 상태를 프로메테우스로 관측합니다.
