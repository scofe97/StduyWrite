## 요점

- 동시성과 정합성 설계: 완강 포인트 중복 지급은 멱등성 키와 유니크 제약으로 방어하고, 잔액 변경은 원장 패턴의 불변 행 누적으로 추적성을 확보합니다.
- 분산 트랜잭션과 비동기 메시징: 서비스 연계 부분 실패는 트랜잭셔널 아웃박스로 메시지 유실을 막고, 사가 패턴의 보상 트랜잭션으로 상태를 정합시킵니다.
- 멱등 컨슈머 구축: Kafka EOS는 브로커 내부 토픽 간 처리에 한정되므로, 외부 RDB 변경 시 컨슈머 레벨에서 오프셋·메시지 식별자를 트랜잭션에 묶어 멱등성을 보장합니다.
- 대규모 페이징 최적화: 건너뛸 행을 계산하는 OFFSET 대신 키셋 페이지네이션을 채택하고, PostgreSQL의 행 생성자 비교와 MySQL의 조건 전개 특성을 구분해 인덱스를 태웁니다.
- 풀 고갈 방지와 부분 색인: 장기 점유 쿼리의 커넥션 풀 고갈을 방지하고, 소프트 삭제 환경의 이메일 재가입 충돌은 활성 행만 색인하는 부분 유니크 인덱스로 해소합니다.
- 계층별 트래픽 방어: 서킷 브레이커로 외부 연동 장애 전파를 차단하고, CloudFront OAC로 원본 스토리지를 비공개 격리하며 서명된 URL로 유료 미디어를 보호합니다.
- 렌더링 부하 제어: 가상 공간의 다수 동일 객체는 InstancedMesh로 draw call 수를 줄이고, WCAG 2.2 지침에 맞춘 키보드 포커스 제어를 적용합니다.



## 경고

- ⚠ 벡터 DB·시계열 DB 우선순위 일반화: 원문은 문서형 DB보다 벡터·시계열 DB를 깊게 공부하라고 권하나, 모든 서비스 도메인에 적용되는 우선순위는 아닙니다 (원문 50줄). — 미확인: 학습 우선순위는 화자의 설계 의견
- ⚠ 상태 관리 패러다임 단정: 원문은 상태 변화가 많은 작업에서 객체지향이 함수형보다 낫다고 단정하나, 아키텍처 특성과 도메인 요구에 따라 판단이 다릅니다 (원문 50줄). — 미확인: 객체지향 대 함수형은 설계 의견
- ⚠ MySQL 키셋 페이지네이션 인덱스 범위 스캔 실패: 행 생성자 비교는 생성자가 인덱스 접두를 덮지 못하면 일부 열만 인덱스로 쓰고, OR 조건으로 풀어 쓰면 전체 열을 씁니다(MySQL 8.0 문서 예시 key_len 4 에서 12). 범위 스캔 자체가 불가능하다는 서술은 문서에 없습니다 — 정정: [MySQL 8.0 Row Constructor Expression Optimization](https://dev.mysql.com/doc/refman/8.0/en/row-constructor-optimization.html)
- ⚠ Kafka Exactly-once 보장 범위 오해: Kafka EOS는 토픽 간 전달에 한정되며, 외부 RDB로의 반영은 멱등 컨슈머 설계 없이는 정확히 한 번 처리가 보장되지 않습니다 (원문 55줄, 130줄). — 확인됨: [Kafka Design](https://kafka.apache.org/40/design/design/)
- ⚠ CDN 오리진 보호와 오리진 쉴드 혼동: 원문의 오리진 보호는 S3 직접 접근을 막는 OAC 역할이며, 오리진 쉴드는 캐시 계층으로 접근 제어 기능이 아닙니다 (원문 56줄, 211줄). — 확인됨: [CloudFront Origin Shield](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/origin-shield.html), [CloudFront OAC](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/private-content-restricting-access-to-s3.html)
- ⚠ InstancedMesh와 Flyweight의 동일 계층 취급: 원문은 두 기법을 공통 자원 공유로 묶었으나, InstancedMesh는 GPU draw call 최적화이고 Flyweight는 객체 메모리 절감으로 계층이 다릅니다 (원문 57줄, 229줄). — 미확인: InstancedMesh 쪽만 확인, 계층 구분은 의견
- ⚠ 결제 취소 시 기사용 포인트 처리 정책 누락: 결제 취소 시 이미 사용된 포인트를 마이너스 잔액으로 둘지 환불액에서 차감할지 정책 결정 없이 질문에만 그쳤습니다 (원문 58줄, 116줄). — 미확인: 결제 정책 결정 사항이라 공식 문서 없음
- 확인됨: 분산 환경 완강 포인트 중복 적립 방지는 멱등성 키 헤더([IETF Idempotency-Key](https://www.ietf.org/archive/id/draft-ietf-httpapi-idempotency-key-header-07.html))와 DB 유니크 제약으로 해결합니다.
- 확인됨: 분산 서비스 부분 실패는 트랜잭셔널 아웃박스([microservices.io Outbox](https://microservices.io/patterns/data/transactional-outbox.html))와 사가 패턴([microservices.io Saga](https://microservices.io/patterns/data/saga.html))으로 조율합니다.
- 확인됨: Kafka 프로듀서 멱등성은 3.0부터 기본 활성화([Apache Kafka Upgrade](https://github.com/apache/kafka/blob/3.9.0/docs/upgrade.html))이며 외부 저장소 연동은 멱등 컨슈머가 필요합니다([Apache Kafka Design](https://github.com/apache/kafka/blob/4.1.0/docs/design.html)).
- 확인됨: 대규모 데이터에서 OFFSET 방식은 건너뛸 행까지 읽어 비효율적입니다([PostgreSQL LIMIT and OFFSET](https://www.postgresql.org/docs/16/queries-limit.html)).
- 확인됨: 행 생성자 비교 `(a, b) < (x, y)`는 PostgreSQL에서 복합 인덱스 조건으로 쓰입니다([PostgreSQL Row Comparison](https://www.postgresql.org/docs/16/functions-comparisons.html#ROW-WISE-COMPARISON)).
- 확인됨: 커넥션 풀 대기 시간이 타임아웃을 넘으면 SQLException이 발생합니다([HikariCP README](https://github.com/brettwooldridge/HikariCP/blob/HikariCP-6.3.0/README.md)).
- 확인됨: 소프트 삭제 테이블의 이메일 재가입 유니크 제약 충돌은 부분 유니크 인덱스로 해결합니다([PostgreSQL Partial Indexes](https://www.postgresql.org/docs/16/indexes-partial.html)).
- 확인됨: 외부 연동 장애 전파는 서킷 브레이커 상태 기계로 차단합니다([Resilience4j CircuitBreaker](https://resilience4j.readme.io/docs/circuitbreaker)).
- 확인됨: CloudFront OAC는 S3 오리진 접근을 제한하고([AWS OAC](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/private-content-restricting-access-to-s3.html)), 비공개 콘텐츠는 서명된 URL로 보호합니다([AWS Signed URLs](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/private-content-signed-urls.html)).
- 확인됨: AWS IAM 권한 평가는 명시적 거부(Deny)를 최우선 적용합니다([AWS IAM Policy Evaluation](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_policies_evaluation-logic_policy-eval-denyallow.html)).
- 확인됨: 3D 가상 공간의 동일 메시는 InstancedMesh로 draw call 수를 줄입니다([three.js InstancedMesh](https://github.com/mrdoob/three.js/blob/r160/docs/api/en/objects/InstancedMesh.html)).
- 확인됨: 웹 접근성 키보드 조작과 포커스 가시성은 WCAG 2.2 권고안 기준입니다([W3C WCAG 2.2](https://www.w3.org/TR/2024/REC-WCAG22-20241212/)).
