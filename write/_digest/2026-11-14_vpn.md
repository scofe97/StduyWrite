## 요점

- 캡슐화와 트래픽 가시성 경계: 원본 IP 패킷 전체를 페이로드로 암호화하고 새로운 외부 IP 및 UDP 헤더를 덧붙이는 터널 모드 구조입니다. ISP는 VPN 서버와의 통신 사실만 인지할 뿐 내부 목적지와 실제 데이터는 식별하지 못합니다.
- TUN 가상 인터페이스 기반 데이터패스: 커널 라우팅 테이블이 패킷을 가상 인터페이스로 보내면 파일 디스크립터(`/dev/net/tun`)를 통해 패킷을 가로채 암호화 소켓으로 전송합니다. 서버는 복호화 후 SNAT를 거쳐 외부 인터넷으로 내보냅니다.
- DNS 질의 보호와 Split DNS: 데이터 트래픽만 터널링하고 DNS 요청을 로컬 ISP로 보내면 접속 도메인이 노출되므로 터널 사설 DNS 리졸버 바인딩이 필요합니다. 사내 도메인만 내부 DNS로 질의하는 Split DNS로 정보 유출을 차단합니다.
- 스플릿 터널링 설계: 게이트웨이 트래픽 병목(Hairpinning)을 완화하기 위해 사내 CIDR 대역만 터널로 보내고 일반 트래픽은 로컬로 직행시킵니다. 단말이 공용망과 사내망의 브리지가 되므로 단말 보안 정책이 함께 뒷받침되어야 합니다.
- 캡슐화 오버헤드와 PMTU 블랙홀 방지: 외부 헤더(IP·UDP·암호화 오버헤드 40~80바이트) 추가로 이더넷 MTU를 초과하고 ICMP가 차단되면 패킷이 폐기됩니다. 가상 인터페이스 MTU를 낮추고 방화벽에서 TCP MSS Clamping을 적용하여 연결 멈춤을 방지합니다.
- 신뢰 모델 한계와 ZTNA 전환: VPN은 트래픽 감시 주체를 ISP에서 VPN 운영자로 이전할 뿐 절대적인 익명성을 보장하지 않습니다. 네트워크 진입 후 내부망 전체에 접근 권한이 부여되는 한계를 해결하기 위해 신원 중심의 ZTNA로 전환하는 추세입니다.



## 경고

- ⚠ WireGuard의 UDP 단일 프로토콜 의존성과 방화벽 차단 한계: 원문은 WireGuard가 UDP 전용 설계로 고속·무중단 로밍을 달성한다고 강조합니다(219·222행). 하지만 UDP 트래픽을 엄격히 차단하거나 스로틀링하는 기업 방화벽 및 공용망 환경에서는 TCP 폴백(Fallback) 수단이 없어 연결이 불가능할 수 있습니다. — 확인됨: [WireGuard Known Limitations](https://www.wireguard.com/known-limitations/)
- ⚠ TCP MSS Clamping의 UDP 패킷 단편화 보호 한계: 원문은 TCP MSS Clamping(`--clamp-mss-to-pmtu`)을 통해 PMTU 블랙홀 장애를 예방할 수 있다고 제시합니다(244~247행). 그러나 이는 TCP 트래픽에만 적용되며, QUIC이나 대용량 UDP 트래픽에는 효과가 없어 여전히 IP 단편화 및 패킷 폐기 위험이 남습니다. — 확인됨: [iptables-extensions(8) TCPMSS](https://man7.org/linux/man-pages/man8/iptables-extensions.8.html)
- ⚠ 고정 MTU 1420 설정의 오버레이 환경 호환성 단정: 원문은 캡슐화 오버헤드를 고려해 가상 인터페이스 MTU를 1420으로 설정하면 안전한 것처럼 예시합니다(49·238~239행). 기본 이더넷(1500B)이 아닌 PPPoE(1492B)나 클라우드 가상화 오버레이 망(VXLAN/GENEVE 등 하위 MTU 환경)에서는 여전히 MTU 초과 단편화가 발생할 수 있습니다. — 확인됨: [wg-quick(8)](https://raw.githubusercontent.com/WireGuard/wireguard-tools/master/src/man/wg-quick.8) (MTU 자동 결정 부분만, PPPoE·오버레이 수치는 미확인)
- ⚠ 스플릿 터널링 구성 시 IPv6 사이드채널 유출 간과 위험: 원문은 AllowedIPs에 사내 IPv4 CIDR만 명시하면 스플릿 터널링이 안전하게 동작하는 것처럼 구성합니다(253~256행). 듀얼 스택 클라이언트 환경에서 IPv6를 명시적으로 차단하거나 라우팅하지 않으면 브라우저의 AAAA 질의에 의해 로컬 ISP로 트래픽이 새어나가는 IPv6 Leak이 발생할 수 있습니다(68~69행). — 미확인: IPv6 누수는 구성 설계 판단 사항
