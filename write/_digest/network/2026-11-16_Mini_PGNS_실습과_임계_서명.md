## 요점

한 줄: portal tunnel 의 relay 와 이름 체계(PGNS)를 공부하는 노트에 대해, Sparse Merkle Tree 증명과 서명 기반 상태 전이를 1주차 Go 실습으로 짜고, 멀티 에이전트 빌드 캐시와 DNSSEC 공동 서명 방식을 함께 짚습니다.

- 보일러플레이트:
  - `internal/smt/tree.go` 는 `SHA256(domain)` 을 키로 쓰는 인메모리 SMT입니다. 루트를 매번 재귀로 다시 계산하는 학습용 구현입니다.
  - `internal/registry/transition.go` 는 P-256 ECDSA 로 `PortalLeafRecord` 를 서명하고 소유자 연속성·`Seq`·만료를 검사합니다.
  - `tree_test.go` 는 포함·비포함·변조 거부 세 경우를 시험합니다.
- 비포함 증명: 등록되지 않은 도메인의 경로가 비어 있음을 루트로 증명합니다. 리포트는 이를 "NXDOMAIN 의 암호학적 증명" 이라고 부릅니다.
- Go 빌드 캐시 Action ID 입력(리포트 주장):
  - 툴체인 바이너리 해시, 소스 내용 해시, 빌드 플래그·환경 변수가 들어갑니다.
  - 의존 패키지 export data 해시, `-trimpath` 가 없을 때 작업 디렉터리 경로, 테스트가 읽은 환경 변수·파일도 들어갑니다.
- 멀티 에이전트 캐시 억제: 에이전트마다 `git worktree` 경로가 달라도 `GOFLAGS="-trimpath"` 면 같은 Action ID 가 나온다고 합니다. `-race` 빌드는 따로 두고, `GOCACHE` 는 `overlay2` 밖 별도 볼륨에 두며, 전체 삭제 대신 오래 안 쓴 항목만 지우라고 권합니다.
- 서명 방식 비교:
  - FROST(RFC 9591)는 Schnorr 서명을 2라운드로 만들고 구현이 간결합니다.
  - Threshold ECDSA(GG20·CGGMP21)는 3~6라운드에 구현이 어렵지만 DNSSEC Algorithm 13(ECDSAP256SHA256)과 바로 맞습니다.
  - 리포트 결론은 표준 리졸버의 DNSSEC 검증을 타려면 Threshold ECDSA 이고, FROST 를 쓰려면 클라이언트가 SMT 루트 서명을 직접 검증하게 검증 경계를 옮기라는 것입니다.
- 설계 질문 1(악의적 relay): relay 가 TLS 를 종료하지 않고 SNI 만 읽어 넘기면(TLS passthrough) 키는 종단 터널만 가집니다. relay 는 지연·드롭은 해도 복호화·변조는 못 합니다.
- 설계 질문 2(조작된 루트): Merkle 증명은 "이 루트 안에 있다" 만 보입니다. 독립 감시자가 서명한 append-only 투명성 로그에 루트를 게시해 split-view 공격을 잡습니다.
- 설계 질문 3(복제본과 연결): 맺은 TCP 연결 상태는 그 종단 인스턴스의 커널·메모리가 가집니다. 끊기면 재연결 책임은 클라이언트에 있고, 무중단 이전에는 QUIC connection migration 이나 세션 재개 토큰이 필요합니다.

## 자료와 실습

- 실습:
  - 프로젝트: Mini PGNS 1주차, 주 3회·회당 30분, Go `internal/smt` 입니다.
  - 1회차: 256비트 고정 깊이 SMT, 빈 서브트리 기본 해시 사전 계산, leaf `0x00`·node `0x01` 도메인 분리 프리픽스를 짭니다. 완료: 같은 키를 넣으면 늘 같은 `RootHash` 가 나옵니다.
  - 2회차: 형제 해시 256개를 모으는 `GenerateProof()` 와 루트를 다시 계산하는 `VerifyProof()` 를 짭니다. 완료: 등록 도메인은 포함 증명, 미등록 도메인은 비포함 증명을 통과합니다.
  - 3회차: `PortalLeafRecord{Domain, Target, Seq, Expiry}` 서명·검증과 이전 이하 `Seq` 거부를 짭니다. 완료: 서명 변조·만료 레코드·과거 `Seq` 를 모두 거부하는 시험이 통과합니다.



## 경고

- ⚠ 코드는 실행하지 않았습니다. `tree.go` 는 `fmt` 를 import 하고 쓰지 않아 이대로는 컴파일되지 않습니다.
- ⚠ 곡선 불일치: 실습 표 3회차는 secp256k1 로 서명하라고 하지만, 보일러플레이트는 `elliptic.P256()` 을 씁니다.
- ⚠ FROST 와 DNSSEC: 한 답은 Schnorr 서명을 표준 리졸버가 검증하지 못한다고 하고, 다른 답은 Ed25519(Algorithm 15)의 임계 변형을 대안으로 듭니다. RFC 9591 에 Ed25519 묶음이 있는지, 그 서명이 표준 Ed25519 검증기를 통과하는지 원문으로 확인해야 합니다.
- ⚠ mtime 서술 충돌: 한 답은 Action ID 가 mtime 이 아니라 내용 해시를 쓴다고 하고, 다른 답은 "mtime 뿐만 아니라" 라고 적습니다.
- ⚠ 빌드 캐시 수치: "패치 버전만 바뀌어도 전체 캐시 미스", "`-trimpath` 없으면 캐시 100% 중복", "`go clean -cache` 뒤 5배 느림" 은 근거 없는 주장입니다. `cmd/go` 소스와 `go help cache` 로 대조하지 않았고, Go 가 오래 안 쓴 캐시를 스스로 지우는지도 확인하지 않았습니다.
- ⚠ 라운드 수: Threshold ECDSA "3~6라운드", FROST "전처리 시 1라운드" 는 프로토콜마다 다릅니다.
- ⚠ 루트 앵커링: 블록체인 L2 에 상태 루트를 기록하는 방안은 리포트가 덧붙인 선택지입니다. 원 노트의 설계인지 확인하지 않았습니다.
- ⚠ 원 노트: 이 답들은 사용자의 portal tunnel 학습 노트를 입력으로 받았습니다. "노트 2.6" 같은 절 번호는 그 노트 기준이라 여기서 대조하지 않았습니다.
