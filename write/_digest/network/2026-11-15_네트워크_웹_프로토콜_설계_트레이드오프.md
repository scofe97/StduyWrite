## 요점

한 줄: 1980년대 대역폭이 귀하던 전제에서 나온 표준(16비트 포트·Nagle·평문 UDP DNS)이 지금의 저지연·보안 요구와 부딪힌다고 봅니다.

- 우회의 원칙: 하위 표준은 바꾸기 어렵습니다. 그래서 중간 장비가 통과시키는 모양(HTTP, UDP 443) 위에서 4-tuple·QUIC·`Upgrade` 로 한계를 돌아간다고 정리합니다.
- Nagle: 헤더 40바이트에 1바이트를 실으면 효율이 약 2.4% 입니다. 그래서 ACK 전까지 모아 보냅니다.
- Nagle 과 Delayed ACK 가 만나면 양쪽이 서로 기다려 지연이 튑니다. 저지연 서비스는 `TCP_NODELAY` 를 켭니다.
- `TCP_NODELAY` 만 켜고 작은 `write()` 를 남발하면 작은 패킷이 쏟아집니다. 앱에서 링 버퍼나 `writev()` 로 묶어 보내라고 권합니다.
- 포트 고갈: 서버는 리슨 포트 하나로 많은 연결을 받습니다. 한 목적지로 연결을 많이 맺는 클라이언트·프록시·부하 테스트기는 임시 포트가 바닥납니다(`Cannot assign requested address`).
- 대응: `ip_local_port_range` 확장, 보조 IP 여러 개에 `bind()` 분산, Keep-Alive 커넥션 풀 재사용입니다. Linux 기본 범위는 `32768~60999`(약 28,232개)라고 적습니다.
- HTTP 진화: 1.1 은 응답 순서 때문에 HTTP 층 HOL 이 생겨 브라우저가 도메인당 연결 6개를 열었습니다. 2 는 프레임 다중화로 HTTP 층 HOL 을 풀었습니다.
- HTTP/2 의 남은 문제: 연결 하나 위에 있어 TCP 패킷 하나가 빠지면 모든 스트림이 기다립니다. HTTP/3 는 QUIC 으로 이 TCP 층 HOL 을 없앴습니다.
- HTTP/3 의 대가: 방화벽의 UDP 차단과 사용자 공간 처리의 CPU 비용입니다. 서버가 HTTP/2 와 HTTP/3 를 함께 열고 `Alt-Svc` 로 고르게 합니다.
- 바이너리화의 대가: Telnet 으로 읽을 수 없어 Wireshark 같은 도구가 필요합니다.
- DNS: 50~200바이트 질의라 UDP 로 핸드셰이크와 서버 상태를 없앴습니다. 큰 응답(DNSSEC)은 TCP 로, 프라이버시는 DoT·DoH 로 옮겨 갑니다.
- WebSocket: 새 프로토콜을 바로 열지 않고 HTTP 요청으로 시작해 방화벽·프록시와 인증·라우팅 인프라를 그대로 씁니다.
- 선택 기준: 채팅·협업처럼 진짜 양방향이면 WebSocket, LLM 토큰·알림·시세처럼 서버에서 내려보내기만 하면 HTTP/2 위 SSE 를 권합니다.
- Base64: 크기가 약 33% 늘어납니다. 큰 파일은 JSON 에 싣지 말고 multipart, Presigned URL, Protobuf 로 분리하라고 권합니다.
- TLS 1.3: 정적 RSA 키 교환을 빼서 순방향 비밀성을 기본으로 합니다. 정적 RSA 는 서버 개인키 하나가 새면 저장해 둔 과거 트래픽이 모두 풀립니다.
- 노트 없는 주제: HTTP Request Smuggling 입니다.
- 찾을 키워드: 지연은 `TCP_CORK`, `tcp_tw_reuse` 입니다. DNS·HTTP 는 `EDNS(0)`, `DNS over QUIC`, `h2c smuggling`, `Connection ID` 입니다.

## 경고

- ⚠ 영상 수: 원문은 "8개 대본" 이라고 하지만 분석 대상에는 7개 주제가 있습니다. 출처 표시(` `)도 비어 있어 주장을 영상과 맞댈 수 없습니다.
- ⚠ Smuggling 단정: "HTTP/2 가 Request Smuggling 을 구조적으로 제거했다" 는 과장입니다. 앞단이 HTTP/2 를 받아 뒷단에 HTTP/1.1 로 내리는 다운그레이드 구간에서 같은 계열 취약점이 알려져 있습니다.
- ⚠ HPACK 표현: "정적/동적 허프만 테이블" 은 정적·동적 헤더 표와 허프만 부호화를 섞은 말입니다. "모바일 트래픽 30% 절감" 도 출처가 없습니다.
- ⚠ TLS 1.3 키 교환: 원문은 "ECDHE 만 허용" 이라고 적습니다. TLS 1.3 은 유한체 DHE 도 허용하고, (EC)DHE 없이 PSK 만 쓰는 모드는 순방향 비밀성이 없습니다(확인하지 않음).
- ⚠ 속도 배수: "대칭 키가 비대칭 키보다 약 10만 배 빠르다" 는 출처가 없고 알고리즘·하드웨어에 따라 크게 다릅니다.
- ⚠ DNS 512바이트: "512바이트를 넘는 응답 불가" 는 옛 UDP 한계입니다. EDNS(0) 로 더 큰 UDP 응답을 받을 수 있고, 잘린 응답은 TCP 로 다시 묻습니다. DoH 는 HTTP/3(UDP) 위에서도 돕니다.
- ⚠ 교착 표현: Nagle 과 Delayed ACK 의 상호작용은 타이머가 풀어 주는 지연이지 교착(deadlock)이 아닙니다. "40~200ms" 는 OS 마다 다릅니다.
- ⚠ 포트 계산: "보조 IP 하나당 65,535개씩" 은 실제로는 임시 포트 범위만큼입니다. 같은 출발지 포트도 목적지가 다르면 다시 쓸 수 있어, 고갈은 목적지 하나당의 문제입니다.
- ⚠ 표현 차이: 연결 구분은 프로토콜을 더한 5-tuple 로 적기도 합니다. 원문은 4-tuple 로 적었습니다.
