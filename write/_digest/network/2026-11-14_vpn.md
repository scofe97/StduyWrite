## 요점

한 줄: VPN 은 패킷을 암호화해 캡슐화할 뿐 익명성을 주지 않으며, TUN·SNAT 데이터 경로와 DNS leak·MTU·비대칭 라우팅 같은 운영 문제를 다룹니다.

- 캡슐화: 원본 IP 패킷 전체를 암호화해 새 외부 IP·UDP 헤더로 감쌉니다. ISP 는 VPN 서버와 통신한다는 사실만 보고, 안쪽 목적지와 내용은 보지 못합니다.
- 신뢰 모델: VPN 은 트래픽을 보는 주체를 ISP 에서 VPN 운영자로 옮길 뿐이고 익명성을 주지 않습니다. 접속 뒤 내부망 전체가 열리는 한계 때문에 신원 중심의 ZTNA 로 옮겨 가는 추세입니다.
- 데이터 경로: 라우팅 테이블이 패킷을 TUN 인터페이스로 보내면 사용자 공간 프로세스가 `/dev/net/tun` 에서 읽어 암호화한 뒤 UDP 소켓으로 보냅니다. 서버는 복호화한 뒤 SNAT 로 출발지를 자기 공인 IP 로 바꿔 내보냅니다.
- DNS leak: 데이터만 터널로 보내고 DNS 질의를 ISP 리졸버로 보내면 접속 도메인이 드러납니다. 사내 도메인만 내부 리졸버로 묻는 Split DNS 를 함께 씁니다.
- 스플릿 터널링: 사내 CIDR 만 터널로 보내고 나머지는 로컬로 내보내 게이트웨이 병목을 줄입니다. 대신 단말이 공용망과 사내망을 잇는 다리가 되므로 단말 보안이 받쳐 줘야 합니다.
- 운영 장애: 캡슐화 헤더만큼 패킷이 커져 MTU 를 넘고 ICMP 가 막히면 큰 패킷만 사라집니다. 터널 MTU 를 낮추고 TCP MSS 를 보정합니다. 돌아오는 경로가 터널을 거치지 않으면 비대칭 라우팅으로 패킷이 버려집니다.
- 백엔드 영향: 출구 IP 를 함께 쓰는 사용자가 IP 기반 rate limit 에 한꺼번에 걸립니다. 원문은 사용자 식별자 기반 제한을 권합니다.
- 프로토콜 비교: IPsec(커널, ESP·IKE), OpenVPN(사용자 공간, TLS), WireGuard(커널, Cryptokey Routing·ChaCha20) 셋을 비교합니다.
- 찾을 키워드: `NAT traversal hole punching`, `split tunneling`, `DNS leak`, `split DNS`, `VPN kill switch iptables`, `rate limiting behind NAT` 입니다.

## 자료와 실습

- 자료:
  - [RFC 4301](https://datatracker.ietf.org/doc/html/rfc4301): IPsec 아키텍처의 전송 모드와 터널 모드 차이를 정의한 표준 명세서입니다.
  - [WireGuard 논문](https://www.wireguard.com/papers/wireguard.pdf): Cryptokey Routing 과 커널 구현으로 VPN 복잡성을 해결한 핵심 논문입니다.
  - [Universal TUN/TAP device driver (커널 문서)](https://docs.kernel.org/networking/tuntap.html): Linux 커널에서 가상 네트워크 인터페이스가 유저 공간과 패킷을 주고받는 내부 메커니즘 문서입니다.
  - 『Computer Networking: A Top-Down Approach』 4장·8장: 패킷 캡슐화, IP 헤더, NAT, DNS 원리입니다. 4장 정독 노트는 [cntd 04-04](../../02_os/book/cntd_computer-networking-top-down/04-04.IPv6 와 일반화 포워딩.md) 입니다. 8장은 [cntd 08-04](../../02_os/book/cntd_computer-networking-top-down/08-04.망 계층에 통째로 씌우고 무선에 붙입니다.md) 입니다.
  - 『UNIX Network Programming』 1~4장(소켓 기초)·18장(라우팅 소켓): 커널이 패킷을 생성하고 라우팅하는 시스템 프로그래밍 원리입니다.
  - 『Zero Trust Networks』 1~3장(신뢰 모델 변화)·6장(네트워크 에이전트와 프록시): 전통적 VPN 경계 모델 한계와 mTLS, 신원 기반 프록시 아키텍처입니다.
  - [What is a VPN / How IPsec & WireGuard Work](https://www.cloudflare.com/learning/access-management/what-is-a-vpn/): 패킷 캡슐화, MTU, NAT, DNS 유출의 시각 자료입니다.
  - [How NAT Traversal Works](https://tailscale.com/blog/how-nat-traversal-works): 방화벽과 NAT 뒤의 두 단말이 P2P WireGuard 터널을 뚫는 기법입니다.
  - 코드: `songgao/water` 의 `syscalls_linux.go` 에서 `ifce.Read()`·`ifce.Write()` 구현부를 봅니다. `WireGuard/wireguard-go` 의 `device/send.go`·`device/receive.go`(패킷 암호화·캡슐화)를 봅니다. `tailscale/tailscale` 의 `wgengine/`·`net/dns/`(Split DNS)도 봅니다.
- 실습:
  - Level 1: `tcpdump` 로 VPN 연결 전후 물리 인터페이스와 가상 터널 인터페이스의 패킷 헤더 캡슐화를 관찰합니다. 함정은 macOS 에서 가상 인터페이스 이름이 `utun0`, `utun1` 등으로 동적 할당되는 점입니다. 완료: 물리 인터페이스의 외부 패킷 헤더와 가상 인터페이스의 원본 패킷 헤더 차이를 캡처 로그로 설명합니다.
  - Level 2: `songgao/water` 와 대칭키 암호화, `iptables MASQUERADE` 로 미니 UDP 암호화 IP 터널을 구현합니다. 함정은 `0.0.0.0/0` 라우팅 때 서버 공인 IP 로 가는 패킷까지 터널로 들어가 무한 라우팅 루프가 나는 점으로, `/32` 예외를 먼저 둡니다. 완료: `curl ifconfig.me` 에서 VPN 서버 공인 IP 가 나오고 정상 응답을 받습니다.
  - Level 3: 사내 CIDR 스플릿 터널링과 사내 DNS 프록시, 장애 시 평문 유출을 막는 Kill Switch 를 구현합니다. 함정은 VPN 프로세스가 강제 종료될 때 방화벽 규칙이 풀리지 않거나 네트워크가 차단되는 상태 불일치입니다. 완료: 게이트웨이 강제 종료(`docker kill`) 때 평문 물리 인터페이스로 트래픽이 나가지 않고 차단됩니다.



## 경고

- ⚠ WireGuard 는 UDP 만 씁니다. UDP 를 막거나 늦추는 방화벽에서는 TCP 로 돌아갈 수단이 없어 연결되지 않을 수 있습니다. — 확인됨: [WireGuard Known Limitations](https://www.wireguard.com/known-limitations/)
- ⚠ TCP MSS clamping(`--clamp-mss-to-pmtu`)은 TCP 에만 듣습니다. QUIC 이나 큰 UDP 트래픽은 여전히 단편화·폐기 위험이 남습니다. — 확인됨: [iptables-extensions(8) TCPMSS](https://man7.org/linux/man-pages/man8/iptables-extensions.8.html)
- ⚠ 원문은 터널 MTU 를 1420 으로 고정하면 안전한 것처럼 예시합니다. PPPoE(1492B)나 VXLAN·GENEVE 오버레이처럼 하위 MTU 가 작은 망에서는 여전히 넘칠 수 있습니다. — 확인됨: [wg-quick(8)](https://raw.githubusercontent.com/WireGuard/wireguard-tools/master/src/man/wg-quick.8) (MTU 자동 결정 부분만, PPPoE·오버레이 수치는 미확인)
- ⚠ 원문 설정 예시는 AllowedIPs 에 사내 IPv4 대역만 둡니다. 듀얼 스택 단말에서 IPv6 를 막거나 라우팅하지 않으면 IPv6 트래픽이 로컬 ISP 로 샐 수 있습니다. — 미확인
- ⚠ 비교표의 "WireGuard L3 (커널 공간 / eBPF 가속 가능)"과 "IP 가 바뀌어도 즉시 무중단 로밍"은 출처가 없습니다. 로밍은 상대가 새 주소에서 인증된 패킷을 받은 뒤에 갱신되는 구조라 "즉시"는 과장일 수 있습니다.
- ⚠ 캡슐화 오버헤드 "40~80바이트"와 설정 주석의 60B 는 IPv4 외부 헤더 기준입니다. 외부 헤더가 IPv6 이면 20바이트가 더 붙습니다.
- ⚠ 『UNIX Network Programming』 의 "18장 라우팅 소켓"은 판과 권에 따라 장 번호가 다를 수 있어 확인하지 않았습니다.
- ⚠ 『Zero Trust Networks』 2판(2023)의 장 번호는 확인하지 않았습니다.
- ⚠ Cloudflare·Tailscale 의 NAT traversal 글은 버전이 고정되지 않은 블로그 글이라 내용이 바뀔 수 있습니다.
