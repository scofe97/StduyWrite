## 요점

- SDD 필요성과 TDD 대비: 구현 대상이 불분명한 신규 도메인은 테스트 우선 작성이 어렵습니다. 자연어 스펙을 먼저 작성해 코드 생성과 검증을 이끌도록 구성합니다.
- 사고방식과 역할의 전환: 사람은 코드 작성자에서 아키텍처와 엣지 케이스를 검토하는 판단자로 이동합니다. 작업 규칙과 결정을 문서화해 에이전트 실패를 방지합니다.
- 5단계 루프와 주도권 분리: 설계와 교정은 사람이 주도하고 계획과 구현은 에이전트가 주도합니다. 결정 맥락을 ADR로 남겨 에이전트의 임의 구조 변경을 차단합니다.
- 좋은 스펙의 5대 필수 요소: 입출력 동작, 성공 기준(수용 기준), 제약, 경계(범위 밖 명시), 엣지 케이스 오류 처리 표를 갖추어야 합니다.
- 단계 파일 설계와 컨텍스트 격리: 마스터 스펙을 단일 세션 크기의 컴포넌트 스펙으로 나눕니다. 독립 세션에서 돌 수 있도록 선행 읽기 파일과 실행 수용 기준을 명시합니다.
- 상태 색인 파일과 세션 릴레이: 새 세션은 이전 맥락을 기억하지 못하므로 단계별 상태와 요약을 색인 파일에 기록합니다. 누적 요약을 다음 프롬프트에 전달합니다.



## 경고

- ⚠ `claude -p` 유료 과금 전환 오해: 원문은 `claude -p`가 API 과금제로 바뀌었다고 단정합니다(23·109행). 이는 공식 발표에서 보류된 계획이며 여전히 구독 한도 내에서 동작합니다. — 확인됨: [Claude Help Center Agent SDK](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)
- ⚠ 컨텍스트 사용량 문턱의 주관적 단정: 원문은 컨텍스트가 30~40%를 넘거나 7단계에 이르면 작업이 불가능하다고 단정합니다(101행). 특정 사용량 문턱 수치는 객관적 근거 없는 주관적 체감입니다. — 미확인: 화자의 체감 수치라 공식 근거 없음
- ⚠ AI 생산성에 대한 근거 없는 비유: 원문은 AI 하나가 엔지니어 100명보다 많은 코드를 쓴다고 주장합니다(53행). 정량적 데이터나 통계적 근거가 없는 과장된 수치 표현입니다. — 미확인: 화자의 과장 비유라 공식 근거 없음
- ⚠ 하네스 프레임워크 실존 여부 미확인: 자체 프레임워크와 스타 221개 지표는 자막 오인식으로 공개 저장소를 확인하지 못했습니다(37행). — 미확인: 공개 저장소 실존 여부 확인 불가
- ⚠ `caffeinate` 유휴 잠자기 방지 조건 누락: 원문은 `caffeinate` 실행만으로 잠자기가 방지된다고 설명합니다(119행). 옵션 없이 실행 시 디스플레이 없이 덮개를 닫으면 프로세스가 중단됩니다. — 미확인: 덮개 닫힘 동작은 man 문서에 없음
- 확인됨: Agent SDK 및 `claude -p`는 구독 한도로 유지되며 Max/Team 플랜에 월 API 크레딧이 추가되었습니다 ([공식 안내 문서](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)).
- 확인됨: 향후 헤드리스 실행의 기본값으로 `--bare` 모드가 적용될 예정입니다 ([공식 헤드리스 문서](https://code.claude.com/docs/en/headless)).
- 확인됨: 패스트 모드는 Opus 모델을 최대 2.5배 가속하지만 토큰당 단가가 높습니다 ([공식 패스트 모드 문서](https://code.claude.com/docs/en/fast-mode)).
- 확인됨: 세션 지속에 따른 추론 주의력 저하 현상은 공식 기술 문서에서 context rot으로 다룹니다 ([공식 세션 관리 기술 블로그](https://claude.com/blog/using-claude-code-session-management-and-1m-context)).
- 확인됨: Spec Kit은 원칙 정의 후 4단계 파이프라인으로 SDD를 구현한 오픈소스 도구입니다 ([GitHub Spec Kit 저장소](https://github.com/github/spec-kit)).
