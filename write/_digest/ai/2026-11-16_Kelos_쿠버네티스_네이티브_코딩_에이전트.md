## 요점

한 줄: 권한 확인 없이 혼자 도는 코딩 에이전트를 팀에서 안전하게 돌리려고, 코드 저장소·하네스·실행 자원·이벤트 트리거를 Kubernetes 커스텀 리소스 네 개로 선언하고 에이전트마다 격리된 파드에서 실행하는 프레임워크입니다.

- 풀려는 문제 둘:
  - 권한 확인을 끈 에이전트가 호스트 파일과 자격 증명에 닿지 않게 격리해야 합니다.
  - 기존 래퍼는 프롬프트만 넘겼고, 저장소·자원·하네스·도구 환경을 한 API 로 다루지 못했습니다.
- `Task`: 에이전트 한 번 실행입니다. 에이전트 종류·모델·프롬프트·Secret 인증을 적으면 독립 파드에서 돕니다. 일회성 `Job` 에 가깝습니다.
- `Workspace`: 저장소 URL 과 기준 브랜치입니다. init 컨테이너가 클론해 볼륨으로 붙이고, 여러 `Task` 가 한 `Workspace` 를 공유하며 병렬로 돕니다.
- `AgentConfig`: `CLAUDE.md`·`AGENTS.md` 지침, 스킬·플러그인, MCP 서버 설정을 묶은 재사용 하네스입니다.
- `TaskSpawner`: GitHub 이슈·PR·코멘트, Cron, Slack·Linear·Jira·웹훅을 지켜보다 조건이 맞으면 템플릿으로 `Task` 를 만듭니다.
- 에이전트 교체: 오케스트레이터와 에이전트 사이에 표준 컨테이너 인터페이스를 두어 Claude Code·Codex·Gemini·OpenCode·자체 에이전트를 스펙 한 줄로 바꿉니다.
- 통합: `TaskSpawner` 없이 GitHub Actions·Slack 봇·스크립트에서 `Task` YAML 을 바로 제출해도 됩니다.
- 자가 개발 루프: Kelos 저장소 자체를 Kelos 로 개발했습니다.
  - Cron 이 코드를 점검해 이슈를 만들고, 분류 에이전트가 거릅니다.
  - 작업 에이전트가 PR 을 열고, 리뷰 코멘트가 달리면 응답 에이전트가 고쳐 다시 커밋합니다. 병합은 사람이 합니다.
- 운영 지표(발표 시점 주장): 에이전트가 만든 이슈 약 287건 중 125건이 닫혔고, PR 약 360건 중 267건이 병합됐습니다. 메인테이너는 휴대폰에서 라벨과 코멘트만 남겼습니다.
- 쓰임새: 이벤트 기반 위임, 같은 `Workspace`·프롬프트에 모델·하네스만 바꾸는 에이전트 비교 평가, 기존 Prometheus·Grafana 로 관측, 대규모 병렬 실행입니다.
- 비용: 소규모 개인 작업에는 컨트롤 플레인 운영이 과합니다. 무한 루프와 토큰 과소비를 막을 실행 시간 제한·비용 한도가 필요합니다.

## 자료와 실습

- 자료:
  - [Custom Resources (Kubernetes 문서)](https://kubernetes.io/docs/concepts/extend-kubernetes/api-extension/custom-resources/): CRD 와 컨트롤러 구조의 공식 설명입니다. 정독 노트는 [Operator](../../08_cloud/book/kubernetes-patterns/28-01.Operator — CRD로 도메인 지식을 자동화하기.md) 입니다.
  - [Init Containers (Kubernetes 문서)](https://kubernetes.io/docs/concepts/workloads/pods/init-containers/): 클론·하네스 주입을 맡는 init 컨테이너 생명주기를 봅니다.
  - [MCP 명세](https://modelcontextprotocol.io/specification): `AgentConfig` 가 외부 도구를 붙일 때 쓰는 프로토콜입니다.
  - 『Programming Kubernetes』 1~4장: API 기초·client-go·커스텀 리소스 사용을 다룹니다. 최신 controller-runtime 문법은 공식 문서로 보완합니다.
  - 『Container Security』 4장·8장: 컨테이너 격리와 seccomp·gVisor·Kata 를 다룹니다. 정독 노트 [container-security](../../08_cloud/book/container-security/README.md) 가 있습니다.
  - 『AI Engineering』(Chip Huyen) 에이전트·평가 장: 에이전트 구조와 평가 파이프라인 기준을 잡습니다.
  - [Kubebuilder Book](https://book.kubebuilder.io/): Go 로 CRD 와 컨트롤러를 처음부터 짜는 공식 실습서입니다.
  - [Building effective agents](https://www.anthropic.com/engineering/building-effective-agents): 에이전트 설계 원칙을 다룬 글입니다.
  - 코드: kubebuilder `pkg/cli/` 와 생성된 `internal/controller/*_controller.go`(Reconcile 골격)를 봅니다. argo-workflows `workflow/controller/`(아티팩트 마운트와 병렬 파드)와 gvisor `runsc/`(OCI 인터페이스를 유지한 사용자 공간 커널)도 봅니다.
- 실습:
  - Level 1: `Job` YAML 하나로 `Task`+`Workspace`+`AgentConfig` 를 흉내 냅니다. init 컨테이너가 `emptyDir` 에 클론하고 ConfigMap 의 `CLAUDE.md` 를 복사합니다. 함정은 두 컨테이너의 UID 불일치로 생기는 `Permission Denied` 입니다. 완료: 에이전트가 주입된 규칙을 따르며 고친 `git diff` 를 출력합니다.
  - Level 2: Kubebuilder 로 `Workspace`·`AgentTask` CRD 와 `Job` 을 만드는 컨트롤러를 짭니다. 함정은 중복 Reconcile 의 `AlreadyExists` 와 `OwnerReference` 누락입니다. 완료: `AgentTask` 셋을 동시에 적용하면 파드 셋이 병렬로 돌고 `kubectl get agenttasks` 에 각 상태가 보입니다.
  - Level 3: 이슈 라벨·PR 코멘트 웹훅으로 `AgentTask` 를 만들고 PR 을 자동으로 엽니다. `runtimeClassName: gvisor` 와 출구 제한 NetworkPolicy 를 겁니다. 함정은 에이전트 자신의 코멘트가 다시 트리거를 거는 무한 루프입니다. 완료: 이슈 → PR → 리뷰 반영 → 병합이 손 개입 없이 한 바퀴 돕니다.
