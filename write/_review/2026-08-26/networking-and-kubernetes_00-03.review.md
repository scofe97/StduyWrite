### Q1. 정의 — 한 줄로 답할 수 있는가

**질문**: 프레임 헤더의 네 칸 `[출발지 MAC][목적지 MAC][출발지 IP][목적지 IP]` 중, 노트북에서 구글까지 가는 동안 **값이 바뀌는 칸과 안 바뀌는 칸**을 각각 대고, IP 칸과 MAC 칸이 답하는 질문이 어떻게 다른지 한 문장으로 정의하라.

**자기 답** (보고 답하지 말 것):

```
(여기에 자기 답 작성)
```

<details>
<summary>정답 보기 (먼저 자기 답 적은 뒤)</summary>

MAC 두 칸은 구간마다 통째로 새로 쓰이고, 목적지 IP는 끝까지 그대로다. 출발지 IP는 NAT 지점에서 한 번 바뀐다.

**IP 칸은 의도(어디로 가려는가), MAC 칸은 실행(지금 누구에게 건네는가)** 을 담는다. 둘은 같은 질문에 답하지 않는다 — 원본 §1 「IP는 방향이고 MAC은 배달입니다」.
</details>

**자가 점수 (0~5)**: __
*점수 기준: 0=완전 못 답함, 1=틀린 답, 2=부분 답+큰 누락, 3=핵심 맞음+세부 누락, 4=정확하지만 머뭇, 5=막힘 없이 정확*

### Q2. 동기 — 왜 이 개념이 등장했는가

**질문**: IP가 이미 기계를 구분하는데 MAC이 왜 또 필요한가. 컴퓨터를 막 켠 순간을 예로 들어 설명하라.

**자기 답**:
```
(여기에 자기 답 작성)
```

<details>
<summary>정답</summary>

컴퓨터를 막 켰을 때 IP가 없다. IP를 받으려면 "IP 하나 주세요"를 보내야 하는데 그 시점에 출발지 IP 칸에 적을 값이 없다. MAC은 랜카드에 이미 붙어 있어 이때 쓸 수 있다 — **IP만 있는 세계였다면 첫 통신을 시작할 방법이 없다.**

이유는 더 있다. 스위치는 IP 헤더를 아예 열지 않으므로 자기 층의 주소가 필요하고, 이더넷은 IP만이 아니라 ARP·IPv6도 나른다 — 원본 §1 「왜 셋 다 필요한가」.
</details>

**자가 점수 (0~5)**: __

---

### Q3. 메커니즘 — 그림 없이 말로 흐름을 설명할 수 있는가

**질문**: 도식을 보지 말고, `노트북 → 라우터A → 라우터B → 구글` 여정에서 **L2 구간이 몇 개**인지 세고, 라우터가 각 경계에서 무엇을 읽어 무엇을 정하는지 말로 설명하라.

**자기 답**:
```
(여기에 자기 답 작성)
```

<details>
<summary>정답</summary>

**L2 구간은 3개** — 라우터 하나가 늘 때마다 구간이 하나 는다.

전체 여정은 하나로 이어진 이동이 아니라 **L2 구간의 릴레이**다. 구간 안에서는 MAC만으로 배달이 끝나고, 경계마다 라우터가 **목적지 IP를 읽어 다음 구간의 상대 MAC을 정한다.** 읽은 IP를 헤더에 옮겨 적는 것이 아니다 — 옮겨 적으면 최종 목적지 정보가 사라져 더 갈 곳을 잃는다.

라우터는 두 구간에 양발을 걸치고 있어도 둘을 하나로 잇지 않는다. 프레임을 통과시키는 게 아니라 **겉봉을 새로 써서 내보낸다** — 원본 §1.
</details>

**자가 점수 (0~5)**: __

### Q4. 적용 — 실무 시나리오에 응용할 수 있는가

**질문**: 노트북을 켰는데 인터넷이 안 된다. `ip addr show`·`netstat -rn`·`arp -a`·`dig` 를 어떤 순서로 쳐서 어디가 끊겼는지 좁히겠는가. 각 명령이 무엇을 확인하는지 붙여라.

**자기 답**:
```
(여기에 자기 답 작성)
```

<details>
<summary>정답</summary>

아래에서 위로 올라간다.

1. `ip addr show` (macOS `ifconfig`) — 인터페이스에 IP가 붙었는가. 없으면 DHCP 단계에서 실패한 것 (§2·§3)
2. `netstat -rn` — 기본 경로(`0.0.0.0/0`)가 있는가, 게이트웨이 IP가 맞는가 (§3·§6)
3. `arp -a` — 게이트웨이의 MAC이 해석됐는가. 없으면 같은 동네 안에서 막힌 것 (§5)
4. `dig example.com +short` — 이름이 IP로 바뀌는가. 조회가 실패하면 그 뒤 모든 것이 시작조차 못 한다 (§7)

DHCP가 IP·마스크·게이트웨이·DNS 네 가지를 한 묶음으로 주므로, 1이 실패하면 2~4가 전부 무의미하다 — 원본 §3.
</details>

**자가 점수 (0~5)**: __

### Q5. 함정 — 흔한 실수 패턴을 진단할 수 있는가

**질문**: 허브에 4대가 붙어 있고 1번이 2번에게 유니캐스트 프레임을 보냈다. **몇 대에 도착하는가.** 그리고 그 답이 스위치로 바꾸면 어떻게 달라지며, "브로드캐스트가 비싸다"는 말이 어느 환경에서 성립하는가.

**자기 답**:
```
(여기에 자기 답 작성)
```

<details>
<summary>정답</summary>

허브에서는 **3대 전부**에 도착한다. 허브는 목적지 MAC 칸을 **아예 읽지 않아** 포트를 고를 근거가 없고, 전부에 복사한다. 골라내는 일은 **받는 쪽 랜카드**가 한다 — 자기 것이 아니면 받아서 버린다.

스위치로 바꾸면 유니캐스트만 1대로 좁혀지고, 브로드캐스트는 여전히 3대다(`ff:ff:ff:ff:ff:ff` 는 어느 포트의 MAC도 아니라 표에서 찾을 수 없다).

그래서 **"브로드캐스트가 비싸다"는 스위치 환경에서만 성립한다.** 허브에서는 유니캐스트도 어차피 전원에게 갔으므로 비용 차이가 없었다. 브로드캐스트가 나빠진 게 아니라 **스위치가 유니캐스트를 싸게 만든 것** 이다 — 원본 §4·§5.
</details>

**자가 점수 (0~5)**: __
