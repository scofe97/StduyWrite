## Q&A 7문제

### Q1. 정의 — HOL 블로킹 (04-02 §3)

**질문**: 크로스바·입력 큐 FCFS. 입력 A 의 맨 앞 패킷은 출력 1(입력 B 가 쓰는 중)로, 두 번째 패킷은 비어 있는 출력 2 로 간다. 두 번째 패킷은 나갈 수 있나. 현상의 이름, 라우터의 어느 큐, 58% 는 무엇의 문턱인가.

**자기 답**:

```
두 번째 패킷은 첫 번째가 못 나가니 지연된다. 이름은 HOL(발음 "핫 블로킹 오브 라인").
58% 는 지연율이 58% 이면 큐가 계속 누적되는 수치.
(되묻기 1 — 입력/출력 어느 큐, 58% 는 무엇을 무엇으로 나눈 값 → "입력 쪽 큐", "나가는 속도와 들어오는 속도의 차이?")
```

**점수 (0~5)**: **2.5** (채점: AI — 이름·뜻은 첫 자답에 도달, 회차 2 의 HTTP 층 HOL 오답을 교정. 큐 위치는 되묻기 1회 뒤. 58% 가 도착률/용량 비율이라는 것 미도달)

---

### Q2. 동기 — 두 평면 (04-01 §1 · 핵심 요약)

**질문**: (가) 패킷마다 표를 보고 출력 포트로 내보내는 일(100Gbps 에서 5.12ns 마다 하나) (나) OSPF·BGP 로 이웃과 대화하며 표를 채우는 일. 각각의 이름·평면·시간 척도·구현. "패킷 하나하나를 BGP 가 보낸다"는 무엇이 틀렸나.

**자기 답**:

```
가는 전송을 위해 라우팅한 것, 나는 광고에서 받아온 것. 평면은 모르겠다.
BGP 는 AS 간 라우터 정보를 공유하는 개념, OSPF 는 AS 내부.
(되묻기 1 — 공유받은 정보는 라우터 안 어디에 쓰이나, 5.12ns 안에 소프트웨어가 대화할 수 있나
 → "외부 AS 목적지로 가려면 어느 게이트웨이로 가는지 정보. 패킷은 게이트웨이 쪽에서 쏜다",
   "중간에 끼어들면 밀릴 텐데… 같은 시간에서 논다? 설명을 모르겠다")
```

**점수 (0~5)**: **1** (채점: AI — BGP·OSPF 가 나르는 정보는 정확하나 묻는 축(포워딩/라우팅 이름 · 데이터/제어 평면 · 나노초/초)은 되묻기 뒤에도 미도달. (가)를 "라우팅"이라 부름. 2026-09-14 드릴 "라우터 사이 통신을 BGP 로 보면 되나"에 이은 **두 번째 막힘**)

---

### Q3. 메커니즘 A — 최장 접두 일치 (04-01 §4)

**질문**: 주소 하나당 한 줄이면 몇 줄이 필요한가. 예시 표가 네 줄로 끝나는 기준은. 21비트 줄과 24비트 줄에 동시에 맞으면.

**자기 답**:

```
21억 개 정도. CIDR 로 매길 수 있어 줄이 압축된다.
(되묻기 1 — 어느 부분이 같은 것끼리 묶나, 두 줄에 맞으면
 → "앞자리가 많이 같을수록 정확", "/n 이면 2^(32-n) 개", "24비트 줄 — 더 구체적인 쪽")
```

**점수 (0~5)**: **3** (채점: AI — 첫 자답 방향(CIDR 압축)은 맞고 줄 수(2^31)는 틀림. 되묻기 1회로 접두·최장 접두 일치·블록 크기 산수 도달. 회차 2 (b) "무슨 말인지 모르겠음"에서 상승. `/31` 을 "현재 주소 +1"로 봄 — 블록은 2의 배수 경계에서 시작)

### Q4. 메커니즘 B — DF·단편화 (04-03 §1)

**질문**: 4,000바이트(헤더 20) IPv4 데이터그램, 다음 링크 MTU 1,500. (a) DF=0 이면 라우터는 무엇을, 조각 몇 개, 누가 되붙이나 (b) DF=1 이면 (c) 조각 하나가 사라지면.

**자기 답**:

```
(a) 조각 3개, 되붙이는 건 모르겠다 (b) 못 쪼개니 쪼개서 보내라고 전달해 줄 것
(c) TCP 가 시퀀스 번호로 유실을 알고 재전송을 요구할 것
(되묻기 1 → (a) "라우터는 보내기만 하니 목적지" (b) "쪼개지 말라고 클라이언트에게 보내는 것, 그 이상은 모르겠다"
 (c) "다 와야 올려 줄 수 있다. TCP 자체의 한계이고 UDP 로 해결")
```

**점수 (0~5)**: **2** (채점: AI — 조각 수만 첫 자답, 목적지 재조립은 되묻기 1회 뒤. DF=1 이면 **버린다**가 끝까지 안 나옴 — 드릴 "큰 데이터가 깨져서 보내진다"에 이은 **두 번째 막힘**. (c) 재조립을 TCP 의 일로 봐 UDP 가 해법이라 답함 — 층 혼동)

---

### Q5. 적용 — 상황형: 버퍼블로트 (04-02 §5)

**질문**: 집 공유기, 다른 기기는 쉬는데 한 사람이 큰 파일을 올리는 동안 게임 핑이 수백 ms 로 고정, 손실 0%. (a) 이름 (b) 왜 지연이 유지되나 (c) 버퍼를 키우자는 제안은 왜 해법이 아닌가.

**자기 답**:

```
(a) 백로그 초과? 이름은 모르겠다 (b) 버퍼가 크고 쌓인 양이 늘지도 줄지도 않아 지연
(c) 처리량이 늘지 않으면 버퍼를 키워도 손실만 안 날 뿐 지연은 그대로
(되묻기 1 — TCP 송신자는 언제 다음 세그먼트를 큐에 넣나 → "HTTP/1.1 기준 응답이 와야… HOL 이슈, HTTP/2 는 한 번에 보내지만 응답은 순서대로")
```

**점수 (0~5)**: **2** (채점: AI — (c) 방향 정확, (b) 는 "큐 길이 불변"까지. 되묻기 뒤 TCP ACK 를 HTTP 요청·응답으로 답해 층이 섞임 — 회차 2 Q1 과 같은 모양. **버퍼블로트 이름 2연속 미도달**)

---

### Q6. 진단 — 상황형: PMTUD 블랙홀 (04-04 §3)

**질문**: IPv6 서버 → 터널(안쪽 1,480) 너머 사용자. SSH 로그인·ping 은 되는데 큰 파일에서 멈춤, 서버 캡처에 1,500바이트 세그먼트가 같은 크기로 재전송되다 끊김. 무슨 일, 서버가 받았어야 할 것과 사라진 자리, 상태의 이름.

**자기 답**:

```
IPv4 헤더로 한 번 감싸 1,500 이 1,520 이 되니 크기 초과로 안 된다. 이름은 모르겠다.
(되묻기 1 — IPv6 라우터는 쪼개지 않는다면 그 패킷에 무엇을, 서버에 무엇을 / 같은 크기 재전송의 뜻
 → "버리고 ICMP 로 너무 크다고 보낸다", "보내야 할 것이 유실됐다")
(정답 공개 후 재진술: "알림이 서버에 닿지 않았다, 가장 흔한 자리는 방화벽 차단")
```

**점수 (0~5)**: **2.5** (채점: AI — 원인(캡슐화로 초과)은 첫 자답, 버리고 알린다·알림 유실은 되묻기 1회 뒤. 사라진 자리와 블랙홀 이름 미도달. 방화벽은 정답 공개 뒤 재진술이라 미채점)

---

### Q7. 함정 — 상황형: 서브넷 (04-03 §2)

**질문**: 라우터 셋이 점대점 링크로 이어지고 각 뒤에 호스트 망. (가) "서브넷은 호스트 망 셋뿐" (나) "R1 쪽 인터페이스에 `223.1.7.0`". 각각 무엇이 틀렸나, 서브넷 세는 절차.

**자기 답**:

```
처음: "모르겠다, 뭘 말해야 하지?" → 출제자가 7-1·7-2 로 나눠 재출제(질문 모호 — 되묻기로 세지 않음)
7-1 "양 끝 인터페이스는 같은 서브넷 — 링크도 서브넷이라 해야 하나? 맞는 것 같기도"
7-2 "예약된 주소라 인터페이스에 붙이면 안 되지 않나, 무엇에 쓰는지는 모르겠다"
(되묻기 1 — 라우터를 지우고 인터페이스만 남기면 몇 덩어리 → "질문 의도를 모르겠다, 인터페이스는 라우터 안에 있는 것 아닌가")
```

**점수 (0~5)**: **2** (채점: AI — 결론 둘(링크도 서브넷 · `.0` 불가)은 재출제 뒤 스스로 냄. `.0` 의 용도(네트워크 주소)와 **세는 절차** 미도달. 회차 2 0.5 에서 상승. "떼어 낸다"는 원문 비유가 물리적 분리로 읽혀 막힘)

재학습 순서 제안: **층 구분 표적 학습**(누가 무엇을 자르고 누가 되붙이나 — HTTP 메시지 · TCP 세그먼트(MSS) · IP 데이터그램/조각(MTU)) → 04-01 §1 두 평면 → 04-03 §1 DF → 04-02 §5 버퍼블로트(ACK 클록킹) → 04-03 §2 세는 절차. 그 뒤 회차 4 에 **회차 2 Q6 흐름 표 두 줄**(04-04 §5 부하 분산)을 넣는다.

### 정답 1

**HOL(Head-of-the-Line) 블로킹** — 자기 출력 포트가 비어 있는데도 줄 맨 앞의 다른 패킷에 막혀 기다리는 현상. **입력 포트의 큐**에서 일어난다. 원인은 속도가 아니라 목적지가 다른 패킷이 한 줄에 섞여 FCFS 로 꺼내지는 구조라, 패브릭을 빠르게 해도 남는다.

58% 는 **입력 링크의 도착률이 링크 용량의 58%** 에 이르는 순간부터 입력 큐가 무한히 길어진다는 문턱이다(닫힌 형태 `2 − √2`, 노트의 읽기). 입력 큐잉은 링크를 절반 남짓밖에 못 쓴다. 해법은 출력별로 큐를 가르는 **VOQ**(큐 N² 개 · 매 슬롯 짝짓기) — 원본 04-02 §3.

### 정답 2

| | (가) 포워딩 | (나) 라우팅 |
|---|---|---|
| 무엇 | 입력 링크 → 출력 링크로 옮기는 라우터 내부의 행동 | 출발지~목적지 경로를 정하는 망 전체의 과정 |
| 평면 | 데이터 평면 | 제어 평면 |
| 시간 척도 | 몇 나노초 | 몇 초 |
| 구현 | 대개 하드웨어 | 대개 소프트웨어 |

둘을 잇는 것이 포워딩 테이블이다. 라우팅은 가끔 표를 **채우고**, 포워딩은 매 패킷 표를 **읽는다**. BGP 는 패킷을 보내지 않는다 — 경로 정보를 받아 표에 반영할 뿐이고, 패킷은 각 라우터의 데이터 평면이 표를 보고 내보낸다 — 원본 04-01 핵심 요약 · §1.

### 정답 3

주소 하나당 한 줄이면 `2³²`, **40억 개가 넘는다**. 그래서 주소가 아니라 **접두(앞 N비트)** 를 본다 — 앞 21·24·21비트가 같은 범위를 한 줄씩 묶어 네 줄이 된다. 한 주소가 여러 줄에 맞으면 **가장 긴 접두**의 줄을 따른다(최장 접두 일치) — 원본 04-01 §4.

### 정답 4

(a) 라우터는 MTU 에 맞춰 쪼갠다 — 데이터 1,480 씩 조각 **3개**(1,500 · 1,500 · 1,040, 합 4,040). 같은 식별자, 오프셋 0·185·370, 마지막만 MF=0. 되붙이는 것은 **목적지만**.
(b) DF=1 이면 쪼개지 않고 **그 자리에서 버린다**(RFC 791 §2.3). 버렸다는 ICMP(타입 3 코드 4)가 송신자에게 가면 송신자가 크기를 줄인다 — 04-04 §3 경로 MTU 발견.
(c) 조각 하나를 잃으면 **전부 잃는다**. 목적지는 타이머(권고 15초)가 끝나면 받은 조각까지 버리고, IP 에는 재전송이 없어 TCP 가 세그먼트를 통째로 다시 보낸다. 재조립은 **IP 층**의 일이라 UDP 도 같은 손실을 겪는다(앱이 떠안음) — 원본 04-03 §1.

> 세션 중 보충: 자르는 층이 셋이다 — HTTP(메시지), TCP(바이트 흐름을 MSS 로 세그먼트화, 보통 1,460 = 1,500 − 20 − 20), IP(데이터그램을 다음 링크 MTU 로 조각화, IPv4 도중 라우터만). 붙이는 쪽도 다르다 — IP 는 한 데이터그램의 조각을 식별자·오프셋으로, TCP 는 여러 세그먼트를 시퀀스 번호로.

### 정답 5

(a) **버퍼블로트**. (b) **ACK 클록킹** — 큐에서 세그먼트 하나가 나가 서버에 닿으면 그 TCP ACK 가 한 RTT 뒤 돌아오고, 송신자는 곧바로 새 세그먼트 하나를 같은 큐에 넣는다. 나간 만큼 들어와 큐 길이가 줄지 않는다 — 파이프는 꽉 차 처리량은 좋은데 큐잉 지연이 일정하게 지속되고, 넘치지 않으니 손실도 없다. (c) 버퍼를 키우면 늘 차 있는 줄만 길어져 지연이 는다. 줄이면 링크가 놀 위험이 돌아온다. 해법은 크기가 아니라 **차기 전에 알리는 AQM**(DOCSIS 3.1) — 원본 04-02 §5.

### 정답 6

터널 입구는 1,500 을 **버리고** 서버에 **ICMPv6 Packet Too Big**(타입 2, 다음 링크 MTU 1,480 기재)을 보낸다. 서버가 그걸 받아 줄이는 절차가 **경로 MTU 발견(PMTUD)**. 같은 크기 재전송은 알림이 **닿지 않았다**는 뜻이고, 흔한 자리는 모든 ICMP 를 막은 방화벽(그 밖에 ICMP 를 안 보내는 라우터, 출발지만 보고 버리는 상태 추적 방화벽, 연결 없는 서버로 보내는 ECMP 앞단). 핸드셰이크는 끝났는데 큰 데이터부터 멈추는 이 상태가 **블랙홀 연결**(RFC 8201), 알림을 못 받는 경우가 **ICMP 블랙홀**. 대처는 ICMP 허용 · MSS 클램핑 · PLPMTUD · MTU 1280 고정 — 원본 04-04 §3.

### 정답 7

**세는 절차**: 각 인터페이스를 붙은 호스트나 라우터에서 떼어 내어 고립된 망의 섬을 만든다 — 그 섬 하나하나가 서브넷이다. 라우터 몸통을 지우면 인터페이스가 각자 선에 매달려 남고, 호스트 망 셋 + 라우터 사이 링크 셋 = **여섯**(Figure 4.20).

(가) 라우터 사이 링크도 섬이라 서브넷이다. (나) 호스트 자리가 전부 0 인 `223.1.7.0` 은 **서브넷 자체를 가리키는 주소**라 인터페이스에 붙일 수 없다(RFC 1812, 전부 1 은 브로드캐스트). 원서 그림이 R1 에 이 주소를 적은 것이 원문 정오다 — 원본 04-03 §2.
