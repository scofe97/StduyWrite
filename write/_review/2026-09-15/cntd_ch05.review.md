## Q&A 7문제

> 축 배분: 메커니즘 2 · 동기 1 · 적용 1 · 진단 2 · 함정 1. 정의 축은 Q1 (나) 로 흡수. Q4~Q7 은 상황형.

### Q1. 메커니즘 — 링크 하나가 끊긴 SDN 망 (05-03 §4)

**질문**: 간선 s1-s2, s1-s3, s1-s4, s2-s4, s3-s4 인 SDN 망에서 최단 경로 앱이 돈다. s1-s2 가 끊겼다. (가) 흐름 표가 바뀌는 스위치를 모두 꼽고 각자 무엇이 달라지나. (나) s1 이 장애를 알아챈 순간부터 표가 고쳐지기까지 누가 누구에게 알리고 계산은 어디서 일어나나.

**자기 답**:

```
(가) s3, s4 — 2개 링크 모두 s1 을 거쳐 s2 로 갈 수 있기 때문
(나) s1 이 알아차리고 s3, s4 에 전파하지 않을까
```

되묻기 1((가) s1→s2 패킷은 이제 어디를 거치나 / (나) s1 이 s3·s4 에 알리면 계산은 누가, 다익스트라 주체는 어디) → (가) `1-3-4-2`·`1-4-2` 두 우회로 발견, (나) "노드마다 한 번씩 하는 것 아닌가"로 빗나감.
되묻기 2((가) 최단 경로라면 어느 길, 그 길 위 스위치의 일이 달라지나 / (나) 회차 1 Q1 에서 스스로 한 "컨트롤러가 만들고 라우터는 전송만" 과 대조) → (나) "컨트롤러가 모두 계산해 전파" 로 도달. (가) `1-4-2` 선택은 맞았으나 "s4 는 4-2 직통이 있으니 신경 쓰지 않는다" 로 미도달.

**점수 (0~5)**: **1** (채점: AI — (나)는 되묻기 2회로 도달, (가)는 우회로까지만. 흐름 표가 *지나가는 남의 패킷* 규칙도 담는다는 점이 없어 s4 를 뺐다. 회차 1 은 0)

### Q2. 동기 — 인터넷 전체를 OSPF 하나로 돌리면 안 되나 (05-02 §1)

**질문**: 동료가 "OSPF 는 다익스트라로 최소 비용을 정확히 푸니 인터넷 전체를 OSPF 로 돌리면 BGP 가 필요 없지 않나"라고 묻는다. 원문의 이유 셋으로 답하라.

**자기 답**:

```
모든 인터넷으로 하면 모든 목적지를 계산하기에 비용이 매우 크고,
변경될 때마다 연관 스위치들에게 통보를 해줘야 해 비용이 매우 클 것 같습니다.
```

첫 자답에 규모. 되묻기 1(AS 는 주인이 다른 회사, OSPF 는 주어진 비용에서 최소 비용 경로를 찾는 장치만 제공 — 최소 비용 말고 무엇이 끼어드나) → "정책. 특정 AS 를 거치지 않게" 로 도달.
되묻기 2(AS 안에서는 무엇을 쫓을 수 있고, AS-PATH 만으로 그걸 잴 수 있나) → "AS 사이 광고는 한 라우터에서만 받고 내부에 공유해야 한다"(iBGP 필요 이유) 로 빗나감.

**점수 (0~5)**: **2** (채점: AI — 규모 첫 자답, 정책 되묻기 1회, 성능 미도달. 회차 1 에 이어 **설계 이유를 물었는데 BGP 동작(회차 1 TCP 179, 이번 iBGP 전파)으로 답함**이 두 번째. 회차 1 은 1)

### Q3. 메커니즘 (부재) — NEXT-HOP 이 가리키는 서브넷이 OSPF 에 없으면 (05-02 §4)

**질문**: 1b 가 iBGP 로 `x 는 AS2 AS3 로, NEXT-HOP 10.0.0.2` 를 받았는데, 1c 가 자기에게 붙은 `10.0.0.0/30` 을 OSPF 로 알리지 않는다. 1b 는 `(x, 인터페이스)` 를 만들 수 있나, 어디서 끊기나.

**자기 답**:

```
만들 수 없습니다. 1c 가 정확히 어디 있는지는 모르겠지만 1c 를 OSPF 로 알리지 않으면 1b -> 1c 가 안 되기 때문.
```

1c 위치(AS1 게이트웨이, 2a 와 `10.0.0.0/30` 링크)는 회상 대상이 아니라 제공. 되묻기 1(1c 다른 링크는 광고되니 1c 라우터까지 길은 알 수 있다 — 그래도 끊긴다면 1b 가 OSPF 쪽에서 찾던 것은 무엇이고 어느 쪽 답이 비나) → "1c 까지 길은 알아도 1c 로 왜 가야 하는지를 모른다" 로 도달.

**점수 (0~5)**: **3** (채점: AI — 되묻기 1회로 두 답을 잇는 다리가 끊긴다는 핵심 도달. 찾는 대상이 *NEXT-HOP 주소가 든 서브넷*이라는 점, 비는 쪽이 *OSPF 의 답*이라는 점은 명시하지 못함. 정답 공개 뒤 재진술에서 "iBGP 는 AS 안 각 라우터로 가는 경로를 알려 준다" 는 오해가 나와 교정함)

### Q4. 적용 — 상황형: 모두가 같은 박자로 옮겨 가면 (05-01 §3)

**질문**: 클라이언트 수백 대가 10초마다 "지금 부하가 더 낮은 경로(A/B)"를 재서 옮긴다. 트래픽이 A·B 를 통째로 오간다. (가) 왜인가. (나) "시작 시각만 다르게 두면 해결"은 충분한가, 부족하면 무엇을.

**자기 답**:

```
(가) 트래픽은 시간에 따라 변하기 때문. A 가 혼잡하지 않아 거기로 라우팅하면 일정 시간 뒤 A 가 혼잡, 이후 B 가 혼잡되는 사이클
(나) 모르겠음
```

되묻기 1((가) 한 대가 옮기는 것과 수백 대가 같은 박자에 같은 측정값을 보고 옮기는 것의 차이 / (나) 시작 시각 분산이 노린 효과와 그것이 한 시간 뒤에도 남으려면) → (가) "모두 똑같이 측정해 한곳의 혼잡도 폭증" 도달, (나) "판단 시점을 나눠 쏠림 방지(매번 적절히 나눠야)" 절반.
되묻기 2((나) 처음 한 번 준 어긋남이 '매번' 보장되나, 안 되면 회차마다 판단 시점을 어떻게) → 시뮬레이션으로 "결국 한 번씩 스왑되는 구간이 생긴다" 까지. 자기 동기화·무작위화 미도달.

**점수 (0~5)**: **2** (채점: AI — (가) 되묻기 1회, (나) 되묻기 2회로 절반)

### Q5. 진단 — 상황형: ICMP 가 원본을 얼마나 담았나 (05-04 §2)

**질문**: 내가 보낸 UDP 패킷은 IP 20 + UDP 8 + 데이터 12 = 40B. 돌아온 `time exceeded` 가 `length 36` 과 `length 48`. (가) 각 라우터는 원본을 얼마나, 어디까지 담았나. (나) 36 짜리만으로 알림을 넘길 소켓을 가려낼 수 있나, 무엇이 단서인가.

**자기 답**:

```
(최초 출제) (가) 2개 패킷을 보고 TTL 이 얼마나 되었는지 알아내라는 건가? (모르겠음) / (나) 어느 소켓이 보낸 탐침이라는 게 무슨 말인지 모르겠음
   → 출제자 책임. "인용"·"소켓" 정의와 ICMP 메시지·원본 구조 그림을 보강해 재출제
(재출제) (가) IP, UDP, 데이터 내용 같다. 보통 UDP 까지 기록하지 않을까, 데이터는 안 볼 거니까 / (나) 36 인 경우가 뭔지 모르겠다
```

되묻기 1((가) length 에서 ICMP 헤더 8 을 빼 복사본 크기를 원본 그림에 대 보라) → "28, 40. IP+UDP, IP+UDP+데이터" 도달. (나) 는 (가) 뒤 재질문 → 첫 자답 "UDP 헤더의 포트와 IP 헤더의 IP 정보겠지?" 로 도달.

**점수 (0~5)**: **3** (채점: AI — (가) 되묻기 1회, (나) 첫 자답 정확하나 머뭇. 출제 누락으로 인한 재출제는 감점하지 않음)

> **세션에서 나온 요청**: "탐침" 이라는 낱말이 헷갈린다 — 대화와 노트 전반에서 "패킷" 으로. 같은 날 cntd 폴더 노트에 반영 중.
> **질문**: "ICMP 헤더 설명은 어디 있나" — 노트에 구조 설명이 없고 흩어진 두 줄뿐이었다(05-03 §5, 05-04 §2). 같은 날 05-04 §2 에 원문 밖 보충으로 반영 중.

### Q6. 함정 — 상황형: 같은 주소를 쓰는 서버 셋 앞에 도착한 Packet Too Big (05-02 §5 콜아웃)

**질문**: 데이터센터 마지막 라우터 뒤 S1·S2·S3 가 같은 IP 하나를 쓴다. 라우터는 TCP 를 IP+포트로, ICMP 를 IP 로만 해시한다. 사용자–S2 TCP 연결 중 S2 의 큰 패킷이 중간 라우터에서 버려져 Packet Too Big 이 돌아온다. (가) 알림이 S2 에 도착한다고 보장되나, 목적지 주소부터. (나) 닿지 못하면 무엇이 깨지나.

**자기 답**:

```
(가) 못합니다. ICMP 거부는 IP 만 있기에 IP 가 같으면 정상 라우팅이 힘들 것
(나) 패킷을 보냈는데 성공 여부를 못 받고 그냥 손실 처리
+ 전제 질문: 서버 3개가 어떻게 같은 IP 를 쓰나? IP 는 독립 개념 아닌가?
```

전제(애니캐스트: 라우터는 같은 주소 광고 여럿을 한 목적지로 가는 길 여럿으로 여긴다)를 채점 전에 설명. 되묻기 1((가) 알림의 목적지 주소, 해시에서 빠지는 값 / (나) 줄이라는 알림을 못 받은 TCP 는 재전송 크기를 어떻게) → (가) "포트가 빠진다" 도달, 목적지 주소는 "그 라우터에 오기 전 라우터의 주소" 로 오답. (나) "줄여서 보내라는 알람이 뭐지?" — Packet Too Big 개념 부재. 전제 공백이 커서 되묻기 2 없이 전제 설명 후 정답 공개.
정답 뒤에도 "각 서버 IP 는 독립이고 사이에 IP 가 같은 공통 라우터가 있다는 흐름인가?" 로 전제가 서지 않음을 확인.

**점수 (0~5)**: **1** (채점: AI — 되묻기 1회로 포트 누락만. 회차 1 Q7(애니캐스트와 연결 상태) 2 에 이어 **2연속 ≤ 2** → 재학습 트리거)

### Q7. 진단 — 상황형: 흐름 표에 한 방향만 넣었을 때 (05-04 §3)

**질문**: OVS 에 `in_port=1,actions=output:2` 한 줄. ns1→ns2 ping 100% 손실, `ip neigh` 는 `FAILED`, 계수기 `n_packets=3, n_bytes=126`. (가) 어느 방향에서 무엇이 끊겼고 ping 은 나갔나. (나) "ns2 가 없다" 와 "ns2 는 답했는데 스위치가 버렸다" 를 스위치에서 어떻게 가르나.

**자기 답**:

```
ns1 -> ns2 ip 라우팅에 실패한 거 아닌가? 패킷 3개, 크기 126, 1포트에서 2로 나간다고 적혀 있다
(in_port 1 과 actions=output2 가 실제로 뭘 하는 건가?)
```

흐름 표 한 줄 = 일치 조건 + 동작, 일치 없으면 폐기, 계수기는 줄 단위 — 를 채점 전에 설명. 같은 망이라 라우터가 없다는 전제 교정. 되묻기 1(ARP 는 묻고 답하는 절차 — ns2 의 답은 몇 번 포트로 들어오고 맞는 줄이 있나) → "포트 2 로 들어오는데 맞는 줄이 없어 버려짐?" 도달.
이어 (가) 마지막 조각(ping 은 나갔나, 126/3 과 이더넷 14·ARP 28)과 (나) 재질문 → (가) "ARP 를 쏘는 것 자체가 IP 로 MAC 조회이니 쐈을 것, 그래서 실패 기록" — 나간 것이 ARP 뿐이라는 계산 미도달. (나) "라우터에서 매칭돼서 전송했나 안 했나 값?" — 방향만.

**점수 (0~5)**: **2** (채점: AI — (가) 핵심 되묻기 1회, 마지막 조각 미도달, (나) 미도달)

## 정답 (자답 후 펼치기)

> 일곱 문항에 *먼저 자답한 뒤* 읽는다.

### 정답 1 (05-03 §4 「링크 하나가 끊어지면」)

(가) **s1·s2·s4.** s1 은 s2 행 패킷을 s4 를 거쳐 보내고, s2 는 s1 이 보낸 패킷을 s4 에게서 받기 시작하며, **s4 는 s1 이 s2 로 보내는 패킷을 날라야 한다** — 장애를 겪지 않았는데 표가 바뀐다. s3 는 우회로 `s1-s4-s2` 를 지나지 않아 그대로다.

(나) 여섯 걸음 — s1 이 OpenFlow port-status 로 **컨트롤러에게만** 알림 → 컨트롤러가 링크 상태 DB 갱신 → 미리 등록한 라우팅 앱이 알림 수신 → 앱이 새 최소 비용 경로 계산(**스위치 밖 별도 앱**) → 흐름 표 관리자와 고칠 표 결정 → OpenFlow 로 **s1·s2·s4 를 한꺼번에** 갱신. **조율이 프로토콜의 수렴이 아니라 한 곳의 계산이 된다.**

원문 밖 보충: s3→s2 는 s1 경유·s4 경유가 동점(2홉)이라, 끊기기 전 s1 쪽을 골라 두었다면 s3 표도 바뀔 수 있다. 원문은 동점을 따지지 않는다.

### 정답 2 (05-02 §1 「안과 밖에 서로 다른 프로토콜을 쓰는 이유」)

1. **정책** — AS 사이는 정책이 지배한다(특정 AS 회피, 통과 트래픽 통제). AS 안은 같은 관리 아래라 정책 비중이 작다.
2. **규모** — AS 사이는 확장성이 결정적이다. AS 안은 커지면 AS 둘로 쪼개면 된다(OSPF 영역도 같은 처방).
3. **성능** — AS 사이는 정책 중심이라 경로 품질이 부차적이다. **AS 홉 수 말고는 비용이라는 개념 자체가 없다.** AS 안은 정책 걱정이 적어 성능에 집중한다.

**AS 안은 성능을 쫓고 AS 사이는 정책을 집행한다.**

### 정답 3 (05-02 §4 「NEXT-HOP 이 다리인 이유」)

만들 수 없다. **BGP 는 어느 출구로 나가는지를, OSPF 는 그 출구까지 어떻게 가는지를 답하고, 두 답이 NEXT-HOP 주소 하나에서 만난다.** 정상 흐름은 iBGP 경로 수신 → OSPF 로 `10.0.0.0/30 은 1c 에 붙어 있다` 수신 → 1b 가 NEXT-HOP `10.0.0.2` 를 들고 OSPF 쪽에서 **그 주소가 든 서브넷**을 찾음 → `(x, I)`. 이 문항은 셋째 걸음에서 끊긴다 — BGP 의 답은 있는데 OSPF 쪽에서 `10.0.0.2` 가 든 서브넷을 찾지 못해 "어느 인터페이스로" 가 빈다. 1c 라우터까지 길을 알아도 소용없는 것은 찾는 대상이 라우터가 아니라 주소가 든 서브넷이기 때문이다. (`10.0.0.0/30`·`I` 는 노트의 읽기.)

### 정답 4 (05-01 §3 「부하를 비용에 넣으면 진동합니다」)

(가) 비용이 부하를 따라가면 **모두가 같은 값을 보고 같은 판단을 내려 다 같이 옮기고, 옮겨 간 자리가 그 순간 비싸진다.** "지금 싸다" 가 "곧 비싸진다" 와 같은 말이 된다.

(나) 막는 방법 둘 중 비용이 부하에 기대지 못하게 하는 쪽은 라우팅 목적 하나를 버리는 셈이라 받아들이기 어렵고, 동시에 돌지 않게 하는 쪽이 현실적이다. 그런데 **처음에 서로 다른 시각에 돌기 시작해도 결국 저절로 맞춰진다**는 사실이 관측돼 있다(**자기 동기화**). 그래서 실제 대처는 **광고를 보내는 시각을 무작위로 흔드는 것** — 주기에 무작위를 섞는다. 캐시 만료 몰림·재시도 타이머 맞물림도 같은 얼개다.

### 정답 5 (05-04 §2 「ICMP 가 인용하는 것 — 36 과 48」)

(가) `10.204.127.21` 의 36 = 8 + (IP 20 + UDP 8) — RFC 792 최소치 그대로. `192.168.0.1` 의 48 = 8 + (IP 20 + UDP 8 + 데이터 12) — 원본 통째로. 같은 트레이스에 둘이 함께 나와 **라우터마다 정책이 다르다**는 것을 보인다. (05-03 §5: 최소치는 RFC 792, RFC 1812 는 576 바이트를 넘지 않는 선에서 가능한 한 많이 담으라고 권한다.)

(나) 가려낼 수 있다. 최소치는 IP 헤더 전체 + 앞 8바이트이고, UDP 면 헤더 전체, TCP 면 출발지 포트 2 + 목적지 포트 2 + 순서 번호 4 다. **어느 경우든 포트 둘이 반드시 들어간다** — 그것이 8 이라는 수의 이유이고, 포트가 있어야 받은 쪽이 자기 어느 소켓의 문제였는지 안다.

### 정답 6 (05-02 §5 콜아웃 · 06-05 §3 · 04-04 §3)

전제: IP 애니캐스트는 여러 서버에 **같은 IP 주소**를 주고 각자 광고하게 한다. 라우터는 같은 주소 광고 여럿을 **한 장소로 가는 여러 경로**로 여기고 하나를 고른다(05-02 §5). 데이터센터 안에서는 마지막 라우터가 ECMP 해시로 서버 여럿에 흐름을 나누는 제한된 형태로 쓴다(RFC 7690).

(가) 보장되지 않는다. Packet Too Big 의 **출발지는 버린 중간 라우터, 목적지는 큰 패킷을 보낸 쪽 = 서버 셋이 함께 쓰는 주소**다(06-05 §3, RFC 4443 §2.2). 마지막 라우터는 ICMP 를 IP 로만 해시하므로 TCP 연결을 S2 로 보내던 **포트가 빠진다.** 원래 흐름으로 식별되지 않아 그 흐름과 같은 다음 홉으로 해시될 가능성이 낮다(05-02 §5 콜아웃, Cloudflare 사례). 포트는 ICMP 헤더가 아니라 **인용된 원본 안**에 있다.

(나) 알림이 S1·S3 에 떨어지면 S2 는 줄이라는 말을 못 들어 **같은 크기로 재전송만** 한다. 핸드셰이크는 되고 큰 데이터부터 멈추는 **블랙홀 연결**이 된다(04-04 §3). 재전송은 타임아웃마다 간격을 두 배로 늘리며 물러서고(03-03), RFC 2923 의 트레이스에서는 같은 크기로 열세 번 나간 뒤 리셋됐다(04-04 §3).

### 정답 7 (05-04 §3 「한 방향만 넣으면 ARP 에서 끊깁니다」·「답이 왔는지 아무도 없었는지는 계수기가 가립니다」)

(가) 끊긴 층은 ICMP 가 아니라 **ARP** 다. 흐름 표의 줄은 방향이 있다 — `in_port=2` 줄이 없으니 ns2 의 ARP 답이 포트 2 로 들어오다 버려진다. ns1 은 `FAILED`, **ping 은 시작조차 못 했다.** `126 / 3 = 42` = 이더넷 14 + ARP 28 이므로 나간 셋은 전부 ARP 요청이다. 둘은 스위치 하나에 붙은 같은 망이라 IP 라우팅은 등장하지 않는다.

(나) 돌아오는 방향에 줄을 넣고 **그 줄의 계수기**를 본다. `priority=200,arp,in_port=2,actions=drop` → `n_packets=2, n_bytes=84`. **버리는 줄이라도 맞은 것은 센다** — ARP 응답 둘이 도착했고 스위치가 버렸다. ns2 가 없었다면 0. 한쪽 끝에서 본 침묵으로는 못 가르고 **중간에서 센다**(§2 `* * *` 와 같은 규칙).
