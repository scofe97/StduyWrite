# 드릴 세션 프롬프트

---

> 세션을 열 때 아래 한 덩어리를 그대로 붙여 넣습니다. 평일과 주말, 새 회차와 이어받기를 알아서 가릅니다.

## 쓰는 법

> 프롬프트는 하나입니다. 상황마다 다른 것을 고를 필요가 없습니다.

새 세션을 열고 아래 블록을 붙여 넣으면 됩니다. 오늘 몫을 뽑고 파일을 만드는 데까지가 한 덩어리이고, 그다음은 대화로 진행합니다.

날짜를 지정하고 싶으면 프롬프트 끝에 한 줄 덧붙입니다. 지난 회차를 이어받을 때도 같은 프롬프트를 씁니다. 이미 만들어진 파일이 있으면 새로 만들지 않고 빈칸부터 잇습니다.



## 통합 프롬프트

> 아래 블록을 그대로 복사해 붙여 넣습니다. 수정할 곳은 없습니다.

```bash
runners-high/write/_drill/README.md 와 curriculum.md 를 먼저 읽어라.

1. 오늘이 평일이면 지면 모드, 주말이면 실습 모드다.
2. 오늘 날짜 파일이 이미 있으면 새로 만들지 말고 빈칸부터 이어간다.
3. 없으면 curriculum.md 에서 오늘 몫을 뽑는다.
   - 지면 모드: 상태가 미출제이거나 재출제 날짜가 오늘 이전인 문항 2~3개.
     한 계층에 몰지 말고 섞어라. 근거가 — 인 문항은 우선순위를 낮춘다.
   - 실습 모드: 재현 칸이 kind·docker·로컬 인 문항 중
     이번 주에 점수 3 이하였던 것 1~2개.
4. _template/drill-template.md 로 오늘 파일을 만들고 증상만 채운다.
   대조 블록은 함께 쓰되 접힌 채로 둔다.
5. 증상에 원인을 가리키는 단어를 넣지 마라. 다 쓴 뒤 대조를 닫고
   증상만 읽어 답이 유추되면 다시 써라.
6. 파일 경로를 알려주고 멈춰라. 내가 세 칸을 채운다.

내가 답한 뒤에는:
- 정합성만 본다. 완전한 해설을 붙이거나 다음 문항을 미리 설명하지 마라.
- 내가 짚지 않은 것이 있으면 되물어라. 대신 답하지 마라.
- 한 문항씩 처리한다. 여러 문항을 한 응답에 몰아 채점하지 마라.
- 점수는 내가 매긴다. 네가 대신 매기지 마라.

내가 스킵이라고 하면:
- 근거를 대라거나 설득하지 마라. 즉시 같은 계층의 다른 문항으로 바꾼다.
- curriculum.md 상태를 스킵으로 바꾸고 날짜를 적는다.
- 하루에 스킵이 2개를 넘으면 그날은 A 와 B 계층에서만 뽑는다.

회차가 끝나면:
- 점수 3 이하 문항을 _mistakes.md 에 이관한다.
- 점수 2 이하 문항은 curriculum.md 상태를 재출제로 바꾸고 사흘 뒤 날짜를 적는다.
- README.md 진행 표에 한 줄 추가한다.
- 같은 원인이 세 번 반복됐으면 _mistakes.md 반복 패턴 표에 올리고
  어느 노트를 보강해야 하는지 알려라.
```



## 실습 모드에서 지킬 것

> 주말 회차에만 해당합니다. 명령은 제시하되 실행은 직접 합니다.

재현 명령을 대신 실행하지 않습니다. 환경이 준비됐는지 확인하는 명령만 예외입니다. 손으로 쳐 보는 것이 실습의 목적이므로 대신 치면 남는 것이 없습니다.

실행 전에 예측을 먼저 적습니다. 예측과 실제가 갈리는 지점이 실제로 배우는 자리입니다.

고친 뒤에는 되돌려서 원래 증상이 다시 나오는지 확인합니다. 고쳤다는 사실만으로는 무엇이 원인이었는지 고정되지 않습니다. 되돌렸을 때 증상이 재현되어야 그 변수가 원인이었다고 말할 수 있습니다.
