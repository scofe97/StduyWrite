# docs/orca
---
> ADE(Agentic Development Environment) ORCA를 격리·관측·조율 세 축으로 정리합니다. 원서는 Windows·v1.4.176 기준이고 이 노트는 macOS·v1.4.188에서 다시 밟았습니다. 원서와 갈리는 자리는 감추지 않고 그때마다 적었습니다.

## 무엇을 다루는가

> 에이전트를 하나 쓸 때는 없던 문제가 둘로 늘리는 순간 세 가지 생깁니다. ORCA는 그 셋에 하나씩 대응하는 도구이고, 이 폴더는 그 대응이 실제 명령과 상태 모델로 어떻게 떨어지는지를 봅니다.

`11_AI/` 본문의 [`02-05.AI Agentization`](../../02-05.AI%20Agentization%20—%20워크플로우와%20에이전트%20사이.md)과 [`02-02.Harness Engineering`](../../02-02.Harness%20Engineering%20—%20모델을%20감싸는%20오케스트레이션%20층.md)이 개념을 다뤘다면, 여기는 그 개념이 제품으로 구현됐을 때 무엇이 실제로 어렵고 어디서 새는지를 봅니다.

원서는 「[ORCA 따라하기](https://wikidocs.net/book/20731)」(이창근, wikidocs)입니다. 공개 1~10장과 부록A~C, 유료 전자책 편 11~13장의 미리보기까지 59페이지를 근거로 삼았습니다.



## 기준 버전과 근거 등급

> 원서 자신이 페이지마다 `[검증]`과 `[참고]`로 실측과 문서 대조를 나눠 두었습니다. 이 노트는 거기에 한 칸을 더합니다.

| 등급 | 뜻 |
|------|-----|
| 실행 | 이 맥북 설치본(v1.4.188)에서 직접 실행해 확인 |
| 스키마 | `orca agent-context --json` 으로 존재와 플래그만 대조 |
| 원서 | 원서 서술만 있고 이쪽에서 확인하지 못함 — 본문에 "원서 기준"으로 표시 |

원서는 v1.4.176 기준이고 명령이 223개였습니다. 이 노트의 설치본은 **v1.4.188에 232개**입니다. 열두 버전 사이에 고쳐진 것과 그대로인 것이 갈렸고, 그 대조를 본문 곳곳에 표로 남겼습니다.

가장 큰 변화는 원서가 공개 편에 정오까지 실었던 `orca click` 결함이 **해소됐다**는 점입니다. 반대로 `cookie delete`의 범위 문제, `intercept`의 무동작, 가려진 창에서의 스크린샷 실패는 그대로였습니다.

## 이 노트가 다루지 않는 것

> 확인 수단이 없어 비운 자리를 밝혀 둡니다. 중요도가 낮아서가 아닙니다.

이슈 연동(`linear` 27개)은 워크스페이스가 없어 통째로 비웠습니다. 모바일 에뮬레이터는 붙어 있는 기기가 없어 목록 조회까지만 봤습니다. 원격 런타임과 환경 레시피는 두 번째 기기와 클라우드 계정이 필요해 개념까지만 다뤘습니다.

컴퓨터 유즈는 접근성 권한을 승인해야 화면을 읽을 수 있는데, 그것이 시스템 보안 설정이라 이 노트에서는 승인하지 않았습니다. 승인 이전 단계까지만 확인했습니다.

유료 전자책 편(11~13장, 부록D·E)은 공개된 미리보기 범위만 반영했습니다. 지시 설계의 본론, 복구 절차 상세, 고급 브라우저 자동화는 그쪽에 있습니다.



## 실습 저장소

> 본문 예제는 `write/` 밖의 연습용 저장소에서 돌렸습니다.

홈 아래 `orca-practice`에 작은 git 저장소를 만들어 워크트리 생성·삭제, 터미널 대기, 오케스트레이션 흐름, 브라우저 조작을 확인했습니다. 학습 문서에는 이론과 검증 기록만 두고 실습 코드는 밖에 둡니다.

명령 출력에 다른 프로젝트 경로와 개인·사내 정보가 함께 나오는 문제가 있어서, 이 폴더의 모든 예제는 홈 경로를 치환하고 무관한 항목을 지운 뒤 실었습니다.
