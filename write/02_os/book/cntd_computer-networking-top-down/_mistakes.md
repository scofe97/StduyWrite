# cntd 오답 노트

> 복습 회차에서 quality ≤ 3 인 문항을 박제한다. 같은 패턴이 3회 이상이면 원본 챕터 본문이 명확하지 않다는 신호다(`review-template.md` §5).

---

## 2026-09-11 — ch04 Q6: 집약 붕괴를 읽지 못함

- **자기 답**: "저 범위를 쓰는 부서가 다른 ISP 로 이관된 것 같다" — 이관은 짚었으나 중첩 구조와 줄 수 증가로 연결하지 못함
- **정답**: `/20` 1줄 → `/21` 추가 → 그 안에서 `/24` 추가로 **1줄이 3줄**이 됐다. ISP-C 블록은 ISP-B 블록의 일부. 집약은 줄을 줄이려는 것이고 예외 하나마다 그 효과가 깎인다 (04-03 §3)
- **원인 추정**: 개념 분리. **최장 접두 일치는 동작으로 알고 집약은 목적으로 연결이 안 된다.** 같은 회차 Q6 전반에서 `200.23.24.77` 을 세 항목 중 `/24` 로 정확히 보냈으면서, 그 예외가 테이블을 부풀린다는 반대 방향은 읽지 못했다
- **재방문 트리거**: 2026-09-14 회차 2 — 첫 문항으로 배치

> **2회 연속이다.** Phase 4(2026-09-08 이전) 검증2 에서 "집약 붕괴(부분)" 로 막혔고 회차 1 에서 다시 막혔다. `review-routine.md` §1 주석대로 같은 축 2연속은 간격 리셋으로 부족하다 — 회차 2 에서도 막히면 04-03 §3 을 ZPD 내림으로 재학습한다.

## 2026-09-11 — ch04 Q1·Q3·Q5·Q7: 용어와 실질의 분리 (패턴)

개별 문항이 아니라 **회차 전체를 관통한 패턴**이라 한 항목으로 묶는다.

| 문항 | 동작은 아는가 | 이름을 대는가 |
|---|---|---|
| Q1 네 장치를 묶는 틀 | 부분 | ✗ `일치-동작` |
| Q3 메모리 스위칭 한계 | ✗ (용량으로 오인) | — |
| Q5·Q6 겹칠 때 긴 쪽 | **○ 정확히 적용** | ✗ `최장 접두 일치` |
| Q2 최선형의 동기 | **○ 논지 정확** | ✗ `최선형` |
| Q4 규율 넷 | **○ 정확** | ✗ `일 보존` |
| Q7 NAT 반환 경로 | **○ 정확** | ✗ `종단 간 논증` |

- **원인 추정**: 노트를 *읽어* 이해했고 *불러* 본 적이 없다. 인출 연습에서 이름은 별도 경로라 함께 훈련되지 않았다
- **영향**: 면접 축(메타인지 A) 이 3 점에 묶인다. 동작을 설명할 수 있어도 용어가 안 나오면 아는 것으로 안 읽힌다
- **재방문 트리거**: 회차 2 부터 각 문항 끝에 "이 규칙의 이름은?" 을 한 줄 덧붙인다. 별도 문항을 만들지 않고 기존 7문항에 얹는다

## 2026-09-11 — ch04 Q3: 메모리 스위칭 한계를 용량으로 오인

- **자기 답**: "메모리는 실제 RAM 을 사용하기에 전송이 RAM 의 **크기**와 연관되고 프로세스에도 영향을 끼친다"
- **정답**: 한계는 용량이 아니라 **대역폭**이다. 메모리가 초당 B 패킷을 읽거나 쓸 수 있으면 처리량은 `B/2` 아래 — 패킷마다 쓰기 1 + 읽기 1 이 필요하기 때문 (04-01 §5)
- **원인 추정**: 되묻기 1회 때 접근 횟수를 3번(복사·조회·복사) 으로 셌다. **조회는 포워딩 테이블을 보는 일이고, 세는 대상은 패킷 자체가 메모리를 드나든 횟수**라는 구분이 없었다
- **재방문 트리거**: 2026-09-14 회차 2

## 2026-09-14 — ch05 Q1·Q2·Q5·Q7: 값은 뚫리고 설계 동기는 막힌다 (패턴)

회차 전체를 관통한 선이라 한 항목으로 묶는다. ch04 의 「용어와 실질의 분리」와는 다른 축이다 — 이번에는 이름이 아니라 **왜 그렇게 설계했나**가 안 나왔다.

| 문항 | 무엇을 물었나 | 결과 |
|---|---|---|
| Q3 count-to-infinity | 숫자를 주고 계산·메커니즘 | **4** — 첫 자답에 즉답 |
| Q6 TTL 두 자리 | 출력을 주고 해석 | 2 — 되묻기 후 계산법을 스스로 세움 |
| Q4 NEXT-HOP | 절차의 빈칸 | 3 — 되묻기 1회 |
| Q1 두 제어 모델의 구분 | 원문이 못 박은 경계 | 2 |
| Q7 애니캐스트와 연결 상태 | 무엇이 깨지는가 | 2 |
| Q2 안팎 프로토콜이 갈리는 이유 | **왜 이렇게 설계했나** | 1 |
| Q5 링크 실패와 s4 | **조율이 어디서 일어나나** | **0** |

- **원인 추정**: 값과 절차가 주어지면 따라갈 수 있는데, **경계가 왜 거기 그어졌는지**를 묻는 문항에서 무너진다. Q2 는 "AS 를 왜 나누고 안팎을 왜 가르나", Q5 는 "닿지도 않은 스위치가 왜 바뀌나"로 둘 다 눈앞의 계산이 아니다. MEMORY 의 `feedback_learner_weak_on_absence_constraints`(부재·제약 축에서 무너진다)와 같은 결로 보인다
- **영향**: 메타인지 A(면접) 가 2 에 묶인다. 5장은 "정답을 고르는 일이 아니라 틀리는 방식을 고르는 일"이 논지라, 동기 축이 비면 장 전체의 논지가 서지 않는다
- **재방문 트리거**: 2026-09-15 회차 2. Q5(05-03 §4) 와 Q2(05-02 §1) 를 먼저 낸다

## 2026-09-14 — ch05 Q5: 한 곳에서 계산한다는 조율 모델이 통째로 안 나옴

- **자기 답**: "모르겠음" → 되묻기 1 "직행이 없어졌으니 다른 곳으로 가야겠지" → 되묻기 2 "모르겠는데"
- **정답**: s4 는 우회로 `s1-s4-s2` 위에 있어 s1 이 s2 로 보내는 패킷을 나르게 된다. 스위치는 서로가 아니라 **컨트롤러에게만** 알리고, 컨트롤러가 한 번 계산해 s1·s2·s4 표를 한꺼번에 고친다 — **조율이 프로토콜의 수렴이 아니라 한 곳의 계산이 된다** (05-03 §4·핵심 요약)
- **원인 추정**: 우회로가 어디로 나는지를 그림 없이 짚지 못했다. 05-03 §4 의 여섯 걸음을 절차로 읽고 넘겼을 뿐, "누가 누구에게 알리는가"라는 축으로 다시 세우지 않았다
- **재방문 트리거**: 2026-09-15 회차 2 의 첫 문항

## 2026-09-14 — ch05 Q2: 정책이 AS 경계의 이유라는 것이 안 나옴

- **자기 답**: "정확히는 모르겠다. iBGP, eBGP 로 쪼개진 것만 안다" → 되묻기 2회 후에도 "AS 는 TCP 로 통신하니 제대로 된 거리를 몰라서"
- **정답**: 정책·규모·성능 셋이고 첫째가 정책이다. AS 사이에는 **AS 홉 수 말고는 비용이라는 개념 자체가 없다** (05-02 §1)
- **원인 추정**: 인과가 거꾸로다 — 거리를 몰라서 정책을 쓰는 것이 아니라, 정책이 먼저라 비용 개념이 없는 것이다. 그리고 TCP 179 는 §3 의 전송 방식이지 안팎이 갈리는 이유가 아닌데 그 둘을 같은 층으로 읽었다
- **재방문 트리거**: 2026-09-15 회차 2

## 2026-09-14 — 트러블슈팅 드릴에서 드러난 4·5·6장 선행 개념 공백 (패턴)

복습 회차가 아니라 드릴 문항 [몇몇 사용자만 들어오지 못하는 사이트](../../../troubleshooting/os/2026-09-14_몇몇%20사용자만%20들어오지%20못하는%20사이트.md)(quality 2)에서 나왔다. 막힌 자리가 전부 이 책 4·5·6장 개념이라 여기 박제하고 다음 회차 문항에 얹는다. 사용자가 "정말 어려웠다, 복습 회차에 이 부분을 보자"고 요청했다.

| 막힌 개념 | 드릴에서 나온 말 | 바른 이해 | 노트 자리 |
|---|---|---|---|
| 제어 평면과 데이터 평면 | "라우터 사이 통신을 BGP 로 보면 되나" | BGP·OSPF 는 가끔 표를 채우는 제어 평면이고, 매 패킷을 내보내는 일은 데이터 평면이 전달 표를 보고 한다 | 04-01 §1 |
| 후보 찾기와 하나 고르기 | "목적지 IP 만 본다며 왜 해시가 포트까지 보나" | 최장 접두 일치로 다음 홉 후보를 찾고, 후보가 여럿일 때만 흐름 값을 해시해 하나를 고른다 | 04-01 §4 · 06-05 §3 |
| 같은 주소를 여러 기계가 씀 | "다른 서버 셋인데 같은 IP 인 경우가 뭔가", 스프링 8080~8082 인스턴스로 비유 | 기계마다 같은 주소를 광고하고 라우터가 경로로 나눈다. 목적지 IP 로는 서버를 못 가린다 | 05-02 §5 |
| 해시에 포트를 넣는 이유 | 위와 같음 | 목적지만 해시하면 한 곳에 몰리고 패킷마다 고르면 연결이 찢어진다. 네 값이면 연결 단위로 흩되 한 연결은 한 경로다 | 06-05 §3 |
| ICMP 알림 패킷의 주소 | 출발지를 서버, 목적지를 사용자로 답함 | 버린 라우터가 새로 만든 별개 패킷이다. 출발지는 그 라우터, 목적지는 큰 패킷을 보낸 쪽이다. ICMP 헤더에는 포트가 없고 원본 앞부분을 인용한다 | 05-04 §2 · 04-04 §3 |
| DF 와 블랙홀 | "큰 데이터가 깨져서 보내진다" | DF 가 서 있으면 쪼개지 않고 통째로 버린다. 알림을 못 받은 송신자는 같은 크기로 재전송만 한다 | 04-03 · 04-04 §3 |
| 알림이 왔는데도 멈춤 | "알림이 있으니 멈춘 것" | 알림은 "줄여라"다. 도착했는데 멈추면 받는 호스트 자신(호스트 방화벽 등)을 본다 | 04-04 §3 |

- **원인 추정**: 증상을 진단하기 전 단계인 구조 개념이 비었다. "IP 주소 하나 = 기계 하나"라는 암묵 전제가 애니캐스트·ECMP 구조를 가렸고, 거기서 "목적지 IP 가 같으니 같은 서버로 간다"는 추론이 나왔다. ch05 회차 1 Q7(애니캐스트와 연결 상태) 2점과 같은 뿌리로 보인다
- **노트 쪽 조치**: 같은 날 04-03(단편화 소절), 04-04(경로 MTU 발견·블랙홀), 05-02(§2 OSPF 진전 넷 도식, §5 데이터센터 안 애니캐스트 콜아웃), 05-04(§2 콜아웃), 06-05(§3 흐름 해시 소절)를 보강했다
- **재방문 트리거**: 다음 ch04 회차(2026-09-15)에 04-01 두 평면·조회 단계와 04-03 DF 를 한 문항씩 얹는다. 다음 ch05 회차(2026-09-15)에 Q7 을 "같은 주소 뒤 서버 셋에서 포트 없는 ICMP 는 어디로 가나"로 바꿔 낸다. ch06 은 미착수라 06-05 §3 은 학습 세션 때 이 표부터 연다. 드릴 쪽 재출제는 2026-09-17 이다

## 2026-09-15 — ch05 회차 2: 두 회차 연속 quality 2, 같은 축이 다시 무너짐 (패턴 · 재학습 등록)

회차 1(2026-09-14)의 「값은 뚫리고 설계 동기는 막힌다」가 회차 2 에서도 그대로 나왔다. 이번에는 두 갈래가 더 또렷했다.

| 갈래 | 회차 1 | 회차 2 | 무엇이 반복됐나 |
|---|---|---|---|
| 설계 이유를 동작 방식으로 답함 | Q2 "AS 는 TCP 로 통신해서" (1) | Q2 되묻기 2 에 "게이트웨이만 받고 iBGP 로 공유" (2) | "왜 안팎이 갈리나"에 BGP 가 *어떻게 도는가*를 가져온다 |
| 전제 구조가 서지 않음 | Q7 애니캐스트와 연결 상태 (2) | Q6 애니캐스트 뒤 Packet Too Big (1) | "IP 하나 = 기계 하나" — 정답 뒤에도 "서버 IP 는 독립이고 사이에 같은 IP 의 공통 라우터가 있나"로 되물음 |

- **원인 추정**: 두 번째 갈래가 첫째를 부른다. 서버 여럿이 한 주소를 쓰는 구조가 머릿속에 없으니, 그 위에 선 설계 판단(애니캐스트는 연결 상태와 어긋난다, 알림은 포트가 없어 흐름을 못 찾아간다)을 세울 자리가 없다. 필요한 조각이 04-04 §3·05-02 §5·05-04 §2·06-05 §3 에 흩어져 있다는 지적도 사용자에게서 나왔다
- **조치**: 간격 리셋이 아니라 재학습(ZPD 내림) — `_queue.md` ch05 행과 책 README `learning.next_lesson` 에 순서를 적었다. 노트 쪽은 같은 날 05-04 §2 에 ICMP 헤더 구조와 개념 노트 `흐름을-가르는-다섯-값` 으로 가는 이어 읽기, 05-03 §4 도식에 위상을 넣는 보강을 시작했다
- **재방문 트리거**: 재학습을 마친 뒤 회차 3. 첫 문항은 애니캐스트 전제("서버 셋이 같은 주소를 어떻게 쓰나")를 그림 없이 설명하게 한다

## 2026-09-15 — ch05 r2 Q1: s4 는 "자기 목적지까지 직통이 있으니" 안 바뀐다고 봄

- **자기 답**: (가) 바뀌는 스위치 "s3, s4" → 되묻기 후 우회로 `1-4-2` 는 골랐으나 "s4 는 4-2 직통이 있으니 신경 쓰지 않는다". (나) "s1 이 s3·s4 에 전파" → "노드마다 한 번씩 계산" → 되묻기 2 로 "컨트롤러가 모두 계산해 전파"
- **정답**: s1·s2·s4. **s4 는 s1 이 s2 로 보내는 패킷을 날라야 해서** 장애를 겪지 않았는데도 표가 바뀐다. 스위치는 컨트롤러에게만 알리고 한 곳에서 계산해 셋을 한꺼번에 고친다 (05-03 §4)
- **원인 추정**: 흐름 표를 "내가 어디로 가나"의 표로만 읽고, **지나가는 남의 패킷을 어디로 넘기나**라는 줄을 떠올리지 못했다. 처음 (나) 는 SDN 문항에 라우터마다 제어 모델로 답했다. 도식에 위상이 없어 우회로를 그림에서 못 읽은 것도 한몫(같은 날 도식 보강)
- **재방문 트리거**: 회차 3

## 2026-09-15 — ch05 r2 Q4: 시작 시각을 한 번 벌려 두면 된다고 봄 (자기 동기화)

## 2026-09-15 — ch05 r2 Q6: Packet Too Big 의 목적지와 개념 자체가 비어 있음 (r1 Q7 에 이은 2연속)

- **자기 답**: (가) "못 한다, ICMP 는 IP 만 있어 IP 가 같으면 정상 라우팅이 힘들다" + 전제 질문 "서버 3개가 어떻게 같은 IP 를 쓰나". 되묻기 1 로 "포트가 빠진다"는 도달, 알림의 목적지는 "그 라우터에 오기 전 라우터의 주소"로 오답. (나) "줄여서 보내라는 알람이 뭐지?"
- **정답**: 알림의 출발지는 버린 중간 라우터, **목적지는 큰 패킷을 보낸 쪽 = 서버 셋이 함께 쓰는 주소**(06-05 §3). 마지막 라우터가 ICMP 를 IP 로만 해시해 포트가 빠지므로 S2 로 간다는 보장이 없다(05-02 §5 콜아웃). 못 받은 S2 는 같은 크기로 재전송만 해 **블랙홀 연결**이 된다(04-04 §3)
- **원인 추정**: 전제 둘(애니캐스트, PMTUD·Packet Too Big)이 없어 문항이 인출이 아니라 짐작이 됐다. **애니캐스트 전제 공백은 3회째**(회차 1 Q7 · 2026-09-14 드릴 "다른 서버 셋인데 같은 IP 인 경우가 뭔가" · 회차 2 Q6)이고, **알림 주소를 잘못 짚은 것은 2회째**(드릴 표 "ICMP 알림 패킷의 주소" · 회차 2 Q6)다
- **재방문 트리거**: 재학습 1·2순위(05-02 §5 → 04-04 §3). 드릴 재출제 2026-09-17 과 겹치므로 드릴을 먼저 풀어도 된다

## 2026-09-15 — ch05 r2 Q7: 한 방향 흐름 표를 IP 라우팅 실패로 읽음

## 2026-09-16 — ch03 회차 1 Q2: 링크 CRC 의 범위를 "링크 헤더만"으로 알고 있었다

- **자기 답**: "CRC 는 라우터에서 체크섬을 빠르게 하기 위한 기술로만 이해했었음" → 되묻기 1 후 "링크 체크섬은 링크 헤더의 값(맥주소?)이고 전송계층은 IP·PORT 에 대한 전체적 검사 아닐까? (사실 잘 모르겠음)"

## 2026-09-16 — ch03 회차 1 Q5: "반쯤 열린 연결"이라는 상태가 없었다

- **자기 답**: "윈도우(버퍼)가 꽉 차서 버려졌기에 그런 것 같습니다" → 되묻기 1 로 "출발지·목적지 IP·포트의 소켓 정보를 갖고 있어야 한다"까지 → 쿠키 쪽은 "기억하지 못하면 판단할 수 없습니다"로 미도달
- **정답**: 서버는 SYN-ACK 를 보내며 **연결 변수와 버퍼를 할당**하고 1분 넘게 들고 있다. SYN 쿠키는 그 자리를 아예 만들지 않고, 초기 순서 번호를 **해시로 계산해** 보낸 뒤 ACK 가 오면 **같은 해시를 다시 계산**해 검산한다 — 기억 대신 재계산 (03-04 §3)
- **원인 추정**: 고갈되는 자원을 **데이터용 수신 버퍼**로 읽었다. 연결이 완성되기 전에도 서버가 자리를 잡는다는 상태가 머릿속에 없으니, 그 위에 선 방어(쿠키)도 설 자리가 없었다. ch05 Q6(애니캐스트 전제 부재)와 같은 결의 **구조 전제 공백**이다
- **재방문 트리거**: 회차 2. `_assets/03-04.syn-cookie.svg` 의 "여기까지 안 오면 반쯤 열린 연결이 남음" 라벨을 먼저 보게 한 뒤 출제
