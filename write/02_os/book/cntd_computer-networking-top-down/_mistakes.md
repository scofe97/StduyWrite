# cntd 오답 노트

> 복습 회차에서 quality ≤ 3 인 문항을 박제한다. 같은 패턴이 3회 이상이면 원본 챕터 본문이 명확하지 않다는 신호다(`review-template.md` §5).

---

## 2026-09-11 — ch04 Q6: 집약 붕괴를 읽지 못함

- **자기 답**: "저 범위를 쓰는 부서가 다른 ISP 로 이관된 것 같다" — 이관은 짚었으나 중첩 구조와 줄 수 증가로 연결하지 못함
- **정답**: `/20` 1줄 → `/21` 추가 → 그 안에서 `/24` 추가로 **1줄이 3줄**이 됐다. ISP-C 블록은 ISP-B 블록의 일부. 집약은 줄을 줄이려는 것이고 예외 하나마다 그 효과가 깎인다 (04-03 §3)
- **원인 추정**: 개념 분리. **최장 접두 일치는 동작으로 알고 집약은 목적으로 연결이 안 된다.** 같은 회차 Q6 전반에서 `200.23.24.77` 을 세 항목 중 `/24` 로 정확히 보냈으면서, 그 예외가 테이블을 부풀린다는 반대 방향은 읽지 못했다
- **재방문 트리거**: 2026-09-14 회차 2 — 첫 문항으로 배치

> **2회 연속이다.** Phase 4(2026-09-08 이전) 검증2 에서 "집약 붕괴(부분)" 로 막혔고 회차 1 에서 다시 막혔다. `review-routine.md` §1 주석대로 같은 축 2연속은 간격 리셋으로 부족하다 — 회차 2 에서도 막히면 04-03 §3 을 ZPD 내림으로 재학습한다.

## 2026-09-11 — ch04 Q1·Q3·Q5·Q7: 용어와 실질의 분리 (패턴)

개별 문항이 아니라 **회차 전체를 관통한 패턴**이라 한 항목으로 묶는다.

| 문항 | 동작은 아는가 | 이름을 대는가 |
|---|---|---|
| Q1 네 장치를 묶는 틀 | 부분 | ✗ `일치-동작` |
| Q3 메모리 스위칭 한계 | ✗ (용량으로 오인) | — |
| Q5·Q6 겹칠 때 긴 쪽 | **○ 정확히 적용** | ✗ `최장 접두 일치` |
| Q2 최선형의 동기 | **○ 논지 정확** | ✗ `최선형` |
| Q4 규율 넷 | **○ 정확** | ✗ `일 보존` |
| Q7 NAT 반환 경로 | **○ 정확** | ✗ `종단 간 논증` |

- **원인 추정**: 노트를 *읽어* 이해했고 *불러* 본 적이 없다. 인출 연습에서 이름은 별도 경로라 함께 훈련되지 않았다
- **영향**: 면접 축(메타인지 A) 이 3 점에 묶인다. 동작을 설명할 수 있어도 용어가 안 나오면 아는 것으로 안 읽힌다
- **재방문 트리거**: 회차 2 부터 각 문항 끝에 "이 규칙의 이름은?" 을 한 줄 덧붙인다. 별도 문항을 만들지 않고 기존 7문항에 얹는다

## 2026-09-11 — ch04 Q3: 메모리 스위칭 한계를 용량으로 오인

- **자기 답**: "메모리는 실제 RAM 을 사용하기에 전송이 RAM 의 **크기**와 연관되고 프로세스에도 영향을 끼친다"
- **정답**: 한계는 용량이 아니라 **대역폭**이다. 메모리가 초당 B 패킷을 읽거나 쓸 수 있으면 처리량은 `B/2` 아래 — 패킷마다 쓰기 1 + 읽기 1 이 필요하기 때문 (04-01 §5)
- **원인 추정**: 되묻기 1회 때 접근 횟수를 3번(복사·조회·복사) 으로 셌다. **조회는 포워딩 테이블을 보는 일이고, 세는 대상은 패킷 자체가 메모리를 드나든 횟수**라는 구분이 없었다
- **재방문 트리거**: 2026-09-14 회차 2

## 2026-09-14 — ch05 Q1·Q2·Q5·Q7: 값은 뚫리고 설계 동기는 막힌다 (패턴)

회차 전체를 관통한 선이라 한 항목으로 묶는다. ch04 의 「용어와 실질의 분리」와는 다른 축이다 — 이번에는 이름이 아니라 **왜 그렇게 설계했나**가 안 나왔다.

| 문항 | 무엇을 물었나 | 결과 |
|---|---|---|
| Q3 count-to-infinity | 숫자를 주고 계산·메커니즘 | **4** — 첫 자답에 즉답 |
| Q6 TTL 두 자리 | 출력을 주고 해석 | 2 — 되묻기 후 계산법을 스스로 세움 |
| Q4 NEXT-HOP | 절차의 빈칸 | 3 — 되묻기 1회 |
| Q1 두 제어 모델의 구분 | 원문이 못 박은 경계 | 2 |
| Q7 애니캐스트와 연결 상태 | 무엇이 깨지는가 | 2 |
| Q2 안팎 프로토콜이 갈리는 이유 | **왜 이렇게 설계했나** | 1 |
| Q5 링크 실패와 s4 | **조율이 어디서 일어나나** | **0** |

- **원인 추정**: 값과 절차가 주어지면 따라갈 수 있는데, **경계가 왜 거기 그어졌는지**를 묻는 문항에서 무너진다. Q2 는 "AS 를 왜 나누고 안팎을 왜 가르나", Q5 는 "닿지도 않은 스위치가 왜 바뀌나"로 둘 다 눈앞의 계산이 아니다. MEMORY 의 `feedback_learner_weak_on_absence_constraints`(부재·제약 축에서 무너진다)와 같은 결로 보인다
- **영향**: 메타인지 A(면접) 가 2 에 묶인다. 5장은 "정답을 고르는 일이 아니라 틀리는 방식을 고르는 일"이 논지라, 동기 축이 비면 장 전체의 논지가 서지 않는다
- **재방문 트리거**: 2026-09-15 회차 2. Q5(05-03 §4) 와 Q2(05-02 §1) 를 먼저 낸다

## 2026-09-14 — ch05 Q5: 한 곳에서 계산한다는 조율 모델이 통째로 안 나옴

- **자기 답**: "모르겠음" → 되묻기 1 "직행이 없어졌으니 다른 곳으로 가야겠지" → 되묻기 2 "모르겠는데"
- **정답**: s4 는 우회로 `s1-s4-s2` 위에 있어 s1 이 s2 로 보내는 패킷을 나르게 된다. 스위치는 서로가 아니라 **컨트롤러에게만** 알리고, 컨트롤러가 한 번 계산해 s1·s2·s4 표를 한꺼번에 고친다 — **조율이 프로토콜의 수렴이 아니라 한 곳의 계산이 된다** (05-03 §4·핵심 요약)
- **원인 추정**: 우회로가 어디로 나는지를 그림 없이 짚지 못했다. 05-03 §4 의 여섯 걸음을 절차로 읽고 넘겼을 뿐, "누가 누구에게 알리는가"라는 축으로 다시 세우지 않았다
- **재방문 트리거**: 2026-09-15 회차 2 의 첫 문항

## 2026-09-14 — ch05 Q2: 정책이 AS 경계의 이유라는 것이 안 나옴

- **자기 답**: "정확히는 모르겠다. iBGP, eBGP 로 쪼개진 것만 안다" → 되묻기 2회 후에도 "AS 는 TCP 로 통신하니 제대로 된 거리를 몰라서"
- **정답**: 정책·규모·성능 셋이고 첫째가 정책이다. AS 사이에는 **AS 홉 수 말고는 비용이라는 개념 자체가 없다** (05-02 §1)
- **원인 추정**: 인과가 거꾸로다 — 거리를 몰라서 정책을 쓰는 것이 아니라, 정책이 먼저라 비용 개념이 없는 것이다. 그리고 TCP 179 는 §3 의 전송 방식이지 안팎이 갈리는 이유가 아닌데 그 둘을 같은 층으로 읽었다
- **재방문 트리거**: 2026-09-15 회차 2
