# 레시피와 현대 도구 참조 시트

---

> 《Learning Modern Linux》 부록 A 와 B 의 명령을 한 장에 모은 조회용 시트입니다. 명령마다 본문 어느 장이 설명했는지를 붙였고, find 와 시스템 시계는 따로 풀어 적었습니다.

## 이 문서의 성격

> 정독 노트가 아니라 조회용 시트라서 학습 목표와 면접 질문을 두지 않습니다.

표의 「본문」 열은 그 명령을 설명한 장이고, "본문 밖"은 이 책이 다루지 않은 명령입니다. 출력은 Debian 12 컨테이너(GNU findutils 4.9.0, bash 5.2.15, fish 3.6.0)에서 직접 돌려 받았습니다.



## 1. 그대로 치면 어긋나는 명령

> 아래 여섯은 적힌 대로 치면 실패하거나, 이름에서 기대하는 것과 다른 값을 냅니다.

### 함정 여섯

```bash
# ✗ cat 'foo bar baz' | sed -e 's/foo/quux/'  → cat 이 인자를 파일 이름으로 읽어 No such file or directory 로 끝난다
echo 'foo bar baz' | sed -e 's/foo/quux/'

# ✗ date +%FT%TZ  → 2026-11-10T11:00:00Z (지역 시각 뒤에 Z 가 글자로 붙는다)
date +%FT%T%:z

# ✗ git log (git describe --tags --abbrev=0)..HEAD --oneline  → bash 에서 syntax error near unexpected token '(' 로 끝난다
git log $(git describe --tags --abbrev=0)..HEAD --oneline

# ✗ git diff --color-moved  → 나란히 보기가 아니라 옮겨진 줄을 다른 색으로 칠한다
#   옮기기만 한 변경과 고친 변경을 가를 때 쓴다
git diff --color-moved

# ✗ head -c 450m  → m 은 1,048,576 배라 471,859,200 바이트에서 끊는다
head -c 450MB

# ✗ ls -l /etc | wc -l  → total N 줄이 하나 더해지고 숨은 파일은 빠진다
ls -1A /etc | wc -l
```

| 명령 | 실제 동작 | 대신 쓸 형태 |
|------|----------|-------------|
| `cat 'foo bar baz' \| sed -e 's/foo/quux/'` | `cat` 이 인자를 파일 이름으로 읽어 `No such file or directory` 로 끝납니다 | `echo 'foo bar baz' \| sed -e 's/foo/quux/'` |
| `date +%FT%TZ` | `Z` 는 UTC 표시인데 지역 시각 뒤에 글자로 붙습니다. `TZ=Asia/Seoul` 에서 `2026-11-10T11:00:00Z` 가 나옵니다 | `date +%FT%T%:z`[^date] |
| `git log (git describe --tags --abbrev=0)..HEAD --oneline` | bash 에서 `syntax error near unexpected token '('` 로 끝납니다 | `git log $(git describe --tags --abbrev=0)..HEAD --oneline` |
| `git diff --color-moved` | 옮겨진 줄을 다른 색으로 칠합니다. 나란히 보기가 아닙니다[^git-diff] | 옮기기만 한 변경과 고친 변경을 가를 때 씁니다 |
| `head -c 450m` | `m` 은 1,048,576 배라 471,859,200 바이트에서 끊습니다[^head] | 450,000,000 바이트는 `head -c 450MB` |
| `ls -l /etc \| wc -l` | `total N` 줄이 하나 더해지고 숨은 파일은 빠집니다 | `ls -1A /etc \| wc -l` |

### 셸마다 다른 문법

| 하려는 일 | bash | fish |
|----------|------|------|
| 명령 치환 | `$(cmd)` | `(cmd)` · `$(cmd)` |
| 파이프 각 명령의 종료 코드 | `${PIPESTATUS[@]}` | `$pipestatus` |

bash 에서 `(cmd)` 는 문법 오류입니다. fish 에서 `${PIPESTATUS[@]}` 는 `${ is not a valid variable in fish` 로 거부됩니다. `$(cmd)` 는 bash 5.2 와 fish 3.6 에서 모두 동작합니다.



## 2. 레시피 여덟 묶음

> 묶음 순서는 부록 A 를 따릅니다. 「시간과 날짜」에는 시스템 클럭과 RTC 를 확인하는 명령을 더했습니다.

### 시스템 정보 모으기

```bash
# 리눅스 배포판 버전 확인
cat /etc/*-release

# 커널 컴파일 정보와 버전 확인
cat /proc/version

# 커널 버전과 시스템 아키텍처 확인
uname -a

# CPU 모델과 코어 정보 확인
cat /proc/cpuinfo

# 시스템 메모리 사용 통계 확인
cat /proc/meminfo

# 디스크 I/O 통계 확인
cat /proc/diskstats

# BIOS 정보 확인(-t 에 system·memory 도 조회 가능)
sudo dmidecode -t bios

# 주 메모리와 스왑 사용량을 사람이 읽기 쉬운 단위와 합계(-t)로 확인
free -ht

# 프로세스가 가질 수 있는 최대 파일 디스크립터 수 확인
ulimit -n
```

| 명령 | 본문 |
|------|------|
| `cat /etc/*-release` | 본문 밖 |
| `cat /proc/version` | 1장 |
| `uname -a` | 2장 |
| `cat /proc/cpuinfo` | 1장 · 2장 |
| `cat /proc/meminfo` | 2장 |
| `cat /proc/diskstats` | 본문 밖 |
| `sudo dmidecode -t bios` | 2장 |
| `free -ht` | 8장 둘째 편 |
| `ulimit -n` | 본문 밖 |

### 사용자와 프로세스

```bash
# 로그인한 사용자 목록 확인
who

# 로그인한 사용자와 현재 작업 상세 확인
w

# 특정 사용자의 프로세스별 시스템 메트릭 확인
top -U SOMEUSER

# 전체 사용자의 프로세스를 부모-자식 트리로 본다
ps faux

# 특정 이름을 가진 프로세스 찾기
ps -e | grep python

# 프로세스에 종료를 요청한다(SIGTERM). 무시하면 -9(SIGKILL)
kill PID

# 이름으로 프로세스 종료
killall
```

| 명령 | 본문 |
|------|------|
| `who` · `w` | 본문 밖 |
| `top -U SOMEUSER` | 8장 둘째 편 |
| `ps faux` | 2장 |
| `ps -e \| grep python` | 2장 |
| `kill PID` | 9장 |
| `killall` | 본문 밖 |

`kill -9` 는 `SIGKILL` 을 보내며, 이 시그널은 프로세스가 잡거나 무시할 수 없습니다.

### 파일 정보

```bash
# 아이노드를 포함한 파일 상세 확인
stat somefile

# 셸이 그 명령을 어떻게 해석하는지 확인
type somecommand

# 실행 파일의 위치 확인
which somebinary
```

| 명령 | 본문 |
|------|------|
| `stat somefile` | 5장 |
| `type somecommand` | 3장 첫 편 |
| `which somebinary` | 3장 첫 편 |

### 파일과 디렉터리 다루기

```bash
# 텍스트 파일 내용 보기
cat afile

# 줄 수 세기(total 줄이 더해지고 숨은 파일이 빠지는 함정 주의, §1)
ls -l /etc | wc -l

# /etc 에서 .conf 로 끝나는 파일 찾기(§3)
find /etc -name "*.conf"

# 현재 디렉터리에서 문자열 찾기(§3)
find . -type f -exec grep -H FINDME {} \;

# 두 파일의 차이를 비교
diff -u somefile anotherfile

# 문자 치환(→ com.acme.library)
echo 'Com_Acme_Library' | tr '_A-Z' '.a-z'

# ✗ cat 'foo bar baz' | sed -e 's/foo/quux/'  → foo bar baz 라는 파일을 찾다 실패한다(§1)
# 첫 foo 를 바꾼다(→ quux bar baz)
echo 'foo bar baz' | sed -e 's/foo/quux/'

# 시험용 파일 만들기(크기 1,024,000 바이트)
dd if=/dev/zero of=output.dat bs=1024 count=1000
```

| 명령 | 본문 |
|------|------|
| `cat afile` | 3장 첫 편 |
| `ls -l /etc \| wc -l` | 3장 첫 편 |
| `find /etc -name "*.conf"` | 3장 첫 편 |
| `find . -type f -exec grep -H FINDME {} \;` | 3장 첫 편 |
| `diff -u somefile anotherfile` | 본문 밖 |
| `echo 'Com_Acme_Library' \| tr '_A-Z' '.a-z'` | 3장 첫 편 |
| `cat 'foo bar baz' \| sed -e 's/foo/quux/'` | 3장 첫 편 |
| `echo 'foo bar baz' \| sed -e 's/foo/quux/'` | 3장 첫 편 |
| `dd if=/dev/zero of=output.dat bs=1024 count=1000` | 본문 밖 |

`sed` 의 구분자는 `/` 가 아니어도 됩니다. 경로를 바꿀 때 `echo /usr/bin | sed 's#/usr#/opt#'` 처럼 쓰면 `/opt/bin` 이 나옵니다.

### 리다이렉션과 파이프

```bash
# 표준 출력을 파일로
command 1> file

# 표준 오류를 파일로
command 2> file

# 표준 출력과 표준 오류를 함께 파일로
command &> file

# 같은 일을 하는 다른 방법(표준 출력과 표준 오류를 파일로)
command >file 2>&1

# 출력을 버리기
command > /dev/null

# 표준 입력을 파일에서 받기
command < file

# 한 프로세스의 표준 출력을 다음의 표준 입력으로
cmd1 | cmd2 | cmd3

# 파이프 각 명령의 종료 코드(bash 전용, fish 는 $pipestatus)
echo ${PIPESTATUS[@]}
```

| 명령 | 본문 |
|------|------|
| `command 1> file` | 3장 첫 편 |
| `command 2> file` | 3장 첫 편 |
| `command &> file` | 3장 첫 편 |
| `command >file 2>&1` | 3장 첫 편 |
| `command > /dev/null` | 3장 첫 편 |
| `command < file` | 3장 첫 편 |
| `cmd1 \| cmd2 \| cmd3` | 3장 첫 편 |
| `echo ${PIPESTATUS[@]}` | 3장 셋째 편 |

`&>` 앞에 숫자를 붙인 `2&>` 는 다른 뜻입니다. `ls nosuch 2&> r.txt` 를 돌리면 `2` 가 `ls` 의 인자로 넘어가 `ls: cannot access '2'` 가 파일에 함께 적힙니다.

### 시간과 날짜

```bash
# 지역 시각·UTC·동기화 상태 확인
timedatectl status

# 날짜를 YYYY-MM-DD 형식으로 출력(→ 2026-11-10)
date +"%Y-%m-%d"

# 유닉스 에포크 초 출력(→ 1794276000)
date +%s

# UTC 기준 시각 출력(→ 2026-11-10T02:00:00Z)
date -u +"%Y-%m-%dT%H:%M:%SZ"

# ✗ date +%FT%TZ  → 2026-11-10T11:00:00Z (지역 시각에 Z 가 붙는다, §1)
# 지역 시각을 오프셋과 함께 출력(→ 2026-11-10T11:00:00+09:00)
date +%FT%T%:z
```

| 명령 | 결과 | 본문 · 비고 |
|------|------|-------------|
| `timedatectl status` | 지역 시각·UTC·동기화 상태 | 6장 첫 편 |
| `date +"%Y-%m-%d"` | `2026-11-10` | 3장 둘째 편 |
| `date +%s` | `1794276000` | 3장 둘째 편 · 유닉스 에포크 |
| `date -u +"%Y-%m-%dT%H:%M:%SZ"` | `2026-11-10T02:00:00Z` | UTC. `Z` 가 맞습니다 |
| `date +%FT%TZ` | `2026-11-10T11:00:00Z` | 지역 시각에 `Z` 가 붙습니다(§1) |
| `date +%FT%T%:z` | `2026-11-10T11:00:00+09:00` | 지역 시각을 오프셋과 함께 적습니다 |

결과 열은 `TZ=Asia/Seoul` 에서 에포크 1794276000 을 적은 값입니다. 날짜 계산은 [3장 둘째 편](./03-02.%EC%9E%90%EC%A3%BC%20%EC%B9%98%EB%8A%94%20%EA%B2%83%EC%9D%BC%EC%88%98%EB%A1%9D%20%EC%A7%A7%EC%95%84%EC%95%BC%20%ED%95%9C%EB%8B%A4.md)이 다룹니다.

리눅스 기계에는 시계가 둘 있습니다. **RTC**(하드웨어 클럭)는 전원이 꺼져도 가는 시계입니다. 시스템 클럭은 커널이 1970-01-01 00:00:00 UTC 부터 세는 초입니다.[^hwclock] 부팅 때 RTC 값으로 시스템 클럭을 맞추고 켜져 있는 동안에는 NTP 데몬이 시스템 클럭을 보정합니다.

NTP 로 동기된 상태에서는 커널이 11분마다 시스템 클럭 값을 RTC 에 되적는데, 이 동작은 커널 빌드 옵션에 달려 있습니다.[^hwclock-11] 타임존은 이 초를 화면에 적을 때만 쓰이므로 `/etc/localtime` 을 바꿔도 `date +%s` 는 그대로입니다.[^localtime]

![시계는 둘이고 타임존은 표기에만 붙는다](./_assets/00-01.clock-sync.svg)

`timedatectl` 은 두 시계와 동기 상태를 한 번에 보여 줍니다. 아래는 NTP 데몬을 켜지 않은 Ubuntu 26.04(systemd 259) 가상 머신의 출력입니다.

```bash
# 시스템 시계와 동기화 상태 확인
timedatectl
```

```bash
               Local time: Tue 2026-11-10 11:16:26 KST
           Universal time: Tue 2026-11-10 02:16:26 UTC
                 RTC time: n/a
                Time zone: Asia/Seoul (KST, +0900)
System clock synchronized: no
              NTP service: inactive
          RTC in local TZ: no
```

| 줄 | 뜻 |
|----|----|
| `Local time` · `Universal time` | 시스템 클럭을 타임존을 적용해 적은 값과 UTC 로 적은 값 |
| `RTC time` | 하드웨어 클럭 값. 이 머신에서는 `n/a` 입니다 |
| `Time zone` | `/etc/localtime` 이 가리키는 구역 |
| `System clock synchronized` | 시스템 클럭이 NTP 로 맞춰졌는지 |
| `NTP service` | 시각 동기 서비스가 켜져 있는지 |
| `RTC in local TZ` | RTC 를 지역 시각으로 두는지. `no` 면 UTC 로 둡니다 |

```bash
# 타임존 변경(/etc/localtime 심볼릭 링크를 변경하며 시스템 클럭은 유지)
timedatectl set-timezone Asia/Seoul

# systemd-timesyncd 의 동기 상태 확인
timedatectl timesync-status

# 시각 동기 데몬의 활성화 여부 확인(하나라도 active 면 종료 코드 0)
systemctl is-active chronyd ntpd systemd-timesyncd

# 하드웨어 클럭(RTC) 값을 지역 시각으로 출력
hwclock --show

# 시스템 클럭 값을 RTC 에 저장
hwclock --systohc
```

| 명령 | 동작 · 주의 |
|------|------------|
| `timedatectl set-timezone Asia/Seoul` | `/etc/localtime` 심볼릭 링크를 바꿉니다. 시스템 클럭 값은 그대로입니다[^timedatectl] |
| `timedatectl timesync-status` | systemd-timesyncd 의 동기 상태. 이 데몬이 꺼진 머신에서는 `Failed to query server: Connection timed out` 으로 끝납니다 |
| `systemctl is-active chronyd ntpd systemd-timesyncd` | 어느 시각 동기 데몬이 도는지. 유닛마다 한 줄씩 상태를 찍고, 하나라도 `active` 면 종료 코드가 0 입니다[^systemctl] |
| `hwclock --show` | RTC 값을 지역 시각으로 출력합니다 |
| `hwclock --systohc` | 시스템 클럭 값을 RTC 에 적습니다 |

### Git

```bash
# 저장소를 로컬로 복제
git clone https://github.com/exampleorg/examplerepo.git

# 옮겨진 줄을 다른 색으로 칠한다(§1)
git diff --color-moved

# 작업 트리에서 무엇이 바뀌었는지 확인
git status

# 모든 변경을 담아 커밋
git add --all && git commit -m "adds a super cool feature"

# 현재 커밋 ID 확인
git rev-parse HEAD

# 특정 커밋에 태그 달기
git tag ATAG HASH

# 태그를 원격에 올리기
git push origin ATAG

# ✗ git log (git describe --tags --abbrev=0)..HEAD --oneline  → 마지막 태그 뒤의 커밋 목록(fish 문법, §1)
# 마지막 태그 뒤의 커밋 목록을 한 줄 요약으로 확인(bash 문법)
git log $(git describe --tags --abbrev=0)..HEAD --oneline
```

| 명령 | 비고 |
|------|------|
| `git clone https://github.com/exampleorg/examplerepo.git` | 저장소를 로컬로 복제 |
| `git diff --color-moved` | 옮겨진 줄을 다른 색으로 칠합니다(§1) |
| `git status` | 무엇이 바뀌었는지 |
| `git add --all && git commit -m "adds a super cool feature"` | 전부 담아 커밋 |
| `git rev-parse HEAD` | 현재 커밋 ID |
| `git tag ATAG HASH` | 특정 커밋에 태그 달기 |
| `git push origin ATAG` | 태그를 원격에 올리기 |
| `git log (git describe --tags --abbrev=0)..HEAD --oneline` | fish 문법(§1) |
| `git log $(git describe --tags --abbrev=0)..HEAD --oneline` | 같은 일을 하는 bash 문법 |

`git diff --color-moved` 를 한 글자 별칭으로 줄이는 예는 3장 둘째 편에 있습니다.

### 시스템 성능

```bash
# 메모리 부하 걸기(head 는 471,859,200 바이트에서 끊는다, §1)
yes | tr \\n x | head -c 450m | grep z

# 디렉터리별 디스크 사용량 확인
du -h /home

# 남은 디스크 공간 확인
df -h

# 직접 I/O(oflag=direct)로 디스크 입출력 처리량 재기
dd if=/dev/zero of=/home/some/file bs=1G count=1 oflag=direct
```

| 명령 | 본문 |
|------|------|
| `yes \| tr \\n x \| head -c 450m \| grep z` | 3장 첫 편(`yes`) |
| `du -h /home` | 본문 밖 |
| `df -h` | 5장(`df -i` 로 나옴) |
| `dd if=/dev/zero of=/home/some/file bs=1G count=1 oflag=direct` | 본문 밖 |

부하를 거는 파이프는 칸마다 하는 일이 다릅니다.

- `yes` 가 `y` 를 한 줄에 하나씩 끝없이 냅니다
- `tr` 이 줄바꿈을 `x` 로 바꿔 `yxyx…` 한 줄로 만듭니다
- `head` 가 정해진 크기에서 끊습니다
- `grep` 이 없는 문자 `z` 를 찾느라 그 덩어리를 전부 읽습니다

출력은 없고, `grep` 이 끝까지 읽는 동안 부하가 걸립니다.



## 3. find 로 파일 찾기

> find 는 시작 경로 아래를 내려가며 파일마다 식을 왼쪽부터 평가합니다. 조건 표, 부호 읽는 법, 찾은 이름을 넘기는 법, 지우기 전 확인 순서를 모았습니다.

### 왼쪽부터 AND 로 평가

조건을 나란히 적으면 find 는 그 사이에 `-a`(AND)가 있는 것으로 읽고, 앞 조건이 거짓이면 뒤 조건을 평가하지 않습니다.[^find-and] `-print` 와 `-delete` 같은 동작도 같은 줄에 선 식이라, 왼쪽 조건이 모두 참이어야 그 자리에 닿습니다. 동작을 하나도 적지 않으면 식 전체가 참인 파일에 `-print` 가 적용됩니다.[^find-print]

![find 는 조건을 왼쪽부터 평가하다 거짓에서 멈춘다](./_assets/00-01.find-eval.svg)

```bash
# 조건을 모두 만족하는 파일만 찾는다(-a 생략)
find logs -type f -name '*.log' -mtime +30
```

```bash
logs/app.log
```

```bash
# -print 가 앞에 있어 조건 평가 전에 모든 파일과 디렉터리를 먼저 출력한다
find logs -print -type f -name '*.log' -mtime +30
```

```bash
logs
logs/app.log
logs/app.gz
logs/new.log
```

둘째 명령처럼 `-print` 를 맨 앞에 두면 조건을 보기 전에 이름부터 찍으므로 넷이 모두 나옵니다.

### 조건 옵션

| 조건 | 참이 되는 파일 | 예 |
|------|---------------|-----|
| `-name PATTERN` · `-iname PATTERN` | 디렉터리를 뗀 이름이 셸 패턴에 맞는 파일. `-iname` 은 대소문자를 가리지 않습니다 | `-name '*.conf'` |
| `-type c` | 종류가 `c` 인 파일. `f` 일반 파일, `d` 디렉터리, `l` 심볼릭 링크 | `-type f` |
| `-mtime n` · `-mmin n` | 내용이 바뀐 지 n일(24시간 단위) · n분 | `-mtime +30` · `-mmin -90` |
| `-newer FILE` | FILE 보다 나중에 바뀐 파일. 시각이 같으면 거짓입니다 | `-newer deploy.stamp` |
| `-size n[ckMG]` | 크기가 n 단위인 파일. `c` 바이트, `k` KiB, `M` MiB, `G` GiB | `-size +500M` |
| `-user NAME` · `-group NAME` | 소유자 · 그룹이 NAME 인 파일 | `-user alice` |
| `-perm MODE` | 권한 비트가 MODE 와 같은 파일. `-MODE` 는 적은 비트가 모두 켜진 파일, `/MODE` 는 하나라도 켜진 파일 | `-perm -u=x` |

탐색 범위를 정하는 옵션 둘은 조건이 아니라 전체에 적용되므로 시작 경로 바로 뒤에 적습니다.[^find-global]

| 옵션 | 하는 일 | 예 |
|------|--------|-----|
| `-maxdepth N` | 시작 경로에서 N 단계까지만 내려갑니다. 0 이면 시작 경로만 봅니다 | `find . -maxdepth 1 -type f` |
| `-xdev` | 다른 파일시스템에 있는 디렉터리로 내려가지 않습니다 | `find / -xdev -name cpuinfo` |

```bash
# 전체 경로에서 cpuinfo 검색
find / -name cpuinfo
```

```bash
/proc/cpuinfo
```

```bash
# 다른 파일시스템(-xdev)으로 내려가지 않아 /proc 안을 탐색하지 않는다
find / -xdev -name cpuinfo
```

둘째 명령은 아무것도 찍지 않습니다. `/proc` 은 따로 마운트된 파일시스템이라 `-xdev` 를 붙이면 그 안으로 들어가지 않습니다.

### -mtime 과 -size 의 부호

숫자 앞의 `+` 는 "보다 큼", `-` 는 "보다 작음"이고 부호가 없으면 "정확히 같음"입니다.[^find-num] 비교하는 값은 단위로 나눈 몫입니다. `-mtime` 은 나이를 24시간으로 나눠 소수를 버리고, `-size` 는 크기를 단위로 나눠 올립니다.[^find-round]

![-mtime 은 나이를 24시간으로 나눈 몫과 비교한다](./_assets/00-01.mtime-sign.svg)

`touch -d '25 hours ago' 25h` 처럼 나이가 다른 파일 여섯을 만들어 돌린 결과입니다.

| 조건 | 잡힌 파일 |
|------|----------|
| `-mtime -1` · `-mtime 0` | `1h` `23h` |
| `-mtime 1` | `25h` `47h` |
| `-mtime +1` | `49h` `73h` |
| `-mtime +0` | `25h` `47h` `49h` `73h` |
| `-mmin -90` | `1h` |

`-mtime +1` 은 48시간이 지나야 잡습니다. 24시간을 넘긴 파일 전부는 `-mtime +0` 으로 적습니다.

크기는 0 · 1 · 1048576 · 1048577 · 524288000 · 524288001 바이트 파일로 확인했습니다.

| 조건 | 잡힌 크기(바이트) |
|------|------------------|
| `-size -1M` | 0 |
| `-size 1M` | 1 · 1048576 |
| `-size +1M` | 1048577 · 524288000 · 524288001 |
| `-size +500M` | 524288001 |
| `-size -1048576c` | 0 · 1 |

1바이트 파일도 올리면 1M 이라 `-size -1M` 은 빈 파일만 잡습니다. 1MiB 미만을 잡으려면 `-size -1048576c` 처럼 바이트로 적습니다.

### 따옴표 없는 패턴

`-name *.log` 처럼 따옴표를 빼면 셸이 `*.log` 를 현재 디렉터리의 파일 이름으로 먼저 바꿔서 find 에 넘깁니다.[^find-quote] 결과는 현재 디렉터리에 맞는 파일이 몇 개인지에 따라 갈립니다.

| 현재 디렉터리의 `*.log` | find 가 받는 인자 | 결과 |
|------------------------|------------------|------|
| 없음 | `-name *.log` | `./sub/c.log` 를 찾습니다. 우연히 동작한 경우입니다 |
| `a.log` | `-name a.log` | `./a.log` 만 나오고 `./sub/c.log` 를 놓칩니다. 종료 코드는 0 입니다 |
| `a.log` `b.log` | `-name a.log b.log` | `find: paths must precede expression: 'b.log'` 로 끝나고 종료 코드는 1 입니다 |

`-name '*.log'` 로 감싸면 세 경우 모두 `./a.log` `./b.log` `./sub/c.log` 가 나옵니다.

### 찾은 이름을 명령에 넘기기

| 형태 | 명령이 실행되는 횟수 | 쓰는 때 |
|------|--------------------|--------|
| `-exec CMD {} \;` | 파일마다 한 번 | 파일을 하나씩 다뤄야 할 때 |
| `-exec CMD {} +` | 이름을 명령 뒤에 모아 붙여 훨씬 적게[^find-exec] | `ls`·`chown`·`rm` 처럼 인자를 여럿 받는 명령 |
| `-print0 \| xargs -0 CMD` | xargs 가 이름을 모아 실행 | 파이프 뒤에서 xargs 옵션을 쓸 때 |

```bash
# 매칭된 파일마다 echo 명령을 한 번씩 실행한다
find . -name '*.log' -exec echo run: {} \;
```

```bash
run: ./1.log
run: ./2.log
run: ./3.log
```

```bash
# 매칭된 모든 파일 이름을 뒤에 모아 붙여 echo 명령을 한 번만 실행한다
find . -name '*.log' -exec echo run: {} +
```

```bash
run: ./1.log ./2.log ./3.log
```

파이프로 넘길 때는 구분자가 문제입니다. xargs 는 기본으로 공백과 줄바꿈에서 입력을 끊으므로 이름에 공백이 든 파일이 두 인자로 쪼개집니다.[^xargs] `-print0` 은 이름 끝에 널 바이트를 붙이고 `xargs -0` 은 널에서만 끊습니다.

![xargs 는 구분자에서 이름을 끊는다](./_assets/00-01.find-handoff.svg)

```bash
# 공백이 든 파일 이름이 공백에서 둘로 쪼개져 실패한다
find . -name '*.gz' | xargs ls -l
```

```bash
ls: cannot access './old': No such file or directory
ls: cannot access 'report.gz': No such file or directory
-rw-r--r-- 1 root root 0 Nov 10 04:57 ./plain.gz
```

```bash
# 널 구분자(-print0, -0)로 공백이 든 이름도 안전하게 넘긴다
find . -name '*.gz' -print0 | xargs -0 ls -l
```

```bash
-rw-r--r-- 1 root root 0 Nov 10 04:57 ./old report.gz
-rw-r--r-- 1 root root 0 Nov 10 04:57 ./plain.gz
```

`ls` 대신 `rm` 이었다면 쪼개진 이름 `./old` 와 `report.gz` 가 삭제 대상이 됩니다. 같은 디렉터리에 `old` 라는 파일을 두고 `find . -name '*.gz' | xargs rm -f --` 를 돌려 보았습니다. `old` 가 지워지고 `old report.gz` 는 남습니다. xargs 는 입력이 비어도 명령을 한 번 실행하므로 `-r` 로 막습니다. xargs 의 나머지 쓰임은 [3장 둘째 편](./03-02.%EC%9E%90%EC%A3%BC%20%EC%B9%98%EB%8A%94%20%EA%B2%83%EC%9D%BC%EC%88%98%EB%A1%9D%20%EC%A7%A7%EC%95%84%EC%95%BC%20%ED%95%9C%EB%8B%A4.md)에 있습니다.

### 지우기 전에 -print 로 확인

`-delete` 도 식의 하나라서 조건보다 앞에 두면 시작 경로 아래를 전부 지웁니다.[^find-delete] 같은 조건에 `-print` 를 달아 목록을 먼저 보고, 그 자리만 `-delete` 로 바꿉니다.

```bash
# 지우기 전에 대상 파일 목록을 먼저 확인한다
find logs -name '*.log' -mtime +30 -print
```

```bash
logs/app.log
```

```bash
# 확인한 대상 파일만 삭제한다
find logs -name '*.log' -mtime +30 -delete
ls logs
```

```bash
keep.txt
new.log
```

같은 디렉터리를 다시 만들어 `-delete` 를 앞에 두면 조건과 상관없이 `logs` 까지 사라집니다.

```bash
# -delete 가 조건 앞에 오면 조건을 따지지 않고 logs 디렉터리까지 지운다
find logs -delete -name '*.log' -mtime +30
```

```bash
find: 'logs/new.log': No such file or directory
```

```bash
# logs 디렉터리 자체가 사라졌음을 확인한다
ls logs
```

```bash
ls: cannot access 'logs': No such file or directory
```

### find 레시피

```bash
# 바뀐 지 31일째부터인 로그 목록 확인
find /var/log -name '*.log' -mtime +30 -print

# 같은 조건으로 오래된 로그 파일 삭제
find /var/log -name '*.log' -mtime +30 -delete

# 오래된 압축 파일을 지운다(-- 뒤는 - 로 시작해도 이름으로 읽힌다, §3)
find /var/log -name '*.gz' -mtime +30 -print0 | xargs -0 -r rm -f --

# 루트 파일시스템(-xdev) 안에서 500MiB 를 넘는 파일을 나열
find / -xdev -type f -size +500M -exec ls -lh {} +

# deploy.stamp 보다 나중에 바뀐 설정 파일 찾기
find /etc -name '*.conf' -newer deploy.stamp

# alice 소유 파일의 소유자를 bob 으로 일괄 변경
find /srv/app -user alice -exec chown bob {} +
```

| 명령 | 하는 일 · 주의 |
|------|---------------|
| `find /var/log -name '*.log' -mtime +30 -print` | 바뀐 지 31일째부터인 로그 목록을 봅니다 |
| `find /var/log -name '*.log' -mtime +30 -delete` | 같은 조건으로 지웁니다 |
| `find /var/log -name '*.gz' -mtime +30 -print0 \| xargs -0 -r rm -f --` | 오래된 압축 파일을 지웁니다. `--` 뒤는 `-` 로 시작해도 이름으로 읽힙니다[^rm] |
| `find / -xdev -type f -size +500M -exec ls -lh {} +` | 루트 파일시스템 안에서 500MiB 를 넘는 파일을 나열합니다 |
| `find /etc -name '*.conf' -newer deploy.stamp` | `deploy.stamp` 보다 나중에 바뀐 설정 파일을 찾습니다 |
| `find /srv/app -user alice -exec chown bob {} +` | alice 소유 파일의 소유자를 bob 으로 바꿉니다 |

## 참고 자료

- 《Learning Modern Linux》 Michael Hausenblas, O'Reilly Media, 2022. ISBN 978-1-098-10894-6
- Carla Schroder, 《Linux Cookbook》(O'Reilly) — 더 넓은 레시피 모음
- [Modern UNIX](https://github.com/ibraheemdev/modern-unix) — 계속 갱신되는 현대 도구 목록
- The Changelog 팟캐스트의 현대 UNIX 도구 편
- man7.org 의 [find(1)](https://man7.org/linux/man-pages/man1/find.1.html) · [xargs(1)](https://man7.org/linux/man-pages/man1/xargs.1.html) · [hwclock(8)](https://man7.org/linux/man-pages/man8/hwclock.8.html) · [timedatectl(1)](https://man7.org/linux/man-pages/man1/timedatectl.1.html)

[^date]: [date(1)](https://man7.org/linux/man-pages/man1/date.1.html) (GNU coreutils 9.11) — `%:z` 는 "+hh:mm numeric time zone (e.g., -04:00)" 입니다.

[^git-diff]: [git-diff(1)](https://man7.org/linux/man-pages/man1/git-diff.1.html) (Git 2.55) — `--color-moved` 는 "Moved lines of code are colored differently." 입니다.

[^head]: [head(1)](https://man7.org/linux/man-pages/man1/head.1.html) (GNU coreutils 9.11) — 접미사 `M` 은 1024×1024, `MB` 는 1000×1000 입니다. 컨테이너에서 `yes | tr \\n x | head -c 450m | wc -c` 는 `471859200`, `head -c 450MB` 는 `450000000` 을 냈습니다.

[^hwclock]: [hwclock(8)](https://man7.org/linux/man-pages/man8/hwclock.8.html) (util-linux 2.43) — 하드웨어 클럭은 "operates when the machine is powered off", 시스템 클럭은 "the number of seconds since 00:00:00 January 1, 1970 UTC" 이고, 하드웨어 클럭의 쓸모는 "to keep time when Linux is not running so that the System Clock can be initialized from it at boot" 입니다.

[^hwclock-11]: [hwclock(8)](https://man7.org/linux/man-pages/man8/hwclock.8.html) 의 "Automatic Hardware Clock Synchronization by the Kernel" 절 — 동기 상태의 커널은 "copies the System Time to the Hardware Clock every 11 minutes" 이며 커널 빌드 때 켜는 옵션입니다.

[^localtime]: [localtime(5)](https://man7.org/linux/man-pages/man5/localtime.5.html) — `/etc/localtime` 은 `/usr/share/zoneinfo/` 아래를 가리키는 심볼릭 링크이고 "used by applications for presentation to the user" 입니다. 컨테이너에서 `date +%s` 와 `TZ=Asia/Seoul date +%s` 는 같은 값을 냈습니다.

[^timedatectl]: [timedatectl(1)](https://man7.org/linux/man-pages/man1/timedatectl.1.html) — `set-timezone` 은 "This call will alter the /etc/localtime symlink." 입니다. `timesync-status` 는 systemd-timesyncd 전용이고 systemd 239 에서 들어왔습니다.

[^systemctl]: [systemctl(1)](https://man7.org/linux/man-pages/man1/systemctl.1.html) — `is-active` 는 "Returns an exit code 0 if at least one is active, or non-zero otherwise." 입니다.

[^find-and]: [find(1)](https://man7.org/linux/man-pages/man1/find.1.html) — "Two expressions in a row are taken to be joined with an implied -a; expr2 is not evaluated if expr1 is false."

[^find-print]: [find(1)](https://man7.org/linux/man-pages/man1/find.1.html) — "The -print action is performed on all files for which the whole expression is true, unless it contains an action other than -prune or -quit."

[^find-global]: [find(1)](https://man7.org/linux/man-pages/man1/find.1.html) — "global options should be specified on the command-line after the list of start points, just before the first test, positional option or action."

[^find-num]: [find(1)](https://man7.org/linux/man-pages/man1/find.1.html) — 숫자 인자는 "+n for greater than n, -n for less than n, n for exactly n" 입니다.

[^find-round]: [find(1)](https://man7.org/linux/man-pages/man1/find.1.html) — `-atime` 항목의 "any fractional part is ignored, so to match -atime +1, a file has to have been accessed at least two days ago" 를 `-mtime` 이 그대로 따릅니다. `-size` 는 올림이라 "-size -1M is not equivalent to -size -1048576c. The former only matches empty files" 입니다.

[^find-quote]: [find(1)](https://man7.org/linux/man-pages/man1/find.1.html) 의 `-name` 항목 — "Don't forget to enclose the pattern in quotes in order to protect it from expansion by the shell."

[^find-exec]: [find(1)](https://man7.org/linux/man-pages/man1/find.1.html) — `-exec command {} +` 는 "the command line is built by appending each selected file name at the end; the total number of invocations of the command will be much less than the number of matched files" 입니다.

[^find-delete]: [find(1)](https://man7.org/linux/man-pages/man1/find.1.html) 의 `-delete` 항목 — "putting -delete first will make find try to delete everything below the starting points you specified."

[^xargs]: [xargs(1)](https://man7.org/linux/man-pages/man1/xargs.1.html) — 입력 항목은 "delimited by blanks ... or newlines" 이고, `-0` 을 주면 "Input items are terminated by a null character instead of by whitespace" 입니다. `-r` 은 입력이 비면 명령을 실행하지 않습니다.

[^rm]: [rm(1)](https://man7.org/linux/man-pages/man1/rm.1.html) — `-` 로 시작하는 이름은 `rm -- -foo` 로 지웁니다.
