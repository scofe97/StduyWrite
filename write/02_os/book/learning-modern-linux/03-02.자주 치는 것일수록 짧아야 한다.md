# 자주 치는 것일수록 짧아야 한다

---

> 아주 자주 쓰는 명령일수록 가장 적은 노력이 들어야 한다는 것이 이 구간을 여는 원칙입니다.

## 핵심 요약

> 이 구간 전체가 매달린 하나의 생각은 터미널에서 손이 덜 가게 만드는 방법이 세 층으로 쌓인다는 것입니다.

지금 쓰는 셸 안에서 줄이는 층, 셸 자체를 갈아 끼우는 층, 그리고 터미널을 쪼개 쓰는 층입니다. 첫 층은 이미 가진 것으로 하는 일입니다. 자주 보는 `git diff --color-moved` 를 `d` 한 글자로 줄여 씁니다. 커서를 줄 앞으로 옮기고 왼쪽을 지우는 단축키도 여기 듭니다. 편집기를 열지 않고 텍스트를 다루는 일도 같은 층입니다. 행을 고르는 `grep` 과 열을 뽑는 `awk`, 세는 `sort` 와 `uniq` 를 파이프로 이으면 로그 수만 줄이 답 몇 줄로 줄어듭니다.

둘째 층은 셸을 바꾸는 것입니다. bash 는 1980년대 말부터 있었고 나이가 드러날 때가 있다는 것이 저자의 진단입니다. Fish 는 히스토리를 따로 관리하지 않고 그냥 치면 이전 실행이 나옵니다. 명령마다 자동 제안도 내놓습니다. 셋째 층은 터미널 자체를 다중화하는 것입니다. 창을 여러 개 띄우는 대신 세션 하나 안에서 윈도와 페인으로 나눕니다. 셸을 닫아도 그 상태가 남게 하는 것이 핵심입니다. 저자가 잡 컨트롤 대신 이쪽을 권한 이유를 여기서 채웁니다. 터미널이 끊길 때 무엇이 죽고 무엇이 남는지는 `nohup`, `setsid`, tmux 가 각각 다르게 답합니다.

세 층 가운데 저자가 자기 선택을 밝히는 곳은 둘째와 셋째입니다. 셸은 Fish 를 쓰되 취향이라 못 박지 않습니다. 멀티플렉서는 tmux 를 쓰라고 분명히 말합니다. 2절의 `sed` 소절, 3절과 4절, 5절의 인증서 예, 8절의 세션 분리 명령은 책에 없는 내용입니다. 근거는 각주에 단 공식 매뉴얼입니다. 출력은 Debian 12 컨테이너에서 직접 돌려 얻었습니다.



## 학습 목표

> 이 구간을 읽고 나면 아래 다섯 가지를 스스로 해낼 수 있습니다.

1. 자주 쓰는 명령을 줄이는 방법을 셸별로 구분하고, 셸을 고를 때 던질 두 물음을 댈 수 있습니다.
2. 편집기를 열지 않고 파일을 만들고 덧붙이며, `sed` 로 줄을 바꾸거나 골라낼 수 있습니다.
3. `grep`, `awk`, `sort`, `uniq` 를 파이프로 이어 로그에서 개수를 세고, 문자열 비교와 숫자 비교가 갈리는 결과를 예측할 수 있습니다.
4. 에포크 초로 두 날짜의 차이를 계산하고 2038년에 무슨 일이 생기는지 설명할 수 있습니다.
5. tmux 의 세 단위를 설명하고, 터미널이 끊길 때 `nohup`, `setsid`, tmux 가 각각 무엇을 남기는지 비교할 수 있습니다.

아래는 이 문서 전체를 읽는 순서로 이은 지도입니다. 칸마다 절 번호와 그 절이 답하는 물음 하나를 적었습니다. 색이 붙은 칸이 저자가 셸 선택을 밝히는 자리입니다.

![3장 가운데 구간 노트 전체 지도](./_assets/03-02.chapter-overview.svg)

## 1. 자주 치는 명령 줄이기: 별칭·축약·함수

> 인터페이스에 관한 기본 통찰 하나를 셸에 적용하면 이 절이 나옵니다. 아주 자주 쓰는 명령일수록 입력이 빨라야 한다는 것입니다.

자주 보는 `git diff --color-moved` 를 `d` 한 글자로 줄일 수 있습니다. bash 에서는 별칭, Fish 에서는 축약이라 부릅니다. Fish 의 축약은 인자를 받지 않는 단순 명령에 알맞습니다.

```bash
abbr -a -U -- d 'git diff --color-moved'
abbr -a -U -- k kubectl
abbr -a -U -- l 'exa --long --all --git'
abbr -a -U -- s 'git status'
abbr -a -U -- cat bat
```

`exa` 는 유지보수가 끝나 `l` 축약을 그대로 옮기면 설치부터 막히므로 후속 포크인 `eza` 로 바꿔 넣습니다([앞 노트](./03-01.%EC%85%B8%EC%9D%98%20%EC%8B%A4%EC%B2%B4%EB%8A%94%20%EC%8A%A4%ED%8A%B8%EB%A6%BC%EA%B3%BC%20%EB%B3%80%EC%88%98%EC%99%80%20%EC%A2%85%EB%A3%8C%20%EC%83%81%ED%83%9C%EB%8B%A4.md)). 인자를 받거나 여러 동작을 묶을 때는 함수를 씁니다.

```bash
function c
      git add --all
      git commit -m "$argv"
end
```

## 2. 편집기를 열지 않고 텍스트를 다루기

> 한 줄을 넣자고 매번 편집기를 띄우고 싶지는 않습니다. 스크립트 안에서는 아예 그럴 수도 없습니다.

리다이렉션과 기본 도구로 파일 생성과 치환, 비교를 처리합니다.

```bash
echo "First line" > /tmp/something
echo "Second line" >> /tmp/something
sed 's/line/LINE/' /tmp/something
cat << 'EOF' > /tmp/another
First line
Second line
Third line
EOF
diff -y /tmp/something /tmp/another
```

`>` 는 파일 생성·덮어쓰기이고 `>>` 는 덧붙이기입니다. `<<` (히어 도큐먼트)는 여러 줄을 한 번에 넣을 때 쓰며 `diff -y` 는 두 파일을 나란히 비교합니다. 명령 출력을 파일처럼 견줄 때는 bash 의 프로세스 치환 `<(명령)` 을 씁니다.[^bash-procsub] 아래는 `1 kim`, `2 lee`, `3 park` 세 줄이 든 `names.txt` 를 견준 것입니다. 이 노트의 코드 블록에서 짧은 출력은 명령 옆이나 아래의 `#` 주석으로 적고, 세 줄 이상인 출력은 바로 아래 별도 블록에 둡니다.

```bash
diff -u names.txt <(sed 's/lee/yi/' names.txt)
```

```bash
--- names.txt	2026-11-10 02:22:23.359479222 +0000
+++ /dev/fd/63	2026-11-10 02:22:23.367479126 +0000
@@ -1,3 +1,3 @@
 1 kim
-2 lee
+2 yi
 3 park
```

둘째 줄의 `/dev/fd/63` 이 `<(…)` 가 만든 파일 이름입니다. 서버 둘의 설정을 견줄 때도 `diff <(ssh web1 cat 파일) <(ssh web2 cat 파일)` 꼴을 씁니다. 대상 서버가 여럿이면 `ssh 서버 md5sum 파일` 로 해시부터 견주고 다른 서버만 `diff` 로 엽니다. `-u` 통합 형식과 `-r` 재귀 비교는 [레시피 시트](./00-01.%EB%A0%88%EC%8B%9C%ED%94%BC%EC%99%80%20%ED%98%84%EB%8C%80%20%EB%8F%84%EA%B5%AC%20%EC%B0%B8%EC%A1%B0%20%EC%8B%9C%ED%8A%B8.md)에 있습니다.

### sed 로 줄을 바꾸고 골라내기

`sed` 는 입력을 한 줄씩 패턴 스페이스 버퍼에 올려 명령을 적용하고 끝에 이르면 버퍼를 출력한 뒤 다음 줄을 읽습니다. `-n` 을 주면 자동 출력이 꺼져 `p` 명령을 만난 줄만 나옵니다.[^sed-cycle]

![sed 가 한 줄을 읽어 바꾸고 내보내는 한 바퀴](./_assets/03-02.sed-cycle.svg)

| 하려는 일 | 명령 |
|---|---|
| 줄마다 첫 일치만 · 모든 일치 · 대소문자 무시하고 바꾸기 | `sed 's/foo/bar/'` · `'s/foo/bar/g'` · `'s/foo/bar/gI'` |
| 10행부터 20행만 · 두 패턴 사이만 출력 | `sed -n '10,20p'` · `sed -n '/WARN/,/reset/p'` |
| `#` 로 시작하는 줄과 빈 줄 지우기 | `sed '/^#/d; /^$/d'` |
| 3행 앞에 한 줄 넣기 · 뒤에 넣기 | `sed '3i\새 줄'` · `sed '3a\새 줄'` |
| 그룹을 잡아 순서 바꾸기 · 줄 끝 공백 지우기 | `sed -E 's/^([^=]+)=(.*)$/\2=\1/'` · `sed 's/[[:space:]]*$//'` |
| 맞은 줄에서 값만 뽑기 | `sed -n 's/^version=//p'` |

`gI` 의 `I` 는 대소문자를 가리지 않게 하는 GNU 확장입니다. `s` 뒤의 구분자는 `/` 가 아니어도 되므로 경로처럼 `/` 가 든 값을 바꿀 때는 다른 글자를 고릅니다.[^sed-s]

```bash
echo 'foo Foo foo' | sed 's/foo/bar/'               # bar Foo foo
echo 'foo Foo foo' | sed 's/foo/bar/g'              # bar Foo bar
echo 'foo Foo foo' | sed 's/foo/bar/gI'             # bar bar bar
echo '/usr/local/bin' | sed 's|/usr/local|/opt|'    # /opt/bin
echo 'name=app' | sed -E 's/^([^=]+)=(.*)$/\2=\1/'  # app=name
```

`sed` 는 결과를 `stdout` 으로 낼 뿐 파일은 그대로 둡니다. 파일을 직접 고칠 때는 `-i` 를 줍니다.[^sed-i] 제자리 수정은 되돌릴 길이 없으므로 먼저 `-i` 없이 결과를 확인하고 `-i.bak` 으로 원본을 남깁니다.

```bash
cat > sshd_config << 'EOF'
# This is the sshd server system-wide configuration file.

Port 22
#PermitRootLogin prohibit-password
PasswordAuthentication yes
  # indented comment

X11Forwarding no
EOF
sed -E 's/^#?PermitRootLogin.*/PermitRootLogin no/' sshd_config | grep -n PermitRootLogin
# 4:PermitRootLogin no
sed -i.bak -E 's/^#?PermitRootLogin.*/PermitRootLogin no/' sshd_config
ls sshd_config*                                     # sshd_config  sshd_config.bak
```

`^#?` 는 줄 맨 앞에 `#` 가 있어도 없어도 맞으므로 주석 처리된 줄과 풀린 줄을 한 번에 맞춥니다.

### 긴 파일을 보는 법

긴 파일에는 `less` 나 `bat` 같은 페이저를 쓰며 일부만 볼 때는 `head` 와 `tail` 을 씁니다.

```bash
head -5 /tmp/longfile
sudo tail -f /var/log/Xorg.0.log
```

`-f` 는 열린 파일 디스크립터를 따라가므로 로그 로테이션으로 이름이 바뀌면 옛 파일에 머뭅니다. `-F` 는 파일 이름을 따라가 사라지면 다시 엽니다.[^tail]

```bash
echo one > r.log
tail -F r.log &
mv r.log r.log.1; echo two > r.log; echo three >> r.log
```

```bash
one
tail: 'r.log' has been replaced;  following new file
two
three
```

같은 순서를 `tail -f` 로 돌리면 `one` 에서 멈춥니다. 바이트 단위는 `head -c 19 app.log` 처럼 자릅니다. 화면과 파일에 동시 기록하는 `tee` 는 [8장 노트](./08-01.%EC%9E%AC%EB%8A%94%20%EA%B2%83%EC%9D%80%20%EB%B0%94%EA%B9%A5%EC%9D%B4%EA%B3%A0%20%EC%95%8C%EA%B3%A0%20%EC%8B%B6%EC%9D%80%20%EA%B2%83%EC%9D%80%20%EC%95%88%EC%9D%B4%EB%8B%A4.md)가 설명합니다.



## 3. 행을 고르고 열을 뽑기: grep·cut·awk

> 로그가 수만 줄이어도 필요한 것은 그중 몇 줄이고, 그 줄에서도 한두 칸입니다. 행을 고르는 도구와 열을 뽑는 도구를 파이프로 이으면 편집기를 열지 않고 그 칸까지 갑니다.

파이프 원리는 [앞 노트](./03-01.%EC%85%B8%EC%9D%98%20%EC%8B%A4%EC%B2%B4%EB%8A%94%20%EC%8A%A4%ED%8A%B8%EB%A6%BC%EA%B3%BC%20%EB%B3%80%EC%88%98%EC%99%80%20%EC%A2%85%EB%A3%8C%20%EC%83%81%ED%83%9C%EB%8B%A4.md) 2절에 있습니다. 아래 예는 일곱 줄짜리 `app.log` 를 씁니다.

```bash
2026-11-10 09:01:15 INFO  order-api started
2026-11-10 09:14:40 ERROR payment timeout orderId=1001
2026-11-10 09:14:41 WARN  retrying orderId=1001
2026-11-10 09:20:02 ERROR payment timeout orderId=1002
2026-11-10 10:06:01 error db connection reset
2026-11-10 10:06:02 [ERROR] pool exhausted, errors=3
2026-11-10 11:30:00 INFO  heartbeat
```

### grep 으로 행 고르기

`grep 패턴 파일` 은 패턴과 맞는 줄만 내보냅니다. 옵션은 일치 기준, 검색 대상, 출력 형식으로 갈립니다.[^grep]

| 물음 | 옵션 | 하는 일 |
|---|---|---|
| 무엇을 일치로 보나 | `-i` | 대소문자를 가리지 않음 |
| | `-v` | 맞지 않는 줄을 고름 |
| | `-E` | 확장 정규식. 선택 기호와 `+`, `?`, `{n}` 을 역슬래시 없이 씀 |
| | `-F` | 패턴을 정규식이 아니라 글자 그대로 찾음 |
| | `-w` · `-x` | 단어 단위로 맞음 · 줄 전체가 맞아야 함 |
| 어디를 읽나 | `-r` | 디렉터리 아래를 재귀로 읽음 |
| | `--include='*.conf'` | 재귀 검색에서 이름이 맞는 파일만 읽음 |
| 무엇을 찍나 | `-n` · `-c` | 줄 번호를 앞에 붙임 · 맞은 줄 수만 냄 |
| | `-l` · `-o` | 맞은 파일의 이름만 냄 · 맞은 부분만 냄 |
| | `-A n` · `-B n` · `-C n` | 맞은 줄의 뒤 · 앞 · 앞뒤 n줄을 함께 냄 |

패턴은 기본이 정규식이라 눈에 보이는 글자 그대로 찾지 않을 때가 있습니다.

```bash
grep -c '[ERROR]' app.log        # 6
grep -F '[ERROR]' app.log        # 2026-11-10 10:06:02 [ERROR] pool exhausted, errors=3
grep 'WARN|ERROR' app.log        # 출력 없음
grep -w error app.log            # 2026-11-10 10:06:01 error db connection reset
grep -E 'WARN|\[ERROR\]' app.log
# 2026-11-10 09:14:41 WARN  retrying orderId=1001
# 2026-11-10 10:06:02 [ERROR] pool exhausted, errors=3
```

기본 정규식에서 대괄호는 문자 집합이라 `[ERROR]` 는 한 글자라도 든 줄에 맞습니다. 문자열 그대로 찾으려면 `-F` 를 줍니다. 세로 막대(|)로 둘 중 하나를 찾으려면 확장 정규식 `-E` 가 필요하며 `-w` 는 단어 단위로 일치시켜 `errors=3` 을 거릅니다. 문맥 옵션과 역일치(`-v`)는 아래처럼 씁니다.

```bash
grep -n -B1 -A1 WARN app.log
grep -vE '^[[:space:]]*(#|$)' sshd_config
```

```bash
2-2026-11-10 09:14:40 ERROR payment timeout orderId=1001
3:2026-11-10 09:14:41 WARN  retrying orderId=1001
4-2026-11-10 09:20:02 ERROR payment timeout orderId=1002
Port 22
PasswordAuthentication yes
X11Forwarding no
```

맞은 줄 번호 뒤에는 `:` 가 붙고 문맥 줄에는 `-` 가 붙습니다. `sshd_config` 는 2절에서 고치기 전의 파일입니다. `grep -v '^#'` 만 쓰면 빈 줄과 들여 쓴 주석이 남고 2절 표의 `sed '/^#/d; /^$/d'` 도 들여 쓴 주석은 못 지웁니다. 줄 머리 공백까지 `[[:space:]]*` 로 받아야 세 줄만 남습니다. 아래 `auth.log` 에는 로그인 실패가 세 줄 있고, `conf/` 에는 `timeout=30` 인 `a.conf` 와 `c.txt`, `timeout=60` 인 `b.conf` 가 있습니다.

```bash
grep -c 'Failed password' auth.log               # 3
grep -rl --include='*.conf' 'timeout=30' conf    # conf/a.conf
zgrep -c ERROR app.log.1.gz                      # 3
grep -o 'orderId=[0-9]*' app.log | tr '\n' ' '   # orderId=1001 orderId=1001 orderId=1002
```

`c.txt` 는 `--include` 가 걸러 냈습니다. `zgrep` 은 압축 로그를 풀지 않고 검색하며 옵션은 그대로 `grep` 에 넘깁니다.[^zgrep] `grep` 종료 상태는 맞으면 0, 없으면 1, 오류면 2입니다. `if grep -q` 처럼 조건식에 씁니다([앞 노트](./03-01.%EC%85%B8%EC%9D%98%20%EC%8B%A4%EC%B2%B4%EB%8A%94%20%EC%8A%A4%ED%8A%B8%EB%A6%BC%EA%B3%BC%20%EB%B3%80%EC%88%98%EC%99%80%20%EC%A2%85%EB%A3%8C%20%EC%83%81%ED%83%9C%EB%8B%A4.md) 4절).

### cut 과 awk 로 열 뽑기

단순 구분자 분리에는 `cut` 을 씁니다. `-d` 로 구분자, `-f` 로 칸 번호, `-c` 로 글자 위치를 지정합니다.

```bash
cut -d: -f1,7 /etc/passwd | head -2
# root:/bin/bash
# daemon:/usr/sbin/nologin
cut -c1-10 app.log | head -1                     # 2026-11-10
```

`cut` 은 구분자 하나를 칸 경계 하나로 세므로 공백이 둘 이어지면 그 사이에 빈 칸이 생깁니다. `echo 'a  b' | cut -d' ' -f2` 는 빈 줄을, `echo 'a  b' | awk '{print $2}'` 는 `b` 를 냅니다. 공백으로 줄을 맞춘 출력에는 `awk` 를 씁니다.

`awk` 는 연속 공백을 하나의 구분자로 묶고 칸을 `$1`, `$2` 로 부릅니다.[^gawk-fields] 구분자는 `-F:` 처럼 바꿉니다. `$0` 은 줄 전체, `NF` 는 칸 수, `NR` 은 읽은 줄 번호, `$NF` 는 마지막 칸입니다. 프로그램 구조는 `패턴 { 동작 }` 입니다. 패턴이 참인 줄에서만 동작을 실행하고, 동작을 빼면 그 줄을 그대로 찍으며 패턴을 빼면 모든 줄에서 실행합니다. `BEGIN` 은 첫 줄 전, `END` 는 마지막 줄 뒤에 한 번씩 돕니다.

![awk 가 df 한 줄을 칸으로 나눠 패턴을 견주고 찍는 과정](./_assets/03-02.awk-record.svg)

입력 `df.txt` 는 `df -P` 의 출력 꼴입니다. `-P` 는 장치 이름이 길어도 파일시스템 하나를 한 줄에 찍으므로 다섯째 칸이 늘 사용률입니다.[^df]

```bash
Filesystem     1024-blocks      Used Available Capacity Mounted on
/dev/sda1         41152736  17283548  21755756      45% /
/dev/sdb1        103081248  97927188         0     100% /data
/dev/sdc1         51474912  46327424   2509728      95% /var/log
tmpfs              8139112         0   8139112       0% /dev/shm
```

```bash
awk '{print NR, NF, $NF}' df.txt | head -2
# 1 7 on
# 2 6 /
awk -F: '$3 >= 1000 && $7 !~ /(nologin|false)$/ {print $1, $3, $7}' /etc/passwd
# dev 1000 /bin/sh
```

머리글 줄은 `Mounted on` 이 두 칸으로 갈려 `NF` 가 7입니다. 둘째 명령은 UID 1000 이상이면서 셸이 `nologin`·`false` 가 아닌 로그인 계정을 `!~` 정규식 부정으로 고릅니다. 컨테이너에 만든 `dev`(1000, `/bin/sh`)와 `svc`(1001, `/usr/sbin/nologin`) 가운데 `dev` 만 나왔습니다. `/etc/passwd` 구조는 [4장 노트](./04-01.%EC%A0%84%EB%B6%80%20%EC%95%84%EB%8B%88%EB%A9%B4%20%EC%A0%84%EB%AC%B4%EC%97%90%EC%84%9C%20%EC%9E%98%EA%B2%8C%20%EC%AA%BC%EA%B0%9C%EB%8A%94%20%EC%AA%BD%EC%9C%BC%EB%A1%9C.md)에 있습니다.

### awk 비교가 문자열로 떨어질 때

사용률 90% 이상을 고를 때 `$5 >= 90` 으로 쓰면 100% 를 놓칩니다.

```bash
awk 'NR>1 && $5 >= 90 {print $6, $5}' df.txt      # /var/log 95%
awk 'NR>1 && $5+0 >= 90 {print $6, $5}' df.txt
# /data 100%
# /var/log 95%
```

`awk` 는 칸 내용이 숫자 꼴일 때만 숫자로 비교합니다. `95%` 는 `%` 때문에 문자열이며 한쪽이 문자열이면 문자열 비교가 되어 앞 글자부터 견주므로 `100%` 가 `90` 보다 작습니다.[^gawk-cmp] `$5+0` 처럼 산술 연산을 걸면 앞머리의 숫자 부분만 수로 바뀝니다(100% 는 100).[^gawk-conv] `NR>1` 이 없으면 머리글 `Capacity` 까지 내보내며, `grep '9[0-9]%'` 같은 패턴 매칭은 100% 를 놓치므로 임계 비교는 칸을 숫자로 바꿔서 합니다.

자주 쓰는 꼴은 아래와 같습니다. `access.log` 는 일곱 줄짜리 접근 로그로 첫 칸이 클라이언트 IP, 아홉째 칸이 상태 코드입니다.

```bash
awk -v limit=90 'NR>1 && $5+0 >= limit {print $6}' df.txt | tr '\n' ' '   # /data /var/log
awk 'NR>1 {sum += $3} END {print sum}' df.txt                     # 161538160
awk 'BEGIN {OFS=","} NR>1 {$1=$1; print}' df.txt | head -1        # /dev/sda1,41152736,17283548,21755756,45%,/
awk '$9 == 500 {n++} END {print n}' access.log                    # 3
awk 'NR>1 {printf "%-10s %5.1f%%\n", $6, $3/$2*100}' df.txt | head -2
# /           42.0%
# /data       95.0%
awk '{count[$1]++} END {for (ip in count) print count[ip], ip}' access.log | sort -rn
# 4 10.0.0.7
# 2 10.0.0.9
# 1 10.0.0.3
free -m | awk '/^Mem:/ {printf "%.1f%%\n", $7/$2*100}'           # 76.4%
awk -v n="$(nproc)" '{print ($1 > n ? "over" : "ok"), $1, n}' /proc/loadavg   # ok 0.71 8
```

`-v` 는 외부 변수를 넘길 때 쓰고, `OFS` 출력 구분자를 바꾼 뒤에는 `$1=$1` 처럼 필드를 재할당해야 새 구분자로 조립됩니다.[^gawk-rebuild] 배열 순회 `for (ip in count)` 는 도는 순서가 정해져 있지 않아 `sort -rn` 과 함께 씁니다. `free` 의 `Mem:` 행에서는 일곱째 칸 `available` 을 둘째 칸 `total` 로 나누며,[^free] `/proc/loadavg` 는 첫 칸인 1분 평균 부하를 코어 수와 견줍니다.[^loadavg] 지표 원리는 [8장 둘째 노트](./08-02.%EC%9E%90%EC%9B%90%EB%A7%88%EB%8B%A4%20%EC%B0%BD%EC%9D%B4%20%EB%94%B0%EB%A1%9C%20%EB%82%98%20%EC%9E%88%EC%96%B4%20%EC%96%B4%EB%8A%90%20%EC%B0%BD%EC%9D%84%20%EC%97%AC%EB%8A%90%EB%83%90%EA%B0%80%20%EA%B3%A7%20%EC%A7%84%EB%8B%A8%EC%9D%B4%EB%8B%A4.md)에서 봅니다.



## 4. 세고 정렬하기: sort·uniq·tr·xargs

> 어느 값이 몇 번 나왔는지 세려면 같은 줄을 먼저 붙여 놓아야 합니다. 세는 도구가 바로 이웃한 줄끼리만 견주기 때문입니다.

### 정렬로 같은 줄을 붙여 세기

```bash
grep -oE '^[0-9.]+' access.log | sort | uniq -c | sort -rn
```

```bash
      4 10.0.0.7
      2 10.0.0.9
      1 10.0.0.3
```

![IP 일곱 줄이 정렬되고 세어져 순위가 되는 파이프라인](./_assets/03-02.count-pipeline.svg)

`uniq` 는 이웃한 줄끼리만 비교하므로 `sort` 로 같은 값을 모은 뒤 `uniq -c` 로 세고 `sort -rn` 으로 내림차순 정렬합니다.[^uniq]

| 옵션 | 하는 일 |
|---|---|
| `-n` · `-r` | 숫자로 견줌(키 앞머리의 숫자 부분을 읽음) · 순서를 뒤집음 |
| `-k N` · `-t 글자` | N번째 칸부터를 키로 삼음 · 칸 구분자를 정함 |
| `-u` · `-h` | 같은 줄은 하나만 남김 · `3K`, `12M`, `1.5G` 같은 크기 표기를 크기 순으로 견줌 |

```bash
printf '10\n9\n100\n' | sort | tr '\n' ' '                # 10 100 9
printf '10\n9\n100\n' | sort -n | tr '\n' ' '             # 9 10 100
printf '1.5G\n200M\n3K\n12M\n' | sort -h | tr '\n' ' '    # 3K 12M 200M 1.5G
awk 'NR>1' df.txt | sort -k5 -rn | head -2
# /dev/sdb1        103081248  97927188         0     100% /data
# /dev/sdc1         51474912  46327424   2509728      95% /var/log
```

기본 정렬은 문자열 기준이라 `100` 이 `9` 앞에 옵니다. `sort -n` 은 앞머리의 숫자 부분만 읽어 정렬하므로 `%` 가 붙은 칸도 숫자로 정렬됩니다.[^sort]

```bash
grep ERROR app.log | cut -d' ' -f2 | cut -c1-2 | sort | uniq -c
#       2 09
#       1 10
wc app.log                  #   7  38 337 app.log
ls /proc/$$/fd | wc -l      # 3
```

`wc` 는 줄 수, 단어 수, 바이트 수를 차례로 내고 `wc -l` 은 줄 수만 냅니다. 마지막 줄의 3 은 셸이 연 파일 디스크립터 0, 1, 2 입니다. `uniq -d` 는 두 번 이상 나온 줄만 뽑습니다. Unix 파이프라인을 배치 처리 원형으로 보는 관점은 [DDIA 11장 노트](../../../05_data/book/designing-data-intensive-applications/11-01.%EB%B0%B0%EC%B9%98%20%EC%B2%98%EB%A6%AC%20%EA%B0%9C%EC%9A%94%EC%99%80%20Unix%20%EB%8F%84%EA%B5%AC.md) 2절에 있습니다.

### 글자 바꾸기와 칸 맞추기

`tr` 은 글자 단위 치환, 삭제(`-d`), 연속 문자 축약(`-s`)을 합니다.

```bash
echo 'Com_Acme' | tr '_A-Z' '.a-z'                     # com.acme
echo 'a    b   c' | tr -s ' '                          # a b c
printf 'a\r\nb\r\n' | tr -d '\r' | od -c | head -1     # 0000000   a  \n   b  \n
```

윈도우에서 만든 파일은 줄 끝이 `\r\n` 이라 값 끝에 보이지 않는 `\r` 이 붙습니다. `tr -d '\r'` 로 지우고 `od -c` 로 남았는지 봅니다. 아래 `teams.txt` 에는 `1 dev`, `3 ops` 두 줄이 있습니다.

```bash
paste names.txt teams.txt
```

```bash
1 kim	1 dev
2 lee	3 ops
3 park
```

```bash
join names.txt teams.txt | tr '\n' ' '    # 1 kim dev 3 park ops
printf 'svc enabled active\ncron disabled inactive\n' | column -t
# svc   enabled   active
# cron  disabled  inactive
for s in ssh cron nginx; do
  echo "$s $(systemctl is-enabled "$s") $(systemctl is-active "$s")"
done | column -t
```

`paste` 는 같은 줄 번호끼리 탭으로 붙일 뿐이라 `2 lee` 옆에 `3 ops` 가 옵니다. `join` 은 첫 칸이 같은 줄끼리 붙여 짝이 없는 `2 lee` 를 빼며, 두 파일이 그 칸으로 정렬돼 있어야 합니다.[^join] `column -t` 는 공백 출력을 표 형태로 정렬합니다.[^column] `systemctl` 은 [6장 노트](./06-01.%EB%A8%BC%EC%A0%80%20%EC%BC%9C%EC%A7%80%EB%8A%94%20%EA%B2%83%20%ED%95%98%EB%82%98%EA%B0%80%20%EB%82%98%EB%A8%B8%EC%A7%80%20%EC%A0%84%EB%B6%80%EB%A5%BC%20%EC%BC%A0%EB%8B%A4.md) 5절이 다룹니다. 이 반복문은 systemd 가 없는 컨테이너라 돌려 보지 못했습니다. JSON 은 칸이 공백으로 나뉘지 않아 `jq` 가 맡으며 [다음 노트](./03-03.bash%20%EB%8A%94%20%EC%A1%B0%EC%9A%A9%ED%9E%88%20%EC%8B%A4%ED%8C%A8%ED%95%98%EB%AF%80%EB%A1%9C%20%EC%8B%9C%EB%81%84%EB%9F%BD%EA%B2%8C%20%EB%A7%8C%EB%93%A4%EC%96%B4%EC%95%BC%20%ED%95%9C%EB%8B%A4.md)가 다룹니다.

### xargs 로 입력을 인자로 바꾸기

`rm`, `grep -l`, `ssh` 처럼 처리할 대상을 표준 입력이 아니라 인자로 받는 명령이 많습니다. `xargs` 는 표준 입력 항목을 인자로 바꿔 명령을 실행합니다(기본 명령 `echo`).[^xargs]

```bash
printf 'a\nb\nc\nd\ne\n' | xargs echo                  # a b c d e
printf 'a\nb\nc\nd\ne\n' | xargs -t -n 2 echo
```

```bash
echo a b
a b
echo c d
c d
echo e
e
```

![xargs 가 입력 다섯 줄을 두 개씩 묶어 echo 를 세 번 실행](./_assets/03-02.xargs-argv.svg)

`-n` 은 인자를 몇 개씩 끊어 실행할지 정하고 `-t` 는 실행 명령을 먼저 출력합니다. `xargs` 는 기본으로 공백에서도 항목을 끊으므로 공백 파일명은 `find -print0` 과 `xargs -0` 조합으로 널 문자로 전달합니다. 인자 위치를 지정할 때는 `-I{}` 를 씁니다.

```bash
printf 'my file.txt\nb.txt\n' | xargs -n 1 echo | tr '\n' ' '      # my file.txt b.txt
printf 'my file.txt\0b.txt\0' | xargs -0 -n 1 echo
# my file.txt
# b.txt
find conf -name '*.conf' -print0 | xargs -0 grep -l 'timeout=30'    # conf/a.conf
printf 'a\nb\n' | xargs -I{} echo 'file: {} -> {}.bak'
# file: a -> a.bak
# file: b -> b.bak
```

첫 줄의 `my file.txt b.txt` 는 `my`, `file.txt`, `b.txt` 세 줄로 갈린 출력을 한 줄로 이은 것입니다. `-P N` 은 프로세스를 N개까지 병렬로 실행합니다. `sleep 1` 을 네 번 실행하는 데 `xargs -n 1` 은 4.014초, `xargs -n 1 -P 4` 는 1.009초가 걸렸습니다. `find` 조건식은 [레시피 시트](./00-01.%EB%A0%88%EC%8B%9C%ED%94%BC%EC%99%80%20%ED%98%84%EB%8C%80%20%EB%8F%84%EA%B5%AC%20%EC%B0%B8%EC%A1%B0%20%EC%8B%9C%ED%8A%B8.md)에 있습니다.



## 5. 날짜를 숫자로 다루기

> 인증서가 며칠 남았는지 세려면 날짜를 숫자로 바꿔 빼야 합니다. `date` 는 그 변환을 맡고 유일한 파일 이름을 만드는 데도 쓰입니다.

```bash
date +%s                                    # 1629582883
date -d @1629582883 '+%m/%d/%Y:%H:%M:%S'    # 08/21/2021:21:54:43
```

`date -d` 는 GNU coreutils 옵션으로 `@` 뒤 숫자를 에포크 초로 읽습니다(macOS BSD 는 `date -r`).[^date]

### 에포크 초로 남은 날 세기

날짜 차이는 둘 다 에포크 초로 바꿔 뺍니다. `-enddate` 로 뽑은 만료 시각을 `cut` 으로 떼어 에포크 초로 바꾼 뒤 현재 시각과의 차이를 하루의 초(86,400)로 나눕니다.[^x509] 아래는 유효 기간 30일짜리 자체 서명 인증서를 만들어 돌린 결과입니다.

```bash
openssl x509 -enddate -noout -in cert.pem    # notAfter=Dec 10 02:22:33 2026 GMT
end=$(date -d "$(openssl x509 -enddate -noout -in cert.pem | cut -d= -f2)" +%s)
now=$(date +%s)
echo $(( (end - now) / 86400 ))              # 30
```

### 에포크 시간과 2038년

유닉스 에포크 시간은 1970년 1월 1일 0시 UTC 부터 흐른 초의 수이며 모든 날을 정확히 86,400초로 취급합니다. 부호 있는 32비트 정수를 쓰는 시스템은 2038년 1월 19일에 카운터가 넘칩니다(2038년 문제). 최댓값 2,147,483,647 을 `date -u -d @2147483647` 로 바꾸면 `Tue Jan 19 03:14:07 UTC 2038` 이 나옵니다.



## 6. bash 가 사람 친화적이지 않다는 말

> bash 는 여전히 가장 널리 쓰이는 셸이지만 가장 사람 친화적인 셸은 아니라는 것이 저자의 진단입니다. 1980년대 말부터 있었고 그 나이가 가끔 드러납니다.

매일 쓰는 입력은 bash 와 큰 차이가 없지만 Fish 는 대화형 편의성을 앞세웁니다. 히스토리 관리 없이 명령을 치면 이전 실행이 떠서 바로 고르고, 자동 제안과 시각적 힌트(알 수 없는 명령은 빨갛게)를 기본으로 줍니다.

### Fish 의 환경 변수 문법

| 하려는 일 | Fish 명령 |
|---|---|
| 환경 변수 `KEY` 를 값 `VAL` 로 내보내기 · 지우기 | `set -x KEY VAL` · `set -e KEY` |
| 한 명령에만 환경 변수 붙이기 | `env KEY=VAL cmd` |
| 프롬프트의 경로 길이를 1로 | `set -g fish_prompt_pwd_dir_length 1` |
| 축약 관리 · 함수 관리 | `abbr` · `functions` 와 `funcd` |

Fish 는 마지막 명령 종료 상태를 `$?` 가 아니라 `$status` 에 담습니다. 설정은 `fish_config` 명령으로 브라우저를 띄워 확인하고 변경합니다.



## 7. 어느 셸을 고를 것인가

> 저자는 새 셸을 볼 때 두 가지를 자문하라고 합니다. 그 셸의 초점이 대화형 사용인가 스크립팅인가, 그리고 그 주변 커뮤니티가 얼마나 활발한가입니다.

![저자는 두 가지를 물으라 하고 자기 목록에는 답하지 않는다](./_assets/03-02.shell-choice.svg)

저자가 든 셸 가운데 zsh 는 넓은 bash 하위 호환을 유지하고 Fish 는 일상 입력 차이가 적습니다. 나머지 셸의 호환 여부와 커뮤니티 활성도는 책에서 직접 판정하지 않고 목록 전체에 "항상 bash 호환은 아니다" 라는 단서 한 줄만 붙습니다. Oil 은 Python·JavaScript 사용자를 겨냥해 스크립팅에 초점이 있습니다. murex 는 통합 테스트 틀과 타입 파이프라인을 갖춘 POSIX 셸입니다. Nushell 은 표 형태 출력과 질의 언어를 갖췄고 PowerShell 은 의미론과 상호작용이 POSIX 셸과 다릅니다.

`zsh` 는 Bourne 계열로 자동완성과 테마 지원이 뛰어나며 Oh My Zsh 로 기능을 확장합니다. 설정 파일 다섯 개는 `$ZDOTDIR`(없으면 `$HOME`)에서 읽습니다.

| 파일 | 언제 읽히나 |
|---|---|
| `.zshenv` | 셸을 부를 때마다. 검색 경로와 중요한 환경 변수를 넣되 출력을 내거나 tty 를 가정하는 명령은 넣지 않는다 |
| `.zprofile` | `.zlogin` 대신 쓰는 ksh 사용자용. `.zshrc` 보다 먼저 읽히며 둘을 함께 쓰지는 않는다 |
| `.zshrc` | 대화형 셸에서. 별칭·함수·옵션·키 바인딩을 넣는다 |
| `.zlogin` | 로그인 셸에서. 로그인 셸에서만 실행할 명령을 넣고 별칭이나 환경 변수 설정은 넣지 않는다 |
| `.zlogout` | 로그인 셸이 끝날 때 |

### 저자의 결론

저자는 대화형 생산성을 위해 모던 셸을 권합니다. 명령행에서 보내는 시간을 생각하면 여러 셸을 써 보고 고르라는 것입니다. 자신은 Fish 를 쓰고 동료 다수는 zsh 를 쓴다고 밝힙니다. 저자가 꼽는 걸림돌은 원격 시스템과 설치 제약, 호환성과 습관, 그리고 안내 문서 대부분이 `export FOO=BAR` 처럼 bash 를 전제한다는 점입니다. 그래도 대개 자기가 통제하는 환경에서 일하므로 학습 비용은 회수된다고 봅니다.



## 8. 창을 늘리지 않고 하나를 쪼개기: tmux

> 오픈소스 프로젝트를 만지면서 블로그를 쓰고 서버에 붙고 API 를 두드리는 일은 창을 여럿 요구합니다. 그것들을 묶는 단위가 세션입니다.

![세션이 윈도를 담고 윈도가 페인을 담는다](./_assets/03-02.tmux-units.svg)

터미널 작업에는 여러 창 관리, 연결 끊김 시 작업 보존, 분할 화면 조망이라는 요구가 따릅니다. 터미널 멀티플렉서는 입출력을 다중화해 이를 풉니다. 저자는 원조인 `screen` 을 유지보수 정체와 기능 한계 때문에 다른 선택지가 없는 환경이 아니면 권하지 않습니다. 다만 책이 나온 뒤인 2024년 8월에 `screen` 5.0.0 이 나왔습니다.[^screen-rel]

### tmux 를 다루는 명령

세션을 만들 때는 `tmux new -s`, 다시 붙을 때는 `attach -t`, 분리는 `Ctrl+B 다음 d` 를 씁니다(tmux 에서 `D` 는 다른 명령이므로 소문자 `d` 로 칩니다). `attach` 에 `-d` 를 주면 이전 터미널에서 세션을 떼어 내며 붙습니다. 아래 표의 트리거는 기본 Ctrl+B 이며 저자는 손이 쉽게 닿는 안 쓰는 키로 바꾸라고 권합니다.

| 대상 | 하려는 일 | 명령 |
|---|---|---|
| 세션 | 새로 만들기 · 이름 바꾸기 | `:new -s 이름` · 트리거 + `$` |
| 세션 | 전부 나열 · 닫기 | 트리거 + `s` · 트리거 |
| 윈도 | 새로 만들기 · 이름 바꾸기 | 트리거 + `c` · 트리거 + `,` |
| 윈도 | 전환 · 전부 나열 · 닫기 | 트리거 + `1`~`9` · 트리거 + `w` · 트리거 + `&` |
| 페인 | 가로로 쪼개기 · 세로로 쪼개기 | 트리거 + `"` · 트리거 + `%` |
| 페인 | 확대·축소 토글 · 닫기 | 트리거 + `z` · 트리거 + `x` |

`"` 는 위아래로, `%` 는 좌우로 쪼갭니다. 트리거 + `n`·`p` 는 다음·이전 윈도로 옮깁니다. 트리거 + `[` 는 복사 모드로 지난 출력을 보고 `]` 로 붙여 넣습니다.[^tmux-keys] 세션을 밖에서 끝낼 때는 `tmux kill-session -t` 를 씁니다. 대안으로 Zellij, Byobu, tmuxinator 등이 있지만 저자는 성숙도·안정성·생태계가 검증된 tmux 를 쓰라고 명확히 권합니다.

### 터미널이 끊겨도 명령을 살리기

터미널이 닫힐 때 `SIGHUP` 이 전파되는 과정과 `nohup`·`disown` 의 원리는 [03-01 「터미널이 끊길 때 살아남는 잡」](03-01.셸의%20실체는%20스트림과%20변수와%20종료%20상태다.md#터미널이-끊길-때-살아남는-잡)이 설명합니다.[^signal7][^bash-hup] 여기서는 프로세스를 터미널에서 완전히 떼어 내는 `setsid`·tmux·`systemd-run` 에 집중합니다. 한 셸에서 다섯 가지 방식으로 명령을 띄우고 터미널 쪽을 죽인 뒤 `ps` 로 남은 것을 본 결과입니다.

```bash
sleep 301 &
nohup sleep 302 > /dev/null 2>&1 &
setsid sleep 303 < /dev/null > /dev/null 2>&1 &
sleep 304 & disown
tmux new -d -s work "sleep 305"
```

```bash
# 터미널을 죽인 뒤
    PID    PPID    PGID     SID TT       STAT CMD
    252       1     252     250 ?        S    sleep 302
    254       1     254     250 ?        S    sleep 304
    256       1     256     256 ?        Ss   sleep 303
    258       1     258     258 ?        Ss   tmux new -d -s work sleep 305
    259     258     259     259 pts/1    Ss+  sleep 305
```

끊기 전 셸 250 아래 `pts/0` 에 있던 `sleep 301` 은 셸과 함께 사라졌습니다. `nohup` 의 252 와 `disown` 의 254 는 PPID 가 1, TTY 가 `?` 로 바뀐 채 남았습니다. 256, 258, 259 는 끊기 전과 같습니다.

![터미널이 끊길 때 SIGHUP 이 닿는 프로세스와 닿지 않는 프로세스](./_assets/03-02.hangup-reach.svg)

| 방법 | 살아남는 이유 | 출력이 가는 곳 | 다시 보는 길 |
|---|---|---|---|
| `nohup 명령 &` | 명령이 SIGHUP 을 무시하도록 해 놓고 실행 | 표준 출력이 터미널이면 `nohup.out` | 파일 |
| `명령 & disown` | 셸의 작업 목록에서 빠져 SIGHUP 을 전달받지 않음 | 여전히 그 터미널 | 미리 돌려 둔 파일 |
| `setsid 명령` | 새 세션에서 실행돼 제어 터미널이 없음 | 여전히 그 터미널 | 미리 돌려 둔 파일 |
| `tmux new -d -s 이름 '명령'` | tmux 서버가 만든 다른 터미널에서 실행 | 페인 화면 | `tmux attach -t 이름` |
| `systemd-run --unit=이름 명령` | 서비스 관리자가 부모가 돼 실행 | journal | `journalctl -u 이름` |

`nohup` 은 SIGHUP 을 무시하고 `disown` 은 잡 목록에서 빼 전파를 막지만 입출력은 보호하지 못합니다.[^nohup][^bash-disown] `setsid` 는 제어 터미널 없는 새 세션에서 돌아 터미널 영향에서 벗어납니다.[^setsid] `tmux new -d -s` 는 가상 터미널(`pts/1`)에서 돌려 `tmux attach` 로 화면까지 복원합니다.[^tmux-keys] `systemd-run` 은 `-p` 로 자원을 제한하며,[^systemd-run] `screen` 뿐인 환경은 `Ctrl+A 다음 d` 로 떼고 `screen -r` 로 다시 붙습니다.[^screen]

```bash
screen -dmS build bash -c 'echo building; sleep 30'
screen -ls
```

```bash
There is a screen on:
	789.build	(11/10/26 02:22:40)	(Detached)
1 Socket in /run/screen/S-root.
```



## 9. 터미널과 멀티플렉서와 셸을 한 벌로 묶기

> 셋을 따로 고르는 것으로 끝이 아닙니다. 저자는 이 셋을 설정 파일 하나로 묶어 어느 기계에서든 몇 초 만에 같은 환경을 세웁니다.

![터미널이 셸을 띄우고 셸이 세션에 붙는다](./_assets/03-02.terminal-stack.svg)

기기마다 설정을 손으로 다시 짜지 않도록 터미널·셸·멀티플렉서를 설정 파일로 묶어 Git 으로 버전 관리합니다. 저자의 터미널 Alacritty 는 설정 파일(`alacritty.yml`)의 `shell` 항목으로 멀티플렉서와 셸의 연결을 정의합니다. 책이 나온 뒤 0.13.0 부터 설정은 TOML 입니다(`alacritty migrate` 로 변환). 0.14.0 부터 `shell` 은 `terminal.shell` 입니다.[^alacritty]

```bash
shell:
   program: /usr/local/bin/fish
   args:
   - -l
   - -i
   - -c
   - "tmux new-session -A -s zzz"
```

터미널을 열면 Fish 를 띄우고 `tmux new-session -A` 로 기존 세션에 붙거나 새로 엽니다.[^tmux-A] `tmux-resurrect` 는 세션을 저장·복원하고 `tmux-continuum` 은 이를 15분마다 자동으로 돌려 컴퓨터를 재부팅해도 세션과 윈도와 페인이 거의 그대로 복원됩니다. 프로세스와 함께 사라지는 셸 변수는 예외입니다. 저자의 구성을 그대로 따를 필요는 없고 배치의 이유만 옮기면 됩니다. 자주 치는 입력을 줄이고 상태는 셸 바깥에 두며 설정 파일은 버전 관리합니다.



## 결정 치트시트

> 이 구간이 판단으로 이어지는 자리를 모았습니다. 근거는 본문입니다.

| 상황 | 선택 | 이유 |
|---|---|---|
| 긴 명령을 줄이려 한다 | 인자가 없으면 별칭(bash)·축약(Fish), 있으면 함수 | 축약은 인자 없는 단순 명령에 알맞음 |
| 대괄호나 점이 든 글자를 그대로 찾는다 | `grep -F` | 기본은 정규식이라 대괄호가 글자 묶음으로 읽힘 |
| 공백으로 줄 맞춘 출력에서 칸을 뽑는다 | `awk '{print $N}'` | `cut` 은 공백 하나를 칸 하나로 셈 |
| `%` 나 단위가 붙은 칸을 임계와 견준다 | `awk` 에서 `$5+0` | 숫자 꼴이 아닌 칸은 문자열로 비교됨 |
| 값마다 몇 번 나왔는지 센다 | `sort` 뒤에 `uniq -c` | `uniq` 는 이웃한 줄만 합침 |
| 설정 파일의 한 줄을 고친다 | `-i` 없이 확인한 뒤 `sed -i.bak` | 제자리 수정은 되돌릴 길이 없음 |
| 로테이션되는 로그를 따라간다 | `tail -F` | `-f` 는 이름이 바뀐 옛 파일에 머묾 |
| 공백이 든 파일 이름을 인자로 넘긴다 | `find -print0` 과 `xargs -0` | 기본은 공백에서도 항목을 끊음 |
| bash 호환을 유지하면서 대화형을 개선하려 한다 | zsh + Oh My Zsh | 넓은 하위 호환을 유지 |
| 문법을 바꿔서라도 대화형이 편해야 한다 | Fish | 히스토리 관리 없음, 자동 제안 |
| 원격에 아무것도 깔 수 없다 | 셸은 bash, 멀티플렉서는 `screen` | 저자가 든 유일하게 실질적인 제약 |
| 끊겨도 돌아야 하고 화면도 다시 봐야 한다 | `tmux new -d -s 이름 '명령'` | 서버가 따로 떠 화면을 지님 |
| 끊겨도 돌기만 하면 되고 로그로 충분하다 | `nohup 명령 > 로그 2>&1 &` | SIGHUP 을 무시하고 출력은 파일로 감 |
| 멀티플렉서를 하나만 고른다 | tmux | 성숙·안정·플러그인·자료가 근거 |



## 적용 관점

> 이 구간이 실무로 착지하는 자리는 원격 작업입니다. 클러스터에 붙어 로그를 보면서 다른 창에서 매니페스트를 고치는 작업이 대표적인 상황입니다.

원격 작업 시 tmux 세션을 열고 화면을 쪼개 로그 추적과 파일 편집을 병행합니다. 세션을 떼었다가 다시 붙여 셸을 닫아도 상태가 남는지 눈으로 확인합니다.

```bash
tmux new -s k8s
kubectl logs -f deploy/myapp
tmux attach -t k8s
```

`kubectl logs -f` 같은 추적 작업은 멀티플렉서 세션 안에서 실행해야 네트워크 단절이나 이동 중에도 상태가 유지됩니다. 로그 분석에서는 예외 추적(`grep -B`/`-A`), 시간대별 집계(`cut` | `sort` | `uniq -c`), `awk` 연산이 바로 쓰입니다. 안내 문서에 `export KUBECONFIG=...` 라고 적혀 있어도 Fish 에서는 `set -x KUBECONFIG ...` 로 바꿔 칩니다.

1. 자주 쓰는 명령을 줄이는 방법을 셸별로 말해 보십시오.
2. 히어 도큐먼트는 무엇이고 언제 씁니까?
3. 로그에서 값마다 나온 횟수를 셀 때 `uniq -c` 앞에 `sort` 를 두는 이유는 무엇입니까?
4. 다섯째 칸이 `8%`, `45%`, `100%`, `95%` 인 네 줄에 `awk '$5 >= 50 {print $5}'` 를 돌리면 무엇이 나옵니까? 왜 그렇고 어떻게 고칩니까?
5. 유닉스 에포크 시간은 무엇이며 2038년 문제는 왜 생깁니까?
6. 셸을 새로 고를 때 무엇을 자문해야 합니까?
7. tmux 의 세 단위를 큰 것에서 작은 것 순으로 말하고 각각을 설명해 보십시오.
8. 터미널이 끊겨도 명령이 계속 돌게 하는 방법 셋을 대고, 각각 무엇이 남는지 견주어 보십시오.



## 정답 (자답 후 펼치기)

### 정답 1 — 셸별 명령 축약 방법

bash 에서는 별칭을, Fish 에서는 축약을 씁니다. 축약은 인자를 받지 않는 단순 명령에 알맞고, 인자를 받거나 여러 줄이 필요하면 함수를 정의합니다.

### 정답 2 — 히어 도큐먼트의 용도

`cat << 'EOF' > 파일` 형태로 여러 줄을 한 번에 파일에 넣는 방법입니다. 편집기를 열 수 없는 스크립트 안에서 설정 파일을 만들 때 특히 쓸모가 있습니다.

### 정답 3 — sort 와 uniq -c 의 결합 이유

`uniq` 는 연속으로 중복된 줄만 알아봅니다. 같은 값이 흩어져 있으면 따로따로 1씩 셉니다. `sort` 가 같은 값을 붙여 놓아야 `uniq -c` 가 한 덩이로 셉니다.

### 정답 4 — awk 문자열 비교 함정과 숫자 변환

`8%` 와 `95%` 가 나옵니다. `%` 가 붙은 칸은 문자열로 판정되어 문자열 비교를 거칩니다. 앞 글자부터 견주므로 `8%` 는 `50` 보다 크고 `100%` 와 `45%` 는 작게 취급됩니다. 이를 `$5+0 >= 50` 으로 고치면 수로 바뀌어 `100%` 와 `95%` 가 정상 출력됩니다.

### 정답 5 — 에포크 시간과 2038년 문제

1970년 1월 1일 0시 0분 0초 UTC 부터 흐른 초의 수이고, 모든 날을 정확히 86,400초로 취급합니다. 이 값을 부호 있는 32비트 정수로 저장하면 2038년 1월 19일에 카운터가 넘칩니다.

### 정답 6 — 새 셸 선택 시 자문할 기준

그 셸의 초점이 대화형 사용인지 스크립팅인지, 그리고 주변 커뮤니티가 얼마나 활발한지입니다. 여기에 bash 호환이 필요한 환경인지를 함께 봅니다.

### 정답 7 — tmux 세 단위의 위계

세션은 특정 일에 바친 작업 환경이고 다른 모든 단위를 담는 그릇입니다. 윈도는 세션에 속한 브라우저 탭 같은 것이며 쓰는 것은 선택입니다. 페인은 실제로 셸 하나가 도는 곳이고 윈도의 일부이며 가로나 세로로 쪼갤 수 있습니다.

### 정답 8 — 터미널 단절 시 명령 보존 방법

`nohup` 은 SIGHUP 을 무시하며 출력은 `nohup.out` 이나 지정 로그 파일에 남습니다. `setsid` 는 제어 터미널 없는 새 세션에서 돌려 출력은 미리 돌려 둔 파일에 남습니다. tmux 는 가상 터미널에서 돌려 `tmux attach` 로 화면까지 복원하며, `Ctrl+B 다음 d` 로 떼어 두면 터미널이 닫혀도 세션이 유지됩니다.
