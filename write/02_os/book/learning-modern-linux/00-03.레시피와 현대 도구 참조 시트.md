# 레시피와 현대 도구 참조 시트

---

> 원서의 부록 A 와 B 를 한 장으로 합친 조회용 문서입니다. 명령마다 본문 어느 장이 그것을 설명했는지를 붙여, 부록을 이 책 전체의 색인으로 쓸 수 있게 했습니다.

## 이 문서의 성격

> 정독 노트가 아니라 조회용 시트입니다. 그래서 학습 목표도 면접 질문도 두지 않고, 도식도 넣지 않았습니다.

원서의 부록 둘은 합쳐 1,396단어입니다. 가장 짧은 9장의 3분의 1이고 산문이 거의 없습니다. 부록 A 는 저자가 시간이 지나며 모아 온 레시피 목록이고 부록 B 는 사실상 표 하나입니다.

저자 스스로 완전하지도 깊지도 않다고 밝힙니다. 더 넓은 레시피 모음으로는 Carla Schroder 의 《Linux Cookbook》(O'Reilly)을 권합니다.

그래서 이 문서에는 도식이 없습니다. 나열에는 그릴 형태가 없고, 빈칸을 채우려고 없는 관계를 그리는 것이 학습 문서에서 가장 흔한 실패이기 때문입니다.

대신 두 가지를 더했습니다. 첫째는 명령마다 **본문 어느 장이 그것을 설명했는지**입니다. 부록을 그것만 보고 쓰면 왜 그렇게 되는지를 알 수 없는데, 장 번호가 붙어 있으면 되돌아갈 자리가 생깁니다. 둘째는 **직접 돌려 본 결과**입니다. 부록의 명령을 Ubuntu 24.04 컨테이너에서 실행해 보았고, 그 과정에서 원문 정오 여섯을 찾았습니다.



## 1. 부록 A 를 그대로 치기 전에

> 부록의 명령 여섯이 적힌 대로는 동작하지 않거나 설명과 다르게 동작합니다. 실행 전에 이 절을 먼저 봅니다.

### 정오 여섯

부록의 명령을 Ubuntu 24.04 컨테이너에서 하나씩 돌려 확인한 것입니다. 셋은 적힌 대로 치면 실패하고, 셋은 설명이나 수치가 실제와 다릅니다.

> **원문 정오**: `cat 'foo bar baz' | sed -e 's/foo/quux/'` 는 동작하지 않습니다. `cat` 은 인자를 파일 이름으로 받으므로 `foo bar baz` 라는 이름의 파일을 찾다가 실패합니다. 실행해 보면 `cat: 'foo bar baz': No such file or directory` 가 나오고 종료상태는 `1` 입니다. 바로 앞의 `tr` 예제는 `echo` 를 제대로 쓰므로 이 줄만 어긋났습니다. `echo 'foo bar baz' | sed -e 's/foo/quux/'` 로 고치면 `quux bar baz` 가 나옵니다.

> **원문 정오**: `date +%FT%TZ` 를 두고 저자는 "같은 ISO 8601 형식이되 지역 시각" 이라고 적습니다. 그런데 끝의 `Z` 는 ISO 8601 에서 UTC 를 뜻하는 표시입니다. `%T` 가 시각까지 완성하므로 뒤의 `Z` 는 그저 붙는 글자입니다. `TZ=Asia/Seoul` 로 두고 재어 보면 `date -u +"%Y-%m-%dT%H:%M:%SZ"` 는 `2026-09-06T05:16:45Z` 를, `date +%FT%TZ` 는 `2026-09-06T14:16:45Z` 를 내놓습니다. 아홉 시간 차이 나는 두 시각에 똑같이 `Z` 가 붙는 것입니다. 지역 시각을 ISO 8601 로 적으려면 오프셋을 붙여야 하고, `date +%FT%T%:z` 가 `2026-09-06T14:16:45+09:00` 을 줍니다.

> **원문 정오**: `git log (git describe --tags --abbrev=0)..HEAD --oneline` 은 bash 에서 문법 오류입니다. `bash: syntax error near unexpected token '('` 가 나옵니다. 괄호만으로 명령 치환을 하는 것은 Fish 의 문법이고, bash 에서는 `$(...)` 를 써야 합니다. 저자가 3장에서 자신이 Fish 를 쓴다고 밝혔으므로 그 손버릇이 남은 것으로 보입니다. bash 에서는 `git log $(git describe --tags --abbrev=0)..HEAD --oneline` 으로 씁니다.

> **원문 정오**: `git diff --color-moved` 를 저자는 "지역 변경을 색으로 보고 추가·삭제된 줄이 어디인지 나란히 보여 준다" 고 설명합니다. 그 옵션이 하는 일이 아닙니다. `git-diff(1)` 은 "옮겨진 코드 줄이 다르게 색칠된다(Moved lines of code are colored differently)" 고만 적습니다. 나란히 보기 기능은 없고, 색으로 보는 것 자체는 `color.ui` 기본값 덕분에 이 옵션 없이도 됩니다. 이 옵션의 쓸모는 다른 데 있습니다. 코드를 옮기기만 한 변경과 실제로 고친 변경을 눈으로 갈라 줍니다.

### 부록이 셸을 섞어 씁니다

부록 어디에도 어느 셸을 쓰는지 적혀 있지 않은데, 실제로는 한 셸로 전부 칠 수 없습니다. 직접 확인한 결과입니다.

| 명령 | bash | fish |
|------|------|------|
| `git log (git describe --tags --abbrev=0)..HEAD --oneline` | 문법 오류 | 정상 동작 |
| `echo ${PIPESTATUS[@]}` | 정상 동작 | `${ is not a valid variable in fish` |

앞의 것은 Fish 전용이고 뒤의 것은 bash 전용입니다. 부록을 처음부터 끝까지 한 셸에서 치려 하면 반드시 한 번은 막힙니다.

다음 둘은 처음 이 시트를 쓸 때 "정오까지는 아니다" 로 눅여 두었다가 검증에서 되돌린 것입니다. 저자가 *틀리게 적은 수와 서술* 이므로 정오가 맞습니다.

> **원문 정오**: `head -c 450m` 은 450,000,000 바이트가 아닙니다. 저자는 "head 명령이 450 million bytes(약 450 MB)에서 끊는다" 고 적는데, GNU `head` 에서 소문자 `m` 접미사는 1,048,576 배를 뜻합니다. 실제로 `yes | head -c 450m | wc -c` 를 돌리면 `471859200` 이 나옵니다. 450 MiB 이고, 저자가 적은 수보다 2,186만 바이트 많습니다. 부하를 거는 것이 목적이라 결과는 달라지지 않지만, 수를 그대로 인용하면 틀립니다.

> **원문 정오**: `ls -l /etc | wc -l` 이 "디렉터리의 파일 수를 센다" 는 서술은 두 방향으로 틀립니다. `ls -l` 이 맨 위에 `total N` 줄을 내므로 하나가 더해지고, 숨은 파일은 기본으로 나열하지 않으므로 그만큼 빠집니다. 파일 셋만 있는 디렉터리에서 재어 보면 `4` 가 나옵니다. 세는 것이 목적이면 `ls -1A | wc -l` 처럼 긴 형식을 버리고 숨은 파일을 포함해야 합니다.



## 2. 레시피 — 원서 묶음 순서대로

> 저자가 나눈 여덟 묶음을 그대로 두고, 오른쪽에 본문 어느 장이 그 명령을 설명했는지 붙였습니다. "본문 밖"은 이 책이 다루지 않은 명령이라는 뜻입니다.

### 시스템 정보 모으기

| 명령 | 하는 일 | 본문 |
|------|--------|------|
| `cat /etc/*-release` | 리눅스 버전 | 본문 밖 |
| `cat /proc/version` | 커널 정보 | 1장 |
| `uname -a` | 커널과 아키텍처 | 2장 |
| `cat /proc/cpuinfo` | CPU 정보 | 1장 · 2장 |
| `cat /proc/meminfo` | 메모리 정보 | 2장 |
| `cat /proc/diskstats` | 디스크 통계 | 본문 밖 |
| `sudo dmidecode -t bios` | BIOS 정보. `-t` 에 `system`·`memory` 도 쓸 만합니다 | 2장 |
| `free -ht` | 주 메모리와 스왑 사용량 | 8장 둘째 편 |
| `ulimit -n` | 프로세스가 가질 수 있는 파일 디스크립터 수 | 본문 밖 |

### 사용자와 프로세스

| 명령 | 하는 일 | 본문 |
|------|--------|------|
| `who` · `w` | 로그인한 사용자 목록. `w` 가 더 상세합니다 | 본문 밖 |
| `top -U SOMEUSER` | 특정 사용자의 프로세스별 시스템 메트릭 | 8장 둘째 편 |
| `ps faux` | 전체 사용자의 프로세스를 트리로 | 2장 |
| `ps -e \| grep python` | 특정 프로세스 찾기 | 2장 |
| `kill PID` | 프로세스 종료. 무시하면 `-9` 를 붙입니다 | 9장 |
| `killall` | 이름으로 프로세스 종료 | 본문 밖 |

`kill PID` 에 저자가 붙인 단서가 9장의 표와 이어집니다. 프로세스가 이 시그널을 무시하면 `-9` 를 쓰라는 것인데, 그것이 `SIGKILL` 이고 잡을 수도 막을 수도 무시할 수도 없는 둘 중 하나입니다.

### 파일 정보

| 명령 | 하는 일 | 본문 |
|------|--------|------|
| `stat somefile` | 아이노드를 포함한 파일 상세 | 5장 |
| `type somecommand` | 셸이 그 명령을 어떻게 해석하는지 | 3장 첫 편 |
| `which somebinary` | 실행 파일의 위치 | 3장 첫 편 |

### 파일과 디렉터리 다루기

| 명령 | 하는 일 | 본문 |
|------|--------|------|
| `cat afile` | 텍스트 파일 내용 보기 | 3장 첫 편 |
| `ls -l /etc \| wc -l` | 저자는 파일 수 세기라 적습니다 | 3장 첫 편 · **정오** |
| `find /etc -name "*.conf"` | `/etc` 에서 `.conf` 로 끝나는 파일 찾기 | 3장 첫 편 |
| `find . -type f -exec grep -H FINDME {} \;` | 현재 디렉터리에서 문자열 찾기 | 3장 첫 편 |
| `diff -u somefile anotherfile` | 두 파일의 차이 | 본문 밖 |
| `echo 'Com_Acme_Library' \| tr '_A-Z' '.a-z'` | 문자 치환. `com.acme.library` 가 나옵니다 | 3장 첫 편 |
| `cat 'foo bar baz' \| sed -e 's/foo/quux/'` | 저자가 적은 형태 | 3장 첫 편 · **정오** |
| `echo 'foo bar baz' \| sed -e 's/foo/quux/'` | 위를 고친 형태 | 3장 첫 편 |
| `dd if=/dev/zero of=output.dat bs=1024 count=1000` | 시험용 파일 만들기. 정확히는 1,024,000 바이트입니다 | 본문 밖 |

`sed` 의 구분자가 `/` 일 필요는 없다고 저자가 덧붙입니다. 경로나 URL 안의 내용을 바꿀 때 편합니다.

### 리다이렉션과 파이프

3장에서 파일 디스크립터와 스트림을 세운 것이 그대로 쓰입니다.

| 명령 | 하는 일 | 본문 |
|------|--------|------|
| `command 1> file` | 표준 출력을 파일로 | 3장 첫 편 |
| `command 2> file` | 표준 오류를 파일로 | 3장 첫 편 |
| `command &> file` | 표준 출력과 표준 오류를 함께 파일로 | 3장 첫 편 |
| `command >file 2>&1` | 같은 일을 하는 다른 방법 | 3장 첫 편 |
| `command > /dev/null` | 출력을 버리기 | 3장 첫 편 |
| `command < file` | 표준 입력을 파일에서 받기 | 3장 첫 편 |
| `cmd1 \| cmd2 \| cmd3` | 한 프로세스의 표준 출력을 다음의 표준 입력으로 | 3장 첫 편 |
| `echo ${PIPESTATUS[@]}` | 파이프 각 명령의 종료 코드. **bash 전용입니다** | 3장 셋째 편 |

`&>` 는 8장의 정오와도 이어집니다. 8장에서 저자가 `2&>` 라고 적은 자리가 있는데, 그것은 `2` 를 인자로 넘기고 `&>` 만 리다이렉션으로 처리합니다. 여기 부록에는 `&>` 가 올바르게 적혀 있습니다.

### 시간과 날짜

| 명령 | 결과 | 본문 · 비고 |
|------|------|-------------|
| `timedatectl status` | 지역 시각·UTC·동기화 상태 | 6장 첫 편 |
| `date +"%Y-%m-%d"` | `2021-10-09` | 3장 둘째 편 |
| `date +%s` | `1633787676` | 3장 둘째 편 · 유닉스 에포크 |
| `date -u +"%Y-%m-%dT%H:%M:%SZ"` | `2021-10-09T13:55:47Z` | UTC. `Z` 가 맞습니다 |
| `date +%FT%TZ` | `2026-09-06T14:16:45Z` | 저자가 적은 형태. **정오** — 지역 시각에 `Z` 가 붙습니다 |
| `date +%FT%T%:z` | `2026-09-06T14:16:45+09:00` | 위를 고친 형태 |

3장 둘째 편에도 `date` 가 나옵니다. 거기서도 저자의 날짜 예제에 정오가 하나 있었고, `date -d` 가 GNU 문법이라 macOS 에서는 거부된다는 것도 그 노트에 적혀 있습니다.

### Git

원서의 순서 그대로입니다.

| 명령 | 하는 일 |
|------|--------|
| `git clone https://github.com/exampleorg/examplerepo.git` | 저장소를 로컬로 복제 |
| `git diff --color-moved` | **옮겨진 줄을 다르게 색칠**합니다. 나란히 보기가 아닙니다. **정오** |
| `git status` | 무엇이 바뀌었는지 |
| `git add --all && git commit -m "adds a super cool feature"` | 전부 담아 커밋 |
| `git rev-parse HEAD` | 현재 커밋 ID |
| `git tag ATAG HASH` | 특정 커밋에 태그 달기 |
| `git push origin ATAG` | 태그를 원격에 올리기 |
| `git log (git describe --tags --abbrev=0)..HEAD --oneline` | 저자가 적은 형태. **정오** — bash 에서 문법 오류 |
| `git log $(git describe --tags --abbrev=0)..HEAD --oneline` | 위를 고친 형태 |

`git diff --color-moved` 는 3장 둘째 편에도 나옵니다. 저자가 하루에 수백 번 치기 때문에 `d` 한 글자로 줄여 쓴다고 자랑하는 그 명령입니다. 매일 치는 명령의 설명이 부록에서 어긋난 셈입니다.

### 시스템 성능

| 명령 | 하는 일 | 본문 |
|------|--------|------|
| `yes \| tr \\n x \| head -c 450m \| grep z` | 메모리 부하 걸기. 실제로는 471,859,200 바이트. **정오** | 3장 첫 편(`yes`) |
| `du -h /home` | 디렉터리별 디스크 사용량 | 본문 밖 |
| `df -h` | 남은 디스크 공간 | 5장(`df -i` 로 나옴) |
| `dd if=/dev/zero of=/home/some/file bs=1G count=1 oflag=direct` | 디스크 입출력 처리량 재기 | 본문 밖 |

부하를 거는 파이프를 저자가 한 칸씩 풀어 설명합니다.

- `yes` 가 `y` 를 한 줄에 하나씩 끝없이 냅니다
- `tr` 이 그것을 `yx` 의 연속 스트림으로 바꿉니다
- `head` 가 정해진 크기에서 끊습니다
- `grep` 이 없는 문자 `z` 를 찾느라 그 덩어리를 전부 읽습니다

그래서 출력은 없지만 부하는 계속 걸립니다.



## 3. 현대 도구 열넷

> 부록 B 의 표를 원문 그대로 옮긴 것입니다. 라이선스와 대체 대상은 저자의 표기이고, 이 노트가 확인한 것은 따로 표시했습니다.

기존 명령을 그대로 갈아 끼울 수 있는 것도 있고 새것도 있다고 저자가 밝힙니다. 대부분은 사용자 경험을 개선한 것이며, 더 단순한 사용법과 색 있는 출력으로 흐름을 효율적으로 만든다는 것이 공통점입니다.

| 도구 | 라이선스 | 기능 | 대체·보완 대상 |
|------|---------|------|---------------|
| `bat` | MIT · Apache 2.0 | 표시·페이징·구문 강조 | `cat` |
| `envsubst` | MIT | 템플릿 기반 환경 변수 | 해당 없음 |
| `exa` | MIT | 뜻이 있는 색 출력, 합리적 기본값 | `ls` |
| `dog` | European Union Public Licence v1.2 | 단순하고 강력한 DNS 조회 | `dig` |
| `fx` | MIT | JSON 처리 도구 | `jq` |
| `fzf` | MIT | 명령줄 퍼지 파인더 | `ls` + `find` + `grep` |
| `gping` | MIT | 다중 대상, 그래프 | `ping` |
| `httpie` | BSD 3-Clause | 단순한 사용자 경험 | `curl`. `curlie` 도 있다고 덧붙입니다 |
| `jo` | GPL | JSON 생성 | 해당 없음 |
| `jq` | MIT | 네이티브 JSON 처리기 | `sed` · `awk` |
| `rg` | MIT | 빠르고 합리적인 기본값 | `find` · `grep` |
| `sysz` | The Unlicense | `systemctl` 을 위한 `fzf` 인터페이스 | `systemctl` |
| `tldr` | CC-BY(내용) · MIT(스크립트) | 명령의 사용 예에 집중 | `man` |
| `zoxide` | MIT | 디렉터리를 빠르게 옮겨 다니기 | `cd` |

> **노트의 읽기**: `exa` 는 지금 고르기 전에 한 번 확인하는 편이 낫습니다. 원 저장소 `ogham/exa` 는 마지막 커밋이 2024년 9월 24일이고, 포크인 `eza-community/eza` 는 2026년 8월까지 커밋이 이어집니다. 두 저장소 모두 보관 처리되어 있지는 않으므로 버려졌다고 단정할 수는 없지만, 활동의 차이는 분명합니다. 책이 나온 2022년에는 `eza` 가 아직 없었으니 저자의 선택은 그 시점에 맞습니다.

여기 있는 도구 중 셋이 본문에서도 쓰였습니다. `jq` 는 JSON 로그를 다룰 때 8장의 `journalctl -o json` 과 짝이 되고, `sysz` 는 6장의 `systemctl` 을, `dog` 는 7장의 `dig` 를 대신합니다.

저자가 덧붙인 자료 둘도 옮깁니다. The Changelog 팟캐스트의 현대 UNIX 도구 편과, GitHub 의 [Modern UNIX](https://github.com/ibraheemdev/modern-unix) 저장소입니다. 뒤의 것은 계속 갱신되는 목록이라 부록 B 보다 최신입니다.



## 4. 본문으로 되돌아가는 자리

> 위 표의 "본문" 열을 장 기준으로 뒤집은 것입니다. 어떤 명령이 왜 그렇게 되는지를 알고 싶을 때 어디로 갈지 알려 줍니다.

| 장 | 부록이 기대는 명령 |
|:--:|------------------|
| 1 | `cat /proc/version` · `cat /proc/cpuinfo` |
| 2 | `uname -a` · `/proc/cpuinfo` · `/proc/meminfo` · `dmidecode` · `ps` 계열 |
| 3 | 리다이렉션과 파이프 묶음 전체 · `cat` · `find` · `tr` · `sed` · `type` · `which` · `wc -l` · `yes` · `date` · `git diff --color-moved` · `${PIPESTATUS[@]}` |
| 4 | 없음 |
| 5 | `stat` · `df` |
| 6 | `timedatectl` · `systemctl` |
| 7 | `dig` |
| 8 | `free` · `top` |
| 9 | `kill` 과 `-9` |

이 표는 각 명령의 문자열을 아홉 장 노트에서 실제로 찾아 만든 것입니다. 처음 이 시트를 쓸 때는 기억에 기대어 채웠는데, 검증에서 여섯 칸이 틀린 것으로 드러나 전부 다시 세었습니다.

세어 보니 3장이 압도적입니다. 부록 A 의 여덟 묶음 중 리다이렉션과 파이프 묶음이 통째로 3장에 기댑니다. 파일 다루기 묶음도 대부분 그렇습니다. 그다음이 2장이고, 4장에 기대는 명령은 하나도 없습니다.

본문이 다루지 않는 것도 적지 않습니다. `cat /etc/*-release`·`/proc/diskstats`·`ulimit`·`who`·`w`·`killall`·`diff`·`dd`·`du` 가 그렇습니다. 저자가 이 부록을 "완전하지도 깊지도 않다" 고 밝힌 자리가 그런 곳이고, 이 시트에서 "본문 밖" 으로 표시한 칸입니다.
