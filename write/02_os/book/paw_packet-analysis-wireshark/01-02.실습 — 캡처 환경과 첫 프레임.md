# 실습 — 캡처 환경과 첫 프레임

---

> [01-01](./01-01.%ED%8C%A8%ED%82%B7%20%EB%B6%84%EC%84%9D%EA%B8%B0%EC%99%80%20Wireshark.md) 의 개념 넷을 맥북에서 직접 확인하는 실습입니다.

먼저 환경 절에서 캡처 권한부터 확인하고 §1 에서 인터페이스 목록을 살핍니다. §2 는 분석기가 프레임을 봉투째 받는 모습을, §3 은 잡는 일과 읽는 일의 분업을 봅니다. §4 는 계획에 없이 들어온 남의 기기 이름을 기록합니다.

## 환경

> macOS(Apple Silicon), Wireshark 4.6 계열 Homebrew 설치. 2026-09-14 실행.

```bash
# 둘 다 깔려 있는지
which tshark dumpcap

# 캡처는 /dev/bpf* 를 여는 일이다. 기본은 root 전용
ls -l /dev/bpf0

# Wireshark 가 함께 설치하는 ChmodBPF 가 이 그룹에 문을 열고 설치 사용자를 넣는다
id -Gn | tr ' ' '\n' | grep -i bpf
```

```bash
/opt/homebrew/bin/tshark
/opt/homebrew/bin/dumpcap
crw-rw----  1 root  access_bpf  /dev/bpf0
access_bpf
```

그래서 아래 명령이 전부 `sudo` 없이 돕니다.



## 1. 인터페이스 목록

> `dumpcap -D` 와 `ifconfig` 를 같은 기준으로 세어 비교합니다.

확인하려는 물음은 "캡처 권한이 없는 인터페이스는 `dumpcap -D` 목록에서 빠지는가"입니다. 빠진다면 `dumpcap -D` 가 `ifconfig` 보다 적게 나와야 합니다.

```bash
# 번호와 설명이 함께 나온다 — en0 (Wi-Fi) 처럼
dumpcap -D

# 시스템의 모든 인터페이스 개수
ifconfig -l | tr ' ' '\n' | wc -l
```

```bash
1. ap1
2. en0 (Wi-Fi)
...
26. stf0

26
```

`dumpcap -D` 는 번호와 설명을 함께 주고 `ifconfig` 는 이름만 줍니다. 개수는 26 대 26 으로 같았습니다.

ChmodBPF 로 전부 열린 이 맥북에서는 걸러낼 것이 없으니 물음에 답하지 못한 결과입니다. 권한이 제한된 환경이라도 답은 libpcap 판에 따라 갈립니다. [01-01](./01-01.%ED%8C%A8%ED%82%B7%20%EB%B6%84%EC%84%9D%EA%B8%B0%EC%99%80%20Wireshark.md) §3 둘째 단계가 적었듯이 libpcap 1.10 설명서는 권한이 없는 장치가 목록에서 빠진다고 하고 1.11 설명서는 목록에는 나오되 캡처를 시작할 때 막힐 수 있다고 합니다. 그래서 목록 확인과 실제 캡처 시작을 따로 점검합니다.



## 2. 프레임 한 장 통째로

> 분석기가 링크 계층 프레임을 봉투째 받는지 화면에서 확인합니다.

```bash
# -c 1 은 한 장만, -V 는 계층을 전부 펼쳐라
tshark -i en0 -c 1 -V 2>/dev/null | head -25
```

```bash
[Protocols in frame: eth:ethertype:ip:udp:mdns]
Ethernet II, Src: <MAC>, Dst: IPv4mcast_fb (01:00:5e:00:00:fb)
    Destination: IPv4mcast_fb (01:00:5e:00:00:fb)
        .... ...1 .... = IG bit: Group address (multicast/broadcast)
```

`-V` 출력의 첫 블록은 `Frame` 이고 위 발췌는 그 끝줄 `[Protocols in frame: …]` 부터 옮겼습니다. `Frame` 블록은 Wireshark 가 붙인 캡처 메타데이터(도착 시각·길이)이고 선을 지나간 헤더가 아닙니다. 실제 헤더는 그 아래 `Ethernet II` 부터 찍힙니다. IP 헤더가 아니라 이더넷 헤더가 먼저입니다. `Protocols in frame` 의 왼쪽이 바깥 봉투, 오른쪽이 안쪽 내용물입니다.

발췌에서 뺀 `Frame` 줄에 찍힌 길이는 290바이트였습니다. 290바이트 프레임이면 이더넷 14 + IP 20 + UDP 8 = 42바이트가 봉투고 나머지가 내용물입니다.

목적지는 멀티캐스트(`01:00:5e:...`)였습니다. 명령에 `-p` 를 주지 않았으니 promiscuous 모드는 기본값대로 켜진 채였습니다. 다만 이 프레임은 모드와 상관없이 들어옵니다. 이 장비가 받기로 한 멀티캐스트 그룹은 promiscuous 모드를 꺼도 NIC 가 올리기 때문입니다([01-01](./01-01.%ED%8C%A8%ED%82%B7%20%EB%B6%84%EC%84%9D%EA%B8%B0%EC%99%80%20Wireshark.md) §4 IG 비트). 이 프레임의 정체는 §4 에서 봅니다.



## 3. 오프라인 분업

> 잡는 일과 읽는 일을 갈라 실행합니다. 원격 서버에서 잡아 가져오는 경로와 같은 구조입니다.

```bash
# 20장 잡고 스스로 끝난다
dumpcap -i en0 -c 20 -w ~/Desktop/paw-ch01.pcapng

# 확장자와 무관하게 내용물 형식을 판별한다
file ~/Desktop/paw-ch01.pcapng

# -i 없이 -r 만으로 읽는다. 이게 오프라인 모드다
tshark -r ~/Desktop/paw-ch01.pcapng | head -5
```

```bash
Packets captured: 20
Packets received/dropped on interface 'Wi-Fi: en0': 20/1 (flushed:1) (95.2%)

pcapng capture file - version 1.0
```

형식은 pcapng 입니다. 원문이 전제하는 `.pcap` 으로 쓰려면 `-F pcap` 을 줘야 합니다.

캡처 요약의 `20/1` 은 받은 수와 떨어뜨린 수입니다. 이번의 1 은 전부 `flushed` 에서 나왔습니다. `flushed` 는 20장을 채워 멈추기로 한 뒤 들어온 프레임입니다. 저장하지 않았을 뿐이라 캡처 손실이 아닙니다([01-01](./01-01.%ED%8C%A8%ED%82%B7%20%EB%B6%84%EC%84%9D%EA%B8%B0%EC%99%80%20Wireshark.md) §3 다섯째 단계). 떨어뜨린 수가 `flushed` 보다 크면 그 차이가 진짜 손실이고 그때는 "안 보인다"를 "도착하지 않았다"로 읽을 수 없습니다.



## 4. 계획에 없던 관찰

> 기본 설정으로 잡은 20장 안에 같은 네트워크의 다른 기기 이름이 들어왔습니다.

`tshark -r` 출력의 mDNS 응답에 옆 사람 iPhone 과 MacBook 의 기기 이름이 실명째 찍혔습니다. 목적지는 `224.0.0.251` 멀티캐스트입니다.

SPAN 도 TAP 도 쓰지 않았습니다. promiscuous 모드는 기본값대로 켜져 있었지만 결과와 상관이 없습니다. mDNS 는 자기 이름을 링크 전체에 스스로 알리는 멀티캐스트라 모드를 꺼도 들어옵니다.

[01-01 §3 의 첫째 단계](./01-01.%ED%8C%A8%ED%82%B7%20%EB%B6%84%EC%84%9D%EA%B8%B0%EC%99%80%20Wireshark.md#첫째-허락받았는지-확인합니다)가 "허락받았는지 확인" 인 이유가 이것입니다. 기술적으로 아무것도 뚫지 않아도 남의 정보가 들어옵니다.

```bash
# 실습 파일은 실행 직후 지웠고 저장소에 넣지 않았다
rm ~/Desktop/paw-ch01.pcapng
```

이 일로 다음 실습인 [02-04](./02-04.%EC%8B%A4%EC%8A%B5%20%E2%80%94%20%ED%95%84%ED%84%B0%EC%99%80%20%ED%95%B4%EC%84%9D.md) 는 캡처 자리를 루프백으로 옮겨 남의 프레임이 들어오지 않게 했습니다.



## 남은 것

> 1장 범위에서 재현하지 못한 축입니다.

- **monitor 모드** — 6장에서 다룹니다. `airport` 유틸리티가 제거된 이후 macOS 에서 경로를 확인해야 합니다.
- **promiscuous 모드의 효과 대조** — 켜고 끈 상태를 비교하려면 같은 스위치에 트래픽을 만드는 두 번째 기기가 필요합니다.
- **원문 예제 캡처 파일** — `normal-connection.pcap` 등은 PDF 에 이름만 나와 있어 원본을 구하지 못했습니다.
