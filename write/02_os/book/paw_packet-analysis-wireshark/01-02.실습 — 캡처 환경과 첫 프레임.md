# 실습 — 캡처 환경과 첫 프레임

---

## 환경

> macOS(Apple Silicon), Wireshark 4.6 계열 Homebrew 설치. 2026-09-14 실행.

```bash
# 셋 다 깔려 있는지
which tshark dumpcap

# 캡처는 /dev/bpf* 를 여는 일이다. 기본은 root 전용
ls -l /dev/bpf0

# Wireshark 가 함께 설치하는 ChmodBPF 가 이 그룹에 문을 열고 설치 사용자를 넣는다
id -Gn | tr ' ' '\n' | grep -i bpf
```

```bash
/opt/homebrew/bin/tshark
/opt/homebrew/bin/dumpcap
crw-rw----  1 root  access_bpf  /dev/bpf0
access_bpf
```

그래서 아래 명령이 전부 `sudo` 없이 돕니다.



## 1. 인터페이스 목록

> `dumpcap -D` 와 `ifconfig` 를 같은 기준으로 세어 비교합니다.

```bash
# 번호와 설명이 함께 나온다 — en0 (Wi-Fi) 처럼
dumpcap -D

# 시스템의 모든 인터페이스 개수
ifconfig -l | tr ' ' '\n' | wc -l
```

```bash
1. ap1
2. en0 (Wi-Fi)
...
26. stf0

26
```

26 대 26 으로 같았습니다. 노트 심화 학습이 적은 "캡처 권한이 실제로 있는 인터페이스만 나온다" 는 권한이 제한된 환경에서 드러나는 성질이고, ChmodBPF 로 전부 열린 이 맥북에서는 걸러낼 것이 없습니다. 리눅스에 일반 계정으로 붙어 `CAP_NET_RAW` 없이 돌리면 목록이 빕니다.

`dumpcap -D` 만 주는 것은 번호와 설명입니다. `ifconfig` 는 이름만 줍니다.



## 2. 프레임 한 장 통째로

> 분석기가 링크 계층 프레임을 봉투째 받는지 화면에서 확인합니다.

```bash
# -c 1 은 한 장만, -V 는 계층을 전부 펼쳐라
tshark -i en0 -c 1 -V 2>/dev/null | head -25
```

```bash
[Protocols in frame: eth:ethertype:ip:udp:mdns]
Ethernet II, Src: <MAC>, Dst: IPv4mcast_fb (01:00:5e:00:00:fb)
    Destination: IPv4mcast_fb (01:00:5e:00:00:fb)
        .... ...1 .... = IG bit: Group address (multicast/broadcast)
```

맨 위가 `Ethernet II` 입니다. IP 헤더가 아니라 이더넷 헤더가 먼저 찍힙니다. `Protocols in frame` 의 왼쪽이 바깥 봉투, 오른쪽이 안쪽 내용물입니다.

290바이트 프레임이면 이더넷 14 + IP 20 + UDP 8 = 42바이트가 봉투고 나머지가 내용물입니다.

목적지는 멀티캐스트(`01:00:5e:...`)였습니다. promiscuous 모드를 켜지 않아도 NIC 가 통과시키는 갈래입니다.



## 3. 오프라인 분업

> 잡는 일과 읽는 일을 갈라 실행합니다. 원격 서버에서 잡아 가져오는 경로와 같은 구조입니다.

```bash
# 20장 잡고 스스로 끝난다
dumpcap -i en0 -c 20 -w ~/Desktop/paw-ch01.pcapng

# 확장자와 무관하게 내용물 형식을 판별한다
file ~/Desktop/paw-ch01.pcapng

# -i 없이 -r 만으로 읽는다. 이게 오프라인 모드다
tshark -r ~/Desktop/paw-ch01.pcapng | head -5
```

```bash
Packets captured: 20
Packets received/dropped on interface 'Wi-Fi: en0': 20/1 (flushed:1) (95.2%)

pcapng capture file - version 1.0
```

형식은 pcapng 입니다. 원문이 전제하는 `.pcap` 으로 쓰려면 `-F pcap` 을 줘야 합니다.

캡처 요약의 `20/1` 은 한 장을 떨어뜨렸다는 뜻입니다. 분석 결과가 이상할 때 먼저 볼 숫자입니다.



## 4. 계획에 없던 관찰

> 기본 설정으로 30초 잡은 20장 안에 같은 네트워크의 다른 기기 이름이 들어왔습니다.

`tshark -r` 출력의 mDNS 응답에 옆 사람 iPhone 과 MacBook 의 기기 이름이 실명째 찍혔습니다. 목적지는 `224.0.0.251` 멀티캐스트입니다.

promiscuous 모드도, SPAN 도, TAP 도 쓰지 않았습니다. mDNS 가 자기 이름을 네트워크 전체에 스스로 외치는 프로토콜이라 그냥 들어옵니다.

노트 §3 의 첫째 관문이 "허락받았는지 확인" 인 이유가 이것입니다. 기술적으로 아무것도 뚫지 않아도 남의 정보가 들어옵니다.

```bash
# 실습 파일은 실행 직후 지웠고 저장소에 넣지 않았다
rm ~/Desktop/paw-ch01.pcapng
```



## 남은 것

> 1장 범위에서 재현하지 못한 축입니다.

- **monitor 모드** — 6장에서 다룹니다. `airport` 유틸리티가 제거된 이후 macOS 에서의 경로 확인이 필요합니다.
- **promiscuous 모드의 효과 대조** — 켜고 끈 상태를 비교하려면 같은 스위치에 트래픽을 만드는 두 번째 기기가 필요합니다.
- **원문 예제 캡처 파일** — `normal-connection.pcap` 등은 PDF 에 이름만 나와 있어 원본을 구하지 못했습니다.
