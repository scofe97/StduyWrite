# 터미널에서 같은 화면을 읽는 법

---

> [02-02](./02-02.%EC%9E%A1%EC%9D%80%20%ED%8C%A8%ED%82%B7%EC%9D%84%20%EC%9D%BD%EB%8A%94%20%EB%B2%95.md) 가 Wireshark 의 네 창으로 설명한 판단을 터미널에서 그대로 합니다. 창을 열 수 없는 서버에서, 또는 같은 판단을 명령 한 줄로 되풀이해야 할 때 보는 대응표입니다.

## 핵심 요약

> 이 편이 매달린 하나의 생각은 **GUI 가 클릭으로 주는 것이 tshark 에서는 옵션 하나에 대응하며, 대응이 없는 자리가 바로 GUI 가 따로 해 주는 일이라는 것**입니다.

같은 캡처를 두 도구로 읽으면 어긋나는 자리가 드러납니다. 색은 GUI 에서 기본이지만 터미널에서는 `--color` 를 붙여야 나옵니다. 필터는 필터 칸 대신 `-Y` 에 넣습니다. Details 창의 트리는 `-V`, Bytes 창의 덤프는 `-x` 가 글자로 찍습니다.

**대응이 없는 자리가 더 중요합니다.** 필드를 클릭하면 GUI 는 그 바이트를 덤프에서 강조해 줍니다. `-x` 는 그런 표시를 하지 않아 오프셋을 직접 세야 합니다. 어느 쪽이 편한지가 아니라, GUI 가 무엇을 대신 해 주고 있었는지가 이 대조에서 보입니다.



## 학습 목표

> 이 편을 읽고 나면 아래 네 가지를 스스로 해낼 수 있습니다.

1. 예제 캡처를 손으로 떠서 이 편의 명령을 그대로 따라 할 수 있습니다.
2. GUI 의 색·필터·시간 형식을 터미널 옵션으로 바꿔 쓸 수 있습니다.
3. `-V`·`-O`·`-x` 로 Details 와 Bytes 창에 해당하는 것을 글자로 꺼낼 수 있습니다.
4. 링크 계층이 이더넷일 때와 루프백일 때 출력이 어디서 갈리는지 말할 수 있습니다.

이 편에서 새로 만나는 낱말입니다. `어디서` 는 그 낱말이 실제로 설명되는 절입니다.

| 키워드 | 뜻 | 학습 포인트·연결 개념 | 어디서 |
|---|---|---|---|
| `--color` | 터미널에 컬러링 규칙을 입히는 옵션 | GUI 는 기본 · 터미널은 선택 | §2 |
| `-T fields` · `-e` | 목록 대신 고른 필드만 탭으로 찍음 | Packet List 의 열 대신 필드 이름 | §2 |
| `-Y` | 디스플레이 필터를 거는 옵션 | 읽은 뒤 거르는 것이라 되돌릴 수 있음 | §3 |
| `-f` | 캡처 필터를 거는 옵션 | 잡는 동안에만 · 파일 읽기에는 거절 | §3 |
| `-t` | 시간 형식을 고르는 옵션 | 상대·절대·직전 프레임 기준 | §5 |
| `-V` · `-O` | 트리를 전부 · 한 프로토콜만 펼침 | Details 창에 대응 | §6 |
| `-x` | 16진수와 ASCII 덤프 | Bytes 창에 대응 · 강조는 없음 | §6 |



## 1. 예제 캡처를 직접 뜨는 법

> 이 편은 캡처 파일을 싣지 않으니 §2 부터의 터미널 예시는 아래 명령으로 루프백에서 뜬 파일을 읽습니다. 본문 출력은 문서용 주소로 합성한 캡처라 주소 · 포트 · 프레임 번호가 다릅니다.

합성 캡처는 17프레임입니다. 1번 ARP, 2~7번 내 호스트와 서버의 HTTP 한 번, 8~9번 DNS 질의와 응답이 들어 있습니다. 10~15번은 셋째 호스트의 느린 응답과 재전송이고 16~17번은 23번 포트로 간 SYN 과 RST 입니다.

명령이 읽는 파일은 대부분 lo0 캡처입니다. §4 와 §6 끝의 이더넷 대조만 아래 en0 캡처를 읽습니다.

```bash
# 1. 서버 — 빈 폴더라야 디렉터리 목록이 캡처에 담기지 않습니다
python3 -m http.server 18080 --bind 127.0.0.1 --directory "$(mktemp -d)" > /dev/null 2>&1 &
sleep 1

# 2. 캡처와 요청 — 네 줄을 한 번에 붙여 넣습니다. 18080 은 응답, 18081 은 거절입니다
#    -f 는 잡는 동안 거르는 캡처 필터입니다(§3)
dumpcap -i lo0 -f 'tcp port 18080 or tcp port 18081' -a duration:6 -w ~/paw-0202.pcapng &
sleep 1 && curl -s http://127.0.0.1:18080/ -o /dev/null
curl -s http://127.0.0.1:18081/ -o /dev/null
wait $!

# 3. 읽기 — 16프레임 안팎이 나옵니다. --color 는 §2 에서 봅니다
tshark -r ~/paw-0202.pcapng --color
```

- `Packets captured: 0` 이면 6초 안에 curl 이 나가지 않은 것이니 2번 네 줄을 함께 다시 붙여 넣습니다. `Address already in use` 가 나면 명령 속 포트를 모두 28080 · 28081 로 바꿉니다.

[02-02](./02-02.%EC%9E%A1%EC%9D%80%20%ED%8C%A8%ED%82%B7%EC%9D%84%20%EC%9D%BD%EB%8A%94%20%EB%B2%95.md) §3~§5 가 보인 MAC · ARP · 바이트 대조는 루프백에서 되살아나지 않습니다. 루프백 링크 계층이 이더넷이 아닌 4바이트 `Null/Loopback` 이고 주소도 모두 `127.0.0.1` 이기 때문입니다. 이 예시만 Wi-Fi 에서 좁은 캡처 필터를 붙여 뜹니다. `-p` 로는 브로드캐스트 · 멀티캐스트가 걸러지지 않습니다.[^tshark-p]

```bash
# Wi-Fi — 내 기기와 example.com 사이 80번 포트만, IPv4 로
dumpcap -i en0 -p -f 'host example.com and tcp port 80' -a duration:6 -w ~/paw-0202-en0.pcapng &
sleep 1 && curl -4 -s http://example.com/ -o /dev/null
wait $!

# ARP — 내 MAC(ifconfig en0 의 ether 줄)이 오간 것만. 캐시가 차 있으면 비어 있을 수 있습니다
dumpcap -i en0 -p -f 'arp and ether host <내 MAC>' -a duration:60 -w ~/paw-0202-arp.pcapng
```

ARP 캡처는 이 편에서 읽지 않고 02-02 §4 의 ARP 길이 42바이트를 직접 확인할 때 씁니다. `en0` 두 필터는 `dumpcap -d` 로 문법만 확인했습니다. 노트에 옮길 때는 내 IP · MAC 을 문서용 주소(`192.0.2.0/24`)와 문서용 MAC(`00:00:5e:00:53:xx`)으로 바꿉니다.

```bash
# 정리 — 이 편을 다 읽은 뒤
pkill -f 'http.server 18080'
rm -f ~/paw-0202.pcapng ~/paw-0202-en0.pcapng ~/paw-0202-arp.pcapng ~/paw-0202-f.pcapng
```



## 2. 색 — 터미널에서는 `--color` 를 붙여야 나옵니다

> GUI 는 컬러링 규칙을 기본으로 입히지만 터미널은 옵션을 붙여야 나옵니다. 읽는 규칙 파일은 같습니다.

tshark 로만 캡처를 읽어 왔다면 [02-02](./02-02.%EC%9E%A1%EC%9D%80%20%ED%8C%A8%ED%82%B7%EC%9D%84%20%EC%9D%BD%EB%8A%94%20%EB%B2%95.md) §2 의 색을 본 적이 없을 수 있습니다. tshark 의 기본 출력은 글자뿐입니다. 색은 `--color` 옵션을 붙여야 켜집니다. man page 는 이 옵션이 표준 Wireshark 색 규칙대로 줄에 색을 입힌다고 적습니다. Windows 가 아닌 환경에서는 24비트 트루컬러 이스케이프를 처리하는 터미널이 필요하다는 조건을 붙입니다.[^tshark-color] 아래 명령의 파일은 §1 에서 뜬 lo0 캡처입니다.

```bash
tshark -r ~/paw-0202.pcapng --color
```

트루컬러 터미널에서 위 명령을 실행하면 줄마다 GUI 와 같은 배경색이 깔립니다. 같은 명령을 `| cat -v` 로 넘겨 확인해 보니 색 이스케이프가 하나도 없었습니다. 색은 터미널에 바로 찍을 때만 붙었습니다.

색을 볼 수 없는 자리에서는 어느 규칙이 걸렸는지를 글자로 뽑습니다. `frame.coloring_rule.name` 이 규칙 이름을 담는 필드입니다.[^dfref-frame] `-T fields` 는 목록 대신 `-e` 로 고른 필드만 탭으로 나눠 찍는 출력 형식입니다(§5 에서 다시 봅니다). 아래는 합성 캡처의 출력입니다. 같은 규칙이 이어지는 줄은 `...` 로 줄였습니다.

```bash
tshark -r ~/paw-0202.pcapng --color -T fields -e frame.number -e _ws.col.protocol -e frame.coloring_rule.name
```

```bash
1	ARP	ARP
2	TCP	HTTP
...
8	DNS	UDP
...
15	TCP	Bad TCP
16	TCP	TCP SYN/FIN
17	TCP	TCP RST
```

`--color` 를 빼고 같은 명령을 돌리면 셋째 열이 빈 채로 나왔습니다. 규칙 이름이 필요하면 이 옵션을 함께 붙입니다. 직접 뜬 lo0 캡처에는 ARP · DNS · 재전송 줄이 없어 `TCP SYN/FIN` · `TCP` · `HTTP` · `TCP RST` 네 규칙만 나왔습니다.

2번 줄이 눈에 걸립니다. Protocol 은 `TCP` 인 SYN 인데 걸린 규칙은 `TCP SYN/FIN` 이 아니라 `HTTP` 입니다. 규칙은 위에서부터 차례로 대조되고 공식 문서의 표현으로 "The first match wins" 이기 때문입니다.[^wsug-color] 아래 표는 기본 규칙 21개 가운데 합성 캡처와 lo0 캡처에 걸린 일곱 개입니다. 순서는 파일에 적힌 그대로 옮겼습니다. `TCP` 는 lo0 캡처에만 걸렸습니다.

| 순서 | 규칙 이름 | 조건 |
|:---:|------|------|
| 1 | Bad TCP | `tcp.analysis.flags && !tcp.analysis.window_update && …` |
| 6 | ARP | `arp` |
| 8 | TCP RST | `tcp.flags.reset eq 1` |
| 14 | HTTP | `http \|\| tcp.port == 80 \|\| http2` |
| 17 | TCP SYN/FIN | `tcp.flags & 0x02 \|\| tcp.flags.fin == 1` |
| 18 | TCP | `tcp` |
| 19 | UDP | `udp` |

2번 SYN 은 80번 포트로 가므로 14번째 `HTTP` 규칙에서 먼저 걸렸습니다. 17번째 규칙까지는 내려가지 못했습니다. 23번 포트로 간 16번 SYN 은 `HTTP` 조건에 맞지 않아 `TCP SYN/FIN` 이 붙었습니다. 직접 뜬 lo0 캡처도 18080 포트라 SYN 에 `TCP SYN/FIN` 이 붙습니다. 80번 포트 SYN 에 `HTTP` 가 먼저 걸리는 모습은 en0 캡처(`~/paw-0202-en0.pcapng`)에서 볼 수 있습니다.

규칙은 설정 폴더의 `colorfilters` 파일에 한 줄씩 들어 있습니다. 공식 문서에 따르면 개인 설정 폴더에 이 파일이 있으면 그것을 읽고 없으면 전역 설정 폴더의 파일을 읽습니다.[^wsug-files] 두 폴더의 실제 위치는 `tshark -G folders` 의 `Personal configuration` 과 `Global configuration` 줄에 나옵니다. macOS 에서 앱 번들로 설치했다면 전역 폴더는 `Wireshark.app/Contents/Resources/share/wireshark` 입니다.[^wsug-files]

`-V` 로 트리를 펼칠 때 걸린 규칙이 어떻게 찍히는지는 §6 에서 봅니다.



## 3. 필터 — 필터 칸 대신 `-Y` 에 넣습니다

> 디스플레이 필터는 필터 칸 대신 `-Y` 에 넣습니다. 읽은 뒤 거르는 것이라 같은 파일을 조건만 바꿔 다시 볼 수 있습니다.

tshark 에는 필터 칸이 없으니 [02-02](./02-02.%EC%9E%A1%EC%9D%80%20%ED%8C%A8%ED%82%B7%EC%9D%84%20%EC%9D%BD%EB%8A%94%20%EB%B2%95.md) §3 처럼 칸 색으로 문법 오류를 알아챌 수도 없습니다. 디스플레이 필터는 `-Y` 뒤에 같은 문법으로 넣습니다. man page 는 이 옵션이 캡처 필터가 아닌 읽기·디스플레이 필터 문법을 쓴다고 적습니다.[^tshark-y] 필터 칸이 빨개질 자리에서는 tshark 가 오류 메시지를 찍고 끝납니다. 02-02 §3 에서 원문 정오가 짚은 세 필터를 그대로 넣었습니다.

```bash
tshark -r ~/paw-0202.pcapng -Y 'tcp.srcport=2222'
tshark -r ~/paw-0202.pcapng -Y 'Snmp'
tshark -r ~/paw-0202.pcapng -Y 'http || dns | ssl'
```

```bash
tshark: "=" was unexpected in this context.
    tcp.srcport=2222
               ^
tshark: "Snmp" is not a valid protocol or protocol field.
    Snmp
    ^~~~
tshark: "|" was unexpected in this context.
    http || dns | ssl
                ^
```

세 번 모두 종료 코드가 4 였고 패킷은 한 줄도 찍히지 않았습니다. 캐럿(`^`)이 가리키는 글자가 02-02 의 정오가 짚은 자리와 같습니다. 오류 메시지는 어느 캡처 파일을 읽든 같습니다. 고친 필터 `http || dns || tls` 는 합성 캡처에서 HTTP 네 줄과 DNS 두 줄을 돌려주었습니다. 옛 이름 `ssl` 로 바꿔 넣어도 같은 여섯 줄이 나왔습니다.

캡처 필터는 옵션이 다릅니다. `-f` 가 캡처 필터입니다.[^tshark-f] 인터페이스에서 잡는 동안에만 쓸 수 있습니다. 같은 포트를 두 문법으로 적으면 이렇습니다. 첫 줄은 앞의 예제 캡처와 같은 루프백에서 6초만 잡고 앞 파일을 덮어쓰지 않게 이름을 달리합니다.

```bash
# 캡처 필터(BPF): 인터페이스에서 잡을 때 거릅니다
tshark -i lo0 -f 'tcp port 18080' -a duration:6 -w ~/paw-0202-f.pcapng
# 디스플레이 필터: 저장된 파일을 읽을 때 보이는 범위만 좁힙니다
tshark -r ~/paw-0202.pcapng -Y 'tcp.port == 18080'
```

파일을 읽으면서 `-f` 를 주면 tshark 가 `Only read filters, not capture filters, can be specified when reading a capture file.` 를 찍고 거절합니다.



## 4. 원문의 세 번 시도를 터미널에서 되짚기

> 원문이 GUI 에서 세 번 고쳐 가며 좁힌 필터를 같은 순서로 명령에 옮겨, 무엇이 왜 걸렸는지 한 줄씩 확인합니다.

이 시도는 lo0 캡처로는 갈리지 않습니다. 세 필터를 lo0 캡처에 걸어 보니 출발지와 목적지가 모두 `127.0.0.1` 이라 셋 다 16줄 전부를 돌려주었습니다. 그래서 명령은 en0 캡처(`~/paw-0202-en0.pcapng`)를 읽습니다. `<내 IP>` 에는 `ifconfig en0` 의 `inet` 값을, `<서버 IP>` 에는 목록의 Destination 열에 찍힌 example.com 주소를 넣습니다.

아래 출력은 합성 캡처라 원문의 HOSTA 자리에 `192.0.2.10`, HOSTB 자리에 `198.51.100.20` 을 두었습니다. 셋째 호스트 `203.0.113.30` 도 섞었습니다. 이 호스트는 같은 HOSTB 와 따로 통신합니다. 직접 뜬 en0 캡처는 example.com 과의 연결만 담으므로 셋째 호스트 줄은 나오지 않습니다. 첫 시도는 출발지를 고정합니다.

```bash
tshark -r ~/paw-0202-en0.pcapng -Y 'ip.src == <내 IP>'
```


## 5. 시간 — `-t` 로 형식을 고릅니다

> Time 열의 기준을 GUI 에서 메뉴로 바꾸던 것을 `-t` 한 옵션으로 고릅니다.

GUI 에서는 목록의 줄을 골라 오른쪽 클릭으로 Set Time Reference 를 걸어 기준을 옮겼습니다([02-02](./02-02.%EC%9E%A1%EC%9D%80%20%ED%8C%A8%ED%82%B7%EC%9D%84%20%EC%9D%BD%EB%8A%94%20%EB%B2%95.md) §4). tshark 에는 그렇게 고를 목록이 없습니다. man page 의 `-t` 형식 목록에도 기준 패킷을 고르는 값은 없습니다.[^tshark-t] 대신 형식을 바꿔 같은 질문에 답합니다. `-t ad` 는 날짜가 붙은 절대 시각을, `-t dd` 는 바로 앞에 표시된 패킷과의 간격을 찍습니다.[^tshark-t]

```bash
tshark -r ~/paw-0202.pcapng -t dd -Y http
```

합성 캡처에서는 이렇게 나옵니다.

```bash
    5              192.0.2.10 → 198.51.100.20 HTTP 101 GET /index.html HTTP/1.1
    6   0.070000 198.51.100.20 → 192.0.2.10   HTTP 98 HTTP/1.1 200 OK
   13   0.330000 203.0.113.30 → 198.51.100.20 HTTP 95 GET /slow HTTP/1.1
   14   1.500000 198.51.100.20 → 203.0.113.30 HTTP 97 HTTP/1.1 200 OK
```

HTTP 만 남긴 뒤 간격을 찍었으니 6번의 `0.070000` 과 14번의 `1.500000` 이 곧 요청 뒤 응답까지 걸린 시간입니다. 첫 줄은 앞에 표시된 패킷이 없어 시간 칸이 비었습니다. 요청이 둘인 것은 합성 캡처라서입니다. lo0 캡처에서는 요청과 응답 한 쌍 사이에 수 밀리초가 찍힙니다. 요청과 응답 사이에 다른 HTTP 줄이 끼면 이 간격은 틀어지므로 응답 시간만 필요하면 응답 프레임의 `http.time` 필드를 열로 뽑는 편이 정확합니다.

```bash
tshark -r ~/paw-0202.pcapng -Y http.response -T fields -e frame.number -e ip.dst -e http.time
```

```bash
6	192.0.2.10	0.070000000
14	203.0.113.30	1.500000000
```

`-T fields` 와 `-e` 는 Packet List 의 일곱 열 대신 원하는 필드만 골라 탭으로 나눠 찍습니다.[^tshark-e] 열 이름이 아니라 필드 이름을 쓰므로 Details 에서 본 이름을 그대로 가져오면 됩니다.



## 6. 트리와 바이트 펼치기

> Details 창의 트리는 `-V` 와 `-O` 가, Bytes 창의 덤프는 `-x` 가 글자로 찍습니다. 없는 것은 필드를 클릭했을 때의 강조뿐입니다.

tshark 의 한 줄 출력만 보면 Details 창과 Bytes 창에 해당하는 것이 없어 02-02 §5 가 짚은 계층을 확인할 곳이 없어 보입니다. `-V` 가 Details 창의 트리를, `-x` 가 Bytes 창의 16진수·ASCII 덤프를 글자로 찍습니다.[^tshark-vx] 명령은 HTTP 요청만 골라 펼칩니다. 아래는 합성 캡처의 5번 요청을 펼친 출력입니다. 길어서 `...` 로 줄인 곳이 있습니다.

§2 의 `--color` 를 `-V` 와 함께 붙이면 Frame 블록 끝에 걸린 규칙이 대괄호로 붙습니다. 공식 문서도 프레임 상세가 적용된 규칙과 그 조건을 함께 보여 준다고 적습니다.[^wsug-color]

```bash
tshark -r ~/paw-0202.pcapng -Y 'tcp.flags.reset == 1' -V --color
```

합성 캡처의 15번 재전송 줄을 같은 방식으로 펼치면 아래처럼 나옵니다. lo0 캡처의 RST 줄에서는 같은 자리에 `[Coloring Rule Name: TCP RST]` 와 조건 `tcp.flags.reset eq 1` 이 찍혔습니다.

```bash

    ...
    [Coloring Rule Name: Bad TCP]
    [Coloring Rule String: tcp.analysis.flags && !tcp.analysis.window_update && !tcp.analysis.keep_alive && !tcp.analysis.keep_alive_ack]
```

```bash

```
