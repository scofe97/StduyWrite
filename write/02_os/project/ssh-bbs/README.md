# ssh-bbs — 프로젝트 인덱스

---

> `ssh 닉@호스트` 로 어디서든 들어오는 레트로 BBS 를 Go 로 만들며 배우는 프로젝트의 인덱스입니다. 따라갈 책이 없으므로 단계마다 학습 문서를 이 폴더에 쓰고, 진행 상태도 이 README 에 둡니다.

코드·ADR·리허설 기록은 실습 저장소에 있습니다.

## 이 폴더는 무엇인가

> 실습 저장소가 무엇을 만들지를 맡고, 이 폴더는 그 밑의 원리를 배우는 문서를 맡습니다.

실습 코드는 `~/study/runners-lab/net/ssh-bbs`(GitHub 모노레포 `scofe97/StudyLab`)에 둡니다. 단계 순서와 범위는 그 저장소의 `docs/roadmap.md` 가 정본이고, 단계별 요구사항은 이슈 #33~#44 에 있습니다.

npg 는 책 정독 노트가 Phase 1~2 를 맡았지만 이 프로젝트에는 책이 없습니다. 그래서 단계에 들어갈 때마다 RFC 와 공식 문서를 근거로 학습 문서를 이 폴더에 새로 씁니다. 다른 폴더에 이미 다룬 개념(고루틴, 처리율 제한, 포털 터널 같은)은 다시 쓰지 않고 링크로 연결합니다.



## 단계와 문서

> 단계마다 학습 질문 하나를 세우고, 문서를 쓰면 이 표에 행을 채웁니다.

| 단계 | 이슈 | 학습 질문 | 문서 | 상태 |
|---|---|---|---|---|
| S1 SSH 서버 | #33 | 처음 보는 서버에 접속할 때 SSH 는 무엇으로 서버와 사람을 믿는가 | — | 시작 전 |
| S2 채팅방 | #34 | 손님 한 명이 느려도 방 전체가 멈추지 않게 하려면 무엇을 버려야 하는가 | — | 시작 전 |
| S3 터미널 화면 | #35 | 바이트 흐름만 오가는 연결 위에서 화면과 입력 줄을 어떻게 그리는가 | — | 시작 전 |
| S4 Telnet 입구 | #36 | 같은 화면을 다른 전송에 붙이려면 경계를 어디에 그어야 하는가 | — | 시작 전 |
| S5 BBS 게시판 | #37 | 파일 하나짜리 DB 가 여러 사람의 동시 쓰기를 어떻게 견디는가 | — | 시작 전 |

| S7 도어 게임 | #39 | 여러 사람의 입력을 한 판의 상태로 어떻게 맞추는가 | — | 시작 전 |
| S8 포트 포워딩 | #40 | SSH 연결 하나가 어떻게 다른 TCP 연결을 실어 나르는가 | — | 시작 전 |
| S9 노드 간 연동 | #41 | 늘 붙어 있지 않은 서버끼리 같은 글을 한 번씩만 갖게 하려면 무엇이 필요한가 | — | 시작 전 |
| S10 남용 방지 | #42 | 인터넷에 연 SSH 서버에서 정상 사람을 지키며 봇을 늦추는 방법은 무엇인가 | — | 시작 전 |
| S11 관측 | #43 | 대화 내용을 남기지 않고도 장애 원인을 찾으려면 무엇을 재야 하는가 | — | 시작 전 |

## 함께 읽을 폴더

> 터널과 프록시는 다른 프로젝트에서 먼저 다룬 것을 이어 씁니다.

S8 포트 포워딩은 [portal-tunnel](../portal-tunnel/README.md) 의 역방향 연결·다중화 노트와 npg 확장 트랙 X9 리버스 터널에 기댑니다. S2 느린 손님과 S10 남용 방지는 [npg-lab](../npg-lab/README.md) 의 다운스트림 층 판단과 겹치므로, 그 문서를 먼저 읽고 SSH 쪽에서 무엇이 달라지는지만 씁니다.
