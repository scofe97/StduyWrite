# 컨테이너는 어떻게 만들어지나(EP6) 대비 write 커버리지 점검
---
> EP6 「컨테이너는 어떻게 만들어지나」 분석 글의 네 절에서 뽑은 64개 원자 항목을 `write/` 전체와 대조했습니다. 45건은 정식 노트에서 다루고, 16건은 일부만 다루며, 3건은 빠져 있습니다.

## 1. 점검 기준과 방법

> 대조 대상은 2026-11-28 기준 `write/` 전체 문서이며 1차 대조와 재검증 두 단계를 거쳤습니다. 외부 요약만 모은 `_digest/` 에만 실린 항목은 정식 학습 노트가 아니므로 `△` 로 판정했습니다.

EP6 관련 보강 범위를 정하려면 먼저 기존 `write/` 문서가 어디까지 다루는지 가려야 합니다. 분석 글 1~4절에서 원자 항목 64개를 뽑아 `write/` 전체와 대조했습니다.

1차 대조에서는 `grep` 검색 뒤 본문을 열어 61개 항목을 판정했습니다. 이어서 2차 재검증으로 Kyverno 판정을 바로잡고 누락 3건을 더해 64건을 확정했습니다. 출처는 2026-11-27~28 대조 작업 보고서(로컬)입니다.

- `O`(다룸): 정식 학습 노트나 참조 문서에서 원리, 절차 또는 실습을 직접 찾습니다.
- `△`(일부): 연관 개념은 있으나 연도·탈출 원리·실습이 빠졌거나 `_digest/` 에만 있습니다.
- `X`(없음): 관련 개념이 없거나 다른 맥락의 우연한 일치만 남은 상태입니다.



## 2. 커버리지 요약과 공백 목록

> 전체 64건 가운데 다룸(`O`)은 45건, 일부(`△`)는 16건, 없음(`X`)은 3건입니다. 개념과 이론은 대부분 정식 노트에 있으나 연도 세부와 호스트 직접 관찰 실습, 벤치마크 스위트가 비어 있습니다.

| 점검 단계 | 다룸 (`O`) | 일부 (`△`) | 없음 (`X`) | 합계 |
|---|---:|---:|---:|---:|
| 1차 대조 | 42 | 16 | 3 | 61 |
| 1차 교정(Kyverno) | 43 | 15 | 3 | 61 |
| 누락 3건 포함 최종 | 45 | 16 | 3 | 64 |

### 없음 3건 요약

- `cgroups` 기원: Google·IBM 이 커널 `2.6.24` 에 넣었다는 귀속만 있습니다. 2006년 연도와 옛 이름 Process Containers 는 없습니다.
- CPU Throttling v1 인터페이스명: v2 의 `cpu.max` (`100000` µs)와 `--cpu-period` 만 다룹니다. `cpu.cfs_period_us` 와 `cpu.cfs_quota_us` 는 없습니다.
- 토이 프로젝트 2번: `runc`·`gVisor`·`Firecracker` 이론 비교 표만 있습니다. 콜드 스타트·메모리·시스템 콜 실측 벤치마크 스위트는 없습니다.

### 일부 16건과 빠진 부분

- `chroot` 등장 기원·연도: Version 7 AT&T UNIX 등장은 있습니다. 다만 `1979년` 연도 표기가 없습니다.
- `chroot` 탈출 한계·원리: 옛 루트가 마운트로 남는 점은 다룹니다. 작업 디렉터리(`cwd`) 잔존을 이용한 탈출 원리와 실습이 없습니다.
- 네임스페이스 8종 연도: Mount(2002)·PID·Network(2008)·User(2013) 연도만 정식 노트에 있습니다. UTS·IPC·cgroup 연도가 없고 Time(2020)은 `_digest` 에만 있습니다.
- Time 네임스페이스: 시계 오프셋과 커널 `5.6` 은 정식 노트에 있습니다. 2020년 표기는 `_digest` 에만 있고 독립 절과 실습이 없습니다.
- `container_cpu_cfs_throttled_periods_total`: `_digest` 2편에 PromQL 한 줄만 있습니다. `06_observability/` 나 `08_cloud/docs/` 정식 관측 노트가 없습니다.
- OverlayFS Copy-up 오버헤드: 통째 복사 원리는 있습니다. 실행 중 대용량·로그 수정의 성능과 디스크 영향은 `_digest` 요약 수준입니다.
- Ephemeral Storage 고갈 예방: 디스크 회계·`emptyDir`·`stdout` 설명은 각각 있습니다. 다만 copy-up 과 연결한 예방 절차가 `_digest` 에만 있습니다.
- 실습 1번 (미니 컨테이너): `alpine-minirootfs` + `unshare` + `chroot` 까지만 실습했습니다. `mount -t overlay` 와 `pivot_root` 통합 랩이 없습니다.
- 실습 2-1 (`cgroups v2` 직접 제한): `cpu.max` 수동 실험은 있습니다. v2 `memory.max` 에 직접 값을 써서 OOM Kill 을 내는 실습이 없습니다.
- 실습 2-2 (`stress-ng` 제한): `systemd-run -p MemoryMax=300M` + `stress-ng` 600M 실측은 있습니다. 스왑 `2G` 허용이라 OOM Kill·CPU 50% 검증이 없습니다.
- 실습 3-3 (`upperdir` 화이트아웃 관찰): `/proc/mounts` 관찰과 `c 0,0` 설명은 있습니다. Docker 삭제 뒤 호스트 `upperdir` 를 직접 본 기록이 없습니다.
- 실습 4-1 (`--cap-drop=ALL --read-only`): 두 옵션을 함께 쓴 배포 예시는 있습니다. 파일 쓰기와 `ping` 차단을 함께 검증한 실험이 없습니다.
- 추천 서적 『How Linux Works』: 2장 `§2.19` 인용과 읽기 계획만 있습니다. 3~8장 정독 노트가 없습니다.
- 필독 강연 *Containers From Scratch*: GitHub·YouTube 링크와 한 줄 요약만 있습니다. Go 소스나 강연 본문 해설 노트가 없습니다.
- 토이 프로젝트 1번 (Go `syscall` 런타임): `_digest` 의 실습 제안 문구(`Cloneflags`·`SysProcAttr`)만 있습니다. 실제 구현 프로젝트나 노트가 없습니다.
- 포트폴리오 2번 (copy-up·Throttling 리포트): `_digest` 에 Throttling 감시 계획만 있습니다. copy-up 까지 묶은 탐지 리포트가 없습니다.



## 3. 항목별 대조표

> 재검증 판정을 반영해 EP6 1~4절의 64개 항목을 일곱 소절로 나누어 담았습니다. 근거 경로는 저장소 상대 링크로 적었고, 본문과 다른 전제나 보충 사실은 빠진 것·비고 열에 남겼습니다.

## 4. 찾은 노트 간 어긋남

> 대조와 실측 과정에서 기존 노트끼리 결론이 부딪히는 지점 두 곳을 찾았습니다. 두 곳 모두 원인만 확인했고 해당 문서는 아직 고치지 않은 상태입니다.

### PID 1 SIGTERM 종료 동작

[2026-09-12_배포할 때마다 잠깐 나오는 502](../troubleshooting/kubernetes/2026-09-12_%EB%B0%B0%ED%8F%AC%ED%95%A0%20%EB%95%8C%EB%A7%88%EB%8B%A4%20%EC%9E%A0%EA%B9%90%20%EB%82%98%EC%98%A4%EB%8A%94%20502.md) 56~58행은 미실행 상태입니다. 이 문서는 PID 1 셸이 `SIGTERM` 에 종료되면 커널이 네임스페이스를 `SIGKILL` 로 정리해 앱이 즉사한다고 적습니다.

반면 [06-03.lifecycle hook과 Pod 생애주기 전체](../08_cloud/book/kubernetes-in-action/06-03.lifecycle%20hook%EA%B3%BC%20Pod%20%EC%83%9D%EC%95%A0%EC%A3%BC%EA%B8%B0%20%EC%A0%84%EC%B2%B4.md) 342~346행은 다릅니다. 핸들러 없는 PID 1 에서는 `SIGTERM` 이 무시되어 유예 시간 30초를 끝까지 버틴다고 적습니다.

OrbStack Docker `29.8.2`(arm64)에서 비대화형 busybox·bash·dash 를 실측했습니다. 핸들러 없는 PID 1 셸은 `SIGTERM` 에 죽지 않고 유예 끝까지 남은 뒤 종료 코드 `137` 로 끝났습니다. `docker stop -t 10` 으로 쟀고, Kubernetes 와 30초 유예는 재지 않았습니다. 즉 `06-03` 346행이 맞고 `502` 노트의 즉사 서술(22·56·58·60행)은 틀립니다.

`502` 서술의 즉사는 실측한 구성 가운데 전달 없이 `exit` 하는 `trap` 이나 `--init` 구성에서만 재현됐습니다. 또한 `shell form` 이면 셸이 PID 1 이 된다는 일반화도 셸 종류에 갈립니다. `bash` 기반 `al2023` 이나 단일 외부 명령을 준 `alpine`·`busybox` 에서는 `exec` 최적화로 앱이 PID 1 이 됩니다. 두 노트 모두 아직 고치지 않은 상태입니다.
