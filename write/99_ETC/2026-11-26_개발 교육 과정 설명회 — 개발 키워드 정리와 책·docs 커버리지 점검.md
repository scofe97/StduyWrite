# 개발 교육 과정 설명회 — 개발 키워드 정리와 책·docs 커버리지 점검
---
> 개발 교육 과정 설명회 녹취 1부·2부에서 나온 28개 주제의 개발 키워드를 바로잡은 용어로 정리하고, `write/*/book`과 `write/*/docs` 1,241개 문서의 커버리지를 4단계로 판정합니다. 1부 끝 분산락 구간과 2부 끝 마무리 안내 구간은 각 녹취가 30분에서 끊긴 지점까지를 범위로 삼습니다.

## 1. 자료 범위와 판정 기준
> 대조 대상은 `write/*/book`과 `write/*/docs` 아래 정식 정리본 1,241개 문서로만 제한합니다. 녹취에 없는 관련 개념과 STT 오인식 용어는 본문과 부록에서 분리해 표시합니다.

설명회 주제마다 정식 문서가 실제 실무 깊이까지 답하는지 가리려면 먼저 대조 경계부터 긋고 판정 기준을 세워야 합니다. 설명회 1부 녹취와 2부 녹취는 각 30분에서 끊겼으며 사이에 빈 곳이 있을 수 있습니다. 이를 기준으로 본문 주제 1~27의 111개와 녹취 범위 밖 주제 28의 1개를 나누어 점검합니다.

- 대조 대상: 10개 분야 `book`과 `docs` 폴더 1,241개 문서
- 분야별 수량: `01_language` 271개, `02_os` 341개, `03_architecture` 75개, `04_messaging` 4개, `05_data` 76개
- 분야별 수량(계속): `06_observability` 54개, `07_devops` 137개, `08_cloud` 243개, `09_spring` 6개, `10_AI` 34개
- 대조 제외: `_` 접두 폴더, `05_data/01_foundation`, `04_messaging/04_BrokerArchitecture`, `09_spring/03_network` 등 기타 폴더
- 경계 표기: 녹취에서 직접 이름을 대지 않은 개념은 `녹취에는 이름이 없음, 관련 개념`으로 구분합니다.
- 중단 표기: 1부 끝 분산락 구간과 2부 끝 특별 안내·Q&A 직전은 각 녹취가 끊긴 지점까지만 정리합니다. 뒷부분은 `녹취 끊김`으로 적습니다.

| 판정 | 기준 | 링크 규칙 |
|------|------|------|
| 다룸 | 설명회가 묻는 트레이드오프나 실무 해결 구조까지 정식 설명 | 관련 문서 1개 이상 연결 |
| 일부 | 원리나 기초만 있거나 Java·Spring·Redis 실무 적용이 빠짐 | 관련 문서 연결 후 빈틈 명시 |
| 언급만 | 본문 전개 없이 용어나 수식 이름만 1~2회 스쳐 감 | 해당 위치 연결 |
| 없음 | `book`과 `docs` 1,241개 문서에 해당 개념 설명이 없음 | `-` 표시 |
| 녹취 범위 밖 | 설명회 녹취에 제목만 나오고 본문 설명이 빠짐 | 커버리지 합산에서 제외 |

## 3. 책과 docs에 없는 키워드
> `없음`으로 판정된 27개 키워드는 1부의 Spring Kafka 운영 세부·Redis Cluster 명령·SQL 진단에 더해, 2부의 사내 SDK 전환·로그 파이프라인 교체·금융 전문 변환·다국어·AI 도구 영역에 몰려 있습니다. 앞으로 보강할 문서를 고를 때 우선순위로 삼을 수 있습니다.

- **Kafka 영역 (4개)**
  - `Parallel Consumer`: 처리 끝난 레코드만 선택 커밋
  - 파티션 증설과 `auto.offset.reset=latest`: 증설 직후 메시지 유실
  - 컨슈머 카나리 전략 및 `Partition Assignor` 무중단 재할당
- **캐시·게이트웨이 영역 (7개)**
  - API 게이트웨이의 `Passport` 내부 토큰
  - Pub/Sub 및 Redis Streams 기반 2단 캐시 무효화 전파
  - Redis 대량 조회 분배 전략과 `mget` 다중 키 일괄 조회
  - 클라이언트 라이브러리 내부 분배 동작, `hash tag` 및 `cluster slot`
  - 캐시 버전업 순간의 cache miss 폭증과 dual write 전환
- **Redis 운영 명령 영역 (5개)**
  - `DEL`과 `UNLINK` 블로킹 차이, `SCAN` 대량 조회 주의, 트리형 키 설계
  - Redis Cluster 노드 다운 시 Lettuce `topology refresh`
  - `SLOWLOG` 기반 Redis·앱 병목 구분
- **DB·락 영역 (4개)**
  - `EXPLAIN` 실행 계획 검증
  - Hibernate interceptor 기반 쿼리 통계·미사용 인덱스 탐지·SQL 주석
  - 락 보호 대상(barrier) 근접 배치와 시간 불일치 장애
  - 단일 Redis `SETNX` 분산락
- **MSA·로깅·보안 영역 (5개)**
  - 사내 공통 SDK 제공 대비 서비스별 독립 HTTP 호출 전환
  - `Logstash`에서 `Vector`로 로그 수집기 교체
  - `Elasticsearch`에서 `VictoriaLogs` 전환 및 Kibana 쿼리 어댑터
  - 외부사 연동 유저키 해시·`IP whitelist`·내외부 보안 증적 분리
  - 금융권 고유 `TCP` 전문 통신 게이트웨이 변환
- **테스트·글로벌·AI 도구 영역 (2개)**
  - 글로벌 다국어(`i18n`) 코드·메시지·DB 다층 통합 관리
  - `Swagger` 기반 `Admin Builder` 및 사내 CS·검수 자동화 AI 에이전트



## 4. Kafka 컨슈머·브로커·운영
> Kafka 기본 구조인 파티션 병렬 처리, 리밸런스, DLQ, 멱등 키, Consumer lag은 책과 docs에 탄탄하게 들어 있습니다. 반면 `Parallel Consumer`, 컨슈머 카나리, 파티션 증설 유실 같은 실무 운영 패턴은 빠져 있습니다.

## 11. 녹취 범위 밖 주제
> 1부에서 보류했던 프로파일러·네트워크·MSA·CPU 4개 영역은 2부 본문으로 모두 이동했습니다. 이제 1부·2부 합산 녹취에 제목만 남고 세부 설명이 없는 `UPF` 1개만 `녹취 범위 밖`으로 남습니다.

### 28. 제목만 언급된 영역
1부 인사말에 스쳐 간 `UPF`는 2부 끝까지 본문 설명이 나오지 않으며, 2부 마지막 특별 안내와 Q&A는 30분 제한으로 `녹취 끊김` 상태입니다.

| 키워드 | 녹취 상태 | 판정 | 참고 |
|------|------|------|------|
| UPF | 1부 도입부에 제목만 스쳐 감 | 녹취 범위 밖 | 녹취에 상세 없음 (기업 기술 컨퍼런스 발표 주제) |
| 특별 안내·Q&A | 2부 30분 제한으로 중단 | 녹취 끊김 | 뒷부분 전사 없음 |
