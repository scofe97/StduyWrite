# OS 주제별 책 읽기 순서
---
> 열 주제 모두 원리(OSTEP) → 리눅스 API(TLPI) → 리눅스 실물·커널 → 성능 → 컨테이너·언어 런타임 순서로 읽습니다. 주제 번호가 곧 권하는 학습 순서이고, 커널·성능 쪽은 노트가 이미 많아 남은 일은 주로 원리와 API 층입니다.

## 표 읽는 법

> 상태 열은 2026-11-19 기준이고, ✅ 는 `write/` 에 노트가 있다는 뜻입니다. 미작성은 책이 Drive 에 있고 노트가 없는 경우이고, OSTEP 은 공식 홈페이지에서 장별 PDF 로 받습니다.

- ✅ 노트는 링크를 걸었습니다. 미작성 장은 장 번호와 원제만 적었습니다.
- 「선택」은 앞 장을 읽고 더 궁금할 때만 봅니다.
- 「(하위)」 행은 따로 주제로 세우지 않고 가장 가까운 주제 안에 둔 항목입니다.
- 같은 내용을 다룬 책이 둘이면 하나만 남기고 다른 하나는 「겹침」으로 적었습니다.

### 헷갈리는 CPU 용어

| 용어 | 뜻 |
|---|---|
| Physical core | 실제 CPU 코어 |
| Logical CPU | OS 가 스케줄링 대상으로 보는 CPU. SMT 를 켜면 코어 하나가 둘 이상으로 보인다 |
| vCPU | 가상 머신에 주는 가상 CPU. 호스트에서는 스레드 하나로 돈다 |
| CPU share | 경쟁할 때만 쓰이는 상대 가중치 |
| CPU quota | 주기(period)마다 쓸 수 있는 CPU 시간의 상한. 넘으면 throttling |
| CPU steal | 게스트가 돌고 싶었지만 호스트가 다른 일을 하느라 못 돈 시간 |

겹침: Virtualization Essentials 의 1~3장(개념 입문)은 OS Concepts 16장과 겹쳐 건너뜁니다. 7·8장은 vCPU 와 메모리 오버커밋을 다뤄 위 표에 넣었습니다.

## 주제가 겹치는 곳

> OSTEP 4·5·6장은 네트워크를 뺀 아홉 주제의 바닥입니다. 어느 주제로 시작하든 이 세 장을 먼저 쓰면 나머지 노트가 이 세 편을 링크로 받습니다.

- TLPI 13장은 파일 시스템과 I/O 에, TLPI 63장(`epoll`)은 I/O 와 네트워크에 같이 걸립니다.
- Container Security 노트는 가상화(namespace)·보안(capability·seccomp)·자원 관리(cgroup)에 나뉘어 걸립니다.
- gVisor 가 목표면 가상화 → 메모리 → 프로세스 순서로 갑니다.



## 넣지 않은 주제

> 동기화, 커널 내부 구조, 시간 관리는 따로 세우지 않았습니다. 앞의 둘은 다른 주제 안에 이미 들어 있고, 시간 관리는 Drive 에 전용 책이 없습니다.

- 동기화와 병렬 처리: 1번 주제의 OSTEP 28~32, Linux Kernel Programming 12~13장, Learn Concurrent Programming with Go 12장.
- 커널 내부 구조와 시스템 콜: 주제마다 흩어져 있습니다. 묶어 볼 때는 [Linux Kernel Programming 정독 인덱스](../02_os/book/linux-kernel-programming/README.md) 에서 시작합니다.
- 시간 관리와 클럭: TLPI 10 Time, 23 Timers and Sleeping 과 How Linux Works 7장이 가장 가깝습니다.
