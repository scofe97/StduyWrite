# 서버 접속 도구 기능과 터미널 대응
---
> 현장마다 쓰는 서버 접속 도구가 다릅니다. 다섯 도구가 SSH 위에 얹은 편의 기능과, 같은 일을 터미널 명령으로 하는 방법을 참고용으로 정리합니다.

저는 맥 터미널에서 `ssh`·`sftp` 를 직접 씁니다. 그래서 이 문서의 목적은 도구 사용법을 익히는 것이 아닙니다. 현장 PC 에서 이 도구들을 만났을 때 어떤 기능이 어느 메뉴에 있는지 짐작하고, 터미널에서는 무엇으로 대신하는지 찾아보는 데 씁니다.



## 1. 도구가 공통으로 하는 일

> 다섯 도구 모두 핵심은 SSH 접속과 SFTP 파일 전송입니다. 도구 사이의 차이는 그 위에 얹은 편의 기능에서 납니다.

도구마다 화면은 달라도 서버와 주고받는 것은 같습니다. SSH(Secure Shell)는 원격 서버에 암호화된 셸을 여는 프로토콜입니다. SFTP(SSH File Transfer Protocol)는 같은 SSH 연결 위에서 파일을 주고받는 프로토콜입니다. 접속 도구는 이 둘에 접속 정보 저장, 탭, 끌어다 놓는 전송, 여러 서버에 같은 명령 보내기를 더합니다.

그래서 도구를 바꿔도 서버 쪽에서 일어나는 일은 같습니다. 인증이 거부되거나 `Permission denied` 가 나면 도구가 아니라 계정·권한·경로를 봐야 합니다.



## 2. 도구별 기능

> SecureCRT·Xshell 은 여러 세션을 한꺼번에 다루는 기능이, Termius 는 기기 간 동기화가, MobaXterm 은 그래픽 창과 파일 창이 강점입니다. PuTTY 는 기본 기능만 갖춘 무료 도구입니다.

| 도구 | 플랫폼·라이선스 | 눈에 띄는 기능 |
|------|----------------|---------------|
| SecureCRT | Windows·macOS·Linux, 유료 | 접속한 탭에서 SFTP 탭 열기(File > Connect SFTP Session). Command 창에서 모든 세션이나 탭 묶음에 같은 명령 보내기. Python·VBScript 스크립트로 반복 작업 자동화 |
| Xshell | Windows, 유료(개인·교육용 무료판은 업무에 못 씀) | Compose Bar 로 현재 세션·세션 그룹·창 안 전체·모든 세션에 같은 문자열 보내기. 로컬 프롬프트(`Ctrl+Alt+]`)에서 `sftp` 실행. 파일 전송 창은 별도 프로그램 Xftp 가 맡음 |
| Termius | Windows·macOS·Linux·iOS·Android | Vault 에 호스트·키·자주 쓰는 명령(snippet)·포트 포워딩 규칙을 저장하고 기기 사이에 종단 간 암호화로 동기화. 좌우 창 사이에 끌어다 놓는 SFTP. 동기화와 snippet 은 Pro 요금제(2026-10 요금표 기준) |
| MobaXterm | Windows, 무료판·유료판 | X11 서버 내장(서버의 GUI 프로그램 창을 Windows 에 띄움). SSH 로그인하면 왼쪽에 SFTP 파일 창이 열리고, 원격 파일을 더블클릭해 고치면 서버에 자동 저장. MultiExec 로 모든 터미널에 동시 입력 |
| PuTTY | Windows 중심, 무료·오픈소스 | 기본 SSH 터미널. 함께 오는 `pscp`·`psftp`(전송), Pageant(키 에이전트), PuTTYgen(키 생성), `plink`(명령줄 접속) |

Xshell 의 "새 파일 전송" 메뉴는 Xftp 를 엽니다. Xftp 가 없으면 설치 안내창이 뜨므로, 내장 SFTP 를 쓰려면 위의 로컬 프롬프트로 갑니다.



## 3. 터미널로 같은 일 하기

> GUI 도구의 편의 기능은 대부분 OpenSSH 설정과 `tmux` 로 대신할 수 있습니다. 끌어다 놓는 전송만 명령으로 바뀝니다.

| GUI 기능 | 터미널 대응 |
|---------|------------|
| 세션(호스트) 저장 | `~/.ssh/config` 에 `Host` 별칭을 적고 `ssh 별칭` |
| 키·암호 관리 | `ssh-agent`, `ssh-add` |
| SFTP 탭, 끌어다 놓는 전송 | `sftp`, `scp`, `rsync` |
| 탭, 여러 세션에 동시 입력 | `tmux` 창 나누기와 `synchronize-panes` |
| 포트 포워딩 | `ssh -L`(로컬), `-R`(원격), `-D`(SOCKS 프록시) |
| 서버 GUI 창 띄우기 | `ssh -X` (맥은 XQuartz 설치 필요) |
| 세션 기록 | `script`, `tmux` 의 `pipe-pane` |

세션 저장은 `~/.ssh/config` 한 곳에 모읍니다. 한 번 적어 두면 `ssh`·`sftp`·`scp`·`rsync` 가 모두 같은 별칭을 씁니다.

```bash
# ~/.ssh/config
Host dev
    HostName dev.example.com
    User deploy
    Port 22
    IdentityFile ~/.ssh/id_ed25519
```

```bash
ssh dev                                             # 접속
sftp dev                                            # 대화형 전송
rsync -avP ./artifact.tar dev:/remote/target/       # 끊겨도 이어받고, 진행률 표시
tmux setw synchronize-panes on                      # 현재 창의 모든 pane 에 같은 입력
```

`sftp` 프롬프트에서는 앞에 `l` 이 붙은 명령이 내 PC 쪽, 붙지 않은 명령이 서버 쪽입니다.

| 서버 쪽 | 내 PC 쪽 | 하는 일 |
|--------|---------|--------|
| `pwd` | `lpwd` | 현재 폴더 보기 |
| `cd` | `lcd` | 폴더 이동 |
| `ls` | `lls` | 목록 보기 |
| `get 파일` | `put 파일` | 서버→PC 받기 / PC→서버 올리기 |

`put` 은 지금 있는 서버 폴더에 올립니다. 그래서 올리기 전에 `pwd` 로 위치를 확인합니다. `cd root` 처럼 `/` 없이 쓰면 현재 폴더 아래의 `root` 를 찾으므로, 절대 경로는 `/` 로 시작합니다.



## 4. 전송 확인과 주의

> 진행률 표시는 완료가 아닙니다. 서버 목록에서 파일명과 크기를 보고, 배포 파일이면 해시까지 비교합니다.

GUI 의 진행률 화면이나 "Drop files here" 표시는 전송 중이거나 놓을 자리를 가리킬 뿐입니다. 끝난 뒤 서버에서 `ls -l` 로 크기를 보고, 동일성이 중요한 배포 파일이면 양쪽 해시를 비교합니다.

```bash
shasum -a 256 artifact.tar                          # 맥
ssh dev 'sha256sum /remote/target/artifact.tar'     # 서버(Linux)
```

전송이 막힐 때는 증상에 따라 확인할 곳이 다릅니다.

- 인증 거부: 호스트·계정·인증 방식을 확인합니다. 반복해서 다시 시도하기보다 담당자 확인이 먼저입니다.
- `No such file or directory`: `pwd`·`lpwd` 로 위치를 봅니다. 서버 경로에는 `cd`, 내 PC 경로에는 `lcd` 를 썼는지도 봅니다.
- 올렸는데 안 보임: 올린 폴더와 `ls` 를 실행한 폴더가 같은지 `pwd` 로 봅니다.
- `Permission denied`: 대상 폴더의 쓰기 권한을 확인합니다. 권한을 넓히거나 관리자 계정으로 우회하지 않습니다.

비밀번호와 개인 키는 문서·스크린샷·명령줄에 넣지 않습니다. 키는 `ssh-agent` 나 승인된 비밀정보 저장소에 둡니다.
